# ⚓ Blockside（方舷）

哼，歡迎上船。這裡是本小姐的海 —— 每一艘船都是用方塊一格一格雕出來的風帆戰艦，0.1 公尺一格、整艘照實際尺寸。
砲彈打到哪裡，哪裡的格子就碎掉飛出去；打斷桅杆帆就掉、打穿水線船就進水，進得夠多就沉。

**▶ 線上玩：https://tim099.github.io/Blockside/**

（單一網頁、零外部依賴，下載完直接在瀏覽器跑；第一次載入約 4 MB，請耐心等「開戰」按鈕亮起來。電腦玩最好，手機也有畫面上的按鈕。）

名字的由來：broadside（側舷齊射）→ **block**side。想要正式一點也可以叫 *Old Blocksides* —— 致敬憲法號的綽號 Old Ironsides。

## 🌊 這片海有什麼

- **一格一格的破壞**：船殼、甲板、桅杆全是格子。實心彈打穿船殼、爆裂彈炸開甲板、鏈彈撕帆；碎木片會飛出去，打斷的那一截船身會分離漂走。每一格有自己的材質（橡木、松木、鐵甲、包銅皮…）：鐵甲的洞小、砲彈在裡面停得快，也重得多。
- **會進水、會沉**：水線下的破洞照洞的大小與深度灌水，水往低處流、船往進水那一舷傾斜；抽水跟不上就沉。彈藥庫被打中會殉爆（慢動作特寫）。
- **帆與繩是物理**：帆吃風鼓起來、繩會垂、被打斷就鬆脫；帆桁跟著風轉，收帆（W／S）決定快慢。
- **船上的人**：砲班、送藥手、陸戰隊、軍官、舵手、預備水手 —— 照甲板與梯子找路，缺人就補位；傷員會被搬到醫療艙，治好再回來。落水的人會游回船上。有廚房的船（光榮號）多一位廚師：預備水手輪流當伙夫去爐灶領飯，吃過的那一桌**工作效率** ×1.1（裝填、抽水、修補、救火都快一成），廚師倒下就斷炊。
- **艦隊**：我方與敵方各自編隊，同時在場最多 16 艘，沉了的由候補遞上；每一方有一位指揮官下令，砲長各有個性（先打水線、先打甲板人員、先打桅…）。
- **天氣**：晴天或暴風雨（雨、閃電、大浪、風會轉）。
- **自己調**：船隻配置頁（船員組成、艙房擺什麼、航速與硬度）、砲的設定頁（傷害、重量、裝填、連發數…）、畫質與物理設定，全部存在你的瀏覽器裡。

## 🔧 給好奇的人

- 原始碼在 `src/`（`template.html`、`js/`、`config/game.json`、`admin.py`、工具）；成品 `index.html`（入口）＋ `ships/`（每艘船一個檔，要用才載）由 `python -I src/admin.py build` 產生 —— ⛔ 不要直接改 `index.html`；`ships/` 跟 `index.html` 一起提交（`git add -A ships index.html`），搬成品也要連 `ships/` 一起。開發說明：[`src/README.md`](src/README.md)。
- 設定後台：雙擊 `admin.cmd`（＝ `python -I src/admin.py serve --open`，只聽本機）。
- 船是雕刻區的作品匯出的 `.vxk`（`VoxelKit/_cache/`，不入版控；換機器 ⇒ `python -I src/admin.py cache` 從作品重新匯出、跟指紋比），內嵌在網頁裡；同一份模型（例如同一門砲）幾艘船只存一次，所以六艘船擠得進幾 MB。
- 2026-10-15 以前在 ArtGallery 開發（`HtmlGames/_build/ame_constitution_broadside/`，歷史還在那邊的 git log）。
- 部署：正式站（Blocksail 那份叫 `release`，Valhalla 那份舊的叫 `origin`）push 到 `main` ⇒ GitHub Actions（`.github/workflows/pages.yml`）上傳到 Pages；`dev`（測試站）照分支部署，見下面第 2 步。
- **分支與發版**（Tim 2026-10-17：「預設開發時都是先 merge 到 dev 然後 push 到 dev，dev 測試版本 ok 後再發版本到 main」）：
  0. **開發用的工作副本在 Blocksail 的 `external/Blockside`**（Tim 2026-10-20：「之後我希望Blockside開發直接在Blocksail的submodule內開發(確保同步)」）：
     - submodule checkout 在 `dev` 分支（不是 detached），它就是「共用工作區」；worktree 從它開：`git -C <Blocksail>/external/Blockside worktree add <路徑> -b <分支> heads/dev`。
     - 船的 `.vxk`（`VoxelKit/_cache/`）也放在這一份。
     - Valhalla 裡的 `Blockside/` 不再開發，只會落後。之前從它開的 worktree：分支推上 `dev` 遠端，或在這一份 `git fetch` 那個 repo 的分支再合。
     - 這一份的遠端：`origin` 和 `dev` 都是測試站那個 repo（`.gitmodules` 記的網址），正式站叫 `release`。
  1. **開發合回 `dev`**：`dev` 分支是開發主線。改程式照施工場規則開自己的 worktree（從 `dev` 開，見上一條），做完**合回 `dev`**（不是 `main`）；合併那一步在共用工作區（Blocksail 的 `external/Blockside`）照合併後的 `src/` 重建 `index.html` 再提交（那台沒有 `VoxelKit/_cache` ⇒ `python -I src/admin.py build --code`：只重建入口、船檔照舊，船變了它會擋 ⇒ 要在有 `_cache` 的機器整份建置；見 `src/README.md`「建置」）。換行一律 LF（`.gitattributes`），新 worktree 不用轉換；成品裡記著它是照哪些來源建的，`python -I src/admin.py srccheck` 對得回來（裝了鉤子 ⇒ 提交到 `dev`／`main`、推到 `dev`／`main` 前自動檢查，見 `src/README.md`）。
  2. **推測試站**：`git push dev heads/dev:dev` —— `dev` 遠端的 Pages 設成「Deploy from a branch：`dev`／root」（Tim 2026-10-17 改的），推上去就部署，不走 `pages.yml`。⚠ 遠端和分支都叫 `dev`，只寫 `dev` 時 git 會報 `refname 'dev' is ambiguous` ⇒ 本機分支一律寫 `heads/dev`。⛔ 不用再把 `main` 推到 `dev` 遠端：測試站照 `dev` 分支部署，推 `main` 不會更新它。
     **推完接著讓 Blocksail 同步**：在 Blocksail `git add external/Blockside`、提交（`chore(external): Blockside → <sha>`），Blocksail 才記得新的這一版（`tools/check_core.py` 會檢查）。推 Blocksail 的遠端照 Blocksail 的規矩（Tim 說才推）。
  3. **發版**：Tim 在測試站驗過、說要發 ⇒ 共用工作區 `git switch main`、`git merge --ff-only heads/dev`（快轉不了就停下來問），再 `git push release main`（Valhalla 那份舊的工作副本叫 `origin`）⇒ 正式的 Pages；做完 `git switch dev` 切回開發主線。
  - ⛔ 推之前先 fetch、列出要推的提交（測試：`git log dev/dev..heads/dev`；發版：`git log release/main..main`）。**底下有別人還沒推的提交 ⇒ 一起推**（Tim 2026-10-20：「需要push時 一起推(包含別人commit的改動)」），回報時點名是誰的哪幾筆；⛔ 不另做一份只含自己那筆的提交去推、不 force push。發版（推 `origin` 的 `main`）照舊只在 Tim 說要發的時候。
  - 遠端：`dev` ＝ 開發用、公開但不宣傳的測試環境；`release` ＝ 正式公開（Blocksail 的 submodule 裡 `origin` 也是測試站；Valhalla 那份舊的工作副本 `origin` 才是正式）；另有 `private`（之前的測試環境，不再預設）、`gitlab.com`。網址看 `git remote -v`，⛔ 不寫進文件、提交訊息。
