# 海戰核心 API（TASK-0709）

外殼（Blockside 的主選單；之後別的遊戲把 Blockside 當核心引用）跟海戰核心講話只走這幾個入口：
**戰後狀態**（打完每艘船剩什麼）、**戰前狀態**（帶著上一場的傷開下一場）、**中途加船**（不重開場景）。
程式在 `js/57_core.js`；開局套上戰前狀態的那一格在 `52_fleet.js spawnFleet`。

⛔ 三個入口都**不抽亂數**：沒帶戰前狀態、沒加船 ⇒ 戰局跟沒有這支檔之前逐位元組相同（8 組對拍，§6）。

## 1. 版本

- `CORE_API`（現在 **1**）：格式或語意改了就加一。外殼開局前先比，不認得的版本就不要把存檔餵進來。
- 每一份戰後狀態都帶 `api`；船型另外帶指紋（`sum` ＝ `.vxk` 檔頭的 checksum）—— 同一艘船重新匯入過、格子變了 ⇒ 船殼差對不上，核心**不套船殼差**、記一行在 `log`（模型、帆、繩、船員照套）。

## 2. 戰後狀態 `coreOut()`

```js
{ api: 1, seed, t,            // 種子、打了幾秒
  over, down: { blue, red },  // 這一場結束了沒、每一方是不是全部出局（52_fleet.js teamDown）
  ships: [ <船>… ],           // 照 SHIPS 的順序（開局的、候補進場的、中途加的都在）
  log: [ "…" ] }              // 這一場開局套戰前狀態時對不上的（船型、指紋、編號、人數）
```

一艘船：

| 欄位 | 意思 |
|---|---|
| `hull`、`sum`、`name`、`team`、`i` | 船型代號、船型指紋、船名、陣營（`blue`／`red`）、在 `SHIPS` 的編號 |
| `fate` | `afloat` 還在打／`struck` 降旗／`sinking` 在沉（救不回來）／`sunk` 沉了／`broken` 斷成兩截（彈藥庫殉爆）；`why` ＝ 遊戲寫的原因（`sh.fate`） |
| `at` | 最後的位置 `px`、`pz`（公尺）、船頭 `yaw`、航速 `spd` |
| `cells` | **船殼跟原船的差**：`n` 幾格不同、`gone` 其中幾格被打掉、`d` ＝ base64 的 `n` 筆 5 位元組 —— `[跟前一格的線性索引差 u32 LE, 值 u8]`；線性索引 ＝ `x + sx·(y + sy·z)`（船型格子的尺寸），照索引由小到大；值 0 ＝ 打掉，其他 ＝ 現在的顏色（燒焦換色、木匠補回來的） |
| `models` | 跟開局不一樣的模型（砲、火藥桶、舵輪、帆桁、小艇…）：`{ k, id, kind, hp, alive }`；`k` ＝ 船型模型表的位置，`id` ＝ 物件 id（TASK-0715；沒有 ＝ 空字串，只靠 `k`） |
| `sails` | 被打過的帆：`{ k, hp, dead }` |
| `ropes` | 斷了的繩（船型繩表的位置） |
| `masts`、`guns` | 還立著的桅 `up`／共 `n`、還在的砲 `alive`／共 `n`（都是讀數 —— 戰前狀態不存，開局照格子與模型重推） |
| `crew` | 每個職位（`GUN`、`POWDER`、`OFFICER`、`MARINE`、`TOP`、`HELM`、`HAND`、`SURGEON`、`CARPENTER`、`SAILMAKER`、`OAR`、`COOK`）：`n0` 開局編了幾人、`able` 現在站得住幾人。游到敵艦的人算在敵艦那邊（`n0` 沒有、`able` 有） |
| `cas` | 這一場的陣亡 `dead`、現在的傷員 `wounded`、游走的 `lostTo`、游過來的 `gained` |
| `used` | 開了幾發 `fired`、打中幾發 `hits`、送了幾包火藥 `cart`、木匠用了幾份木材 `wood`、炸掉的彈藥庫 `magGone` |

> 讀法：`n0 − able` ＝ 這一場少掉的人（陣亡、傷員、被抬下去、落水、游走）。哪些人下一場回來（醫好、補員）是外殼的事。

## 3. 戰前狀態

```js
{ blue: [ <船的戰前狀態>… ], red: [ … ] }   // 每一方照「在場的順序」對：第 j 個給那一方開局在場的第 j 艘
<船的戰前狀態> = { hull, sum, name, cells, models, sails, ropes, crew: { <職位>: { out: 幾人不在船上 } } }
```

- `corePreFrom(戰後狀態)` 直接轉：還在海上的（不是 `sunk`／`broken`／`sinking`）照每一方原本的順序排，`crew[職位].out ＝ n0 − able`。外殼要改什麼（修好幾格、補幾個人）改這一份就好。
- 給核心的三種方法：
  - 網址 `#pre=<base64url(UTF-8 JSON)>`（`?start=1` 外部開戰、`?demo` 無頭對拍都認）；太長塞不進命令列 ⇒ 開一頁小的跳轉頁 `location.replace(…)`（src 外的對拍腳本就是這樣帶的）。
  - `?debug=1` 的 `__game.core.pre(P)`，之後 `__game.start()`／`__game.fleet(…)` 那一場開局生效（`pre(null)` 清掉）。
- 開局怎麼套（`coreShipIn`，`makeShip` 之後、第一次 `survey` 之前）：
  - 船殼差照格寫回（打掉 ⇒ `removeVoxel`；換色 ⇒ 改顏色；原船沒有 ⇒ `restoreVoxel`）：進水、尋路、破口照常更新 ⇒ 開局就從那些洞進水。
  - 模型：血量照存的；`alive: false` ⇒ 一開始就不在（不放碎片、不殉爆）。
  - 帆：血量照存的、`dead` ⇒ 一開始就沒有（⛔ 不走 `dropSail`：它撒布片要抽亂數）；斷的繩照標。
  - 船員：照職位從名單後面往前，`out` 個人標成不在船上（`st = 3`、`preOut`）—— 這一場的陣亡、傷員從 0 算；砲班少人照常由預備水手補位。
  - 桅倒沒倒、砲還在不在、模型腳下沒了要掉、繩端沒了要斷 ⇒ **不存**，接著跑的 `survey` 照格子重推（32_hull.js），不存兩份。
- 對不上就不套那一項、記一行在 `CORE_LOG`（下一份 `coreOut().log` 帶出去）：船型不同 ⇒ 整艘不套；指紋不同 ⇒ 船殼差不套；模型的 `id` 對不上 ⇒ 那一個不套；人不夠少 ⇒ 少到沒得少。

## 4. 中途加船 `coreAdd(o)`

```js
coreAdd({ team: 'red', hull: 'monitor', x, z, yaw, name, pre })   // ⇒ 那艘船（sh.addMs ＝ 這一步幾毫秒）；船型沒載好、戰局結束了 ⇒ null
```

- 不重開場景：照候補進場（`spawnReserve`）同一套 —— 開船、套戰前狀態（`pre`，可以不給）、放進 `SHIPS`、第一步、`survey`、砲長、指揮官重排、重挑對手。
- `x`／`z`：世界座標（公尺）；`yaw` 沒給 ⇒ 船頭對著敵方還在打的船的中心。
- 船型要先載好（`__game.loadHull(id)`）。
- ⚠ 開船會抽亂數（相位、裝填、船員）⇒ 加船那一刻之後跟沒加的那一場不同；**同一個時刻加同一艘 ⇒ 照樣逐位元組重現**（§6）。
- 無頭對拍：`?demo=120&core=1&coreadd=red:monitor@60`（多艘用逗號）⇒ 第 60 秒在我方第一艘旁邊加；`#core` 的 `added` 記時間、耗時、加船那一步既有的船有沒有被動到（`same`）。

## 5. 不帶的東西（這一版）

- **砲帶的裝甲**（24_armor.js，莫尼特號、哨兵號、維吉尼亞號）：裝甲格子另外一份網格，戰後狀態沒存它的差 ⇒ 下一場裝甲是新的。
- **火**（49_burn.js）、**艙裡的水**（33_flood.js 的水量）：當作兩場之間撲滅、抽乾；洞還在 ⇒ 開局照洞重新進水。
- **帆的撕洞**（物理開著時的布，30_rig_physics.js）：只帶血量與掉了沒。
- **半截船、斷開的那一團**（22_pieces.js `PIECES`）：不是船、不帶；斷成兩截的船 `fate: broken`，不進下一場。
- **被俘**：核心沒有這個旗標。降旗的船留在海上 ⇒ 外殼照 `fate: struck` ＋ 哪一方贏了（`down`）自己判。
- **彈藥**：砲旁的箱子每場重裝，送藥手照常補（核心的彈藥本來就不會用完，只有彈藥庫炸掉才斷）。
- **候補**（`RESERVE`）不收戰前狀態；要帶傷進場 ⇒ 用 `coreAdd` 的 `pre`。
