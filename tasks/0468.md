# TASK-0468 — 同一棵資料根上可以起第二顆同 id 的 Server（副本／測試用）—— Discord 重送、Inbound 互搶；另開的 Server 在管理頁看不到

## 任務描述

誰在等：Tim。⚠ 細節 Tim 還在想（測試用 Server 怎麼辦），**拍板前不動工**。

## 現象（2026-10-08 12:00～12:01 量到）
Discord 上 tavern seq 22623／22627／22630 各出現兩次，自由時間訊息密集時頻繁發生。

## 成因（已指認，讀數在兩份日誌）
- 主 Server：tavern pid 54360、main pid 19212（`D:/Unity/Senate/publish/server/senate-server.exe`）。
- 第二套：erina 的 session 在自己 scratchpad 放了一份 Senate 副本（`…\4cf0c773-…\scratchpad\wt\`），10:24 用 Debug exe 起了 main（50772）＋ tavern（32548）。
- 兩份的資料根都是 `D:/Unity/Valhalla` ⇒ 兩顆 tavern 都跑 Discord Outbound、共用 `ChatTavern/discord/discord_backfill_state.json`（無鎖）⇒ 同一輪都讀到舊游標就各送一次。
  兩份日誌各有 `📤 tavern seq 22627 → ChatTavern / #guild` 一行。
- 同時發生：Discord Inbound 互搶 `discord_inbound_state.json.tmp`（IOException）、酒保／Gateway 雙開、`_server_endpoint.tavern.json` 被輪流覆寫；兩顆 main 都可能跑每日結算（推測，未驗）。
- 擋不住的原因：`server start` 的單例鎖（`ServerHost.TryAcquireSingletonLock`）與 registry 都在**各自 repo 的 runtime**，看不到同一棵資料樹上的另一份。ProcessAdminPage 也只列本 repo 的 registry（Tim 截圖：只看得到 19212／54360）。

## 候選修法（待 Tim 拍板）
1. **資料樹層級單例鎖**：`<資料根>/_server_singleton.<id>.lock`，FileShare.None 握到 process 結束；拿不到就拒絕並印握著的 pid。
2. **名片不蓋活的**：寫 `_server_endpoint.<id>.json` 前 Probe，心跳新鮮且不是自己 ⇒ 不覆寫。
3. **執行中自檢**：Discord 收發／酒保／每日結算每輪確認名片 pid＝自己，不是就停手（防沒有 ① 的舊 exe）。

## Tim 提出的待定細節
- **測試用 Server**：可能需要另開測試 Server。要決定它怎麼跟正式那顆共存 —— 例：測試 Server 必須指向另一棵資料根（暫存樹）才放行、或有顯式的「測試」身分不跑資料樹單例工作（Discord／酒保／結算）。
- **看得到**：另外開的 Server（不同 repo 根／副本／測試用）**至少要出現在 SCP_GuiProcessAdminPage 與 ServerAdminPage**。現在兩頁只讀本 repo 的 registry ⇒ 要有資料根層級的登記（名片或鎖檔旁的登記）讓兩頁讀得到別份。
