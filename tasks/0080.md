# TASK-0080 — AutoCommit 撞 index.lock 讀數同形於「沒東西可收」：commits=0 且 blocked_repos=0（BUG-47）

> `bug` / `normal` / `done`　開單：summit　參與：gura(dev)、gura(qa)

## 驗收標準

- [x] 撞鎖時 blocked_repos>0（或獨立欄位/明確錯誤），不再與空掃描同形
      ⇒ 實作走「獨立欄位」：`failed_repos`（逐筆 `repo[群] 操作：<stderr 首行>`）＋ `locked_repos`（撞鎖筆數），
        並讓那一輪判 **Failed**（不是 Success）。`blocked_repos` 保留原語意（scan 階段就擋下的 repo），沒有被挪用。
- [x] 重現：手動持鎖跑 op=commit，讀數可分辨且指出哪個 repo 被鎖
- [x] 反向對照 ①：同一個 repo **無鎖** ⇒ failed_groups=0／locked_repos=0／failed_repos=（空）
- [x] 反向對照 ②：真的沒東西可收 ⇒ candidate_files=**0** ⇒ 與撞鎖那一輪在機讀值上互不相同
- [x] 新欄位 **0 也印**（比照既有欄位；只在非零時出現的欄位，讀者分不出「乾淨」與「沒量」）

## 任務描述

op=commit 撞到 index.lock（別人正在跑 git）時四個計數全 0＋Success ⇒ 與「本來就沒東西可收」完全同形，當時實際有 27 個可收檔。失敗要可分辨。溯源：0047.md（已關）。

## 結單說明

撞鎖已有獨立機讀欄位 failed_repos / locked_repos 並判 Failed，指出哪個 repo、哪一群、原文 stderr；三種形狀（撞鎖／無鎖／空掃描）機讀值互不相同。commit 8e33425b。

**QA 代簽紀錄**：QA=gura，⚠ **dev 與 QA 是同一個人**（Tim 指示 dev+QA 全包）—— 原樣寫出不抹平。手動持鎖實跑三格對照見留言 #1；⚠ 開單描述的前提有一半在 2026-08-31 已被 summit 修掉（失敗已判 Failed），今天補的是『哪個 repo、為什麼』那一半，留言 #1 已更正前提。反向對照②用 op=scan，其 commits 恆為 0 是常數不是讀數，已標明。

\## 逐格讀數（實跑；鎖是我自己造的、我自己刪 —— ⛔ 沒有碰任何別人的 lock）

測試標的刻意選**我自己的信件庫 repo**（`mode=letters --arg only_persona=gura --arg include_online=1`）
—— 單一 repo、資料是我自己的，不會波及別人的樹。

| # | 情境 | result | commits | failed_groups | **locked_repos** | **failed_repos** | candidate_files |
|---|---|---|---|---|---|---|---|
| ① | **手動持鎖** 跑 `op=commit` | **Failed** | 0 | 1 | **1** | `` gura[profile] git add：fatal: Unable to create '…/letters/gura/index.lock': File exists. `` | 5 |
| ② | 反向對照：同 repo **無鎖** | Success | 0 | 0 | **0** | （空） | 5 |
| ③ | 反向對照：**真空掃描**（`mode=submodules`） | Success | 0 | 0 | **0** | （空） | **0** |

⇒ 三種形狀**在機讀值上互不相同**。開單時那句「與空掃描完全同形」現在無論比哪一欄都不成立
（①比②差在 `locked_repos`／`failed_repos`／`result`；②比③差在 `candidate_files`）。

📌 ②我用 `op=scan` 而不是 `op=commit` —— **理由是刻意的**：無鎖的 `op=commit` 會真的提交我的信件庫，
而我不想為了打一個勾在別人的樹上留下一筆沒有人要的 commit。
⚠ 代價要講明：`op=scan` 的 `commits` **恆為 0**（它不提交），所以②那一列的 `commits=0` **不是讀數，是常數**。
真正在②做事的是 `failed_groups` / `locked_repos` / `failed_repos` 三欄。

\## ⚠ 誠實標邊界（新欄位自己的失效形狀）

`locked_repos` 是**字串比對** stderr 認出 `index.lock` 的。git 換了訊息就會漏認 ——
那時它退化成 0，而 `failed_repos` 仍然在（原文照登）。
⇒ 漏認的形狀是「**少一格分類**」，不是「靜默通過」。這是我選字串比對而不是自己造 error code 的理由：
最壞情況退回今天已經有的那一格，而不是退回開單那天的空讀數。
