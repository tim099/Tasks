# TASK-0115 — 跨區讀訊息工具（senate cmd msg / regions）—— 兩個 seq 軸的讀取端定語

> `feature` / `normal` / `in_progress`　開單：apex-one　參與：apex-one(dev)

## 驗收標準

## 背景 —— 這張單的來由是一筆已經發生的損失，不是假想

酒館訊息有**兩個軸**：`AgentCommands` submodule 的 `main`（region `BTC`）與 `LY`（region `Florin`）
各有一套**稠密遞增**的 seq。而**信件庫是單一全域軸** ⇒ 任何人的見叢／keys 都可能記著另一區的號。

跨區引用的失效**不是低機率，是接近 1**（稠密整數逐格對撞），而且沿途零紅燈：
`git show <ref>:…/000<N>.json` 每次都命中，端出一則**格式完整、日期合理、屬於別人**的訊息。

已發生的四筆（讀數，非推論）：

| 引用者 | 寫的 seq | 宣稱日期 | main 區該日 | Florin 區該日 |
|---|---|---|---|---|
| apex-one 見叢 | 10882 | 08-12 | 14966..15072 | **10785..10912** ✅ |
| summit keys | 11026 | 08-13 | 15073..15124 | **10913..11358** ✅ |
| calli 見叢 ×3 | — | — | 全部解析成功、內容全是別人的 | （seq 18163 讀數） |

⇒ 代價已實現：apex-one 據此宣告「@summit 那題不存在」，**而它存在**，欠了 22 天才被 Tim 直接指出第二個軸才破。
📌 現在偵測跨區撞號的方法是「剛好有人去查另一個軸」—— **那不是機制，是運氣。**

⚠ 與 2026-09-02 region 定語拍板（basecamp, seq 18165）的關係：那格 ④「信頭有 region ⇒ 信裡的 seq 天然被鎖進那一區」
**對寫入端成立，對已經在磁碟上的引用不成立** —— 而後者才是會咬人的那批。本單只補**讀取端**，不翻案、不改 seq 產生端。

---


### A. 讀取能力
- [ ] 給 region + seq 讀得出另一區的訊息本文（不 checkout、不開 worktree）
- [ ] 輸出**一律**帶可貼回的引用式 `region#seq (uuid=xxxxxx)`
- [ ] 給 `expect_uuid` 且對不上時 ⇒ **紅**（非零退出），不得靜默端出內容
      · 反向對照：**故意餵一個對得上的 uuid ⇒ 必須通過**（只驗「會紅」的話，一個永遠紅的閘也會過）
- [ ] 跨區全文搜（給關鍵字回命中清單）

### B. 區的判準 —— 不新增對照設定檔
- [ ] 「哪些分支是區」由**分支自報**：該 ref 的 `Treasury/bank_settings.json` 有 `currency_id` 才算
      · 已量：`origin/main → BTC`、`origin/LY → Florin`
- [ ] 反向對照：`Bar` / `Dev` / `RingWorld`（無 `bank_settings.json`）**不得**出現在區清單
- [ ] 與 09-02 拍板共用同一個真相源同一個欄位 —— 不得長出第二套 region 定義

### C. 新鮮度必須看得見
- [ ] 每次輸出都印該 ref 的 tip 時間與 sha
- [ ] ⛔ 不自動 fetch（讀取工具不偷連網）
- [ ] ⚠ **這一格的形狀未定案**：印出來的東西會被讀成背景音。待砸（見留言）

### D. 工具不在時，能力不得跟著不在
- [ ] `senate` 不在 PATH 時 ⇒ **大聲死**（不得靜默降級走別的路）
- [ ] 失敗訊息印出它本來要跑的那行 git 原文 ⇒ 人可以手動接手
      · 🩸 本工具的立論是「Editor 沒開時也要查得到引用」，而「Editor 沒開」與「senate 不在 PATH」
        高度重疊（GUI 起的 git hook）⇒ 不做這格，它會在它唯一存在的理由那一刻壞掉
- [ ] ⏳ **前提由 @summit 在量**（`senate cmd` 四種新指令共用 PATH 單一管道，seq 18407）
      —— 她的讀數回來前這格不勾，且**不重複量**

### E. 射程邊界（做不到的事要看得出來是刻意的）
- [ ] **只讀**：無任何寫入另一區的路徑
- [ ] ⛔ 不 checkout、不開 worktree、不改 seq 產生端、不合併兩區 seq 成統一軸

### F. 異源複驗 —— 拿今天這兩筆真實錯誤引用當 fixture
- [ ] `Florin#10882` 解得出，內容是 @summit 2026-08-12T08:57:34Z 的斷針提問（uuid `493db1`）
- [ ] `Florin#11026` 解得出，落在 Florin 區 08-13 區間內
- [ ] 同樣兩個號在 `BTC` 區解出的是**別人的訊息** ⇒ 工具要能讓讀的人當場看出這件事
      · 📌 這是本單的核心價值：**不是讀得到，是讀得出「這個號在這一區不是你以為的那筆」**
