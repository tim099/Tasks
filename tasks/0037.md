# TASK-0037 — op=show 摘要加「最後留言」行 —— 讓「有人回了而我沒讀」變成機械而非自律

> `improvement` / `high` / `todo`　開單：basecamp　參與：summit(dev)、basecamp(qa)、gura(design)

## 驗收標準

PM 裁決（basecamp 2026-08-25）：採 @gura 的規格（企劃 seq 13828 第③題）。
🩸 這張單的血證是 PM 自己。

## 現場

2026-08-24 07:21 我在 TASK-0001 的收工留言寫「還剩：**等 @summit 回我早上那份 QA 意見**」。
而她的回覆是 **04:15** —— 早了三小時零六分。
⇒ 我在她已經回話之後宣告「在等她」，照那句話收工、隔天照那句話排優先序，**單卡一天**，
還連帶把 TASK-0002 一起卡住。

**這張單卡的不是她的回覆，是我沒讀。**

## 為什麼修法不能是「我下次會記得先跑 op=show」

那是**自律**。而這桌的判準是：**攔截來源只有兩個 —— 別人站的位置、長在必經路上的機械。**
自律不在名單上。

⚠ 而 @summit 開這題時說得比我準：
> **「留言有沒有送到」跟「她有沒有讀」是兩個量**，而目前只有前者有機械。

## 讀數（2026-08-25 實測，不是印象）

`op=show <n>` 的**摘要區**（單檔全文之前）**沒有這一格**。
資訊只在下面的單檔全文裡 —— 而 TASK-0017 的全文現在已經好幾千字。
⇒ **掃摘要的人看不到「有人在你上次動作之後回話了」。**

## 規格（@gura 裁決，PM 收下）

摘要區加一行：
```
💬 最後留言：<persona> @ <MM-DD HH:mm>（⚠ 在你上次操作之後有新留言 ／ 你已是最新）
```

**基準＝「當前操作者（caller）在這張單上的最後一次動作」**（留言／wrapup／claim／update 皆算）。

📌 為什麼是這個基準而不是「我的 wrapup」或「我的留言」：
後兩者**只對特定人成立**（沒 wrapup 過的人拿不到基準）；
**「我在這張單上最後做過什麼」對每一個讀的人都成立。**
⇒ PM 原本在企劃討論裡明說「這格我沒有答案」，這是 @gura 補上的。


- [ ] `op=show` 摘要區印出最後一則留言的 **persona ＋ 時戳**
- [ ] 與 caller 的最後動作時戳比對，**兩種結果形狀不同**（不是只有字不同）
- [ ] 讀數 A：由**留言者本人**跑 `op=show` ⇒ 應顯示「你已是最新」
- [ ] 讀數 B：由**另一個參與者**跑 ⇒ 應顯示「⚠ 在你上次操作之後有新留言」
- [ ] 讀數 C：**從未在這張單上動過**的人跑 ⇒ 第三種形狀
      （「沒有基準可比」不可以印成「你已是最新」—— 那是今天抓了一整天的同形）
- [ ] 零留言的單 ⇒ 第四種形狀，且不可印成「你已是最新」
- [ ] **📎 關聯文件帶到單子上**（Tim 2026-08-25「單子可以關聯相關文件」）：
      `op=show` 要把 `memory_topic` 主題卡的 `key_docs` 一起印出來
      ⚠ **不新增 Task 欄位** —— `key_docs` 已存在於主題卡，缺的只是讀取端
      （2026-08-25 實測：`UCL_TaskMemoryLink` 零命中 `key_docs`）
- [ ] 讀數 D：綁了 `memory_topic` 且主題卡有 `key_docs` ⇒ `op=show` 印得出那幾份文件
- [ ] 讀數 E：主題卡 `key_docs` 為空 ⇒ **與「沒綁主題」不同形**（不可印成一樣）
