## 🔬 分析讀數（kaguya 2026-09-22 量）

### 要搬的那一塊有多大

`UCL_BartenderDaemon.cs` 全檔 1276 行，跨日扣繳主體約 **369 行**（`907` → 檔尾）。
它做四件事：讀餘額 → 逐帳戶算超額與費率 → `Debit` 繳費者＋`Credit` 央行 → 發一則酒館廣播。

### ⭐ 結論：**可以搬，而且零件已經全到齊了**

那 369 行依賴的東西，在 Senate/SCP_Core **都已經有等價物**：

| Unity 那側用的 | Senate 側現況 |
|---|---|
| `UCL_CentralBankSettings`（門檻／費率／央行／豁免） | ✅ `SCP_BankPolicy` |
| `UCL_TreasuryLedger.Debit/Credit` | ✅ `SCP_BankLedger.Debit/Credit`（**寫入端本來就在這裡**）|
| 餘額／每日結帳 | ✅ `SCP_BankClosing` |
| 帳號解析 | ✅ `SCP_BankAccountResolver`（TASK-0269 今天收斂完）|
| 酒館廣播 | ✅ `SCP_Cmd_TavernWriter` |

逐行掃那一段的識別字，**Unity-only 的只剩 `Debug.Log` 與 `UCL_ChatTavernIO`** —— 兩個都有對應。
⇒ 📌 也就是說：**它今天之所以住在 Unity，是歷史，不是依賴。**

### ⚠ 而真正的重點不是「搬得動」，是搬完之後那條路會變短

現況每一筆扣款是 **Unity → 檔案協議 → Server → 寫帳**（`UCL_TreasuryAuthority` 檔頭自己寫著
每筆寫錢多一次 Server 往返，2026-09-18 實測 `server-ping` 1.216s）。
搬完之後扣款在 Server **in-process** 完成 ⇒ 那個往返整段消失。

  而 Tim 說「觸發之後也要遷移」⇒ 那是本單之後的事（排程／常駐），本單只把它留在 Unity。
- ⚠ **TASK-0273 未結**（今天 work_post 一度整天 0 筆）—— 動扣款那條路之前先確認它的成因已知，
  ⛔ 否則兩件事的症狀會疊在一起，而它們長得一樣。
