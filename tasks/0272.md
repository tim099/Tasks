# TASK-0272 — 券互換交易與匯率轉換機制（Voucher Swap & Exchange）—— 串接預言機匯率行情，支援不同券種間的模擬交易與小數點無縫結算

> `feature` / `normal` / `in_progress`　開單：gura　參與：gura(pm)、gura(qa)、gura(dev)

## 驗收標準

- [ ] ① 預設互轉開關守衛：券與券之間預設禁止直接轉換，需待匯率系統正式啟用（`fx_system_enabled: true`）才開放互轉功能；未開放時呼叫一律明確拒絕
- [ ] ② 匯率本地快取與定期同步：系統本地快取匯率（如 `Market/rates_cache.json`），支援定時/跨日從網路同步即時行情，離線或未到期時讀本地快取
- [ ] ③ 雙向報價模型（Bid / Ask Spread）：匯率體系區分買入價（Bid）與賣出價（Ask），計算買賣價差，杜絕無成本往返套利
- [ ] ④ USD 中介樞紐路由（Hub-and-Spoke）：互轉非任意直轉，所有資產必須透過 USD 作為結算樞紐（例：BTC 轉 Gold 必須拆為「BTC 賣出換 USD」＋「USD 買入換 Gold」兩段式執行）
- [ ] ⑤ 券互換交易引擎（Voucher Swap）：實作兩段式撮合換算，扣除來源券並增加目標券，並無縫套用 TASK-0271 小數點進位規則（滿 1 進可用券，餘數留存小數池）
- [ ] ⑥ 餘額充足守衛：兌換前驗證來源券總額（整數＋小數）是否足夠，不足時拒絕交易並明確出聲，嚴禁扣出負數
- [ ] ⑦ Senate CLI 交易指令出口：提供 `senate cmd voucher swap --arg from=<券> --arg to=<券> --arg amount=<數量>` 命令，交易成功後回報雙方整數與小數讀數
- [ ] ⑧ 反向對照：當開關未啟用時發起互轉，交易立即被擋下且券本一個 byte 都未改動；同券種互轉或試圖繞過 USD 樞紐直轉時亦被正確拒絕

## 任務描述

Tim 2026-09-22 拍板「券互換交易與匯率系統」完整規範：
1. **預設禁止互轉**：券與券之間預設不能互相轉換，需等新系統（匯率系統）上線後才正式開放。
2. **非全開放直轉，採 USD 樞紐交易對（Hub-and-Spoke）**：
   - 互轉並非全開放，例如 BTC 不能直接換黃金。
   - 必須透過 USD 進行兩段式轉換：先「BTC 換 USD（賣出 BTC）」，再「USD 換黃金（買入黃金）」。
3. **雙向報價（Bid / Ask）**：
   - 匯率區分買入價與賣出價，參考真實金融市場價差，杜絕高頻無損套利。
   - 匯率資料直接從公開端點獲取。
4. **匯率本地快取與定期同步**：
   - 系統本地快取一套匯率，依據一定頻率（例如每日跨日結算）同步現實行情。
5. **小數點無縫結算**：
   - 交易結算無縫套用 TASK-0271 的券小數點累積模型（Fractional Voucher），滿 1 自動進位可用券。

PM 規劃（gura）：
- 核心模組：`SCP_VoucherSwap` 與 `SCP_MarketRateCache`。
- 路由規則：USD 樞紐兩段撮合（AssetA -> USD -> AssetB）。
- 前置依賴：依賴 TASK-0271 小數點累積模型。
- 入口介面：Senate CLI `senate cmd voucher swap`。

### 💬 #2 gura 2026-09-22T15:32:51.999Z
\### 🦈 PM (gura) 匯率來源分析與系統架構規劃

依據 Tim 2026-09-22 拍板需求，針對 **TASK-0272** 匯率來源、緩存機制、Senate 後台與通用介面展開架構分析：

---

\#### 1. 匯率來源（Oracle Sources）多樣性分析

| 資產類別 | 代表券種 | 推薦公開端點 / 來源 | 取得方式與特性 | 報價形式 |
|---|---|---|---|---|
| **主流加密貨幣 (Crypto)** | BTC, ETH | **Binance Public Ticker**<br>`api.binance.com/api/v3/ticker/bookTicker?symbol=BTCUSDT` | 免 Key、極高頻、高可靠度 | 原生提供最優買價 (`bidPrice`) 與最優賣價 (`askPrice`) |
| **加密貨幣廣域備援** | BTC, Altcoins | **CoinGecko Simple Price**<br>`api.coingecko.com/api/v3/simple/price` | 免 Key (Public tier 10~30 req/min)，適合定時緩存更新 | 給予 Mid-Price，由系統價差模型推導 Bid/Ask |
| **貴金屬 (Precious Metals)** | Gold (XAU), Silver | **GoldAPI.io / Metals-API / Yahoo Finance (GC=F)** | 每日定時抓取國際現貨金價（美元/盎司） | 現貨中間價，疊加系統設定之點差/價差 |
| **外匯法幣 (Forex)** | USD, EUR, JPY, TWD | **Frankfurter API**<br>`api.frankfurter.app/latest?from=USD` | 歐洲央行公開資料，開源免費無 Key、穩定 | 基準匯率，疊加法幣兌換價差 |
| **封閉/內部自訂券** | 特殊成就券、內部活動券 | 無公開市場報價 | **無緩存資訊** | **標記為不可兌換 (Unexchangeable)** |

---

\#### 2. 通用匯率撈取架構（統一抽象介面 + 可插拔 Provider）

為避免上層交易邏輯與特定外部 API 強耦合，在 `SCP_Core` 建立統一抽象：
- **`IRateSourceProvider`**：
  - `string ProviderName { get; }`
  - `bool CanHandle(string assetSymbol, string baseCurrency)`
  - `Task<RateQuoteResult?> FetchQuoteAsync(string assetSymbol, string baseCurrency)`
- **實作層分工**：
  - `BinanceRateProvider`（Crypto 主力，原生雙向盤口價）
  - `CoinGeckoRateProvider`（Crypto 備援）
  - `GoldRateProvider`（貴金屬）
  - `FrankfurterRateProvider`（法幣）
  - `LocalMockRateProvider`（離線測試與固定報價 fallback）
- **`CompositeRateOracle`**：
  - 統一調度器，根據資產符號自動分派 Provider，並提供 Fallback 鏈與快取落盤機制。

---

\#### 3. 匯率緩存機制與安全守衛

- **儲存位置**：`Treasury/Market/rates_cache.json`。
- **快取結構**：記錄 `base_currency` ("USD")、`updated_at_utc`、各券種相對於 USD 的 `bid` 與 `ask`、報價時間戳與來源 `source`。
- **核心守衛（無緩存視為無法兌換）**：
  - 並非所有券都能互換。
  - 兩券互換時，若來源券或目標券任一方在快取中**無有效報價**（不存在、過期或報價無效），系統一律判定為 **`Unexchangeable`（無法兌換）**，強行中斷交易並防禦性報警。
  - 杜絕任意無錨定資產隨意轉移。

---

\#### 4. Senate 匯率查看後台（`MarketRatesPage` / `RateAdminPage`）

於 Senate CLI 實作匯率查看後台：
1. **基準券選擇器 (Selector)**：可自由切換指定檢視之「A 券」（例如 `BTC`、`GOLD` 等）。
2. **匯率矩陣對照表**：列出 A 券對系統中其餘所有已知券種的：
   - **買入價 (Bid)**：賣出 1 單位 A 券能換得多少 B 券。
   - **賣出價 (Ask)**：買入 1 單位 B 券所需支付多少 A 券。
   - **兌換狀態**：🟢 `可兌換` / ⚪ `無報價（無法兌換）`。
   - **資料來源與更新時間**。
3. **管理動作**：
   - `[🔄 立即同步匯率 (Fetch & Refresh Cache)]`：手動透過 Oracle 向外部來源重新拉取報價並原子更新快取。
