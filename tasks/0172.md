## 任務描述

## 症狀

`Cmd_Invoke` 的**回傳值只進 `Debug.Log`**，不進 result json 的 `values`／`outputs`。
⇒ 呼叫端拿到的是 **`✓ Success` ＋ 一片空白**：

```
$ senate ucmd run Invoke --persona summit --arg target='$page' \
      --arg member=m_LastStatus --arg kind=field --arg nonPublic=true
  ✓ Cmd completed → Success（result 檔判定，非推論）

$ python -c "…讀 _cmd_results/<id>-invoke.json…"
  Success
  （values 空　outputs: None）
```

而值其實在 Unity 的 log 裡，好好的：

```
$ grep -a 'AgentCmd:Invoke' "$LOCALAPPDATA/Unity/Editor/Editor.log" | tail -1
  [AgentCmd:Invoke] OK (System.String) = 「Bizarre Small Countries」找到 1 個入口（正本 1 筆／Archive 0 筆）。…
```

## 為什麼這是 bug 而不是「本來就這樣」

`Cmd_Invoke` 的整個用途是**取讀數**（`ArgsSchema` 自己寫著 `storeAs`、`getter`、`kind=property|field`
—— 那些參數存在的理由就是「我要那個值」）。
⇒ 一支**專門用來讀值的 Cmd**，把值送到唯一呼叫端讀不到的地方。

📌 而它的失效樣子是今天第 N 次的同一個形狀：
**`✓ Success`、exit 0、result 檔判定、一應俱全 —— 唯獨少了唯一重要的那件事。**
「這支 API 回 null」與「值沒被送回來」在呼叫端**完全同形**。

## 🔬 代碼位置

`Cmd_Invoke.ExecuteAsync` 步驟 3（`Assets/Plugins/UCL_Core/UCL_Core_Scripts/EditorCore/UCL_AgentCommands/CMD/Cmd_Invoke.cs`）：

```csharp
if (result.ValueType == typeof(void) || result.Value == null)
    Debug.Log("[AgentCmd:Invoke] OK (void / null)");
else
    Debug.Log($"[AgentCmd:Invoke] OK ({result.ValueType?.FullName}) = {result.ValueAsString}");
```

⇒ 兩條分支都只 `Debug.Log`。**沒有任何 `AddValue`／`AddOutput`。**

## 建議

- **(甲) 把值寫進 result 的 `values`**：至少 `value`（`ValueAsString`）＋ `value_type`
  ＋ 一格明確的 `is_null`（⛔ 空字串與 null 不可同形 —— 這支 Cmd 讀得到的欄位本來就會是空字串）。
- **(乙) 順手**：`void` 那條分支也要在 values 裡表態（`value_kind=void`），
  否則「這個 member 沒有回傳值」與「有回傳值但沒送回來」還是同形。
- ⛔ 不建議「叫呼叫端自己去 grep Editor.log」：那把一支**跨 process 的讀值工具**的
  出口綁在一個 14MB、會輪替、路徑依平台的檔上。
