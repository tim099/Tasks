## 任務描述

## 症狀

`bili_meta.py` 對任何 BV／av 一律 **HTTP 412**（風控），於是觀影準備階段的第 0 步整條斷掉 ——
而它的提示字面把人指向一個**已經做對了的方向**：

```
- **失敗在網路層**：HTTPError 412 Precondition Failed
  （412 = 風控擋下。最常見原因是沒帶 User-Agent —— 本工具有帶，若仍 412 代表被更上層擋）
```

⇒ 「本工具有帶」是真的，所以那句話的實際效果是**「無解，別試了」**。

## 🔬 成因（矩陣量出來的，不是推論）

同一台機器、同一組 header，逐支端點打過去：

| 端點 | 結果 |
|---|---|
| `/x/web-interface/view?bvid=` | **412** |
| `/x/web-interface/view` ＋ 完整瀏覽器 header（`Origin`／`Sec-Fetch-*`／`sec-ch-ua`） | **412** |
| `/x/web-interface/view` ＋ 官方 `spi` 發的**真** `buvid3` cookie | **412** |
| `/x/frontend/finger/spi`（發 buvid3） | 200 |
| `/x/player/pagelist?bvid=` | 200 |
| **`/x/web-interface/wbi/view?bvid=`** | **200　`code=0`　欄位完整** |
| **`/x/web-interface/wbi/view?aid=`** | **200　`code=0`** |

⇒ **被擋的是那一支端點，不是本 client 的身分。** UA／cookie 兩條路都排除了（各有讀數）。
⚠ `wbi/view` 名字帶 wbi，但**不需要簽名**就給公開欄位（`title`／`owner{name,mid}`／`pages`／`duration`／`desc`／`pubdate`）。

## 修法（已落盤）

1. **`VIEW_ENDPOINTS` 依序試**：`wbi/view` 為主、舊 `view` 留在尾端當備援
   （它哪天解禁，讀數會自己回來 —— ⛔ 不是刪掉舊的）。
2. **只有網路層失敗才換下一支**。`code != 0` 是 B 站正面回答了「這支不行」（例 `-400`）⇒ 不重試 ——
   重試會把「影片不存在」染成「端點有問題」。
3. **報告印出這次是哪一支回答的** ＋ 失敗時印「依序試過（全部失敗）」的足跡。
   ⛔ 不讓「換過端點」變成看不見的內部行為：「第一支就成功」與「試到第二支才成功」不可同形。
4. **改掉那句被推翻的提示**（UA 不是主因），並把矩陣寫進 docstring 的血證區。
5. 順手：草稿那行原本印 `run_cmd.py`（**已退場**）⇒ 改 `senate ucmd run StreamWatch`。
   遞給人一條退役指令與一條有效指令，在畫面上同形。

## 🩸 而這張單真正的教訓不在 412

舊提示是**我方寫的一句沒有量過的射程宣告**（「最常見原因是沒帶 UA」）。
它不會炸、不會有人回報，因為它讀起來像謹慎的診斷 ——
而它讓一個**只要換端點就能解**的問題，看起來像被平台封死。
📌 形狀＝判準⑤的**窄報**：「這個沒救了」而它自帶出口，
而窄報最不會被追，因為悲觀的自評聽起來像誠實。
