# TASK-0145 — 早安 brief 顯示「寫到一半的書」——先讓 Senate CLI 查得到（cmd book op=writing），brief 與 CLI 同源

> `feature` / `normal` / `in_progress`　開單：basecamp　參與：basecamp(dev)

## 驗收標準

① **CLI 查得到**：`senate cmd book --arg op=writing` 列出 `origin=authored` 且**尚未發布**的書
   （id／書名／作者 persona／章數／最後更動時間），且**每一列說得出它是從哪個檔讀來的**。
   ⛔ 沒給 data root／目錄不存在時要**明說「未量」**，不准印「0 本」——
   🩸 「沒有人在寫書」與「我沒去看」在畫面上同形，而人往那個空格裡填的一定是「沒事」。

② **早安 brief 有一節**：顯示**本人**寫到一半的書（書名／章數／最後更動）。
   ⚠ 別人的書**只給張數、不給內容** —— 未發布的草稿是 `publish_status: draft`，
   那個欄位的語意就是「只有作者看得見」，brief 不是繞過它的地方。

③ **兩端同源**：CLI 與 brief 走**同一個讀取器**（SCP_Core 裡一支），
   ⛔ 不准各自 glob 一次 BookNotes —— 兩份實作＝兩個會各自漂的真相源。
   驗收要能指出那個共用函式的名字。

④ **反向對照（暫存根，不碰真 store）**：造四本 —— authored+writing／authored+published／
   `origin=imported`／完全沒有 origin ⇒ **只有第一本被列出來**。
   ⛔ 只驗「有列出來」不算過，要驗**該被排除的三本真的沒出現**。

⑤ **空狀態**：一本都沒有時印一行明講「目前沒有寫到一半的書」，⛔ 不是空白區塊。

⑥ **真環境讀數**：在真 data root 上各跑一次 CLI 與 brief 重生成，把**列出來的書名逐本貼出來**
   （現況已知有三本 authored：@gura《深海對拍錄》／@Sirius《熄燈前的燈》／@basecamp《山腳的營地》）。
   ⚠ brief 是**機械重生成**的檔 ⇒ 驗收要確認那次重生成**真的發生了**（比時戳），
   不是讀到上一份還在的舊 brief。

## 任務描述

Tim 2026-09-06 提：早安 brief 除了「我在讀什麼」(§6.6 見書)，也該答「我在寫什麼」。他自己點出順序：Senate CLI 要先查得到。現況：三本 origin=authored 的書全部 status=writing / publish_status=draft，而沒有任何一支指令列得出它們——要知道自己寫到哪，只能手動去翻 BookNotes/*/book.json。

\## 兩個設計決定，寫下來給後面的人

**① `op` 的預設值是 `writing`（純讀那個），不是 `add`。**
打錯 op 的代價要是「什麼都沒發生」，不是「建了一本書」。
（同 `cmd watch` 把 `untitled` 當預設的理由。）

**② 讀取器回 `(bool ok, out why)`，不回「一個可能是空的清單」。**
🩸 「一本都沒有」與「我沒去看」在畫面上同形，而人往那個空格裡填的一定是「沒事」。
這條紀律是抄 brief §6 缺陷單那一行的既有寫法，不是我新發明的。
