# TASK-0283 — CLI 側 spawn 注入點的縫 —— 讓 ServerAutoStart 的 TimedOut／SpawnFailed 兩臂驗得到（承接 TASK-0267 ⑦）

> `feature` / `normal` / `todo`　開單：summit　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] ① CLI 側有一條**可注入的縫**讓 `ServerAutoStart` 的 spawn 失敗（⛔ 不是改環境、不是刪檔；同 TASK-0280 的形狀：靜態覆寫＋大聲、可清除）
- [ ] ② **`SpawnFailed` 有活體**：走到那一臂 ⇒ CLI 回非零、`🔢 delegate_failure = autostart_failed`
- [ ] ③ **`TimedOut` 有活體**：等不到就緒 ⇒ `🔢 delegate_failure = autostart_timeout`（⛔ 與 ② 不同字串、不同話）
- [ ] ④ 🔴 兩者在 Editor 這側**讀得出差別**：`UCL_ChatTavernIO` 丟的例外分得出「**不知道**（可能還在載入）」與「**確定沒起來**」—— 憑據是兩段逐字不同的文字，⛔ 不是「都有印東西」
- [ ] ⑤ 反向對照：縫沒注入時同一條路**照常成功**（⛔ 少了這格，一個永遠失敗的實作看起來也會通過 ②③）
- [ ] ⑥ 縫清得掉：`Clear…()` 回傳**被清掉的那個值**（⛔ 不是回 void 讓人以為清了）
- [ ] ⑦ ⚠ 射程：本單**不宣稱** TASK-0267 ⑦ 因此自動成立 —— 勾它的人是 0267 的 QA，不是本單

## 任務描述

⑦ 要的是「『正在啟動』與『啟動失敗』在 Editor 這側**仍然不同形**（A4 已有的四態不得被壓成一個 bool）」。

- **兩個成功臂**（`Started`／`AlreadyRunning`）已有活體 —— TASK-0267 ③⑥ 量到了
- **兩個失敗臂**（`TimedOut`／`SpawnFailed`）**結構上到不了**：`SCP_ServerAutoStart` 跑在 **CLI 那個 process 裡**（Unity 端從來沒呼叫過 `Ensure`），而 TASK-0280 那條縫讓 **CLI 根本起不來** ⇒ 走不到 autostart 的決策迴圈
- ⇒ 要的是 **spawn 注入點上的縫，在 CLI 側**（0280 之於 ⑤ 的同一個形狀）

**為什麼另開不是留在 0267**：修法不同（0267 是 Unity 端接線，本單是 Senate CLI 端的可測性），且 0267 已 18 則留言 ⇒ 照 `ucl-task` §3／§6 判準另開。
**誰在等**：@kotoko —— 她在 0267 明說「建議另開一張承接它，讓 0267 結得掉」，而 ⑦ 是 0267 最後一格未勾。

⛔ 不在本單射程：不改 autostart 的重試／逾時參數（那要先有「真實環境要等多久」的讀數，而本單不產生它）；不碰 `tavern.writer` 的預設值。
