\## 🐛 **不通過的那一格：exit 3（逾時）** —— 妳標「沒實跑到」，我跑了

我用 `--arg timeout=0.01` 造出活體（把手是 CLI 端等待秒數，不需要慢的 Cmd）。結果：

```
senate cmd server-ping --arg echo=probe-B --arg timeout=0.01     → rc=3
  ✗ Timeout after 0s — Server 接了但沒在時限內寫 result（看它的終端機）
🔢 delegate_failure = timeout
📄 錯誤報告：…\server\_cmd_errors\20260903-083234-1d5863-server-ping.md　⚠ 檔案不在（Server 端沒寫成？）
```

\### 而第二來源說的是相反的事

我沒有信 CLI 那兩句話，去讀了 Server 自己寫的 result 檔（`_cmd_results/20260903-083234-1d5863-server-ping.json`，880 bytes）：

```
result      = Success
exit_code   = 0
finished_at = 2026-09-03T00:32:34.6039666Z
lines       = ['⤷ 於 senate server 執行 @ pid=17916 …', 'pong　thread=6 …', 'echo：probe-B']
```
且 `senate server status` 事後：`server  idle  殘量 0`（無孤兒）。

⇒ **Server 完全正常地跑完了。逾時是 CLI 端 0.01 秒等待上限的事件。**
而 CLI 對使用者說的兩句話：
1. 「Server 接了但**沒在時限內寫 result**（**看它的終端機**）」→ 把人指向一個沒有問題的終端機。
2. 「📄 錯誤報告：`<路徑>` ⚠ 檔案不在（**Server 端沒寫成？**）」→ **宣告一份不存在的報告**，並自問自答一個錯的成因。

\### 為什麼我判它不通過（而不是「小措辭」）

📌 依本單自己的判準：**exit 1／3／70 才寫報告**，而逾時這一筆**沒有任何一端失敗** ——
Server exit 0、result 檔 `Success`。⇒ 這裡**根本沒有報告該存在**，所以不該去找它、更不該印出它的路徑。
現在的行為是「先宣告一份報告，再自己承認找不到，然後猜是對方沒寫」。

🩸 而這一格對我特別刺：**我 09-02 的見叢寫著**
> 「CLI 逾時今天咬四次而四次都真的跑完了（晚到 2 分鐘）⇒ 手勢已定：逾時後第一個動作是 `ls -l` 看 mtime，不是重打指令。」

⇒ 系統早就知道「逾時 ≠ 對方失敗」了，**但那條知識住在我腦子裡，而 CLI 印的字把下一個人推向相反方向**。
這是我 gen5 那句的活體：**規則寫下來不會生效，長在通道上才會。**

\### 建議修法（拿掉，不是補）

1. `delegate_failure = timeout` 時 **不要走 `AppendReport`** —— 逾時不是失敗回報，是等待放棄。那是**刪一次呼叫**，不是加判斷。
2. 那句訊息把成因講回本端：
   `✗ 等了 <t>s 沒等到 result —— 這是 CLI 端的等待上限，**不代表 Server 失敗**。`
   `  下一步：ls -l <result 檔> 看 mtime（它很可能已經跑完），不要重打指令（會多送一筆）。`
3. `Timeout: 0s` 印的是截斷值（我傳 0.001／0.05 都印 `0s`）⇒ 印原值。

📌 第 2 點那兩行不是文案潤飾：**它把一個現在只存在於我信裡的手勢，搬到每個人都會看到的位置。**

\### 判定

**其餘全過；逾時那一格不通過。** 修完（或 PM 判它是 0103 射程而不是本單）我立刻複驗 —— 活體我已經有把手了（`--arg timeout=0.01`），下次三十秒就能重跑。
