# TASK-0155 — check_compile 與 Recompile 併進 Senate CLI：unity-recompile（觸發＋等那一趟）／unity-compile-status（只讀）

> `improvement` / `high` / `in_progress`　開單：summit　參與：summit(dev)

## 驗收標準

## 拍板（Tim 2026-09-07）

`check_compile.py` 與 `Cmd_Recompile` 併成 Senate CLI 的一組指令（名稱走 `unity-*`），
**同時做觸發與檢測**；相關 skill 與文件改教 CLI 版本。

## 一、可行性（量過的，不是感覺）

| 格 | 讀數 |
|---|---|
| 資料源 | `<data_root>/.compile_status.json` ＋ `Assets/DebugLogs~/Errors_latest.log` —— 兩個都是純檔案，**零 Unity 依賴** |
| 觸發通道 | 現成 `UnityDelegateCmd`（`morning-*` 十支同形，走 AgentCommand 檔案協議） |
| python 那支規模 | **821 行**（tracker 讀取／ErrorLog 交叉對帳／新鮮度／心跳停跳／Editor.log fallback） |
| 文件遷移面 | **145 處 / 30+ 檔**，含 `en` / `ja` / `zh-Hans` 三個非主語系 |

⇒ **可以整合。**

## 二、⭐ 整合順手修掉 TASK-0154（這是本單最值錢的一格）

python 那支必須**猜**新鮮度基準：問 git、或要人給 `--since-file`。
而 `--watch` 的結束條件只有 `in_progress=false` ⇒ 觸發還沒開始時它已經是 false
⇒ **回上一次的快照，且不印 STALE**（2026-09-07 實測：印出三天前的 09-04T17:14）。

CLI 這側**送出觸發的那一刻天生就是基準** —— 不是多加一道檢查，是那個洞在新結構裡不存在。
⇒ 收單時 TASK-0154 應一起收（或改為由本單 Fixes）。

## 三、⛔ 一格不可以做：不要合成一把兩個宿主共用的尺

`SCP_CodingExitGateHost.cs` 檔頭已拍板：
> 兩個宿主的尺不同形，而且不可以合成一把。Unity 側＝`check_compile`；Senate 側＝`dotnet build`／`build.sh`。

🩸 本單開單當天的活體：同一份 `SCP_Cmd_Keys.cs`，
Unity **0 errors**（LangVersion 9、nullable 沒開，`?` 只是 CS8632 警告），
`dotnet build` **CS8603 紅燈**（nullable 開著且警告當錯誤）。
⇒ 指令名與輸出都要把射程講死：**它量的是 Unity assemblies，不涵蓋 `senate.exe`。**

## 四、形狀：兩支，不是一支

依 `Cmd_Morning.cs` 檔頭那條判準（**參數集合隨動詞改變 ⇒ 一個動詞一支 Cmd**）：

| 指令 | 執行位置 | 做什麼 |
|---|---|---|
| `unity-recompile` | ⤷Unity | 送觸發 → **等到那一趟編譯結束**（基準＝送出時刻）→ 印錯誤清單＋射程 |
| `unity-compile-status` | 本地 | 只讀現況，不觸發；含新鮮度與 ErrorLog 對帳 |

⚠ 兩支必須不同形，因為它們回答的是不同問題：
「**我這次改動編譯過了嗎**」與「**現在磁碟上那份狀態說什麼**」——
把後者當成前者，正是 0154 那隻 bug 的內容。

## 五、驗收標準

- [ ] `unity-compile-status`（本地）：讀 `.compile_status.json` 印出 timestamp／errors／warnings，
      **沒有那個檔時說「沒有這個檔」而不是 0 errors**
- [ ] ErrorLog 第二來源交叉對帳照移（tracker 說 0 而 ErrorLog 有錯 ⇒ 以 ErrorLog 為準）；
      ⛔ 找不到第二來源要明說「無第二來源」，不可以靜默當一致
- [ ] `unity-recompile`（⤷Unity）：送出時刻當基準，等到 `timestamp > 基準 && in_progress=false` 才印
- [ ] **反向對照（就是 0154 那格）**：送出後立刻跑 ⇒ ⛔ **不可以**印出早於基準的快照；
      逾時要說「等不到晚於基準的編譯」，⛔ 不可以退回印舊的
- [ ] 反向對照：編譯早就跑完時 ⇒ 立刻返回（多一個條件不可以變成永遠等）
- [ ] Editor 沒開 ⇒ 委派逾時，明說「沒有量到」；`unity-compile-status` 仍可跑但要標明讀的是哪一次
- [ ] 射程行：輸出必須印「本讀數涵蓋 Unity assemblies，⛔ 不涵蓋 `senate.exe`（那條走 `dotnet build`／`build.sh`）」
- [ ] skill 與文件改教 CLI：`ucl-compile-error`／`ucl-coding` CSHARP.md（各四份鏡像走 `install_skills.py`）、
      `UCL_Core_Entry.md` 常用入口那一行、`CompileError_Diagnose_Workflow.md`（zh-Hant）
- [ ] 非主語系（`en` / `ja` / `zh-Hans`）**單獨一格**：本單不夾帶翻譯，明列它們仍教舊指令
- [ ] 異源複驗：由另一個人在自己那台跑「改一個檔 → `unity-recompile`」，確認拿到的是自己那一趟的讀數

## 六、刻意不做（射程外，寫出來免得下一個人以為漏了）

- **`--fallback-log`（Editor.log 解析）第一版不移**，但要在 CLI 的說明裡明說沒移、以及什麼時候會需要它。
- **python 那支不退場**：照 TASK-0107 的形狀 —— 先上線、量呼叫紀錄、**歸零才**改成指路 stub。
  兩個入口並存期間，它們讀同一個檔、不互相寫，⇒ 並存是安全的。
- 心跳停跳（酒保 heartbeat）那格能不能從 senate 讀到 **未量** —— 不假設它讀得到。
