# TASK-0501 — 雕刻 GPU 預覽：鏡頭只框一次（修透視 Lag）＋右鍵旋轉、左鍵水平平移（Blender 式）

> `improvement` / `normal` / `in_progress`　開單：apex-one　參與：apex-one(dev)

## 驗收標準

- [x] 鏡頭距離與畫面置中只在一開始算一次（換作品、換投影、按「重置鏡頭」才重算）；之後轉、拖、縮放都不再重新框住 —— 畫面跟算一次那一刻逐位元相同　✅ apex-one 2026-10-11
- [x] 右鍵拖曳旋轉（繞目前的中心轉 yaw／pitch，像 Blender），中鍵同右鍵；左鍵拖曳平移畫面中心，只動水平位置（世界 X／Y），高度不變；滾輪縮放照舊　✅ apex-one 2026-10-11
- [x] 透視模式拖曳不再 Lag：真作品（鏡廳、小木屋）透視轉視角每幀時間降到跟正交同一級（附前後讀數）　✅ apex-one 2026-10-11
- [x] 反向對照：釘住之後故意改 yaw ⇒ 中心點與距離一字不變（不是又重新框住）；左鍵拖曳之後中心點的 Z 一字不變　✅ apex-one 2026-10-11
- [x] 球面頁的左鍵拖曳照舊（右鍵／中鍵的新路不影響它）　✅ apex-one 2026-10-11
- [ ] 淨室自測＋Sculpture.md；出廠

## 任務描述

誰在等：Tim。Tim 2026-10-11：問透視切換後為何很 Lag → 讀數：透視每幀 93～188 ms，其中 85～99% 是鏡頭自動框住（每幀把外露 voxel 掃約 14 遍；正交 1 遍）。
Tim 拍板：「鏡頭距離和畫面置中是否可以改為初始計算一次，之後不動態調整；滑鼠左鍵可以拖曳（調整畫面置中，只影響水平位置），右鍵旋轉；旋轉與拖曳可以參考常見的 3D 建模軟體（Blender）」。
⚠ 「只影響水平位置」我讀成：平移只動中心點的世界 X／Y（在地面上平移），Z 不動。若是指螢幕水平方向，改一行。

### 💬 #1 apex-one 2026-10-11T10:00:25.953Z
\## 判定：①～⑤ 有讀數；⑥ 出廠在 commit 後補勾

- 成因讀數（改之前）：透視每幀 93～188 ms，85～99% 在自動框住（外露 voxel 每幀掃約 14 遍；正交 1 遍）。
- 做法：渲染器把實際用的鏡頭（中心、距離／縮放、畫面方向、整張圖對應的世界長度）經 GPU 狀態的 Result 交回；頁面在「自動框的那一版」交回時釘住，之後照原樣送 target＋distance／zoom ⇒ 渲染器不再框。換對象／換投影／「重置鏡頭」才重框。
- 滑鼠：右鍵／中鍵 ⇒ 繞中心轉（yaw／pitch，抓著物體轉）；左鍵 ⇒ 平移中心，只動世界 X／Y；滾輪照舊。指標分按鍵累積（球面只吃左鍵，不受影響）。
- 淨室 SculptCameraPinCleanRoom（透視、正交各一輪）：① 釘住後畫面差 0 位元組；④ 🔴 釘住後轉 yaw／pitch ⇒ 中心與距離／縮放一字不變，反向對照（不釘）會換；平移後 Z 一字不變；往右拖重心 x 121→147（＝0.1 張圖寬）、往下拖 y 133→165。
  突變對照：ApplyPin 不送透視距離 ⇒ ④ 紅（逐位元那格抓不到，這格抓得到）；還原 ⇒ 綠。
- ③ 真資料 SculptCameraPinRealReading（1280×720 含讀回、網格已快取、轉 yaw）：鏡廳 透視自動框 387 ms → 釘住 65 ms（正交 80）；小木屋 226 → 31 ms（正交 35）。
- ⑤ 球面 9 項淨室全綠；雕刻 27 項全綠；預設 39/39。CLI op=view 新舊 exe 出圖 sha256 相同（正交、透視）。
- ⚠ 「只影響水平位置」我讀成世界 X／Y（地面上平移）；若是螢幕水平，改 PanPin 一處。
- 沒量：常駐視窗上沒手點（拖曳要人手）；平移方向只用像素重心驗過。
