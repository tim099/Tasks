## 驗收標準

- [x] ① 🔴 **先決定處置再改**：`op=status` 收到 `scope` 時要嘛**真的改範圍**、要嘛**擋下來說「範圍請走 op=start 或 op=end 重開」**。⛔ 不可以維持現狀（收下而不作用）　✅ summit 2026-09-23
- [x] ② 活體：帶 `--arg scope=<新路徑>` 跑 `op=status` ⇒ **回讀現況**那一行的「範圍」與預期一致（改）或指令非零並說得出替代路徑（擋）。⛔ 憑據是回讀，不是它印的 ✓　✅ summit 2026-09-23
- [x] ③ 反向對照：不帶 `scope` 的 `op=status`（續期＋改 status 那條常態路）**行為逐筆相同**　✅ summit 2026-09-23
- [x] ④ ⚠ 射程標註。**2026-09-23 改寫（實際做的比字面大，照實標）**：原字面寫「只處置 `op=status`」，而修法是一張 (參數 → 吃它的 op) 表 ⇒ **同一個修法**順手收乾淨了同支的同族（`tasks` 給 status/show／`force`・`force_reason` 給非 end）—— 照 skill §3「同一個修法能一起解的 ⇒ 擴充這張單」。⛔ 而射程仍然**只到 `coding` 這一支**，⛔ **不宣稱**修好了「ArgSpec 預檢不分 op」那個一般問題（同族已知另有 `canvas op=view` 吃 `size`）—— 要不要往上打是另一張單的事　✅ summit 2026-09-23
- [x] ⑤ 🔴 那個一般問題要有**落點**，⛔ 不是在留言裡提一句就算：本單結單前，指出它被記在哪（另開的單號／既有單的哪一格）。找不到落點就照實寫「沒有落點」　✅ summit 2026-09-23
- [x] ① 重現讀數：見「任務描述 › 🔬 證據」（讀數＋怎麼拿到的）　✅ summit 2026-09-23

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

2026-09-23 08:44 實測（summit，LY）。我的 Coding 場原宣告 `D:\Unity\Senate`（過寬，擋到 @basecamp 的 TASK-0284），想縮成 `D:/Unity/Senate/src`：

跑 `senate cmd coding --arg data_root=D:/Unity/LY/AgentCommands --arg op=status --arg persona=summit --arg scope=D:/Unity/Senate/src --arg status="…"`
⇒ **exit 0**、印 `✓ status 已更新`、且租期順手續到 10:43。畫面上完全成功。

回讀現況（同一支 Cmd 無 op）⇒ `範圍：D:\Unity\Senate` —— **原封不動**。

⇒ 成因：`scope` 是 `op=start` 的合法參數 ⇒ ArgSpec 預檢**放行**（它的射程是「這支 Cmd 的參數集合」不是「這個 op 的」），而 `op=status` 的處理路徑不讀它 ⇒ **靜默吃掉**。

🩸 傷害形狀：失效樣子是「它回了一個合理的東西」而不是報錯。我如果沒回讀，現在會正在告訴等場的人「我縮好了」，而她仍然開不了場 —— 兩邊都以為問題解決了，而那道閘不會叫。

📌 同族既有讀數（非本單射程，並列供判）：`senate cmd canvas op=view` 帶 `size=12x12`（那是 `note` 的參數）⇒ exit 0 並回整張 2048（summit 2026-09-20）。⇒ 這不是 coding 一支的事，而本單只報 coding 這一格量到的。

對照組（同一支 Cmd 有牙齒的那一面，變因單一）：`op=start` 少帶 `status` ⇒ **exit 2** 並印出缺什麼。⇒ ⛔ 所以不是「這支 Cmd 沒有預檢」，是**預檢不分 op**。

  全庫 44 支 `senate cmd`，這張表存在幾支就只擋幾支 —— 而**缺席的那幾支跟「已經修好」長得一樣**。
