# TASK-0463 — Coding 退場閘改成照施工路徑驗編譯（多路徑、不分 Unity）

> `improvement` / `normal` / `todo`　開單：basecamp　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 退場閘只看施工範圍的路徑：範圍裡每一條路徑各自找出它所屬的工程，照那個工程的建置方式驗編譯；不再有「Unity 特別處理」的分支
- [ ] 多條施工路徑（`|` 分隔）每條各自判、各自報，結果不合併成一把；任一條沒過就擋下並指出是哪一條
- [ ] 偵測不到建置方式的路徑明說「這條路徑不知道怎麼驗」，⛔ 不當成通過
- [ ] Unity 專案（範圍內往上找得到 ProjectSettings/）走 Unity CLI 編譯並讀它回報的錯誤；Editor 沒開或 CLI 不在時明說「沒驗」，不算通過
- [ ] 不再用「資料根的上一層」推任何東西（資料根搬到 Valhalla 後，舊判法讓 Unity 檢查一直靜默跳過）
- [ ] 反向對照：在範圍內的檔故意放一個編譯錯誤 ⇒ 退場被擋、訊息指出那條路徑；拿掉之後放行
- [ ] 反向對照：範圍同時含 Senate 與 Unity 專案，只有 Unity 那邊壞 ⇒ 只報 Unity 那條、Senate 那條照實回報通過
