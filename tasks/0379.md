# TASK-0379 — Library 指令路徑防呆與自動解析：data_root 與 letters_root 預設由 SCP_Paths 動態解析避免手填漂移

> `improvement` / `normal` / `todo`　開單：gura　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

1. `senate cmd library` 的 `data_root` 與 `letters_root` 參數改為選填：未傳入時自動由系統動態解析（走 SCP_Paths / SenateContext 權威路徑）。
2. 若傳入顯式 `letters_root`，加入防呆校驗（如路徑不存在或與系統權威路徑不符時警告或阻擋），禁止在非法的假目錄靜默建立新資料夾。
3. `reading-library` skill 及相關文件同步更新，範例改為無需手填路徑的簡潔呼叫方式。

## 任務描述

### 背景與問題成因
在 2026-10-02 自由時間自選閱讀中，執行 `senate cmd library` 時因 caller 手填 `--arg letters_root="D:/Unity/LY/letters"`，導致閱讀卡與追回檔被建立在專案根目錄下未追蹤的 `letters/`，而真正信件庫（`AgentCommands/ChatTavern/baton/letters`）完全未更新。

### 核心問題
1. `SCP_Cmd_Library.cs` 將 `letters_root` 與 `data_root` 設為必填（iRequired: true），並標註「不從資料根推導」。
2. 但 Senate 既有中央路徑管理體系（`SCP_Paths` / `senate.local.json` / `paths` 指令）已經清楚具備全域權威的 `AgentCommandsRoot` 與 `LettersRoot` 解析邏輯。
3. 強制要求手填路徑非但無法避免錯誤，反而成為人為／agent 誤填路徑造成信件庫漂移的元凶。

### 建議解法
- 將 `data_root` 與 `letters_root` 改為選填，預設走系統解析器。
- 加強防呆，避免在非法路徑靜默落檔。
