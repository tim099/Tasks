# TASK-0156 — Treasury 簽章判準拿銀行 id 比 env marker —— 轉接到 senate 後每筆掛號信郵資都會誤標 signature_mismatch

> `bug` / `wrong` / `normal` / `todo`　開單：summit　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

## 病灶：`MatchesEnvMarker` 拿**銀行 id** 去比 **env marker**，而它至今乾淨只是因為兩個豁免條款一直命中

`UCL_TreasuryLedger.WriteEntry`：
```csharp
string claimedAgent = string.IsNullOrEmpty(callerAgentId) ? accountId : callerAgentId;
bool sigMismatch = !MatchesEnvMarker(claimedAgent, envMarker);
```
`MatchesEnvMarker` 對 `envMarker == "claude-code"` 的判準是 **`lowerId.Contains("claude")`**。

而 `claimedAgent` 在 `caller` 缺席時**退回 `accountId`＝銀行 id**，實測銀行 id 是：

| persona | bank |
|---|---|
| summit | `zeta` |
| basecamp | `cc` |
| kiara | `Myth` |
| Template | `Template` |

**沒有一個含 `claude`。** ⇒ 只要 env marker 被偵測到、而呼叫端沒帶 `caller`，就必然 mismatch。

## 🩸 為什麼現在才現形（這格是重點）

兩個豁免條款一直在擋著它：
1. `if (envMarker == "unknown") return true;` —— 偵測不到就不算 mismatch
2. `if (lowerId == "system") return true;` —— 內部 hook 走 system

近 40 筆帳本：**36 筆 claimed=`system`**、1 筆 env=`unknown`。⇒ 那條路幾乎從來沒被走到過。

而 TASK-0107 把 python 呼叫端轉接到 `senate ucmd` 之後，**senate 一律注入 `_caller_env_marker`**
（`AgentCmdClient.Submit`），於是第 1 條豁免不再命中 ⇒ 這個檢查**開始生效，並且是誤判**。

## ⭐ A/B 對照組（同參數、同帳戶、變因只有 client）

2026-09-07，Tim 授權用 Template 測試銀行真的扣款：

| 路徑 | signature_mismatch | sig_env_marker | 餘額 |
|---|---|---|---|
| **新**（`senate ucmd run Treasury`） | **True** | `claude-code` | 78 → 77 |
| **舊**（`python run_cmd.py run Treasury`） | False | **`unknown`** | 77 → 76 |

⇒ **帳沒有錯**（兩筆金額、kind、ref、description 都對，帳本原檔逐欄查過）。
差的只有簽章欄，而**新路徑那筆才是誠實的**：env marker 真的就是 claude-code。

## 影響

轉接完成後，**每一封掛號信的郵資**都會被標 mismatch，而 `UCL_DiscordTreasuryMirror` 會印
「⚠ signature_mismatch — 簽章與帳戶不符，請查核」。
📌 真正的代價不是那行字，是**它會稀釋一個本來要用來抓假帳的訊號** ——
一個天天亮的警報等於沒有警報。


- [ ] 重現讀數（開單人已填，見上表 A/B）
- [ ] 判準修正：`claimedAgent` 退回 `accountId` 時**不可以拿它跟 env marker 比**
      —— 銀行 id 與 agent id 是兩種東西（`zeta` / `cc` / `Myth` vs `claude-da-xiaojie`）
- [ ] ⛔ 修法不可以是「呼叫端補一個假的 `caller=system`」—— 那是用假身分關掉警報
- [ ] 反向對照：一筆**真的**不相符的（claimed 是別的 agent 的 id）仍要標 True，
      否則這次修完等於把整條檢查關掉
- [ ] 異源複驗：由另一個人在自己的 bank 上跑一筆小額 debit，確認 mismatch 欄位符合預期
- [ ] ① 重現讀數：見「任務描述 › 🔬 證據」（讀數＋怎麼拿到的）
- [ ] ② 修正落盤（commit 帶 `Fixes TASK-0156`）
- [ ] ③ 異源複驗（不重用 ① 的量測路徑 —— 同源多量只證明一致性）

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

2026-09-07 A/B（Tim 授權 Template 測試銀行實扣）：同參數同帳戶，senate 路徑 signature_mismatch=True/env=claude-code（78→77），run_cmd 路徑 False/env=unknown（77→76）。成因：claimedAgent 在 caller 缺席時退回 accountId（銀行 id zeta/cc/Myth/Template，均不含 claude），而 MatchesEnvMarker 對 claude-code 的判準是 lowerId.Contains(claude)。近 40 筆帳本中 36 筆 claimed=system、1 筆 env=unknown ⇒ 兩條豁免一直擋著它。
