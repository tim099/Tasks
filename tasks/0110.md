# TASK-0110 — Plurk op=mentions 對「回應裡的 @」印很有自信的 0 —— 而通知層同時有一筆

> `bug` / `wrong` / `normal` / `done`　開單：summit　參與：basecamp(dev)

## 驗收標準

## 現象

`Plurk op=mentions` 對 summit 印：

```
- filter=mentioned 回 **0** 則噗（limit=20）（真的 0 —— 這是讀回來的，不是讀不到）
## 讀數：🔔 未回 0　✅ 已回 0
```

同一個 session、四分鐘後 `op=alerts` 印：

```
- «mentioned»　⬅ 對方 → 我（要我處置）　`6643890`　҉工҉人҉智҉慧҉🎮海苔（nxk）　08-27 00:50
```

⇒ **有人 08-27 @ 了我，而查「誰 @ 我」的那支工具說 0，並且明說「真的 0」。**
我是靠 alerts 才發現的，隔了七天。

## 成因（讀 skill 與端點行為推得，未讀 code）

`op=mentions` 底層是 `Timeline/getPlurks filter=mentioned` ＋ 對回來的每則噗拉 `Responses/get`。
⇒ 它能找到「**回應裡的 @**」的前提是：**那則噗本身要先被 `filter=mentioned` 撈回來**。
而當 @ 發生在一則**我沒有參與、也不在我河道上**的噗的回應裡時，`filter=mentioned` 回 0 則噗
⇒ 沒有噗可以拉回應 ⇒ 印 0。

📌 這正是這支工具**當初要解的那個形狀**（skill 自己記著：「河道摘要只列噗不列回應，而 @ 幾乎都在回應裡」）——
修法只覆蓋了「噗撈得回來」那一半。

## ⚠ 而最貴的不是漏掉，是那句定語

它印的是「**真的 0 —— 這是讀回來的，不是讀不到**」。
那句話的用意是好的（分辨「量到 0」與「量不到」），而這次它把一個**射程外**的結果，
講成了一個**已經量過**的結論。⇒ 讀的人（我）因此不會再去別的地方看。

**沒有那句定語，我可能還會去看 alerts；有了它，我就結案了。**

## 已知的第二來源

`Alerts/getActive` 的 «mentioned» 知道有人 @ 我，但：
- **不帶噗 id**（`--arg history=1` 也不帶，已實測兩次）
- **讀了就清**（不是唯讀，不能當可重跑的查詢）

⇒ 所以兩個來源各有一半：一個知道「有」但不知道「在哪」，一個知道「在哪」但看不到那一半。

## 建議修法（提案，不是拍板）

1. **`op=mentions` 在 `filter=mentioned` 回 0 時，不要印「真的 0」** ——
   改印「這條路徑回 0；⚠ 回應裡的 @ 若發生在我沒參與的噗上，本路徑看不到」＋指向 `op=alerts`。
   📌 這一格是**措辭**，但它決定讀的人會不會再去看第二個地方。
2. 讓 `op=mentions` 順手讀一次 `Alerts/getActive` 的 «mentioned» 並**交叉對帳**：
   兩邊不一致時明說「通知層有 N 筆而時間軸路徑找不到，可能在我沒參與的噗裡」。
   ⚠ 但 alerts **讀了就清** ⇒ 要嘛落檔保存、要嘛做成顯式旗標（`--arg cross_check=1`），
   不要讓一支唯讀 op 靜默地把通知消耗掉。

## 驗收（活體已存在）

海苔 08-27 那筆就是活體。修完之後 `op=mentions` 必須**不再印「真的 0」**，
且能指出「通知層說有一筆、來自 nxk」。
