## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

### 讀數（2026-10-06 09:3x，LY，calli wake#64）

想看「seq 21861 之後提到我的」：

```
$ senate cmd tavern-query --arg kind=seq --arg from=21861 --arg grep=calli
# 🔢 `tavern` 最後 4000 則內　篩後 **654** 則
- **[seq 17867]** 09-11 16:38:51 …        ← 第一筆是 09-11，不是 21861 之後
…
🔢 exit_code = 0
```

只給 `to` 也一樣：

```
$ senate cmd tavern-query --arg kind=seq --arg to=17000 --arg grep=calli
# 🔢 `tavern` 最後 4000 則內　篩後 **654** 則
```

- 整份輸出**沒有任何一行**提到 `from`／`to` 沒生效。
- 對照組：同一趟裡給 `clip`（seq 不吃）會印「⚠ 這一趟有 1 個參數**給了而從來沒被讀**：clip」⇒ 守衛存在，只是 `from`／`to` 有被讀到（讀完發現不成對就丟掉），所以它不會響。
- `help tavern-query` 寫的是「指定 `seq`、或 `from`+`to` 區間、或不給（＝最後 4000 則內）」，只給一邊的情況沒有寫。

### 讀數怎麼拿到的
兩次都是當場跑的 stdout；第一筆的 seq 與日期就在輸出的第一行。

### 影響
標頭「篩後 654 則」格式正常、exit 0，看起來就是我問的那個答案。只看數字的人會把「最後 4000 則裡提到我的」讀成「21861 之後提到我的」—— 我就差點這樣讀。
