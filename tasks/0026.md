# TASK-0026 — Cmd_Task 寫檔併發：回傳檔改 per-persona ＋ 單檔／index 計數器加鎖（承接 BUG-34，Tim 拍板）

## 驗收標準

承接 **BUG-34**（basecamp 2026-08-25 立案）。Tim 同日拍板修法方向：
> 「Task 相關寫檔流程可能要 lock 避免衝突」

## 為什麼這是三格不是一格

並行是**真的**：`UCL_AgentCommandRunner.cs` L68-75 自己寫著「queue 依 persona 分 lane 後
watcher 會**並行派遣**」，而 2026-08-16 已有同族血證（全域 slot 互相覆蓋、**完全無聲**）。

| # | 位置 | 症狀 | 看得見嗎 |
|---|---|---|---|
| ① | `Tasks/_last_task_report.md` | 讀到別人的視圖 | **看得見**（header 帶 persona） |
| ② | `Tasks/tasks/<index>.md` | read-modify-write 整檔覆蓋，留言消失 | **看不見** |
| ③ | `UCL_TaskIO.IncrementAndGetIndex()` | 讀後寫非原子，兩張單撞號 | **看不見**（自癒還會把撞號痕跡抹平） |

⚠ **拍板的分格只治得了 ①。** ②③ 沒有 header 可以對。
📌 只修被看見的那一格，會漏掉沒人發現的那一格；而沒人發現的那一格，永遠不會有人來說。


- [ ] **① 回傳檔改 per-persona**：落到 `letters/<persona>/cmd/<op>.md`（對齊 `Cmd_GoodMorning`／
      `Cmd_Tavern` 既有慣例），且 `run_cmd` 印出的路徑指向**這次這個人**那一份
- [ ] ① 的讀數：**兩個 persona 幾秒內先後跑同一個帶 persona 語意的 op**（如
      `op=list --arg assignee=<me>`），事後兩份檔各自 header 正確、內容互不覆蓋
- [ ] **② 單檔寫入序列化**：進入 read-modify-write 前取鎖（可抄 `_session/` 既有 per-persona
      lock 原語；或改成 append-only 的時間線寫法）
- [ ] ② 的讀數 ⚠ **不能靠肉眼**：兩個 process **同時**對同一張單各留一則言，
      事後**兩則留言都還在**。這格是本單唯一一個「壞掉不會叫」的驗收，請當作主驗收標準
- [ ] **③ index 計數器原子化**：兩張單同秒 `create` 不得拿到同一個號碼
      （現有自癒只救得了之後的單，救不了已經被蓋掉的那張）
- [ ] ③ 的讀數：並發 create 探針 ×N，事後 `tasks/` 的檔數 == 成功回報數，且無號碼空洞
- [ ] 探針用畢當場標記 cancelled（抄 TASK-0003/0010/0022/0024/0025 先例）
