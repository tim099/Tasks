## 任務描述

可換零件（母單 TASK-0713）的第零段：掛點、換裝表、繩端都要靠它指名，所以排在 TASK-0714 前面。

## 現況：關聯有三種寫法混著用（ame 查過造船規格與遊戲端）
- 照路徑：裝甲 `mount=<砲的路徑>`、鍋爐 `funnel=<煙囪>`、彈藥庫 `hoist=<梯子>`；火藥庫找桶、砲塔巢狀、砲在哪層甲板照路徑前綴 ⇒ 改名、換資料夾就斷（造船規格 §11：改裝船拆掉被指名的部件會斷）。
- 照序號：帆腳 footYard、繩綁哪個模型（10_ship.js linkRopes 存模型序號）⇒ 中間插一件後面全部位移。
- 照位置猜：繩端點離哪個模型外框夠近就綁哪個 ⇒ 零件一換位置就可能綁錯。
- 同名兩義：`mount=` 在砲上是砲架種類（turret／pivot），在裝甲上是指向哪門砲。

## 規格（全文：造船規格 §12，Senate 95a3fb7）
1. 每件東西一個固定 id，寫在它自己的 meta：`<類別>-<序號>`，例 `gun-7`、`oar-12`、`funnel-1`、`ladder-3`、`rope-112`、`sail-4`（序號只用數字）。第一次匯出時由雕刻端發號、寫回作品，之後不變（改名、搬資料夾都不變；刪掉的號不重用）—— 跟著物件走，不是看它在清單第幾個。
2. 指向別的東西一律寫 `id` 或 `id#固定點`：例 `mount_of=gun-7`、`funnel=funnel-1`、`hoist=ladder-3`；繩兩端 `gun-7#breech`、`sail-4#<角名>`。
3. 規格表 config/meta_kinds.json 登記哪些欄位是關聯、能指哪一類；匯入檢查統一驗（指到不存在的 id、類別不對 ⇒ ✗）；遊戲端一支解析函式，取代各處自己比路徑前綴。
4. 改裝船沿用原船的 id（nested prefab），自己加的用自己的號段 `<改裝船代號>.<類別>-<序號>`（原船之後加東西也不會撞）。
5. 玩家存檔（換裝表、艙房）用 id 指。

## 兩頭
- 雕刻端（Senate）：發號、寫回作品、匯出帶 id 與關聯欄位；造船規格寫規則。
- Blockside：解析、匯入檢查、舊寫法的轉換工具（現有的船補 id、路徑寫法轉成 id 寫法）。
