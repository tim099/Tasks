# TASK-0987 — 《Blocksail》城區②：離很遠、自己一份規劃的城區 —— 規劃照那一區、城鎮帳併進主城（第一個用例：埃爾科夫雷）

> `feature` / `normal` / `todo`　開單：kiara　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 城區可以有自己一份規劃（範圍可以在城的範圍外、離很遠）：取樣、規劃、烘焙、手動配置都照那一份；沒寫的城區照舊跟主城區同一份
- [ ] 城鎮帳只有一座城：遠的城區的建築、上工、住宅、衛戍、地產都記在主城，城鎮帳裡不多出一座城
- [ ] 範圍層檢查：遠的城區不跟別的城、別的城區重疊；主規劃那幾區照舊要蓋住城的範圍
- [ ] 地球儀：遠的城區不畫成另一座城；有港口的遠城區停得進去
- [ ] 城鎮模式：🗺 換到遠的城區 ⇒ 鏡頭跳過去、那一份規劃載進來建好；換回去那一份收掉
- [ ] 建築模式在遠的城區蓋、拆照常，帳記在主城
- [ ] 第一個用例 埃爾科夫雷（聖地牙哥的城區，內陸）：開場有銅礦坑、可可園；一年模擬（發船隊）銅礦石、可可都 > 0
- [ ] 反向對照：沒有遠城區的城，規劃雜湊與開場帳逐項跟改之前一樣（君士坦丁堡 00d544cff843a51c、聖地牙哥 ad28084abe3dcffd 是 2026-10-26 的基準）
- [ ] 舊存檔讀得進來（地塊的鍵換了也一樣）

## 任務描述

## 要什麼
Tim 2026-10-26：「目前在想是否可以讓城有多個城區（可以距離很遠 進城不加載遠處城區） 內陸部分當成城區」「主城區可以在內陸 港口有城區就好」「接著做離很遠、自己一份規劃的城區，第一個用例埃爾科夫雷（TASK-0959）」「可以先規劃一下 開task 先不動工」

TASK-0817 做完的是「同一份規劃切幾區」（君士坦丁堡九區）。這張做「離很遠、自己一份規劃」的城區：埃爾科夫雷離聖地牙哥的港口 11.6 km，主規劃的取樣只到城的半徑，長不過去。

## 現況（kiara 2026-10-26 讀 main 6bf5d53）
- 規劃這一路全照「城的 id」一份：取樣／規劃（world/town_sample.js、town.js）、快取與烘焙（world/town_store.js、tools/town_bake.cjs ⇒ world/townplans/<id>.json）、手動配置（world/towns/<id>.js，進指紋）、玩家停靠處（tools/town_dock.cjs 寫進那一筆的 dock／docks）、送給 Blockside（world/mapgen.js townsNear ⇒ api.towns）、建築模式（townEdit 照 plan.id）、地球儀的 planOf[城]。
- 城鎮帳一座城一筆（townstate.js townsOf：範圍層每一筆 town）；開場的建築從規劃來：townProdOf(plan) ⇒ b.town ＝ plan.id、b.id ＝ plan.id/地塊；鎮民上工 staff 照 [城][地塊 id]、家族的地產 owners／famOwnerAt 照地塊 id；衛戍 townGarrisonSync、住宅 townHomesSync 照一份規劃；tools/town_start.cjs 照 planOf(城)。
- 生成器、城鎮帳都不讀 districts（grep 0 處）—— 城區現在只活在範圍層、地球儀停靠、Blockside 載入那三層。

## 做法（規劃，動工前可以改）
1. **資料**：城區多一欄 `plan`（選填）＝ 自己一份規劃：`plan: { tier, style?, seed?, core?, fort? }`。沒寫 ⇒ 跟主城區同一份（君士坦丁堡那九區照舊）。
   - 主規劃那一片 ＝ 城的 `range`；自己一份規劃的城區有自己一圈 `range`（可以在城的範圍外）。
   - areaCheck：「城區要蓋住城的範圍」只算主規劃那幾區；自己一份規劃的那一區不准跟別的城、別的城區重疊。
2. **規劃單位**：`<城 id>~<區 id>`（例 `town-santiago-de-cuba~el-cobre`）。`BSW.townUnits(範圍層)` 合成「規劃用的那一筆」：type town、`city`、`dist`；名字、勢力、era 照城；center／range／port／tier／style／seed／core／fort 照城區。
   ⇒ 取樣、規劃、烘焙（townplans/<單位>.json）、手動配置（towns/<單位>.js）、town_dock、送給 Blockside、建築模式都吃它 —— 那些程式只要拿得到這一筆就不用改。
   ⛔ 合成的那一筆不進城鎮帳、不畫成另一座城（townsOf、famGen、fleetGeoSet、地球儀的圖示與國界都只看真的那幾筆）。
3. **城鎮帳併進主城**：規劃帶 `city` ⇒ townProdOf 記 b.town ＝ 城、b.id ＝ 單位/地塊、b.plan ＝ 單位；staff、owners、famOwnerAt 這幾個以地塊 id 當鍵的，遠的城區改用「單位/地塊」（主規劃照舊是地塊 id ⇒ 舊存檔不動）；衛戍、住宅照城的每一份規劃加總；town_start 讀城的每一份規劃。自動建築照舊只蓋在主規劃（遠的城區另外再說）。
4. **地球儀**：城區有港口 ⇒ 停靠處照那一區（停靠照泊位與距離不變）；ship.docked.id 照舊是城，多記規劃單位；送給 Blockside 的城區清單帶上遠的那幾區（標 plan ＝ 單位）。
5. **Blockside**：🗺 換到遠的城區 ⇒ 焦點移過去（0817 已經有）⇒ 海域的窗換過去 ⇒ 那一份規劃送進來、建好；換走就收（只建選中的那一區）。城鎮介面照城（TWB.town ＝ 城）；建築模式的 townEdit 多帶規劃單位。
6. **第一個用例：埃爾科夫雷** ＝ 聖地牙哥的城區 `el-cobre`（內陸、沒有港口）：範圍、規劃（村、es）、手擺銅礦坑與可可園；一年模擬照船隊跑法（0958 basecamp 的拍板：發 BSW.fleetSeed）。
7. 城區之間的路 ⇒ 另一張單（生成器多一種東西，修法不同）。

## 要小心的
- `~` 不在範圍層 id 的格式裡（ID_RE）：合成的那一筆不過 areaCheck（本來就不該過），但要確認 Blockside、檔名、IndexedDB 的鍵都吃得下。
- 地塊鍵改成「單位/地塊」：存檔、對拍、site.js 建築資訊、Blockside 鎮民上工都要一起換，反向對照用沒有遠城區的城（逐位元組）。
