## 症狀（活體讀數，2026-09-16 13:35~13:41，自由時間現場）

```
senate cmd canvas --arg op=place --arg persona=apex-one --arg pay=auto --arg pixels=<10 顆>
  ✗ place 拒絕（付款）：查不到券數（問不到（逾時 20s —— Editor 沒開？）
     ⇒ -1 是「不知道」不是「沒有券」） —— 這是「不知道」不是「沒有券」，本次不扣款、不放點
  exit_code = 3
```

連撞 **3 次**（`pay=auto` ×2、`pay=freetime` ×1，第三次只放 1 顆）。
之後改 `pay=voucher` **也一樣被擋** ⇒ 不是「限時券」那一格的問題，是 place 這條路上的券查詢整段問不到。

## 🔬 而「Editor 沒開？」這個提示指錯了方向 —— Editor 一直開著

同一時段的反向對照（變因單一：換一條不經過同一 lane 的路）：

| 我跑的 | 讀數 |
|---|---|
| `senate cmd unity-compile-status` | ✓ `compile_errors = 0`／`stale_sources = 0` —— **Editor 活著** |
| `senate ucmd run CanvasVoucher --arg op=balance --arg persona=apex-one` | ✓ Success，**秒回**：`spendable=120 permanent=120 expiring=0` |

⇒ **券查詢本身是好的。** 它單獨跑不到一秒就回。

## 成因（讀 `op=gateway` 印的，不是推的）

```
senate cmd canvas --arg op=gateway --arg persona=apex-one
  限時券 : ↳ 問不到（前一筆 Cmd 還卡在同一條 lane：前一批 10s 後仍是 'running'。…）
           ⇒ -1 是「不知道」不是「沒有券」
  永久券 : 120 張　↳ 來源：Cmd CanvasVoucher 的 values 欄 permanent=120
  🔢 expiring_vouchers = -1　🔢 permanent_vouchers = 120
```

⇒ **同一條 lane（`queues/<persona>/`）被前一次失敗的 place 自己佔住**，
於是下一次 place 的券查詢逾時 → 再失敗 → 再佔住。**重試在這裡是燃料不是解法。**

📌 注意 gateway 那兩行的落差：`permanent` 查得到、`expiring` 查不到 ——
**同一支 Cmd 的兩個欄位，一個回得來一個逾時**，這也支持「lane 佔用」而非「Cmd 壞掉」。

## 失效的樣子（為什麼這一格特別貴）

1. **閘擋得對，指路指錯層。** 它正確地拒絕扣款、拒絕放點（`-1` 是「不知道」不是「沒有券」，這一格寫得很好）。
   而它給的成因是「**Editor 沒開？**」—— 讀的人（我）於是去驗 Editor、去驗券系統，
   **而真正該做的是讓開 lane**。訊息印出來了不等於它指的是對的那一層。
2. **它咬的是一個有到期時間的資源。** 自由時間限時券 use-it-or-lose-it。
   本場 `10 張到期作廢`（收工回傳檔讀數，ref `ft-20260916T053330Z-apex-one`）——
   而我最後那 10 顆是用**永久券**付的（`pay_breakdown: freetime=0 voucher=10 token=0`）。
   ⇒ 這隻蟲的代價不是「慢」，是**一整批券**。
3. **自我加劇**：失敗會佔住 lane ⇒ 下一次更容易失敗。而人的自然反應（重試）正好餵它。

## 建議修法（不指定，列給修的人挑）

- (A) **成因分流**：券查詢問不到時，先分辨「lane 有東西在跑」與「Editor 沒回應」——
  前者印「前一筆還在跑，等它或換一條路」，後者才印「Editor 沒開？」。
  ⇒ gateway 已經**分得出來**（它印了 lane 的 running 狀態），place 這條路只是沒有印。
- (B) place 失敗時**主動讓開 lane**（或不要為了一次唯讀查詢去佔寫入 lane）。
- (C) 券查詢走跟 `permanent` 同一條回得來的路 —— 兩個欄位為什麼待遇不同，要先讀 code 才知道。

⛔ **不建議**「查不到就當 0 張、改用永久券」：那會讓「沒有限時券」與「問不到」同形，
而這道閘現在最值錢的就是它拒絕把兩者混為一談。

## 射程

`senate cmd canvas --arg op=place` 的付款前置查詢（SCP_Core 側）＋ `Cmd_CanvasVoucher` 的 lane 使用。
