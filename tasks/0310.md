# TASK-0310 — 委派給 Server 的 Cmd 把轉發端補進 payload 的參數報成「給了而從來沒被讀」—— voucher op=usage 每次亮 10 個假警告

> `bug` / `wrong` / `normal` / `done`　開單：basecamp　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] ① 委派給 Server 的 Cmd，「給了而從來沒被讀」只列**呼叫端真的給的**參數（轉發端補進 payload 的不算）
- [ ] ② 反向對照：呼叫端真的帶了一個該 op 不吃的參數（例：`voucher op=usage --arg amount=3`），警告照舊亮、而且只列 `amount`
- [ ] ③ 先紅一次：以上面那行 voucher op=usage 重現「10 個參數」的誤報，修後同一行零警告
- [ ] ④ 不回退 0289：不經 Server 的本地 Cmd 行為不變（canvas op=view 吃 size 那個樣本仍然會亮）
- [ ] ① 重現讀數：見「任務描述 › 🔬 證據」（讀數＋怎麼拿到的）
- [ ] ② 修正落盤（commit 帶 `Fixes TASK-0310`）

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

承接 TASK-0289 ⑦（kiara 2026-09-23 查明根因、明寫「真正的解是另一個修法，不在本單射程，要不要另開由 QA 或 Tim 判」—— 之後沒有人開）。

新樣本（basecamp 2026-09-27 BTC，build `0270cdf-dirty.20260927T013344Z`）：
`senate cmd voucher --arg op=usage --arg voucher=canvas --arg persona=basecamp --arg ref=ft-20260926T142240Z-basecamp`
⇒ 結果正確（發 10 剩 0 用 10），但同時印：
「⚠ 這一趟有 10 個參數**給了而從來沒被讀**：amount , confirm , data_root , expires_at , from , from_kind , from_path , region , source , to」
—— **這 10 個我一個都沒給**。

⇒ 跟 0289 ⑦ 同一個成因（`ServerDelegateCmd.cs:179-181` 把 ArgSpecs 全部打包送給 Server），而這次它**不受 ⑥ 的 op/kind 收窄保護**：voucher 有宣告 `op`，所以每一次委派給 Server 的 voucher 呼叫都會亮這一行。
🩸 代價不是吵，是**這道警告在這支 Cmd 上已經失去意義**：09-26 晚上我看到同一行而沒追，隔天猜成「我多帶了 letters_root」—— 猜錯了。一道每次都亮的警告，跟沒有警告一樣，而且更糟：它教人忽略它。
