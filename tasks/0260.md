## 驗收標準

- [x] ⭐ **兩個讀數同時在場**：`senate cmd bank --arg op=balance --arg account=myth` 回正確餘額（exit 0）／`--arg bank_root=<任意路徑>` 被 ArgSpec 預檢當場擋下（exit 2）並列出合法參數清單。⛔ 只驗前者不算 —— 那是改動前就成立的　✅ basecamp 2026-09-21
- [x] `bank_root` **外部填不進來**；宿主層（`Program.cs` 的 `FillRootArg`）**仍然注入且仍然印出來**，⛔ 不改成靜默注入（靜默的症狀是「我沒指定，它卻讀了另一棵資料樹」）　✅ basecamp 2026-09-21
　🔴 **條文改寫（basecamp 2026-09-21，理由見留言 #1）**：原文是「從 `Cmd_Bank.ArgSpecs` **移除**」，⛔ 而那與後半句**互斥** —— `Program.cs` 的 `FillRootArg` 第一行逐字是 `if (ioArgs.ContainsKey(iArgName) || !DeclaresArg(iCmd, iArgName)) return;`　⇒ **移除宣告的同一個動作就關掉了宿主注入**，而 Cmd 內 `iArgs.Get("bank_root")` 會當場丟例外（框架刻意不回空字串）。　⇒ 保留宣告、把「使用者手填」擋在**宿主層**（那是唯一分得出「使用者填的」與「宿主填的」的位置 —— 再往下一行兩者就進同一個 dict 了）。目標不變：**手填的錯值不能蓋過對的推導**
- [x] ⛔ **不改成「本層自己推導」** —— `Cmd_Bank` 跑在 server 上（`delegate_host=server`），而一顆 server 可能服務多棵樹；本層推導會推到 server 那棵不是呼叫端那棵。這一格是 `Cmd_Bank.cs:11` 原始決定要保護的東西，本單只拆「可填」不拆「不推導」　✅ basecamp 2026-09-21
- [x] 三個內部呼叫端逐一確認：`BankAdminPage.cs:271`、`SenateBooksGateway.cs:44`、`SenateCanvasGateway.cs:251/314` —— 改後**各自實跑一次**並記錄 exit code，⛔ 不是「讀 code 看起來沒事」（它們現在是直接塞 `bank_root`，移掉 ArgSpec 之後那個 key 會變成未知參數）　✅ basecamp 2026-09-21
- [x] 舊理由**留在註解裡並標明何時被誰改**（`Cmd_Bank.cs:11-14` 那段），⛔ 不靜默刪掉 —— 下一個人會想「為什麼這支不推導」，答案不能只活在 git log　✅ basecamp 2026-09-21
- [x] 反向對照：改動**前後**各跑一次 `--arg bank_root=<錯路徑>`，前者回「帳號沒有開戶」（假陰性）／後者回「不認得的參數」。兩份輸出貼進單子 —— 這一格才是本單真正修掉的東西　✅ basecamp 2026-09-21
