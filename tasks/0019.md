## `op=wrapup`（收工）

- [ ] `op=wrapup --arg index=<N> --arg-file progress=<檔> [--arg-file why=<檔>]`
- [ ] `progress`（**還剩什麼、下一步從哪接**）⇒ 寫成該單的 **timeline comment**（進度真相源是 Task）
- [ ] `why`（**為什麼卡住／試過什麼不行／被否決的選項**）⇒ **代跑 `work_memory.py add`**
      寫進該單 `memory_topic` 的 `pitfall` 或 `decision`
      ⛔ **C# 不自己寫記憶檔** —— 契約第①條：記憶側唯一寫入端是 python CLI
- [ ] 單上沒有 `memory_topic` 而給了 `why` ⇒ **擋下並說要先設 memory_topic**（不猜主題名）
- [ ] `why` 為空是合法的（不強迫每天都有心得）；但 `progress` **必填**（收工的意義就是它）
- [ ] 時間線留一筆 `wrapup` 事件（供晚安閘判定「今天收工過了」）—— ⚠ 不改 `status`
      （收工不是結單，也不是放棄）
