# TASK-1271 — 《Blocksail》battle.html 自己的開機流程：進地球儀就常駐、用訊息換場（音效、著色器不重來；航海頁不帶選船素材）

## 驗收標準

- [ ] 進地球儀之後 battle.html 在背景先開好（看不見、不畫），按航海／海戰／進城時用訊息換一場：第一次進航海的時間比現在少（哈瓦那出港，新舊交錯各至少三輪）
- [ ] 同一頁連續進出（航海、海戰、進城混著）至少 5 次：每一場開場的狀態跟從網址開機的那一場一樣（船、海域、風、天氣、往來船、城）；反向對照：故意不清某一樣 ⇒ 量得出不同
- [ ] 背景待命時不搶地球儀：地球儀拖曳、縮放的每格時間跟沒有 battle.html 時差不多（讀數）

- [ ] 只有選船才用的素材（選船縮圖 1.26 MB 等）航海那一頁不帶或用到才載；選船頁照舊
- [ ] 記憶體與 GPU：待命、航海中、回地球儀之後的 JS heap 與 WebGL context 數有讀數；內顯掉 context 時能恢復或退回重新開機

## 要什麼

Tim 2026-11-11：「Blockside 開機＋收海圖塊 8.5 秒 開機是否可以在Blocksail進入地球儀後就維持開機」「要多佔 300～380 MB 記憶體 這個沒問題」「另外Blocksail實際用的應該是battle.html 因此有些流程應該跟Blockside可以拆分?」「開單」。

battle.html ＝ Blockside 建好的成品 ＋ Blocksail 的外殼（battle/shell.json；docs/CORE_SHELL.md）。現在每次進航海／海戰／進城都重新載一次 battle.html，所有參數都從網址拿（map=@host、site、blue/red、mode、風…），從頭開機。
這張單把 battle.html 的開機流程跟 Blockside 拆開：Blockside 的 index.html 照舊從網址開機；battle.html 改成進地球儀就常駐，用訊息換場。

## 現況讀數（TASK-1195 #9、#10；哈瓦那出港，有視窗的 Chrome＋CDP，main 35eaa3b9 起地球儀在 Blockside 開機時已經少畫）

- 按下航海 ⇒ battle：第一次平均約 11.3 s（三輪 11.1、10.1、12.7），Blockside 開機（iframe 開始載 ⇒ 'started'）5.4～7.2 s
- 跟海域無關、常駐就省得掉的約 3 s：載 battle.html（單一檔 5.2 MB）＋解析＋載入 1.1～1.8 s、initAudio 約 0.9 s、著色器編譯約 0.5～1 s
- 換了海域還是要做的：海床網格、樹（treePump 約 2.2 s）、城、船的帆與索具（solve 約 1 s；同一型船也許可以留）
- 記憶體：航海中 JS heap 多 300～380 MB（Tim：沒問題）
- 選船縮圖 ship-thumbs-atlas 1.26 MB 只有 72_shippick.js 在用
- 主程式拆成外部 .js（讓 Chrome 留編譯快取）試過，沒有變快（#10）⇒ 不走那條

## 會咬人的地方

- Blockside 核心是一個閉包；外殼掛鉤（window.BS_SHELL）現在只有 ships ⇒ 換場、音效要開新掛鉤或事件（CORE_SHELL §0：依賴只能往下、外殼 → 核心）
- 每一場之間要清乾淨：船、海床、往來船、城、天氣、慢動作、模擬速度、HUD 狀態…（漏一樣就是上一場的東西跑進下一場）
- 筆電內顯掉 WebGL context 的老問題（blockside-igpu-context-loss）：常駐就多一個一直開著的 context
- Blockside 改在 dev 分支（Blocksail external/Blockside），推 dev 照規矩；Blocksail 同一個提交重套 battle.html
