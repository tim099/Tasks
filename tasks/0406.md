## 硬性規定（Tim 2026-10-05）
1. **skill 文檔整份重寫** —— ⛔ 不是把 UCL 那份複製過去改幾個字。舊文寫給「Unity＋python＋Senate 並存期」，搬過去的版本只描述 Senate CLI 的現況。
2. **skill 依賴的文件全部住在 Senate 專案內** —— 搬過去的 skill 裡 ⛔ 不得再有 `ucl_core:` 或指向 UCL_Core 的路徑。
   我的操作定義（Tim 若不同意請改）：住在 `D:/Unity/Senate`（`Docs/` 或 `SCP_Core/Docs~`），且 `senate cmd doc` 查得到。被引用的 UCL_Core 文件要跟著重寫進去（例：早安引用的 `Awakening_Cmd_Flow.md`）。
3. **命名全部改 `scp-xxx`**（跟 `ucl-*` 區隔；拍板時原文寫 spc-，已確認是 scp-）。
   規則：`scp-<原名去掉 ucl- 前綴>`（例：`ucl-goodnight`→`scp-goodnight`、`reading-library`→`scp-reading-library`、`agent-lessons-log`→`scp-agent-lessons-log`）。
   ⚠ 撞名：`ucl-morning` → `scp-morning`，而 Senate 已有一份 `scp-morning` ⇒ **不合併**（Tim 2026-10-05）：直接修改既有的 `scp-morning`，**照目前實際的早安流程整份重寫**（`senate cmd morning-wake` 起手、每步照回傳檔的 next）；`ucl-morning` 不另外搬。
   ⚠ 改名的連鎖：觸發詞、`/ucl-morning` 這類斜線指令、信件與文件裡的 skill 名都會變；重寫時一併處理 skill 自身的引用，其他地方的舊名另列清單交 Tim 決定。

4. **skill 本身只提供入口 CLI**（Tim 2026-10-05）—— 安裝出去的 SKILL.md 只有 frontmatter（名稱／描述／觸發詞）＋入口那一行指令；
   內容由 CLI 查詢時才現場解析文件、可合併多份、呼叫端不處理路徑。
   讀數：`senate cmd doc` 已經是從磁碟現讀、根錨在 exe 所在的 Senate repo（不看 cwd）⇒ 從 LY 呼叫也讀同一棵樹、改文件不必重 build。

   ⚠ 代價：正文不再自動進 context，agent 要真的跑那一行 —— 所以「查不到」必須大聲失敗（見驗收）。

5. **指令回傳文字直接指向指令，不指向 skill**（Tim 2026-10-05）—— 回傳檔／CLI 輸出要提示「下一步跑哪一支指令」，⛔ 不寫「看 skill `ucl-xxx`」。
   而且**指令名在 Code 內動態組**，⛔ 不寫死字串：指令改名或改參數後，提示跟著變，不會過時。
   讀數：`SCP_CmdRegistry.Invoke("<尾巴>")` 已經動態組 `senate cmd` 前綴，但尾巴裡的指令名仍是手寫字串 ⇒ 要能從 Cmd 本身取名字（例：依型別查 `Name`）。
