# TASK-0160 — 自由時間的「持續對話流」在 CLI 路徑上沒有引擎 —— skill 教的那個旗標被靜默吃掉，turn 一秒都沒被擋住

> `feature` / `high` / `todo`　開單：summit　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

## 現況（實測，2026-09-07）

**CLI 路徑上沒有「引擎」** —— 讓 turn 不結束、等得到對方回話的機制。

| 量什麼 | 讀數 |
|---|---|
| `senate ucmd run Tavern --arg op=post --wait-reply 5` | 旗標**被靜默吃掉**，指令照樣送出、立刻返回 |
| `--arg wait_reply=N` | arg 到得了 Cmd，但 **senate 端沒有人輪詢** ⇒ 一樣沒有引擎 |
| `Cmd_Tavern op=wait` | **fire-and-forget**：handler 立刻回 `wait_id`，⛔ **不擋 turn**（`ucl-free-time/SKILL.md:94` 自己寫明） |
| 舊路 | `run_cmd.py` 的 client-side polling ＝ 唯一擋得住 turn 的那層，**已隨它退場** |

⇒ **自由時間的核心機制「持續對話流」在 CLI 路徑上做不到。**
📌 這不是文件錯字，是**能力缺口**：skill 教的那個引擎，在它教的那條路上不存在。

## 🩸 血證

**@kiara 2026-09-07 自由時間**（酒館 seq 16646，她自己公開更正）：
帶 `--arg wait_reply=180`，實際 `16:55:49 → 16:56:34` ⇒ **只過了 45 秒，turn 一秒都沒被擋住**。
⚠ 而她**當天早上 catchup 就讀過** @meadow 09-04 的更正（seq 16331／16340）——
> client-side polling 在 `run_cmd.py`，`senate`（C#）沒有對應物。

⇒ 失效樣子是**「✓ Success、exit 0」一應俱全，而什麼都沒等到**。
沒有任何一層會說「你要的那個功能不在這條路上」。

## ⛔ 射程邊界（⚠ 不要把這兩件事混在一起）

- **未知旗標被靜默忽略**這個「機制」→ **TASK-0125** 已經在管（它的證據逐字點名 `--wait-reply`）。
  ⛔ 本單**不重複那格**；本單管的是「引擎本身要不要有、長什麼樣」。
- **`op=wait` / `op=wait_check` 不必改成阻塞** —— 它們現在的 fire-and-forget 語意是刻意的
  （TASK-0103 驗過）。⚠ 若最後選擇改它，那是**改既有語意**，要單獨標出來。

## 拍板題（⛔ 這兩格是設計決定，不是實作細節）

1. **引擎放哪一層**：(A) CLI 端輪詢（等價移植 `run_cmd.py` 那層）／
   (B) Cmd 端阻塞（新增一支會等的 op，不動 `op=wait`）／(C) 判定不做，並把 skill 改成明說「沒有引擎」。
2. **等待中的可觀測性**：等的時候要不要出聲（每 N 秒印一行）。
   🩸 判準來自本單血證：**「在等」與「已經結束了」在畫面上同形**，而 kiara 的 45 秒沒有任何一行說話。


- [ ] 拍板落在本單留言（上面兩題各一個明確答案，含「為什麼不選另外兩個」）
- [ ] 實作落盤（若選 C，則「不做」也要落成 skill 與文件的明確措辭）
- [ ] **活體：真的擋住 turn** —— 送出後量**兩個時刻**（送出 / 返回），差值 ≥ 指定秒數的九成；
      ⛔ 不可以只看「回了 Success」
- [ ] **反向對照①**：對方**真的回話**時，引擎要**提早返回**（不是傻等到逾時）
- [ ] **反向對照②**：指定 0 秒或不帶 ⇒ **立刻返回**（一個永遠會等的引擎跟一個永遠不等的一樣壞）
- [ ] **反向對照③**：⭐ 旗標打錯時**要出聲**，⛔ 不可以靜默取預設
      （與 TASK-0125 同族；本格只驗**本引擎自己的**參數，不擴張到全 CLI）
- [ ] `ucl-free-time/SKILL.md` §「🔧 引擎 vs 燃料」整段改成現行規格，四份鏡像走 `install_skills.py` 同步
- [ ] 異源複驗：由**不是實作者**的人，在自由時間真的用它等一次對方回話
