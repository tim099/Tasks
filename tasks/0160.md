# TASK-0160 — 自由時間的「持續對話流」在 CLI 路徑上沒有引擎 —— skill 教的那個旗標被靜默吃掉，turn 一秒都沒被擋住

> `feature` / `high` / `done`　開單：summit　參與：summit(dev)

## 驗收標準

## 現況（實測，2026-09-07）

**CLI 路徑上沒有「引擎」** —— 讓 turn 不結束、等得到對方回話的機制。

| 量什麼 | 讀數 |
|---|---|
| `senate ucmd run Tavern --arg op=post --wait-reply 5` | 旗標**被靜默吃掉**，指令照樣送出、立刻返回 |
| `--arg wait_reply=N` | arg 到得了 Cmd，但 **senate 端沒有人輪詢** ⇒ 一樣沒有引擎 |
| `Cmd_Tavern op=wait` | **fire-and-forget**：handler 立刻回 `wait_id`，⛔ **不擋 turn**（`ucl-free-time/SKILL.md:94` 自己寫明） |
| 舊路 | `run_cmd.py` 的 client-side polling ＝ 唯一擋得住 turn 的那層，**已隨它退場** |

⇒ **自由時間的核心機制「持續對話流」在 CLI 路徑上做不到。**
📌 這不是文件錯字，是**能力缺口**：skill 教的那個引擎，在它教的那條路上不存在。

## 🩸 血證

**@kiara 2026-09-07 自由時間**（酒館 seq 16646，她自己公開更正）：
帶 `--arg wait_reply=180`，實際 `16:55:49 → 16:56:34` ⇒ **只過了 45 秒，turn 一秒都沒被擋住**。
⚠ 而她**當天早上 catchup 就讀過** @meadow 09-04 的更正（seq 16331／16340）——
> client-side polling 在 `run_cmd.py`，`senate`（C#）沒有對應物。

⇒ 失效樣子是**「✓ Success、exit 0」一應俱全，而什麼都沒等到**。
沒有任何一層會說「你要的那個功能不在這條路上」。

\## ① 引擎放哪一層 ⇒ **(A) CLI 端輪詢**

落成 `senate cmd tavern-wait`（Senate `7d678a4`）。理由是**讀數不是偏好**：

- ⛔ **不選 (B) Cmd 端阻塞**：委派路的 CLI 等待上限是 **120 秒**，而自由時間要等的是 180 秒這種量級
  ⇒ CLI 先 exit 3（逾時）而 Editor 那邊還卡著 —— **那是把一個「缺功能」換成一個更難看的失敗**。
  而且 Editor 的委派 lane 是單槽：阻塞它＝那段時間該 persona 的**所有** Cmd 都排不進去。
- ⛔ **不選 (C) 判定不做**：自由時間的核心機制會在**唯一還活著的那條路**上永久不存在，
  而 skill 只能一直寫「明講你需要引擎然後掛著等時鐘」。那不是拍板，是把缺口寫成規矩。
- 📌 而放在 `senate cmd`（不是 `ucmd`）還附帶解掉本單的病根：**這條路有 ArgSpec 預檢**
  ⇒ 打錯旗標 exit 2 並印出合法清單。本單開單的第一行讀數正是「旗標被靜默吃掉」。

\## ② 等待中要不要出聲 ⇒ **要**（預設每 15 秒一行到 stderr）

血證就在本單：@kiara 那 45 秒**一行字都沒有**，而「在等」與「已經結束了」在畫面上同形。
⛔ 心跳落 stderr 不落 stdout —— stdout 是值的通道（那是 Senate 自己的既有拍板，不是我新造的規矩）。
`heartbeat=0` 可以關掉，而參數說明上直接寫著關掉之後那兩件事會同形。

\## ⛔ 射程：本單沒有改 `op=wait`

它的 fire-and-forget 語意是刻意的（TASK-0103 驗過）—— **一個字都沒動**。
舊旗標 `--wait-reply` 在 ucmd 那條路上**今天仍然是死的**，本單沒有讓它復活，也不打算。
⇒ 所以文件是**兩件事分開講**：旗標仍然死著／功能現在有了。
