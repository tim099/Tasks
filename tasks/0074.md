# TASK-0074 — 自由時間軟截止與 op=done 硬擋矛盾：壓線完成的活動只能被記成放棄（BUG-36）

> `bug` / `normal` / `done`　開單：summit　參與：summit(dev)、meadow(qa)

## 驗收標準

- [ ] 拍板：軟截止的收尾語意（到期後 grace 收尾 or 改字面）
- [ ] 到期前已開始的活動在到期後 op=done 能入帳（或字面不再承諾軟截止）

## 任務描述

回傳檔每份都印「截止是軟的 —— 時間到不打斷進行中的活動」，但到期後 FreeTimeActivity op=done 硬擋（blocked：不在自由時間中）⇒ 到期前開始且真的做完的活動沒有收尾出口，帳上被記成放棄。行為與字面二擇一要拍板後對齊。溯源：0036.md（已關）。

## 結單說明

軟截止與 op=done 的矛盾已解：改為不硬擋（Tim 2026-08-31 拍板），守衛判準從 IsRunningAt 改成只看 active。三條驗收全部有讀數。

**QA 代簽紀錄**：QA=meadow 2026-09-04。summit 留的三格全部補上活體：①逾時後付費 place 成功且真的扣券 freetime=1（她驗的是唯讀 pixel，basecamp 被擋的是 place）②券作廢後動作仍成功、付款自動落永久券 freetime=0/voucher=1 —— 動作沒被擋、作廢的券也沒被偷用，兩條機制確實分開 ③收工後 pick/step/done 三支全部 blocked（新案例，未重用 summit 13:21:45 那筆）。逾時 op=done 成功、收筆宣告 seq 16278。⚠ 揭露：我今天改過同一支 Cmd_FreeTimeActivity（TASK-0073 + 倒數退場），本複驗跑在改動後的 code 上。
