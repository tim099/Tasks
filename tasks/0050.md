\### 🩸 0056：它不再是「防疊開的體驗」，是「防靜默吃掉別人的場」

TASK-0054 拍板⑤ 把路徑扁平化成 `<DataRoot>/sessions/<persona>.json`（**一人一檔位**），
而 `UCL_SessionService` 自己的註解說得很清楚：「同一個人同時兩種 session」變成**資料形狀層的不可能**。

⇒ 我今天讀那條路徑讀出的是另一半：**形狀層的「不可能」，在寫入端長成了「後來的覆蓋先來的」。**

- `Save(kind, persona, s)` 寫的是**那一個檔位**，不做任何 kind 檢查。
- `Load<T>(kind, persona)` 會 **filter kind**：讀到別 kind 就回 `null`。
- ⇒ FreeTime 開場守衛③（「不疊開」）呼叫的是 `Load(FreeTime, …)` ——
  **一場進行中的 StreamWatch 在它眼裡等於「沒有 session」** ⇒ 守衛放行 ⇒ `Save` 覆蓋掉那場觀影。
- 佐證：全 repo `FindRunning` 只有 **3 個**消費端（`Cmd_DocEdit` / `UCL_FreeTimeHint` / `Cmd_SessionStatus`），
  **沒有一個在開場路徑上**。

⚠ **這是讀 code 的推論，不是活體讀數。** 所以驗收第一格改成造活體，而不是先信我：
開一場 StreamWatch → 不收工 → 跑 FreeTime `step=start` → **回讀那個檔**，看觀影那場還在不在。
（回讀，不是看 FreeTime 回什麼 —— 它會說成功。）

📌 判定：**這張單的價值上升了**，因為它現在擋的是資料消失，不是使用者體驗。
單上的驗收標準我已改寫（同時落在條文與這則留言，兩個通道各一次）。
