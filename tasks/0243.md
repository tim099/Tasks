## 任務描述

Tim 2026-09-18 的設計（原話照收，⛔ 不改寫）：

> 券直接綁定 persona（存放在 persona 信件資料夾內，例如 `letters/basecamp/<x>`）。
> 所有券共用一套系統，且**由銀行 Server 管理**。
> **券不記錄歷史** —— 每種券一個檔案（per persona）紀錄當前數量 ＋ 暫時券數量
> （會到期的券，到期後消失）。暫時券可以有多筆
> （例如 10 張 2026-09-18 10:10 到期、50 張 2026-09-19 8:30 到期，分開計算）。**檔名為券的名稱**。
> 券可以**分區遷移**（遷移時數量加總、可以跨區使用、需要紀錄該區是否跑過遷移 —— 例如 BTC 區跑過了就不再跑）。

## 🏷 `<x>` 的命名：我推薦 **`vouchers/`**

現況是 `<資料根>/Canvas/vouchers/<persona>.json`（一人一檔、**綁專案**、只給畫布用）。
新形狀是 `letters/<persona>/vouchers/<券名>.json`（一券一檔、**跟著人走**、所有券共用）。

理由三格：
1. **跟旁邊的兄弟同形**：`bank/`（錢）、`keys/`、`fragments/`、`portraits/`、`wakes/` ——
   單數名詞給單一主題、複數給「一堆同類檔」。券是一堆同類檔 ⇒ 複數。
2. **`bank` 管錢、`vouchers` 管券**，兩個詞在酒館與 glossary 裡已經是分開的東西
   （`permanent-voucher` / `session-voucher`）—— ⛔ 不要造第三個新詞來指同一件事。
3. `wallet` 這類詞我刻意不選：它暗示「錢包裡有錢」，而券**不是錢**（不同資源、不同帳）。

## ⚠ 三格我要先寫出來，因為它們的失效方式都不會有人喊

### ① 「不記歷史」＝ 存狀態而不是存事件 —— 跟新銀行**正好相反**

新銀行是 append-only、一筆一檔，餘額＝**重放求和**。
它檔頭寫著為什麼不存 `balance_after`：那是去正規化的冗餘，**併發時會說謊而沒有任何一層會喊**。

券要走相反的那條（直接存當前數量）⇒ 代價要明說：
- **扣錯了無法稽核、無法回推** —— 沒有事件流，只剩一個數字
- **兩個寫入端會互相覆蓋**，而覆蓋的結果是一個**完全合法的數字**

⇒ 所以 Tim 那句「**由銀行 Server 管理**」不是架構偏好，它是**這個設計成立的唯一前提**。
⇒ 驗收 ④ 把它從「約定」變成「grep 零命中」。

### ② 「到期後消失」有兩種做法，而它們可逆性相反

- **寫入端刪掉那一筆** ⇒ 不可逆。判錯了（時鐘、時區、邊界）券就真的沒了
- **讀取端過濾掉** ⇒ 可逆。判錯了改判準就回來

📌 既有判準：**寫入端省略不可逆，讀取端過濾可逆** ⇒ 選後者（驗收 ⑤）。
清理留給「下一次本來就要寫這個檔」的時候順手做，⛔ 不另外開一支會刪東西的定時工。

### ③ 跨區共用 ⇒ 那個檔會被**兩個專案**讀寫

`letters/` 是**同一個 git repo 被多個專案掛著**（2026-08-20 實測：LY 與 D:/Unity/Bar 的
`letters/kiara` root commit 與 HEAD 完全相同）。
🩸 銀行那側「一區一檔」正是為了防這個對撞 —— 存單一值的檔會被兩個專案互相覆寫，
**而症狀是「另一個專案的帳號」，一個完全合法的字串，沒有任何一層會出聲。**

券要**刻意跨區共用**（Tim 要的），所以不能靠「一區一檔」擋。
⇒ 擋它的只剩 ①那個前提：**只有一顆 Server 在寫**。
⚠ 而那句話今天成不成立**我沒有量過** —— 兩個專案是不是共用同一顆 Server、
同一個 Server 根，要有讀數（驗收 ⑦）。⛔ 不要拿「設計上是這樣」當答案。

## 🩸 遷移那一格的血證（TASK-0238，2026-09-17，同一族）

銀行遷移時「開帳快照」與「鏡像游標」沒對齊 ⇒ **2 筆錢被算兩次**，
而兩邊分錄都合法、`idem_key` 也不重複 ⇒ **沒有任何一層會喊**；
抓到它的是事後逐戶對帳。

券遷移是「數量**加總**」⇒ 同一族風險：加兩次跟加一次都是合法數字。
⇒ 驗收 ⑧（連跑兩次不變）與 ⑨（中斷後重跑）分開寫，因為它們是**兩種失效**：
前者是「重複執行」，後者是「**標記說跑過了、而券只搬了一半**」——
⚠ 後者更貴，因為它之後**永遠不會再跑一次**。
