# TASK-0249 — FreeTime step=start 發券失敗時 session 已經寫上磁碟 —— 失敗回傳與「什麼都沒做」同形，下一次開場會撞到查不出原因的 blocked

## 驗收標準

- [ ] 反向對照（先做這格）：在 Voucher／Bank 那條路被擋（build_mismatch 或任何 exit≠0）的狀態下跑 `step=start`，然後讀 `AgentCommands/sessions/<persona>.json` —— 現況是 `active:true` 的 session 已寫上磁碟，而 CLI 回的是失敗
- [ ] 修法擇一並寫明理由：①「發券失敗 ⇒ 連同 session 一起回滾」；或 ②「session 保留，但失敗訊息要指名它」。⛔ 不接受只在文件補一句提醒
- [ ] 失敗訊息（或 `_cmd_errors/<id>.md`）必須說出「session 已建立（id=…，至 HH:mm）」與「券未發放」兩件事分別的狀態 —— 受測體＝下一個撞到 blocked 的人，他不必去讀 sessions/*.json 就該知道為什麼
- [ ] 正向不回歸：正常情況下 `step=start` 仍然開得了場、10 張限時券照發（帶讀數）
- [ ] 若採修法②：`step=start` 撞到既有 session 時的 blocked 訊息要能區分「上一場正常沒收工」與「上一場是半套開場（rounds=0 且券未發）」

## 任務描述

## 現場（2026-09-18 17:24，kiara 實測，位址齊）

`senate server` 與 senate.exe build 不符時（`delegate_failure = build_mismatch`），跑：

```
senate ucmd run FreeTime --arg step=start --arg until=17:30
```

CLI 回**失敗**：

```
[Voucher] 讀餘額 被拒絕（exit 3）：✗ 版本不符 …… —— 券**沒有動**。
  at UCL_CanvasVoucherLedger.GetExpiring (UCL_CanvasVoucherLedger.cs:41)
  at Cmd_FreeTime.GrantFreePixelVouchers (Cmd_FreeTime.cs:1057)
  at Cmd_FreeTime.StepStart (Cmd_FreeTime.cs:196)
```

⇒ 而重啟 server 之後再跑一次 `step=start`，回的不是開場，是：

> blocked：**已有進行中的自由時間 session**（至 17:30）—— 不疊開

讀 `AgentCommands/sessions/kiara.json`：

```json
{"session_id":"ft-20260918T092417Z-kiara","start_ts":"2026-09-18T09:24:17.223Z","active":true,"rounds":0}
```

## 時間軸（差 200 毫秒）

| 時刻 | 發生什麼 |
|---|---|
| `09:24:17.223Z` | **session 寫上磁碟**（`active:true`） |
| `09:24:17.4Z` | `GrantFreePixelVouchers` 丟例外 ⇒ Cmd 判失敗 |

## 病

**「它失敗了」與「它什麼都沒做」在回傳上同形，而磁碟上差一個檔。**

- 失敗訊息**一個字都沒提到 session**（它只講券）
- 回傳檔（骰面／時間欄）沒有生成 ⇒ 使用者手上沒有任何 session 存在的線索
- 下一次 `step=start` 撞到 blocked 時，訊息說「已有進行中的 session」——
  對一個以為自己從來沒開成場的人來說，那句話讀起來像系統壞了

⛔ 而 Voucher 那一層**沒有錯**：它印「這一筆沒有送出、券沒有動」，對自己那一格完全誠實。
📌 問題在邊界：**上游已經寫了東西，而下游只回報自己那一格。**

## 影響

本場的實際狀態是**半套**：session 在（佔住不疊開的名額）、券 0 張、輪次 0。
使用者要嘛被迫用完那段時間，要嘛得知道有 `step=end` 這條路才收得掉。

## 誰在等

任何一個在 Voucher／Bank 不通時開自由時間的人 —— 今天至少 kiara 一位撞到，
而 build_mismatch 這種狀態每次有人重建 senate.exe 而沒重啟 server 就會再現。
