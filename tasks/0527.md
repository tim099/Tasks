### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

## 症狀
10-12 18:05 之後，酒館 Server（tavern）與 main 每一次重啟都判定「名片上是另一顆**活著的**」⇒ 照 TASK-0468 讓位：
Discord 收發、酒保、每日結算全部不跑，而 Server 本身照常寫酒館、沒有任何一格紅燈。
- Discord Outbound 游標停在 tavern seq 23102（10-12 18:05），10-13 早上 23103～23135 一則沒送（Tim 回報「Outbound 失效」）。
- 每日結算 10-13 沒跑：`Bank/overnight_job_state.json` 停在 `last_run_date: 2026-10-12`。

## 根因（讀碼＋讀數）
`SCP_Core/Runtime/Process/SCP_ServerEndpoint.cs` `Probe()`（約 339-359 行）判活只看名片 `heartbeat_path` 指的心跳檔裡 `beat_at_utc` 新不新，
**不比對心跳檔的 `pid`／`started_at_utc` 是不是名片上那一顆**。
而心跳檔路徑是照 server id 取的（`_server_heartbeat.tavern.json`／`_server_heartbeat.json`）⇒ 同一個 id 的下一代 Server 寫同一個檔，
每 500 ms 替死掉的那張名片作證 ⇒ 名片永遠是 Alive ⇒ `CheckCardOwner` 的「遺物 ⇒ 補寫接手」那條路永遠走不到。

## 讀數（怎麼拿到的）
- 名片 `D:/Unity/Valhalla/_server_endpoint.tavern.json`：pid=52560、build=433347a-dirty.20261012T054407Z、heartbeat_path=...\_server_heartbeat.tavern.json（cat）
- 同一個心跳檔內容：pid=11468（現役那顆）、beat_at_utc 新鮮（cat）
- `tasklist /FI "PID eq 52560"` ⇒ 沒有這個 process；11468 在跑
- main 同形：名片 pid=1336（tasklist 查無），現役 7604
- 啟動 log `SenateData/runtime/_server_start.tavern_{54276,50076,11468}.log`、`_server_start_{46460,7604}.log`：每份第 5 行都是「名片上是另一顆活著的 … pid=52560／1336 … 狀態=Alive ⇒ 不蓋」
- 舊兩顆的 log（`_server_start.tavern_52560.log`、`_server_start_1336.log`）停在 10-12 18:05，**沒有「已停」那一行** ⇒ 不是正常收工（推測：出廠時被收掉；⚠ 這格是推的，沒量）
