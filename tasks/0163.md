\## 先講結論：①「要嘛給整個檔一把鎖（RMW 全包）」那半**做不到**，不是難做，是形狀不對

我開單時寫的兩個選項：

> ① `UCL_TaskIO` 的 24 個 public 面在併發下安全：**要嘛給整個檔一把鎖（read-modify-write 全包）**，要嘛把 RMW 收成單一入口。

⇒ **前者不成立。** 因為 RMW 的跨度**不在 `UCL_TaskIO` 裡面** —— 它從呼叫端開始。

`Cmd_Task.OpComment`（`Cmd_Task.cs:834-851`）的實際形狀：

```
var e = Require(iArgs, out aIndex);      // ← READ（內部走 UCL_TaskIO.Find ⇒ 讀整個檔）
e.comments.Add(aComment);                // ← MODIFY（在呼叫端的物件上）
UCL_TaskIO.Touch(e, aNow);
// ⛔ [RMW-END] 從本 Op 取得 `e` 到這一行之間不得出現 `await`
UCL_TaskIO.Save(e, "", "", ...);         // ← WRITE（整檔重寫）
```

⇒ 在每個 public 面各包一把鎖，只會讓 `Find` 與 `Save` **各自**是原子的。兩條 lane 仍可以：

```
A.Find  →  B.Find  →  A.Save  →  B.Save
                                  └─ B 拿的是 A 寫入「之前」的內容重寫整檔 ⇒ A 的留言消失
```

而 `Save` 是**整檔重寫**（檔頭 `📌 整檔重寫，但歷史留在檔內`）⇒ 遺失更新是靜默的，
一格都不會紅。**那正好就是檔頭 TASK-0026 判為有害的那把「守不到東西的鎖」** ——
它會讓下一個人以為這裡已經安全了。

⇒ 所以本單的正解**只有第二個選項**：把 RMW 收成單一入口，鎖跨越讀＋寫。
形狀（不是最終 API，交給第二個人挑）：`UCL_TaskIO.Mutate(index, e => { ... }, activityLine)`。

### 💬 #3 summit 2026-09-08T00:44:58.670Z

\## 讀數：併發**今天就存在**，擋著它的只有「RMW 中間沒有 await」這一條慣例

`UCL_AgentCommandRunner`：

```
static string NormAgent(string agentId) => agentId ?? "";        // :48
static readonly HashSet<string> s_RunningAgents = ...;           // :42
public static bool IsRunningForAgent(string agentId)
    => lock (s_RunningLock) s_RunningAgents.Contains(NormAgent(agentId));   // :188-191
```

⇒ 重入守衛是 **per-agent** 的。同一個 agent 的第二趟被擋；**不同 agent 不互擋**
⇒ 兩個 agent 的 Runner 可以同時在飛，在 `await` 邊界交錯（都在主緒，協作式）。

📌 所以檔頭那句要讀準：**「單一主執行緒」不等於「一次只有一支 cmd」。**
真正在保護 `Tasks/` 的是後半句 —— **RMW 中間沒有 await**（10 個 `⛔ [RMW-END]` 前哨就是它的實體）。
⇒ 併發不是 offload 之後才出現的東西，**它現在就有**；offload 拿掉的是「協作式交錯」這個前提，
讓交錯點從 `await` 邊界變成任意指令邊界。

\## ⇒ 於是 ③ 的判準要補一句定語，而它把 ③ 綁在 ⑤ 上

③ 原文：「兩條 lane 同時對 Task 發 cmd（例如同時 `op=comment` 兩張不同單）」。
