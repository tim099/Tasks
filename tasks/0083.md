# TASK-0083 — bank_personas 反向表沒有寫入端：覆蓋率隨建人安靜衰減（BUG-21）

## 驗收標準

### ① 建 agent／fork persona 的路徑同步寫 bank_personas（單一寫入點）—— ⛔ **沒做，而且我建議換形狀**
- [ ] ⚠ **這一格的題目量下去之後變了**：`DoCreateAgent` 建的是**銀行**不是人，它不會讓任何 persona
      進到某家 bank 底下 ⇒ 「建 agent 時同步寫」補不到真正的洞。
      persona↔bank 的連結是在 **`UCL_PersonaProfile.WriteBankAccount()`**（寫 `bank/<region>.md`，
      單一寫入點、已有審計）那一刻成立的，刪除則在 `DeleteBankBinding()`。
      ⇒ 真要補寫入端，是補在那兩支，**而且要有區域守衛**（只在 `iCurrencyId == 本專案 region`
      時才動本專案的 `_registry_meta.json` —— letters 是多專案共用的）。
- [ ] 🩸 **而我量到一件事讓我不建議只做寫入端**：這張表**推導得出來**
      （正向 `bank/<region>.md` 反轉即得，本輪逐格對過）。
      寫入端只在**新增那一刻**生效；之後任何一次手改 `bank/<region>.md` 都會讓它再漂一次。
      ⇒ 推導得出來的索引要的是**產生器＋對帳**，而「記得也寫一筆」是系統不能依賴的東西。
- [ ] ⛔ **未拍板**：寫入端要不要做／做在哪／`bank-audit` 要不要加 `--arg apply=1`。
      ⚠ 加 apply 等於讓共用層寫綁定，那**牴觸 Tim 2026-08-31 的拍板**（讀綁定不是動錢，寫綁定是）。
      這一格我不自己挑。

### ② 對帳：現況 persona 全數在反向表 —— ✅ 已交付（SCP_Core `f95f36b`）
- [x] 做成**可重複取的機械讀數**而不是一次性盤點：`senate cmd bank-audit`（唯讀、不需要 Editor）。

      ⇒ `hole=0 ghost=0 dup=0`、**`mismatch=1`**。
      ⇒ **覆蓋率沒有衰減**（本區 21/21），單上寫的「隨建人安靜衰減」目前**沒有在本區發生**。
- [x] ⭐ **陽性對照**（scratchpad 副本上種故障，⛔ 沒動真表）：拔掉 `basecamp` ⇒ hole 1／
      塞一個 pool 沒有的人 ⇒ ghost 1／`gura` 多塞一家 ⇒ dup 1。**四個偵測器都會叫。**
      ⇒ 真表那三個 0 是有意義的 0，不是「這支不會叫」。
