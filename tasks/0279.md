## 任務描述

BTC 區的帳本裡有一個 `sirius` 帳戶（`Bank/accounts/sirius.json`，status=open，餘額 **1246**），
而 persona `sirius` 的帳號解析回的是 **`Spectre`**（`bank-resolve --arg input=sirius` ⇒ ViaPersona，一跳）。

⇒ 跨日保管費每天對 `sirius` 這個**餘額 key** 算出 12 token 的費用，而寫入端歸一之後
**扣在 `spectre` 身上**。於是兩件事同時成立：
- `sirius` 的餘額**永遠不會下降** ⇒ 它每天都會被重新算一次同樣的費用，⛔ 沒有終點。
- `spectre` 每天替它付。

⚠ 這**不是** TASK-0278 造成的，那張單是照搬既有行為（對拍逐帳戶 0 不符）。
它是搬家時被照出來的既有狀態。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

逐日掃 `Bank/ledger/*/`，`kind=overnight_storage_fee` 且 `ref` 尾段是 `sirius` 的 entry，
每一筆的 `account_id` 都是 `spectre`：

- 2026-09-18 11:20:30　`overnight-fee-2026-09-18-Sirius`　account=**spectre** 12
- 2026-09-20 12:05:44　`overnight-fee-2026-09-20-sirius`　account=**spectre** 12
- 2026-09-22 12:21:17　`overnight-fee-2026-09-22-sirius`　account=**spectre** 12
⇒ 三天共 **36 token**。

而 `sirius` 這個帳戶自己的餘額在這期間**一格都沒動**：把所有 `account_id == "sirius"`
的 entry 重放 ⇒ 1246（09-18 與 09-20 的快照都是 1246）。
⇒ 「已經扣過了」這件事在它身上結構上不會成立，所以它每天都會再被算一次。

解析讀數：`senate cmd bank-resolve --arg region=BTC --arg input=sirius`
⇒ `account = Spectre`／`kind = ViaPersona`／trace「【合一模式】persona `sirius` → 帳號 `Spectre`（一跳）」。
而 `Bank/accounts/sirius.json` 同時存在（`display_name: Sirius`、status open、開戶 2026-09-17T10:25:21Z）。

⚠ 我**沒有**量的：另一區（Florin）有沒有同形的帳戶／persona 對撞。

### 💬 #2 basecamp 2026-09-22T14:07:51.885Z
**[更正：我先前寫的「舊行為是 spectre 一口氣 -37」有兩個毛病]**（Tim 2026-09-22 當場質疑，我回去量了）

**判定**：那句話**把推算講成讀數、把兩筆講成一筆**，兩個毛病疊在一起剛好長得像一句乾淨的結論。
⚠ 同一句也寫進了 `SCP_Core 6cc792c` 的 commit 訊息裡 —— git 改不了，更正留在這裡。

- **-37 是我對「明天」的算術**（12 ＋ 25），⛔ 不是任何一天的讀數。**今天實際是 39。**
- **帳本上一直是兩筆，不是一筆。**「一口氣」在帳本那一層是錯的。

**憑據（帳本逐筆）**
```
09-18  spectre -12  ref …-Sirius      spectre -21  ref …-Spectre   → 33
09-20  spectre -12  ref …-sirius      spectre -30  ref …-spectre   → 42
09-22  spectre -12  ref …-sirius      spectre -27  ref …-spectre   → 39
```

**而「一口氣」在廣播那一層是對的** —— 今天那則酒保公告逐字：
```
- @spectre: balance 1558 → **-39 token** (excess 558 × 5%)
- @sirius:  balance 1246 (今日已扣過 — 冪等命中，**這次沒有動錢**)
```
① spectre 那行**自己對不起來**：558 × 5% ＝ **27**，而它印 **-39** ——
括號裡的算式與前面的數字是**兩個不同來源**（後者是回讀餘額的差，已含前一筆的 12）。
② sirius 那行**是假的**：它沒有「今日已扣過」。它的 12 幾百毫秒前被扣在 spectre 身上，
而 `GetBalance("sirius")` 同樣被解析到 spectre ⇒ 回讀差是負的 ⇒ 舊碼把「沒有變少」讀成「冪等命中」。

📌 單上與 commit 訊息裡的另一句（「09-18／09-20／09-22 各 12，共 36」）**沒有問題** ——
那格是 `…-sirius` 那條 ref 的實測，不受本次更正影響。
