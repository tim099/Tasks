# 為什麼它必須排在寫任何酒館 Cmd 之前

Tim 2026-09-18 拍板**乙（兩顆常駐 process）**，理由是**分開動工**（施工銀行時酒館也能施工）。
而現在 Server 這一層**通篇假設只有一顆** —— 全是單數形，集中在 `src/Senate.Core/SenatePaths.cs` 與 `ServerHost.cs`：

| 東西 | 現值 |
|---|---|
| 單例鎖 | `<RuntimeDir>/_server_singleton.lock`（`ServerHost.cs:358`） |
| queue 根 | `SenatePaths.ServerRoot()` ＝ `<RuntimeDir>/server`（`SenatePaths.cs:92`） |
| 心跳 | `_server_heartbeat.json`（`:71`） |
| 停機請求 | `_server_stop.request`（`:74`） |
| 登記名 | `ServerHost.Tag = "senate_server"`（`ServerHost.cs:100`） |

⛔ 不做這格就起第二顆，失效順序是：

1. 第二顆**拿不到單例鎖 ⇒ 拒絕啟動**（`ServerHost.cs:216`）—— 這格**會叫**，還算好的
2. 若繞過鎖：兩顆掃**同一個** `queues/` ⇒ **互相接手對方的 lane**。
   🩸 而它會**成功**（兩顆載同一份 `Senate.Core`）⇒ 銀行的 Cmd 被酒館那顆跑完，
   **沒有任何一層會叫** —— 這正是本專案今年反覆咬人的那一族
3. `server status` / `stop` / `server-ping` 各只有一條路 ⇒ **停 Server 會停錯顆**

# ⚠ 動工前先知道的兩格

- **PM 自曝**：她 2026-09-18 ship 了 `ServerAdminPage`（`ui --page server`），上面有「啟動 Server」鈕。
  ⇒ **這等於多了一個更容易起第二顆的入口。** 目前防線兩道（頁面先判 `IsRunning`、`server start` 自己拒絕第二顆），
  ⛔ 而那是她自己說的、**沒有第二個人量過** ⇒ 本單完成前**當未驗**，完成後由驗收⑤量它。
- `build.sh:86` 停 Server 用的是 `Get-Process -Name senate, senate-server` ⇒ **全殺**。
  ⚠ 不改它的話，「分開動工」這個選乙的理由**拿不到**（build 銀行照樣停掉酒館）。

# ⛔ 邊界

本單**只做身分化**，⛔ 不寫任何酒館 Cmd、⛔ 不動 `Cmd_Bank`、⛔ 不改冪等（那是 TASK-0242）。
