### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

## 現場（2026-09-21 13:42~13:44，basecamp 實測，LY／Florin，真 CLI → Senate Server pid=26784 build=6bdfeaf-dirty.20260921T034540Z）

做 TASK-0250 出廠驗收時量到的。同一支 `bank`、同一顆 server、兩種失敗，**結局不同**：

```
# A：Cmd 回 Fail(1) —— 正常
senate cmd bank --arg op=balance --arg account=no-such-account-xyz
⇒ 🔢 exit_code = 1
⇒ 📄 錯誤報告：...\20260921-134315-a61c7d-bank.md        ← 檔案真的在，內容完整

# B：Cmd 回 Fail(2) —— 壞的
senate cmd bank --arg op=open --arg account=probe-0250 --arg amount=7
⇒ 🔢 exit_code = 1                                       ← ⛔ Cmd 回的是 2
⇒ 📄 錯誤報告：...\20260921-134316-c0924b-bank.md　⚠ 檔案不在（Server 端沒寫成？）
```

逐字確認過 B 的 Cmd 端回的是 `SCP_CmdResult.Fail(2, …)`（`Cmd_Bank.OpOpen`，TASK-0250 那四道守衛）。
`ls -t _cmd_errors/` 確認 B 那三筆 cmd_id **一份都沒有**落檔。

## 成因（讀了實作，不是推的）

兩段各自都對，是**接縫**錯的：

1. `src/Senate.Core/ServerDelegateCmd.cs:210` —— 只要 `aVerdict == Failed` 就 `aResult.ExitCode = 1` **寫死**，
   ⛔ 不讀 Server 那側 result 檔裡 Cmd 自己回的退出碼。
   ⇒ **任何走 Server 委派的 Cmd，它自己回的 exit 2 都到不了呼叫端。**
2. `src/Senate.Core/CmdErrorReport.ShouldReport(int)` —— 只認 exit 1／70，**exit 2 刻意不寫**
   （檔頭逐字：「打錯字配一份 stack 只會訓練人忽略這個目錄」）。這一段是對的。

⇒ 壓成 1 之後，`UnityDelegateCmd.AppendReport` 就照 1 的規矩去宣告一份路徑，
而寫檔那端照 2 的規矩（正確地）沒寫 ⇒ CLI 自己承認找不到，再猜「Server 端沒寫成？」。

## 📌 這個形狀 TASK-0104 已經流過一次血，而它自己標了沒驗完

`CmdErrorReport.cs` 的檔頭註解逐字記著 exit **3** 的同款（2026-09-04 summit QA 判不通過那格）：
「CLI 照樣宣告了一份報告路徑、再自己承認找不到、再猜『Server 端沒寫成？』」。
⇒ 當時的修法是把 exit 3 從 `ShouldReport` 拿掉 —— **治的是寫檔那端，沒治壓退出碼那端**。
而 TASK-0104 結單留言最後一行自己寫著：「⚠ 未驗：**Server 宿主那條路的活體**（要起 Server），以結構證據涵蓋並標明」。
📌 **我量的就是那一格，而它在那裡是壞的。**

## 誰在等

① 任何一個在 server 委派 Cmd 裡寫 `Fail(2, …)` 的 dev —— 他的「用法錯」在呼叫端跟「執行失敗」同形。
   活體：TASK-0250 的驗收表寫著「無 confirm ⇒ exit 2」，那是 in-process 量的，**真 CLI 上永遠讀不到 2**。
