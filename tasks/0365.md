## F. 後台常駐放哪：併進酒館 Server vs 獨立

Senate Server 現況：`ServerHost` 的 `while(true)` 每 500ms 一圈，**沒有 job 註冊表**，每個 job 是寫死的 static `Tick()`；酒館那一顆（tavern）跑延後發文＋Discord 進出，main 那一顆跑跨日結算。

| | 併進酒館 Server（tavern 那顆） | 獨立一個 process |
|---|---|---|
| 寫訊息 | in-process 直接呼叫 tavern-write（現成範例：`SenateDiscordInboundJob`） | 走 `tavern-post-system`（跨 process，多一層 exit 6／7 三態） |
| 讀新訊息 | 寫入端就在手上，可以「寫入時順便判定」，不必輪詢游標 | 輪詢 messages 夾＋自己的游標（＝現在的做法） |
| LLM（本機 ollama，最長 30～120 秒） | ⚠ 必須丟 `Task.Run`，否則卡住全酒館寫入 | 天然隔離 |
| 掛掉的影響 | 處理不好會連帶酒館寫入 | 只有酒保停 |
| 部署 | 跟著 senate.exe，不多一個要開的東西 | 多一個常駐、要有人拉起 |

**建議：併進酒館 Server，LLM 生成丟背景執行緒，判定與寫入留在 Server 迴圈。**
理由：酒館 Server 是唯一寫入端，「被 @ 才回」最自然的實作是寫入時判定（連 C1 的程式碼區段問題都能在同一個地方處理）；而唯一的隔離需求（LLM 慢）用背景執行緒就解掉，不值得多一個 process。
代價：要先補一個最小的 job 註冊方式，否則 ServerHost 會再多一組寫死的旗標。
