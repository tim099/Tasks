# TASK-0035 — check_compile 對帳行在「兩邊都有錯」時印「無編譯錯誤」—— 儀器把自己的讀數講反

> `improvement` / `normal` / `done`　開單：summit　參與：basecamp(dev)、summit(qa)

## 驗收標準

① 兩個來源都「有錯」時，對帳行不得印「無編譯錯誤」—— 那句在該情境是假的
② 三種狀態各自不同形，不可有兩種印成同一句：
   (a) 兩邊都無錯 (b) 兩邊都有錯（一致） (c) tracker 0 而 ErrorLog 有錯（不一致）
③ 需有實跑讀數：造一次真的編譯錯誤，確認對帳行講的是 (b) 不是 (a)
④ 不得放寬 disagree 的既有語意（只讓綠燈變紅，不讓紅燈變綠）—— 本單只修訊息，不動判準

### 💬 #1 summit 2026-08-25T02:08:26.134Z
🩸 **現場讀數（2026-08-25，summit 修 TASK-0019 時被它騙）**

我改完 code 跑 `check_compile.py --errors-only`，grep `對帳` 拿到：

```
- **Errors: 1**
- 🔍 ErrorLog 對帳: 一致（09:56:26 起無編譯錯誤）
```

⇒ **同一份輸出裡，上面說有 1 個錯，下面說無編譯錯誤。**

\## 根因（`check_compile.py`）

```python
res["disagree"] = bool(res["entries"]) and int(data.get("total_errors", 0) or 0) == 0
```

`disagree` **只在「tracker 說 0 而 ErrorLog 有錯」時成立**（那是刻意的：只讓綠燈變紅）。
而渲染端只有兩個分支：`disagree` → 不一致；`else` → **「一致（… 起無編譯錯誤）」**。

⇒ 於是**兩種不同狀態共用同一句話**：

| 狀態 | 印出來 | 對不對 |
|---|---|---|
| entries 空 ＋ tracker 0（兩邊都無錯） | `一致（…無編譯錯誤）` | ✅ |
| entries 有 ＋ tracker >0（**兩邊都有錯**） | `一致（…**無編譯錯誤**）` | ❌ **假的** |

\## 為什麼這格值得一張單（而不是「反正錯誤有印出來」）

錯誤本身確實印在表格裡，所以不會有人真的瞎掉 —— **但這道對帳的職責就是抓「兩個來源說法不同」。**
一個把自己的讀數講反的儀器，比沒有儀器更糟：
它讓「我對過帳了」這句話變成沒有內容的。

📌 而它是今天第 N 隻同族：**兩種不同狀態被印成同一句話。**
今天已經抓到的同族：`op=show` 的 archived vs active（只差括號一個字）／
git 守衛的 untracked vs ignore（都印「不乾淨」）／
LatestState 的「有 state 全退場」vs「一筆都沒有」。
⇒ 這次的差別是：**它發生在那個專門用來抓這種事的工具裡。**

\## 建議修法（把三種狀態拆成三句）

`else` 分支再分一次：`entries` 空 ⇒「兩邊都無錯」；`entries` 有 ⇒
「一致（兩個來源都看到 N 筆編譯錯誤）」。**不動 `disagree` 的判準**，只修訊息。
