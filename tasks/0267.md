# TASK-0267 — 酒館寫入端接上 ServerAutoStart（Tim 拍 B：Editor 走 senate.exe）＋ AutoStart 搬進 SCP_Core 共用

> `feature` / `normal` / `in_review`　開單：summit　參與：kotoko(qa)、summit(dev)

## 驗收標準

- [ ] ① 🔴 **`ServerAutoStart` 住 `SCP_Core`，而 Unity 與 `senate.exe` 引用同一份**（憑據＝全樹 `ServerAutoStart` 型別只有**一個定義處**，⛔ 不是「兩邊行為看起來一樣」）
- [ ] ② 🔴 **Server 本體不得跟著搬**：`RunForeground`／單例鎖／registry 登記仍在 `Senate.Core`（憑據＝那幾個成員的定義處未變）—— ⛔ Unity 端不該有能力「成為」Server
- [ ] ③ 酒館發訊息時 Server 沒開 ⇒ **Editor 走 `senate.exe`（B）把它拉起來，然後那一則真的寫出去**（憑據＝訊息落盤檔帶 Server 寫入端標記且 seq 接得上）
- [ ] ④ 🔴 **spawn 的人仍然只有一個**：Editor 這條路**不得**自己 `Process.Start` 一顆 Server（憑據＝Unity 端零 spawn 呼叫點，只執行 `senate.exe`）
- [ ] ⑤ 🔴 **起不來仍然整筆失敗且大聲**（D10 丙「不降級」那半沒有翻）：把 Server 執行檔弄成拿不到的狀態 ⇒ 那一則**不得**被寫成本地訊息，且錯誤訊息指得出啟動 log
- [ ] ⑥ 🔴 **不得多開**：同時觸發 N 個需要 Server 的寫入（N ≥ 4）⇒ 登記表裡 `senate_server*` 只有一筆 Alive。⛔ 要**真的併發**，不是循序跑 N 次（循序跑不出競態，而它會綠）
- [ ] ⑦ 「正在啟動」與「啟動失敗」在 Editor 這側**仍然不同形**（A4 已有的四態不得被壓成一個 bool）
- [ ] ⑧ 反向對照（**受詞 2026-09-22 收窄** —— Tim 拍 (A) 整條委派走 CLI，那必然多一跳 process ⇒ 舊字面「逐筆相同」在延遲那一軸上結構性不可滿足）：Server 本來就在跑時，**行為**與改動前逐筆相同（seq 連續無重號／訊息檔逐位元組相同／不會多起一顆）；⚠ 而**延遲允許增加一跳** ⇒ 那一跳要**量出數字**寫在單上，⛔ 不准只寫「可接受」
- [ ] ⑨ ⚠ `senate.exe` 的路徑：**走 PATH**（`FileName = "senate"`，同 `UCL_KnowledgeBaseRunner` 的 `python` 慣例）—— 已實測 Editor 進程 PATH 含 `D:\Unity\Senate\publish` 且它是持久的使用者環境變數。⛔ 不新增解析器、不新增設定檔；而 PATH 沒命中時 OS 報的 `Win32Exception` 要**換成一句能動手的話**
- [ ] ⑩ ⚠ 射程標註：本單**不宣稱** `SCP_GuiProcessAdminPage` 能啟動 Server（那一頁刻意不 spawn），也**不宣稱** 0106 ⑨ 因此可以勾
- [ ] ⑪ ⚠ **本條路是暫時的，而那件事要寫在 code 裡**（Tim 2026-09-22：整套之後會遷移到 Senate）：`DelegateAppendToServer` 的註解要寫明「這一跳 process 是過渡期的代價，終局是整套搬進 Senate（見 TASK-0100 路線圖）」—— ⛔ 不寫的話下一個讀它的人會把它當終局，然後為它做最佳化

⇒ 📌 **自動啟動 ≠ 自動降級**：D10 丙禁止的是「Server 沒跑就改寫本地」（那長出第二個寫入端）；

| 讀數 | 值 |
|---|---|
| `ServerAutoStart` 的呼叫端 | **1 處** —— `ServerDelegateCmd.cs:114`（CLI 委派路） |
| 酒館這條路怎麼處理「沒開」 | `UCL_ChatTavernIO.DelegateAppendToServer`：只 `SCP_ServerEndpoint.Probe()`，`!Alive` ⇒ **throw** ＋印啟動指令 |

⇒ **障礙是組件邊界，不是政策** —— Unity 端引用不到 `Senate.Core`。

### ② 單例鎖（A2）已落地並驗過 —— 這是 A 方案不會製造多開的前提

`ServerHost.cs:256-270` 的取捨逐字：用 **OS advisory lock（獨佔開檔 `FileShare.None`）**，
⛔ 不用 pid 鎖檔（「要靠程式記得刪 ⇒ 當機／強制關掉就留下死鎖」）、
⛔ 不用 Named Mutex（「實務上 Windows-only，而這裡沒有非它不可的理由」）。
⛔ 綁 port 也用不上：我 grep `ServerHost`／`ServerExecutor`，**零** `TcpListener`／`HttpListener`／`Socket`（純檔案協議）。

🩸 而那份註解自己帶著本單最重要的一個讀數：
> **2026-09-14 實測：拿掉鎖，4 顆全登記成功。**
> ⇒ autostart 會把「幾乎踩不到」變成常態（N 顆同時發現沒在跑 ⇒ N 顆一起 spawn）。

📌 ⇒ **A2 必須先落地 A4 才接得上**，而 A2 已經落地。⇒ 本單搬 AutoStart 進 SCP_Core**不需要**再造互斥機制，
它要做的是**確認 Editor 這個新呼叫端仍然落在同一把鎖底下**。

### ③ Server 受 `SCP_GuiProcessAdminPage` 管理 —— 成立，但**那一頁不 spawn**

`ServerHost.cs:107` `const string Tag = "senate_server"`、`:317` `Register(aSelf, TagFor(aServerId), …)`；
多顆時 `senate_server.<id>`（`:161` 逐字相等比對，⛔ 不用 `StartsWith`）。
而 `:250` 那道閘：`SCP_ProcessRegistry` 沒 Configure 就**拒絕啟動**（「沒登記的常駐 ＝ 沒人管得到的孤兒」）
⇒ 登記不是選配。

⛔ 而那一頁的註解逐字「**本頁不 spawn 任何 process**，只讀、只 kill 身分驗證過的、只清殘檔」
⇒ 它是「看得到／收得掉」那半，**不能當本單的解**。
