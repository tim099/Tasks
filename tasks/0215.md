# TASK-0215 — Persona & Agent 管理頁吞掉跨區借用標記 —— 借用別區的綁定與本區真的綁了在畫面上同形

> `bug` / `wrong` / `normal` / `cancelled`　開單：kaguya　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

## 這張單在講什麼

`SCP_PersonaProfile.GetBankAccount` 的檔頭自己下了一條規矩（`UCL_PersonaProfile.cs` 同段轉述）：

> ⚠ `oSource != iCurrencyId` 就代表這不是本區的宣告 —— **呼叫端必須讓它可見**，
> 否則「本區真的綁了」與「借用別區的」在輸出上同形，而前者才是收斂目標。

`UCL_PersonaAgentAdminPage` 是呼叫端（`LoadData` → `UCL_PersonaProfile.GetRaw` → `BuildRaw` → `GetBankAccount`），
**而它把來源標記丟了**：`DrawOverviewPanel` 那一列只畫 `@{p.agent}`。

⇒ 後果：在 Florin 開那頁，`kaguya` 顯示 `@Luna`，跟一個**真的在 Florin 綁了 Luna** 的人逐字同形。
借用只出現在 `Debug.LogWarning` 送進 Unity console 的一行 —— **那不是那一列的讀數**，而且 console 會被洗掉、會被摺疊、會被人關掉。

📌 對照組（同一個問題，別人做對了）：`senate cmd bank-audit` 特地開了 ② `borrowed` 一格，
標題直接寫「**不是錯，只是要看得見**」，並印出「（宣告在 BTC＝Luna）」。⇒ 規矩不是沒人守，是這一個呼叫端沒守。

## 量到的讀數（可重跑）

```bash
senate ucmd run PersonaProfile --persona <me> --arg op=get_bank --arg persona=kaguya --arg currency=Florin
#   account = Luna / source = BTC / note = 本區（Florin）沒有宣告，借用 BTC 的綁定
senate cmd bank-audit --arg region=Florin
#   ② borrowed = 1 → kaguya（宣告在 BTC＝Luna）
```

⇒ **讀取層有把來源交出來**（`source=BTC` 明明白白）。丟掉它的是顯示層。這不是缺資料，是缺一格畫面。

- [ ] 修正：persona 列在**借用**時帶可見標記（例：`@Luna ⤴BTC`），本區宣告時不加 —— 兩者**不得同形**

      ⛔ 不准在頁面自己再讀一次 `bank/*.md` 去猜（那就是這隻病的家族本身）

### A. 讀取層**有**把來源交出來

```

```

### B. 另一個呼叫端**有**把它畫出來（對照組）

```bash
senate cmd bank-audit --arg region=Florin
```
```
## ② borrowed　只有別區宣告　⇒ 不是錯，只是要看得見：1
  - kaguya（宣告在 BTC＝Luna）
```

### C. 磁碟原檔（本體）

```
ChatTavern/baton/letters/kaguya/bank/   → 只有 BTC.md（內容：Luna）
                                          ⇒ Florin.md 不存在 ⇒ 本區確實沒有宣告
```

### D. 出問題的那一列（程式碼位置）

`UCL_PersonaAgentAdminPage.cs` `DrawOverviewPanel`：

```csharp
GUILayout.Label($"@{(string.IsNullOrEmpty(p.agent) ? "(未綁)" : p.agent)}", WrapLabelStyle,
    GUILayout.Width(UCL_GUIStyle.GetScaledSize(140)));
```

⇒ 只有 `p.agent`。`GetBankAccount` 的 `oSource` / `oNote` 在 `SCP_PersonaProfile.BuildRaw` 裡
被送進 `iWarn`（→ `Debug.LogWarning`），**沒有進 `aJd`** ⇒ 頁面的 `PersonaRow` 上根本沒有這個欄位可畫。

📌 所以修法不是「把欄位畫出來」那麼單純：`BuildRaw` 得先讓來源**進得了資料**（或頁面自己呼叫一次
`GetBankAccount` 拿 `oSource`）。⚠ 後者要小心 —— 那是同一支函式的第二次呼叫，不是第二個解析器，
但**每幀重繪時不可以這樣做**（`UCL_PersonaAgentAdminPage.cs:109` 的註解就是在講這件事：
「Resolve() 每呼叫一次就讀一次 persona 檔與 registry；OnGUI 每幀重繪」）⇒ 只能在 `LoadData` 那一趟拿。

### E. ambiguous 那格**沒有活體**（所以它不能靠跑一次來驗）

實測本庫 22 位 persona 的 `bank/` 目錄：沒有任何一位同時在兩個區域都有宣告
⇒ `BankSourceAmbiguous` 這條路目前跑不到。⛔ 不准拿「跑起來沒看到問題」當它通過。
