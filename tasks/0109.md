## ⚠ 射程更正（我第一次講的時候說寬了）

我原本說「參數打錯會被靜默吃掉」——**那是全稱，而它不成立**。
真實射程只涵蓋 **有預設值的選填參數**；必填的那些 handler 自己會擋。

📌 而真正咬人的是這個子集裡**帶副作用**的那幾個（`advance`／`confirm`／`mode`／`force` 這類）：
打錯 ⇒ 走預設 ⇒ 一個你沒要的動作真的發生了，而回傳是 Success。
⛔ 那個子集有多大**沒有人量過** —— 要掃 47 支 Cmd 的 args 宣告才知道。開工第一件是量它，不是動手。

而那個風險**只存在於「擋下」的版本**。純出聲：零行為變更、零相容風險 ⇒ **不需要等 Server。**

\### 名字全集從哪來（Q1：現有架構做得到，不新增宣告）

**`ArgsSchema`（自由文字，48/48 都有）** —— 抽 `<name>=` 樣式的 token 當白名單。

**準確度我量了，靶子選最複雜那支（`Cmd_Task`，35 個參數）：**

| 讀數 | 值 |
|---|---|
| `ArgsSchema` 抽到的名字 | **34** |
| code 真的讀的名字（`GetArg` 樣式） | **35** |
| **會被誤報成「打錯」的**（code 讀了、schema 沒寫） | **2** —— `persona`、`remove` |
| schema 有寫而我的抽取器沒抓到 | 1 —— `type`（走 `ParseEnumArg` 不是 `GetArg`） |

⇒ 兩個誤報的性質**不同**，這是設計的關鍵：
- **`persona`** 是 CLI 每支都注入的（同族還有 `_cmd_id` / `_caller_client` / `_caller_env_marker` / `data_root` / `project`）
  ⇒ 一份**全域注入名單**就解掉，不是每支的事。
- **`remove`** 是**真的文件缺口** —— 它是 `op=link` 的解除旗標，而 `ArgsSchema` 沒寫它。
  🩸 而它正好是本單最危險的那一類：**打成 `remov=1` 會「建立」關聯而不是解除**，回報 Success。
  ⇒ 我今天下午才用過那個旗標，而它不在說明裡。（已另行修掉，見 commit）

⚠ **我的抽取器的上界**：只抓 `GetArg(iArgs, "x")` 樣式 ⇒ 走 `ParseEnumArg`、
直接 `iArgs["x"]`、或別名表的那些**我沒抓到** ⇒ 上面那個「2」是**下界不是總數**。標未量。

\### ⛔ 而它必須印**三態**，不是兩態

42/48 沒有宣告 `ArgsSpec`，而 `ArgsSchema` 的完整度逐支不同 ⇒ 「沒命中」有**兩個讀法**：

| 狀態 | 回傳檔要印 |
|---|---|
| 全部命中 | ✅ 送進來的參數名都在本 Cmd 的 `ArgsSchema` 裡 |
| 有沒命中的 | ⚠ 這幾個名字不在 `ArgsSchema` 裡：`<清單>` —— **可能是打錯（⇒ 已走預設值）**，**也可能是 `ArgsSchema` 沒寫全**。兩個讀法都要印出來 |
| 抽不出白名單（`ArgsSchema` 空／格式異常） | ⛔ **本檢查這一輪沒有跑**（不是「乾淨」） |

📌 第三態是這個設計能不能活的關鍵，而理由本 repo 已經寫過一次
（`UCL_TaskIO.AssertMainThread` 的區塊註解）：**「量不到」不可以長得像「量到了而且正常」。**
🩸 而第二態那句「也可能是 ArgsSchema 沒寫全」不可省 —— 少了它，
**一個文件缺口會被印成「你打錯了」**，而讀的人會去改一個本來正確的呼叫。

⚠ **它一定不可以是 error、不可以非零退出、不可以影響行為。**
理由：誤報率不是 0（上面量到 ≥2），而一個會誤擋的閘活不過三天。

\## ▶ 建議的處置（交 PM 判，我沒動手）

**把本單拆成兩層，而順序是先便宜的那層：**

1. **③ 出聲層（現在就做得到，不等 Server）** —— 資料源 `ArgsSchema` ＋ 全域注入名單，
   純寫進回傳檔、三態、非阻擋。⇒ 它讓「打錯」從**不可觀測**變成**事後查得到**。
   📌 這正是 @kiara 09-07 在共享 lesson 庫寫的那條的同形：
   *當系統的設計不容許事前防堵時，判準收在寫入端 —— 讓「我蓋掉了誰」出現在回報裡。*
2. **② 擋下層（仍照拍板「乙」等 Server）** —— 它需要名字全集的**正式宣告**（不是散文），
   而那正是 Server 那側 `SCP_CmdArgSpec` 已經有的形狀 ⇒ 搬過去就順便有了。
   ⇒ 所以「乙」對這一層仍然成立，而且理由更強了：**別在 Editor 端重造一份 SCP 已經有的宣告。**

⚠ 而驗收標準①（量那 42 支「選填＋有預設＋帶副作用」的清單）**在出聲層之後會變便宜**：
出聲層一上線，跑一輪日常操作就會自己把打錯的名字吐出來 —— 那比我去 grep 我自己列的關鍵字準
（今天我拿 `confirm`/`force`/`advance`/`mode`/`no_notify`/`dry_run` 掃出 3/5/1/5/1/1 支，
而那份清單是我列的，它沒有「我漏了什麼」那一欄 —— 憲法⑦）。
