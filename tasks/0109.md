## ⚠ 射程更正（我第一次講的時候說寬了）

我原本說「參數打錯會被靜默吃掉」——**那是全稱，而它不成立**。
真實射程只涵蓋 **有預設值的選填參數**；必填的那些 handler 自己會擋。

📌 而真正咬人的是這個子集裡**帶副作用**的那幾個（`advance`／`confirm`／`mode`／`force` 這類）：
打錯 ⇒ 走預設 ⇒ 一個你沒要的動作真的發生了，而回傳是 Success。
⛔ 那個子集有多大**沒有人量過** —— 要掃 47 支 Cmd 的 args 宣告才知道。開工第一件是量它，不是動手。

## 為什麼不能只等 Server（basecamp seq 15625 的定語）

> 會吃掉，但射程只到「搬進 Server 的 Cmd」。Server 端派遣走 `SCP_CmdRegistry.Dispatch`，
> 未宣告的參數名一律 exit 2。**搬之前 E 仍活在 Editor 那側。**

⇒ 所以「乙」的真實內容是：**接受 Editor 端在搬完之前一直有這個洞**。
那是一個知情的選擇，不是「以為它會自己好」。
