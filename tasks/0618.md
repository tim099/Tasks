# TASK-0618 — 任務分專案（比母單更上一層，例：Blockside）＋任務頁 TopBar 分兩排、照專案篩選與整理

> `feature` / `normal` / `in_progress`　開單：kiara　參與：kiara(dev)

## 驗收標準

- [ ] 單子可以標專案（frontmatter `project`，比母單更上一層）：`task op=create／update --arg project=<名>` 寫得進去、`unset=project` 清得掉，都進時間線
- [ ] 專案名大小寫不同算同一個：已經有 `Blockside` 時寫 `blockside` 會被擋下並指出既有的拼法（反向對照：沒有既有的就照寫）
- [ ] 子任務沒標專案時跟著母單（顯示與篩選都算進母單的專案，標明是跟著母單的）；自己標了就用自己的
- [ ] `senate cmd tasks --arg project=<名>` 只列那個專案的單；`project=none` 列沒有專案的；不帶參數時印每個專案各幾張（未關／總數）
- [ ] 任務頁：TopBar 分兩排（第一排按鈕與翻頁、第二排篩選）；第二排有「專案」下拉（全部／未分類／每個專案帶張數）
- [ ] 任務頁：每張單看得到它的專案，展開後可以改專案（走 `cmd task`，不直接寫檔）；可以把目前篩選結果一次設成某個專案（要按兩次確認）
- [ ] 現有跟 Blockside（《憲法號對轟》）有關的單都標成 `Blockside`，清單列在單上
- [ ] 舊單（沒有 project 欄）讀得進來、照舊顯示；selftest 全過
- [ ] Task_Management 文件寫上專案這一層怎麼用

## 任務描述

Tim 2026-10-15：「目前需要新增一個功能 可以整理task分類（比母單更上一層 是專案層級）例如目前與Blockside遊戲有關的會放到Blockside類 同時修改TaskManagerPage介面支援這個功能（另外TopBar會需要分兩排 目前太滿了 兩排可以參考SculptureViewerPage）」

誰在等：Tim（任務頁要能照專案整理）。

現況（kiara 2026-10-15 量）：
- 單子的分組只有 epic（`epic_id`／`subtask_indices`，TASK-0600 任務頁已經照它摺疊）、`milestone`、`tags` —— 沒有專案這一層；任務頁的篩選只有狀態／類型／參與者。
- 任務頁 TopBar 一排塞了：重新讀取、開資料夾、狀態、類型、參與者、含已關、四顆翻頁 —— 再加專案就放不下。SculptureViewerPage 的做法：覆寫 `DrawTopBar`，base 畫第一排、`iUi.Row()` 畫第二排（TASK-0504）。

設計（動工前可改）：
- frontmatter 加 `project:`（一個值、自由字串）；寫入端比對既有專案名不分大小寫，拼法不同就擋（免得 Blockside／blockside 分兩類）。
- 「跟著母單」只在讀的時候算（顯示、篩選），⛔ 不寫回子單 —— 母單換專案，子單自然跟著走。
- 寫入照舊只走 `cmd task`（任務頁也是），批次設定 ＝ 一張一張打 `op=update`，每張各進時間線。

範圍：SCP_Core/Runtime/Tasks、SCP_Cmd_Tasks、Senate Cmd_Task、TaskManagerPage、selftest、Task_Management 文件。
⚠ 寫入端是 Senate Server：改完要重新出廠（build.sh）server 才吃得到新欄位。
