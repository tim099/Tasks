# TASK-0620 — 《憲法號對轟》戰鬥報表：船員數、砲數曲線、開砲與命中率…記錄下來分析戰鬥中的問題（第一個案例：維吉尼亞號開砲太少）

> `feature` / `normal` / `todo`　開單：ame　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 每一場記一份戰鬥報表（每艘船、每隔幾秒一格）：船員（還能打的／受傷／陣亡／落水）、砲（還在的／開得動的＝人夠）、每門砲開了幾發、中了幾發、打中什麼（船殼／砲／人／帆）、被打中幾發與打掉幾格、進水與傾斜、航速與出力
- [ ] 遊戲裡看得到：結束畫面（或停格）一頁報表 —— 船員數曲線、砲數曲線、命中率；?dump=1 的 JSON 帶同一份（無頭跑得出來）
- [ ] 存檔：可以匯出成檔（CSV 或 JSON），方便本小姐或 Tim 拿去分析
- [ ] 分析工具：admin.py（或 scratchpad 腳本變正式工具）讀多場報表 ⇒ 每型船的平均曲線、砲被打掉的時間點、砲啞掉的原因（人不夠／砲沒了／沒火藥）
- [ ] 第一個案例：維吉尼亞號 —— 用報表回答「為什麼開砲這麼少」：砲被打爛幾門、什麼時候；砲班減員多快；開得動的砲多少時間在裝填／等火藥／沒人（Tim 2026-10-15 實測：砲本身會被打爛、減員嚴重、輸出低）
- [ ] 效能：記報表的成本有讀數（每步多花多少），關掉時戰局逐位元組相同

## 任務描述

Tim 2026-10-15：「另外開一個 task 吧，可以記錄戰鬥報表，用來分析戰鬥中的問題，例如船員數量曲線、炮數曲線、開炮命中率等需要分析的資料。剛剛我實測，維吉尼亞號最大問題是炮本身會被打爛，且減員嚴重，加上輸出低所以開炮數量少。」

**現況（ame）**
- ?dump=1 已經有一份結尾的讀數（sh.tl 每 10 秒一格：hits、lost、water…），但沒有砲、船員、命中率的時間線，也沒有遊戲裡看得到的頁面。
- 維吉尼亞號第一場（?demo=180 seed 3 對憲法號）：開了 12 發、中 3 發；挨 147–212 發；船殼只掉 1.2–2 萬格（鐵甲 ×16 有用），可是砲與人照樣被打 —— 砲是模型，打中就扣血，跟鐵甲無關；砲門一開，打進砲門的砲彈直接打到砲與砲班。
- 想查的：①砲被打掉是因為砲門太大／砲太靠外（砲口伸進砲門，模型外框露在外面）②砲班站在砲門後面被碎片打到 ③裝填 1.5–1.8 倍、砲班 8 人，人一少就啞掉。報表做出來再決定改哪一條。
