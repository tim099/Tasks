# TASK-0055 — C-1：per-kind close handler＋觀影最小結算 —— 關場統一入口，補收工不再跳結算

> `feature` / `high` / `done`　開單：basecamp　參與：basecamp(dev)、summit(qa)

## 驗收標準

C-1（拍板②）：kind 登記項升級 —— per-kind close handler ＋ 觀影「最小結算」；關場統一入口，AdminPage 補收工不再跳過結算。

- [ ] UCL_SessionKind 登記項升級：每個 kind 可登記 close handler；統一入口（如 UCL_SessionService.CloseWithSettlement(kind, persona, reason)）—— 所有關場路徑（AdminPage 補收工／互斥出口指的收工／晚安自動關）走同一個門
- [ ] FreeTime handler＝現行 Close 三欄（行為不變）
- [ ] StreamWatch handler＝最小結算：已取材分鐘照算、sessions_log 台帳照 append、不發收工公告 —— 結算數字與正常 step=end 同情境對拍一致
- [ ] AdminPage 補收工改走統一入口 ⇒ known-issue「殘留收掉不結算」關閉（附修前／修後兩組讀數：同一殘留場景，修前結算 0、修後有台帳行）
- [ ] 反向對照：正常 step=end 收工全流程行為不變（含公告）
- [ ] 缺 handler 的 kind 走 base Close（明確降級，不靜默失敗）

## ⚖ PM 拍板：射程收窄（basecamp 2026-09-05，Tim 授權我拍）

逐格量過磁碟之後，這張單的三種格子要分開講 —— **它們不是同一件事的三個進度**。

### ✅ 已經達成（0127 ④ 就把它做掉了，不是今天做的）

「所有關場路徑走同一個門」在 **Editor 側已經成立**：`Cmd_SessionClose` 就是那個門，
它做的正是條文第 1、4 格要的三段（① 權威狀態＋回讀確認 ② per-kind 結算 ③ 分段回報），
而 `SCP_GuiSessionAdminPage` 與 `senate cmd sessions` 走的是 `CloseWithSettlement` → gateway → 委派回它。

### ⛔ 我撤回我自己今天早上加的第 ⑦ 格

早上我加了「`Cmd_FreeTime` 與 `Cmd_StreamWatch` 的收工路徑改呼叫 `CloseWithSettlement`」。
**那一格是錯的，撤回。** 理由是量出來的：那兩條路徑**已經先結算再 `Close`**，
再走一次統一入口就是**第二次結算** ⇒ 觀影場會**重複發薪**。
📌 判準：**「所有路徑走同一個門」的射程是「原本沒有結算的那些路徑」，不是「全部路徑」。**
一個通則套在前提不成立的那群人身上，會安靜地毀掉東西（憲法④）。

### 🩸 剩下的真缺口只有一個 —— 而它今天就會咬人

`Cmd_SessionClose` 用 **`if (IsStreamWatch(kind))`** 決定要不要補結算、用一條 if 鏈決定收工指令名。
⇒ **新增一種 kind 要回頭改這一支**，而漏改**不報錯**：它照常關場，然後印
「這個 kind 沒有登記結算 handler ⇒ 只翻三欄」——
**那句話在「真的不用結算」與「有人忘了登記」兩種情況下一模一樣，而後者是酬勞蒸發。**
⚠ 而 @summit 此刻正在 TASK-0058 新增第三種 kind（Coding）⇒ 這一格今天就會被踩到。

- [x] ⑨ `Cmd_SessionClose` 的 per-kind dispatch 改走**登記表**（`UCL_SessionKindHost`）：
      各 kind 在**自己的檔**用 `[InitializeOnLoadMethod]` 登記一次 ⇒ 新增 kind 不必動 `Cmd_SessionClose`
- [x] ⑩ **兩種「沒結算」不同形**（這一格才是本單真正的價值）：
      「登記為不需要結算」與「沒有人登記過它」印不同的話，後者還附上已登記清單
- [ ] ⑪ QA：`Coding` kind 上線後，**不改 `Cmd_SessionClose` 一個字**就能被它正確處置
      （@summit 的 0058 天然就是這一格的活體）

⇒ 對 `SettleResidueAsync != null` 的 kind，這條路的結算**結構性不可達**。

⚠ 反過來也不行：第二道守衛 `aNow <= aEnd ⇒ 「還在進行中」⇒ 未動作`
⇒ 晚安要關的「進行中的場」會被那道擋掉。**兩個次序都過不去，是契約不合不是次序問題**
（那支函式的契約是「補**殘留**」，被接到「關**進行中**」的呼叫端上）。
