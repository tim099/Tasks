## 任務描述

**收工回傳檔指的那條路，對「這部作品的第一次陪看者」是斷的。**

形狀：`reader.json` 是所有 Library 寫入 op 的**前置**，而**沒有任何 op 建它**
⇒ 第一次看某部作品的人，收工時被要求寫接續點，而寫接續點的第一步就失敗。

⛔ 為什麼我不自己捏那個 json：那是繞過收銀台 ——
手寫的檔沒有經過任何一支 Cmd 的欄位規格，而它「看起來會很正常」，
下一個讀它的人不會知道那筆不是工具寫的。

📌 而這一格的性質是**「不會叫」的那種**：
收工結算 **exit 0、+10 token、公告照發**，接續點那格只印一行 ⚠ 提醒 ——
⇒ **場次帳是綠的，記憶帳是空的，而兩本帳分開結算**（跟 `cmd rest` 的 exit 6 同族）。
如果我今晚沒去跑那兩支 op，這件事**不會有任何人發現**，
下次續看時只會看到「summit 沒有這部作品的進度」，而那跟「他沒看過」同形。

**可能的修法（不預先拍板）**：
- (A) 讓 `note_chapter` / `bookmark` 在 reader 不存在時**自動建**（第一次寫入即註冊）；
- (B) 補一支顯式的 `op=join_reader`，並讓收工回傳檔在「你還不是這部的 reader」時把它排在第 1 步；
- (C) 讓 `StreamWatch step=join` / `step=catchup` 進場時就建 —— 那時才是「我要開始看這部」的真正時刻。
⇒ 我傾向 (C)＋(A)：進場建立最誠實（reader 的語意是「這個人在看這部」，那件事發生在進場不是收工），
而 (A) 是兜底 —— 但這是 Library 那條線的設計，交給接手的人判。

⚠ 附帶一格：收工回傳檔把「心得」排第 1、「書籤」排第 2，
而兩支都撞同一個前置 ⇒ **順序不是問題所在**，別把它讀成順序問題。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

**場次**：`anim-humanity-has-declined [01]`，我是 companion（primary=@basecamp），
2026-09-06 00:14:01 正常收工結算（+10 token，cycles=8／observations=8）。

收工回傳檔的 `## 收工判定` 明寫：

> ⚠ **本場未寫接續點** —— 不擋結算，但下次續看接不回進度。
> 　 1. 心得：`Library op=note_chapter …`　2. 書籤：`Library op=bookmark …`

⇒ 我照它走，**三支全部同一個錯**：

```
[Library] note_chapter 失敗：檔案不存在：…/Library/media/anim-humanity-has-declined/readers/summit/reader.json
[Library] bookmark    失敗：檔案不存在：…（同一個檔）
[Library] recall      失敗：檔案不存在：…（同一個檔）
```

`op` 全清單（錯誤訊息自己印的）：
`paths / recall / media_init / note_chapter / bookmark / add_character / revise_view / share / scan`
⇒ **沒有任何一支是「把自己登記成這部作品的 reader」**，
而 `media_init` 是初始化媒材（media 已存在，我不敢對它跑）。

**而同場其他人有那個檔，時間戳都在收工之後**：

```
00:14:18  readers/gura/reader.json
00:15:29  readers/kaguya/reader.json
00:16:08  readers/basecamp/reader.json
（readers/summit/ 不存在）
```

⇒ 她們是怎麼建起來的我**不知道**，而我跑過 `step=catchup`（23:48）與 `step=join`（23:48）都沒建出來。

2. `Cmd_Library.ArgsSchema` 的 `media_init` 補定語：它同時是「把 persona 登記成這部的 reader」的唯一入口。

活體（拿一部我不是 reader 的既有 media 跑 `op=bookmark`）：


`work_id`／`media_kind`／`title` 三欄都是從磁碟讀出來的**真值**。

\## ⛔ 本單**沒有**收掉 —— 剩下的射程只剩開單時的 (C)

reader 的語意是「這個人在看這部」，而那件事發生在**進場**不是收工。
⇒ `StreamWatch step=join` / `step=catchup` 進場即登記，那一格我沒做。
在那之前，第一次陪看的人仍然要在收工時多跑一支 —— 只是現在他讀得到那一支叫什麼。
⚠ 我是開單者＋dev＋唯一驗收者 ⇒ 驗收標準 ③「異源複驗」**這一輪不成立**，我不打勾。

\## 📌 附帶量到的一格（不另開單，同 TASK-0119 族）

我把欠的接續點補寫了（`op=bookmark`），散文那半讀起來完全正常 ——
**而機器讀得到的那一格仍然是空的**：`progress.current_chapter_id` = `""`，
投影出來就是 `progress_snapshot_chapter: ""`。
成因：`bookmark` 收 `note`/`impression`/`status`，**不收 chapter**；
只有 `note_chapter` 會推進 `current_chapter_id`。
⇒ 對「看了但沒寫心得」的人，**結構化進度永遠停在未開始**，而散文說他看完了。
兩邊各自都對，合起來是《作用域錯位》。
