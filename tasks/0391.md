## 任務描述

## 現象
有資料根參數的指令，收到**相對路徑**時：
1. 本地檢查用 CLI 的 cwd 判斷 → 存在，放行（`SCP_Cmd_Canvas` 73-78 行只做 `Directory.Exists`）。
2. 轉給 Server 的仍是那個相對路徑（`SenateCanvasGateway.DispatchVoucher` 把 `Letters(m_DataRoot)` 原樣交出）。
3. Server 用**它自己的 cwd** 去解，找不到券簿 ⇒ `voucher` **成功回 0**（不是「不知道」）。

使用者看到的是「你沒有券」，而券就在磁碟上。這是「安靜給錯值」那族，不會有人發現。

## 修法方向（Tim 2026-10-05 拍板）
**CLI 不收手給的路徑，路徑一律照 Senate 後台設定。** 要換一棵樹 ⇒ 用 `--project <名稱>` 選後台設好的專案，⛔ 不手打根目錄。
（取代原本「相對路徑轉成絕對路徑」的修法：那只修了相對路徑，手打的絕對路徑一樣可能指到舊樹——10-02 在 Bar 那台用的舊 LY 樹就是一例。）

前例：TASK-0260 的 `bank_root` 已經這樣擋了（`Program.cs` 那段：使用者手填就 exit 2，並指路）。這次把同一條擴到 `data_root`／`letters_root`／`glossary_root`／`project_root`。
⚠ 擋的位置跟 0260 一樣在 CLI 入口、`FillRootArg` 之前 —— 只有那裡分得出「使用者給的」與「宿主補的」。內部呼叫走 `SCP_CmdRegistry.Dispatch`，不受影響。

### 會被擋到的呼叫端（2026-10-05 grep，只掃 UCL_Core／Senate src／SCP_Core／LY skills）
- **Unity Editor 兩支**（要先改，否則 exe 一換就斷）：

  - `UCL_TaskSenateBridge.cs:85` —— `task` 帶 `data_root=`
  ⇒ 改成不帶（只有一個啟用專案時自動選），或帶 `--project`。
- **文件／skill 7 份**：`AutoCommit_Config_Workflow.md`(3)、`ucl-commit/SKILL.md`(2，含 LY 安裝副本)、`Commit_Workflow.md`(2)、`FreeTime/Activities/exchange.md`、`book-writing.md`、`SCP_WakeBrief.cs` 印出的提示行(1)。

### 第二格（照舊）
