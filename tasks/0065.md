# TASK-0065 — 觀影中斷／過期殘留必須直接結算＋補台帳（不再 active=false 一筆帶過）

> `bug` / `high` / `todo`　開單：basecamp　參與：summit(qa)

## 驗收標準

- [ ] 人為讓一場 session 過期不收（不跑最後那次 cycle）→ 下一場 `start`／`join`：
      該場**有**結算、**有**進 `sessions_log.jsonl`（seq 區間可回讀）、酬勞不為 0
- [ ] 同一場中斷後接續：在 domain reload（或關掉再開 Editor）之後 `step=cycle` 能接回同一 session_id，
      cycles／cursor 不歸零、接力前緣不回退
- [ ] 開新場次時 scratch 被清，且回傳檔明印清掉了什麼（上一場 id／補結算金額／flush 幾則）
- [ ] 「殘留補結算」與「正常收工」在台帳上**可分**（`end_reason` 有專屬值，不共用 expired）
- [ ] 拿補結算過的那一場實跑 `export-watch --from-session` ⇒ 真的匯得出來（證明台帳補得有效）
- [ ] scratch 檔不進 git（`git check-ignore` 實測命中）；`sessions_log.jsonl` / `segments.jsonl` 仍在版控

## 任務描述

## Tim 2026-08-26 的兩個時點定義（先釘死，這兩件常被混成一件）

| 事件 | 記憶體（static／in-memory） | scratch 檔 | 該做什麼 |
|---|---|---|---|
| **中斷後接續**（同一場，Editor 出問題／domain reload） | **全掉，只能讀檔** | **必須留著** | 靠檔把同一場接回來，繼續跑 |
| **開新場次**（下一段觀影＝Tim 口中的「重啟」） | — | 清除 | 上一場的暫存不該汙染新場 |

⇒ 這正是 `UCL_ProcessRegistryService` 的語意：**檔案留著，reload 後才能「接管」還活著的那顆**
（`CleanupStale` 也只刪驗證為 Dead／PidReused 的，不是全清）。
⚠ 而「清除」的觸發點是**新場次開始**，不是 Editor 載入 —— 現行 code 已經有這個時點的先例：
`StepStart` 的「接力前緣重置：新場＝新的一條前緣（frontier=0）」。照同一個時點做，不是新概念。

## 🩸 而這條需求踩到一個既有的洞（我見叢裡等 Tim 拍板的那條），它比錢更嚴重

`StepStart` 守衛③ 與 `StepJoin` 對**過期殘留 session** 的處置是：
印一行「ℹ 偵測到過期殘留 session（<id>）已自動收掉」，`active=false`、存檔，**然後就沒有了**。

而讀 code 確認：
- `SettleAsync(...)` **只在 `StepCycle` 裡被呼叫**（唯一呼叫點）
- `AppendSessionLog(...)` **只在 `SettleAsync` 裡被呼叫**（唯一呼叫點）

⇒ **一場沒有跑到「cycle 判定收工」的 session，永遠不會被結算、也永遠不會進台帳。** 後果三條：
1. **酬勞蒸發**（已知，見叢那條：「過期殘留收掉不補結算」）
2. **⚠ 它的 seq 區間永久消失** ⇒ 那一場的觀察**再也匯不進書**
   —— 而這正是 `sessions_log.jsonl` 存在的理由（它的血證原文：「apocalypse-hotel 02-04 話的實錄補不出來，
   不是訊息不見了（都在磁碟上），是**沒有任何地方記得那幾場的區間**」）
3. 它**長得跟正常收工一模一樣**（都印「已自動收掉」）⇒ 沒有任何一層會喊

⇒ 所以 Tim 要的「開新場次清暫存」**不能直接實作成清除**：
**清除之前必須先 settle（補結算＋補台帳＋flush 佇列），否則「清暫存」等於同時吃掉上一場的錢與它的實錄。**

## 要做的
1. **scratch 檔（中斷續接用）**：每場一檔、落 `AgentCommands/StreamWatch/` 底下、不進 git。
   ⚠ 現況先講清楚：StreamWatch **大部分狀態本來就在檔上**（`sessions/<persona>.json` 有 cursor／cycles／
   last_cycle_ts／tavern_seq；`relay/` 有前緣；錄影狀態在 `_screenstream/_config.json`）。
   真正只活在記憶體裡的是：① 跑在 Editor 內的等待迴圈（可由 `last_cycle_ts` 重算，已經是檔）
   ② **未來的 `observe_queue`（TASK-0062）—— 這個必須是檔，否則入列必發的承諾撐不住重啟**。
   ⇒ 本單的 scratch 主要是為 ②、以及 in-flight montage／段佔用留位置，不是把已經在檔上的東西再抄一份。
2. **殘留必補結算**：`StepStart`／`StepJeoin` 遇到過期殘留 ⇒ 走 settle 路徑（結算＋台帳＋公告），
   不是 `active=false` 一筆帶過。⚠ 動的是計費語意 ⇒ **要 Tim 明確拍板才動**。
3. **清除必在 settle 之後**，且回傳檔要明印「上一場（<id>）已補結算 +N token／台帳已補 seq 區間 A–B／
   佇列已 flush M 則」——**不能靜默清**。

\## ⭐ 這一刀為什麼是對的（我原本擔心的那格自己消了）
我先前的顧慮是「清暫存會銷毀已計酬未發的觀察」與「seq 區間永久消失 ⇒ 匯不進書」。
**「中斷即結算」直接把兩者都解掉**：結算會跑 `AppendSessionLog`，區間就留住了；
錢也在中斷當下結清，不必等一個可能永遠不回來的 agent。
⇒ 而且它**不需要任何接續機制**。**用不到的正確性比用得到的複雜度值錢。**

   同一話跨「原場＋重看場」匯出時，**會出現兩組重複的段號** ⇒ 排序鍵不能只有 `seg_index`。
   ⇒ 已把這格記進 TASK-0061 的留言。
