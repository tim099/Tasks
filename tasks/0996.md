# TASK-0996 — 《Blocksail》資源類別擴充：自動建築認得類別需求（成員產能照消耗比加權、補最少的）、城鎮食物需求照等級分類別、淡水卡住吃水工坊、醋的消耗量

> `feature` / `normal` / `in_progress`　開單：kotoko　參與：kotoko(dev)

## 驗收標準

- [x] 自動建築的需求、缺口、上游追認得類別（成員供應 ÷ 比例加總）；有甘蔗或野果的城，釀醋坊不再被判糖蜜卡住　✅ kotoko 2026-10-26
- [x] 類別缺口照成員的產能（換成類別份數）平衡：挑產能最少的成員補（反向對照：小麥 20、大麥 50 ⇒ 蓋小麥）　✅ kotoko 2026-10-26
- [x] 城鎮食物需求照等級分類別，糧食缺口走類別那一套；起始檔兩年飢荒、人口不比改之前差　✅ kotoko 2026-10-26
- [x] 淡水：吃淡水的工坊開得起來（起始檔一年有集水場、釀醋坊、陶器坊）　✅ kotoko 2026-10-29
- [x] 醋的日用量照讀數調（Tim「可以增加醋的消耗量嗎」）　✅ kotoko 2026-10-26
- [x] Tim 在遊戲裡看過　✅ kotoko 2026-10-29

## 任務描述

接 TASK-0994（資源類別架構＋第一批：醋料、肉類、魚類）。

Tim 2026-10-26：
- 「之後可以擴充 自動建築能處理類別需求（資源需求本身支援類別） 以及城鎮食物需求支援類別（把食物根據等級分類） 擴大類別的應用與框架泛用性」
- 「類別需求跟對應建築建造邏輯 目前想法是會想辦法平衡產能（例如 主糧類別缺口 目前小麥產量20 大麥產量50 則會優先選擇補充小麥產能 而且產能本身可以根據該類別的消耗比去加權）」
- 「可以增加醋的消耗量嗎」

現況（0994 量到的）：
- 自動建築（world/auto.js）看配方吃料只看主類（prodFull ⇒ inRep）：城裡有甘蔗、野果，釀醋坊照樣被判「糖蜜不夠 ⇒ 卡住」。
- 淡水：起始檔一年沒有任何城蓋集水場（它的值只有上游傳來的那一份，每次輸給別的候選）⇒ 釀醋坊、陶器坊、造紙坊、製皂坊都被「淡水不夠」卡住。一年 0 座釀醋坊（0994 之前也是 0）；醋的日用量 0.0002 ⇒ 0.005（25 倍）仍是 0 座。

要做：
1. 資源需求本身支援類別：需求表（regionTable）、缺口、上游追（upValues、inShort、blocked、inputCost）認得 '@類別' —— 一個類別的供應 ＝ 每一種成員供得上的 ÷ 比例 加起來。
2. 類別缺口要補的時候平衡產能：每一種成員現在的產能換成類別的份數（產量 ÷ 比例）＝ 加權，挑產能最少的那一種去補（Tim 的例：小麥 20、大麥 50 ⇒ 先補小麥）。
3. 城鎮的食物需求照等級分成類別（主糧 1 級、家常 2 級…），自動建築的糧食缺口改走類別那一套（現在是 foodGap ＋ primaryKcal 另一條路）。
4. 淡水卡住：查集水場為什麼總是輸（值只有上游那一份），讓吃淡水的工坊開得起來。
5. 醋的日用量：上面通了之後再照讀數調（現在調高沒有用）。
