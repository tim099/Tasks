# TASK-1362 — 《Blocksail》糖的樞紐價差試航：威廉斯塔德集貨與阿姆斯特丹甜點需求

> `subtask` / `normal` / `todo`　開單：Sirius　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 威廉斯塔德能沿用現有商路從加勒比產糖港實際收到糖。記來源港、運入桶數、集貨前後庫存與採購價。
- [ ] 阿姆斯特丹高級餐館能以現有的糖做甜點。缺糖時依餐館容量、客群與可負擔的餐費產生需求，有料並供餐時實際扣糖，留下供餐份數和用糖量。
- [ ] 用同一份開場、同一艘既有商船與同一航程，分開跑甜點開啟和關閉兩組。記威廉斯塔德裝船價、阿姆斯特丹到港收購價與稅後價差，再對照實際買入及售出桶數、兩端庫存、餐館實耗和未售存貨。用相同試算量比較兩端報價，另列實際成交金額。
- [ ] 兩組跑完威廉斯塔德至阿姆斯特丹的返航，含實際中繼補給。以現金流分列採購、售貨、補給、船員工資、適用的公司陸薪與稅費，核算航段合計淨利與剩餘貨量。注明航程天數、裝載量及成交受限的原因。

## 任務描述

Tim 指定先用糖驗證產區集貨、歐洲高級菜單需求與兩個樞紐間的價差。首輪以威廉斯塔德接加勒比產糖港，阿姆斯特丹高級餐館做一道直接耗用精製糖的甜點。餐館需求沿用既有缺料訊號、客群預算、供餐與扣料。糖的市場設定以產區／轉口／消費端分工為主，兩組沿用同一套庫存初值、現金、價格規則、費率和航線，處理變量只有甜點菜單是否啟用。缺料需求要能在第一批到貨前被市場看到，連續進貨要能隨可消化量及庫存變化反映在收購價上。

採用 1360 的威廉斯塔德集散地、現有區域船隊和 1361 已驗的返航港網。依當月實際導航可經布里奇敦及安格拉補給。使用原始市場的實際產糖、集貨、補給、交易和結算，記錄阿姆斯特丹抵港第一批與末批的價格以及成交上限。淨利單列返航段，避免把前次三角整環的成本混入，也避免把已在實收、實付內扣過的稅費再扣一次。香料與茶留待糖的驗收完成後接續。
