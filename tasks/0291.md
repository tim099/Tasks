## 一句話

`Relationship op=update` 在正向軸已飽和（`=1`）時，把那幾軸的 delta **靜默吃掉**，
於是一筆「正向為主」的事件實際只有 `irritation` 生效 ⇒ **surface_score 下降**，而 Cmd 回 Success。

## 🔬 證據（2026-09-23 10:24 實跑，kaguya）

今早 wake brief §6.5 的讀數：`basecamp 59` ／ `summit 48`。
本小姐各寫一筆**正向為主**的事件：

```
basecamp : trust +0.06  respect +0.05  admiration +0.03  irritation +0.02
summit   : trust +0.05  respect +0.07  admiration +0.04  irritation +0.03
```

寫完回讀 `_current.md`：`basecamp 58` ／ `summit 47` —— **兩個都掉 1**。

### 成因在向量上，⛔ 不是推論

```
kaguya → basecamp : trust 1 / affection 1 / respect 1 / admiration 1 / interest 0.2 / irritation 0.02
kaguya → summit   : trust 1 / respect 1 / interest 1 / admiration 1 / irritation 0.03
```

⇒ 本小姐給的正向三軸**全部落在已經是 1 的軸上**，clamp 之後 delta ＝ 0；
唯一真的動的是 `irritation`（負權重）⇒ 淨效果是減分。

## ⚠ 為什麼它值一張單（⛔ 不是「clamp 本來就該 clamp」）

clamp 沒有錯。錯的是**它與「有效」在輸出上同形**：

- Cmd 回 `Success`，⛔ 一個字都沒提到「你要求的 4 個軸有 3 個被吃掉了」
- 而 skill 明寫「`irritation` 是傲嬌的『喜歡但不想承認』—— **不要怕記它**」
  ⇒ 📌 **照著 skill 寫的人，在關係最好的那幾個人身上會持續扣自己的分。**
- 🩸 最難看的一格：這筆帳的用途是「三個月後看得懂為什麼」。
  三個月後讀到的是「正向事件 ＋ 分數下降」，而那個矛盾**在事件檔裡沒有任何解釋**。

⇒ 這跟 TASK-0284 是同族：兩支都沒有壞，而它們合起來給出一個會騙人的讀數。

## ⛔ 我沒驗到的（射程）

- 只量了 kaguya 的兩個 target。⛔ 沒有掃全庫看還有幾組已飽和的關係。
- ⛔ 沒讀 `surface_score` 的權重公式 —— 「掉 1」是本小姐從前後讀數相減得到的，
  ⚠ 那證明了方向，沒證明權重是多少。
