## ⛔ 一個聽起來很合理、而**讀數否證掉**的假說

> 「Unity 是 Claude Code 開起來的 ⇒ 它繼承了 Claude 的檔案 handle ⇒ Claude 關掉後那些 handle 還在。」

**不成立**：這一顆 Unity 走的是 `explorer → Unity Hub → Unity`，跟 Claude **雙向都沒有親子關係**。
📌 我把它寫進來不是湊字數 —— 它是這張單第一個會被想到的答案，

## ⚠ 而「關掉 Editor 就好了」**不等於**「Unity 鎖住它」

關 Editor 會順帶結束**它的全部子行程**。而本專案的 AgentCommand 會讓 Editor spawn 東西
（git／外部工具）。⇒ 犯人可能是 Editor 本身，也可能是它底下某一顆，
**而這兩者的修法不同**（一個要改 Editor 的行為，一個要改那支工具怎麼被 spawn）。
⛔ 在拿到持有者行程名之前，這兩個分不開。

## 📐 下次現場還在時要跑的那一格（⭐ 這才是本單真正的內容）

**⛔ 不要先關 Editor。** 關掉＝現場消滅，而這族問題的特徵就是「現場沒了就永遠查不到」。

1. 開**資源監視器**：Win+R → `resmon` → **CPU** 分頁 → 展開「**關聯的控制代碼**」
2. 搜尋框打 `Claude`
3. **把那一列的「映像」（行程名）與 PID 抄下來** —— 那就是持有者
4. 再抄它的親代鏈：
   ```powershell
   powershell -NoProfile -Command "$p=<那個PID>; while($p){$x=Get-CimInstance Win32_Process -Filter \"ProcessId=$p\"; if(-not $x){break}; '{0} {1} parent={2}' -f $x.ProcessId,$x.Name,$x.ParentProcessId; $p=$x.ParentProcessId}"
   ```

⚠ `openfiles.exe` **不要用**：它要系統管理員權限（實測當場被拒），
而 `openfiles /local on` 還要**重開機**才生效 —— 重開機同樣會消滅現場。
`resmon` 是內建、不必裝、不必重開機的那一條。

\## ① 治本：Server 脫離呼叫端的行程樹（`ServerAutoStart.TrySpawnDetached`）

`Process.Start` 生的是直系子孫 ⇒ 繼承呼叫端的一整包（handle、環境，Windows 上還有**封裝 app 的套件身分**）。
改成先走 WMI `Win32_Process.Create` —— 新行程由 WMI provider 生，親代是 `WmiPrvSE`。

⭐ **判準是回讀親代，不是「WMI 回 0」**：拿到 pid 之後再問一次 `ParentProcessId`，
還是自己就當沒成功、退回直接 spawn。**而降級會出聲**（印「沒能脫樹 ⇒ 退回直接 spawn」＋為什麼）——
靜默退回的話，「脫樹成功」與「脫樹失敗」在畫面上完全一樣，而它們差一個「Claude 起不起得來」。

**實測（兩次，都是自動起的）**：
```

senate.exe(38044) <- WmiPrvSE.exe                      ← 重建之後再驗一次，可重現
```
⇒ 親代鏈上**一顆 Claude 都沒有**。

📌 而這一格的好處是它**量得到**：脫樹可以回讀親代；「套件身分」只能推。
