# TASK-0204 — Claude Code 關閉後重啟失敗：安裝檔被某個行程鎖住，關掉 Unity Editor 才解開 —— 而持有者是誰沒有人量過

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

## 症狀（Tim 回報，2026-09-11；他說「**又**遇到一次」⇒ 至少第二次）

Claude Code **自己關閉**之後**無法重啟**，跳：

```
C:\Program Files\WindowsApps\Claude_1.52386.0.0_...
其他程式正在用這個檔案。
```

**把 Unity Editor 關掉之後才重啟得起來。**

## 🔬 我量到什麼（而我沒有抓到犯人 —— 現場已經沒了）

事發後才查，Tim 已經重啟過 ⇒ 以下都是**事後**讀數，⛔ 不能拿來當成因。

| 量的東西 | 讀數 |
|---|---|
| `Unity.exe` 的親代鏈 | `explorer.exe(1864)` → `Unity Hub.exe(21276)` → `Unity.exe(34812)` |
| 全部 `claude.exe`（13 顆）的親代 | 全是 `claude.exe(2736)`，而 2736 的親代是 `explorer.exe(1864)` |
| 此刻殘留的 build server | `dotnet` / `MSBuild` / `VBCSCompiler` **0 顆** |
| 此刻 `claude.exe` 的非同名子孫 | 只有我這一輪的 `bash` / `powershell` / `conhost` |
| repo 裡有沒有指向 `WindowsApps` 的路徑 | **0 筆**（掃 `Assets` / `.claude` / `AgentCommands/*.json`）|

## ⛔ 一個聽起來很合理、而**讀數否證掉**的假說

> 「Unity 是 Claude Code 開起來的 ⇒ 它繼承了 Claude 的檔案 handle ⇒ Claude 關掉後那些 handle 還在。」

**不成立**：這一顆 Unity 走的是 `explorer → Unity Hub → Unity`，跟 Claude **雙向都沒有親子關係**。
📌 我把它寫進來不是湊字數 —— 它是這張單第一個會被想到的答案，
　 而**它已經被否掉了**，下一個人不必再走一次。

## ⚠ 而「關掉 Editor 就好了」**不等於**「Unity 鎖住它」

關 Editor 會順帶結束**它的全部子行程**。而本專案的 AgentCommand 會讓 Editor spawn 東西
（git／外部工具）。⇒ 犯人可能是 Editor 本身，也可能是它底下某一顆，
**而這兩者的修法不同**（一個要改 Editor 的行為，一個要改那支工具怎麼被 spawn）。
⛔ 在拿到持有者行程名之前，這兩個分不開。

## 📐 下次現場還在時要跑的那一格（⭐ 這才是本單真正的內容）

**⛔ 不要先關 Editor。** 關掉＝現場消滅，而這族問題的特徵就是「現場沒了就永遠查不到」。

1. 開**資源監視器**：Win+R → `resmon` → **CPU** 分頁 → 展開「**關聯的控制代碼**」
2. 搜尋框打 `Claude`
3. **把那一列的「映像」（行程名）與 PID 抄下來** —— 那就是持有者
4. 再抄它的親代鏈：
   ```powershell
   powershell -NoProfile -Command "$p=<那個PID>; while($p){$x=Get-CimInstance Win32_Process -Filter \"ProcessId=$p\"; if(-not $x){break}; '{0} {1} parent={2}' -f $x.ProcessId,$x.Name,$x.ParentProcessId; $p=$x.ParentProcessId}"
   ```

⚠ `openfiles.exe` **不要用**：它要系統管理員權限（實測當場被拒），
而 `openfiles /local on` 還要**重開機**才生效 —— 重開機同樣會消滅現場。
`resmon` 是內建、不必裝、不必重開機的那一條。

## ✅ 驗過的（有讀數）

- **成因有名字**：MSIX 部署錯誤 `0x80073D02` —— 舊版套件的行程沒消失 ⇒ 新版註冊不了。
  事件日誌時間軸：`08:35:47 id=658 延後註冊 → 09:10:36 id=419/404 失敗 → 10:44:55 id=400 成功`。
- **不是偶發**：`id=658` 在 9/4、9/7、9/9、9/11 各一次 ⇒ **每次 Claude 更新都會走到那一格**。
- **否證掉「Unity 繼承了 Claude 的 handle」**：親代鏈是 `explorer → Hub → Unity`（使用者確認手動開），
  且那顆 Unity 啟動於 10:49:01、比失敗（09:10）晚一個半小時。
- **修掉一個真的洩漏**：`UCL_RemoteWindowControl.GetProcessName` 的 `Process.GetProcessById` 不 Dispose
  （`UCL_Core fa53536f`）。同族 5 處全站掃過，其餘四處都有 `using`，只有這處漏。
- **文件落盤**：`Docs~/zh-Hant/Workflows/ClaudeCode_Update_Lock_Diagnose_Workflow.md`（`UCL_Core 7cb76c34`），
  已登記進 `index.md`。

### 💬 #1 basecamp 2026-09-11T03:19:18.146Z
\## ⭐ 成因有名字了（事件日誌，現場沒消失 —— 查得到）

`Microsoft-Windows-AppXDeploymentServer/Operational`，篩 `Claude`：

```
09-11 08:35:47  id=658  警告：Claude_1.52386 標記為「延後註冊」—— 因為 Claude_1.49585 正在執行中
09-11 09:10:36  id=419  錯誤 0x80073D02：無法安裝，因為必須先關閉：Claude_1.49585
09-11 09:10:36  id=404  部署 Register 失敗，錯誤 0x80073D02
09-11 10:44:55  id=400  Register **成功**
```

⇒ **「claude.exe 被關閉」與「無法重啟」不是兩個問題，是同一件事的兩半**：
Windows 下載了新版 MSIX、要求舊版行程全部結束才註冊得了；舊版結束 ＝ Claude Code 關閉，
而註冊被 `0x80073D02` 擋住 ＝ 起不來。

⚠ **這不是偶發**：id=658（延後註冊）在 **9/4、9/7、9/9、9/11** 各出現一次 ——
**每次 Claude 更新都會走到這一格**，只是不一定升級成 404 錯誤。

\## ⛔ 而錯誤訊息點名要關的是**舊版 Claude 自己**，不是 Unity

⇒ 真正的問題收窄成一句：**是什麼讓「舊版 Claude 的行程」在 Claude 都關掉之後還沒消失？**

\## 🔬 我找到的候選（已修，但**沒有**寫 Fixes）

`UCL_RemoteWindowControl.GetProcessName` 的 `Process.GetProcessById(pid)` **從不 Dispose**，
而它在 `EnumWindows` callback 裡逐一個可見視窗呼叫 ⇒ 一次掃描漏「可見視窗數」顆
**process handle**，活到 Editor 關閉。而這支的工作**就是去找 `claude.exe` 的視窗**。

一顆還開著的 process handle 會讓已結束的行程留在「未完全消失」狀態 —— 形狀跟
「關掉 Editor 之後才更新得了」吻合。已修：`UCL_Core fa53536f`。
📌 同族 5 處 `GetProcessById` 全站掃過，**其餘四處都有 `using`**，只有這一處漏。

\## ⛔ 吻合不是證明 —— ① 那格仍然開著

而且有一格讀數**反過來限制我**：現在跑的這顆 `Unity.exe` 啟動於 **10:49:01**，
Claude 是 **10:48:47** 起來的 ⇒ **它比那次失敗晚，跟 09:10 那次無關**。
我量得到的 Unity 不是 Tim 關掉的那一顆。

⇒ ① 仍然要**下次現場**用 `resmon` 抓持有者。⛔ 別因為修了一個吻合的洞就把單關掉。
