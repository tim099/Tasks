## 驗收標準

> 🔨 **PM 射程改寫（basecamp 2026-09-04）**：TASK-0054 拍板⑤ 把路徑扁平化成
> `<DataRoot>/sessions/<persona>.json`（**一人一檔位**）之後，這張單擋的東西**換了** ——
> 從「防疊開的使用者體驗」變成 **「防後來的那場靜默覆蓋掉先來的那場」**。
> 讀 code 的鏈（2026-09-04，host=這台／repo=`Assets/Plugins/UCL_Core`／ref=`Dev`）：
> `Save(kind,…)` 寫的是那一個檔位、不查 kind；`Load<T>(kind,…)` 會 filter kind、讀到別 kind 回 `null`
> ⇒ FreeTime 守衛③ 呼叫 `Load(FreeTime,…)`，**一場進行中的 StreamWatch 在它眼裡等於「沒有 session」**。
> 佐證：全 repo `FindRunning` 只有 3 個消費端（`Cmd_DocEdit`／`UCL_FreeTimeHint`／`Cmd_SessionStatus`），
> **沒有一個在開場路徑上**。
> ⚠ 以上**是推論不是活體** ⇒ 第 ① 格就是去造那個活體，⛔ 不要先信這段。

- [ ] ① **活體先行**（本單第一格，不可後補）：開一場 StreamWatch → 不收工 → 跑 FreeTime `step=start`
      ⇒ **回讀 `<DataRoot>/sessions/<persona>.json`**，看觀影那場還在不在。
      ⚠ 判準是那個檔的內容，**不是 FreeTime 回什麼**（它會說成功）。修前讀數先落單，才知道修的是什麼。
- [ ] ② 各 kind 開場 op（FreeTime 開場、StreamWatch prepare/start/join；之後新 kind 登記即自動生效）
      先查該 persona 的進行中 session —— 查的是 **`FindRunning`（不 filter kind）**，不是各自的 `Load(自己那個 kind)`
- [ ] ③ 他 kind 有進行中 ⇒ blocked（非零退出）；回傳檔寫明：**原因**（哪一 kind 哪一場、預定到幾點）
      ＋**處理方式**（該 kind 收工指令原文可直接複製執行／或等到期）—— 祈使句、指令直接附上、不解釋代價（Tim 措辭拍板）
- [ ] ④ 同 kind 疊開仍由各 kind 既有守衛管（本單不動、不重造）
- [ ] ⑤ 讀數三組：①觀影進行中開自由時間 ⇒ 擋＋出口指令可直接跑通 ②照出口收工後重跑 ⇒ 放行
      ③無任何 session 時開場 ⇒ 不擋（反向對照 —— 只驗會擋的話，永遠擋的閘也會通過）
- [ ] ⑥ **修後回讀**：重跑 ① 的活體 ⇒ 觀影那場**仍在**（active=true、欄位未被改寫）
      · 這格與 ⑤① 不同形：⑤① 驗「有沒有擋」，這格驗「被保護的那份資料有沒有活著」

> 🔨 **PM 射程再更新（basecamp 2026-09-05，wake#90）**：**機制已經有了，缺的是接線。**
> `SCP_ActivitySessionStore.TryStart`（先查再寫；跨 kind 擋下、點名擋你的那場、被擋後原場不被覆蓋）
> 是 0127 帶進 SCP_Core 的，而且**已經有活體讀數** —— `senate selftest` 的「活動 session 行為」

> ⚠ 而它也是本單最容易假綠的地方：**那一層是綠的**，所以只驗那一層會全過。

- [ ] ⑦ **接線讀數**：`grep -rn 'TryStart' Assets/` 必須命中 FreeTime 與 StreamWatch 的**開場路徑**
      （不是任何一處命中就算 —— 要指出是哪一個 op 的開場）

      層綠而活體紅 ⇒ 就是本單還沒做完；兩欄同時綠才算。⛔ 不准只交層那一欄

\### 成因（讀 code 對上讀數，行號是今天的）

＝ `SCP_ActivitySessionStore.Load<UCL_FreeTimeSession>(root, persona, Kind.FreeTime)`
—— **它 filter kind** ⇒ 一場進行中的 StreamWatch 在它眼裡回 `null`
⇒ `aOld == null` ⇒ 守衛整段跳過 ⇒ `SaveSession`（`:152`）直接覆蓋那個檔位。

📌 而共用層**早就有對的那道門**：`SCP_ActivitySessionStore.TryStart`（先查再寫，`FindRunning` 不 filter kind），
`senate selftest`「活動 session 行為」每次 build 都跑它三格（跨 kind 擋下／點名擋你的那場／被擋後原場沒被覆蓋）。
⇒ **層是綠的，而沒有任何一條真實開場路徑走它** —— 這就是 ⑧ 那格要防的假綠。
