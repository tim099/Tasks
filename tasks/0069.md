# TASK-0069 — commands_schema 產物殘缺：Cmd_Task 零 ArgsSpec、Cmd_Tavern 漏 catchup —— 重跑匯出修不好

> `improvement` / `normal` / `todo`　開單：basecamp　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

## 讀數（basecamp 2026-08-27，先量後跑再量）

| 步驟 | 讀數 |
|---|---|
| 跑前 | `commands_schema.json`：`Task` 是空 `{}`（keys=[]）／`Tavern` 30 ops、**無 `catchup`** |
| 跑 `run ExportCmdSchema` | ✓ **Success** |
| 跑後 `cmp` 前後檔 | **位元組完全相同** ⇒ **重跑修不好它**（`Task ops n=0`、`Tavern catchup: False` 照舊） |

根因（code 讀）：
- `Cmd_Task.cs`：**零 `ArgsSpec` 宣告**（`grep ArgsSpec` 無命中）⇒ 匯出必然是空的
- `Cmd_Tavern.cs`：`catchup` 只在 `switch` 的 `case`（`:249`），**沒被加進 `ArgsSpec.Ops` 字典**（`:103` 起）

⚠ 持續代價：每次呼叫 `Task`／`Tavern catchup` 都印「op 不在 schema 產物內 —— 放行交給 Editor 判」。
**那行永遠不會消失** ⇒ 變成雜訊 ⇒ 真的打錯字那天沒有人會看它（警告貶值）。

## 驗收標準

- [ ] `Cmd_Task` 補 `ArgsSpec`：13 個 op（create/list/show/claim/assign/unassign/update/comment/link/resolve/commit/sweep/wrapup/kanban）
      至少宣告 op 名與各自 `Required`（`show/claim/update/comment/link/resolve` 需 `index`；`wrapup` 需 `index`＋`progress`）
- [ ] `Cmd_Tavern.ArgsSpec.Ops` 補 `catchup`
- [ ] 讀數：跑 `ExportCmdSchema` 後 `cmp` 前後檔**位元組不同**（這次要真的變），且
      `Task ops n>0`、`Tavern catchup: True`
- [ ] 反向對照：拿一個**真的不存在**的 op（例：`--arg op=wrapupp`）跑一次 ⇒ 仍會被擋／被指出
      **（證明修完之後那行警告恢復成有訊號的警告，而不是被一起關掉）**
- [ ] ⚠ 一格要判不要順手做：`Cmd_Task` 掛 `ArgsSpec` 之後，**執行前參數檢查會開始生效** ——
      既有呼叫端（含各 skill 文件裡的範例）若有漏必填的，會從「靜默取預設值」變成「被擋」。
      ⇒ 交件前先 grep 一輪既有用法，把會被新擋下的列出來給 PM 看，**不要自己決定放寬哪一格**

## 任務描述

來源：summit 於 TASK-0019 留言 #9 自報 friction「產物落後，要不要順手跑一次 ExportCmdSchema」。
QA（basecamp）先量後跑，量到**相反的結果**：重跑不會變，因為來源就沒有那些宣告。

📌 一般形（值得記在 code 註解裡）：**當「宣告」與「實作」是兩張表時，匯出器只看得到宣告那張** ——
漏宣告的 op 在產物上與「這個 op 不存在」**同形**。
而 `ExportCmdSchema` 回的 Success 是真的：**它成功的是它自己那一格。**
