# TASK-0069 — Cmd_Task 零 ArgsSpec、Cmd_Tavern 漏 catchup —— Editor 執行前參數閘對這兩支等於不存在

> `improvement` / `normal` / `done`　開單：basecamp　參與：calli(dev)

## 驗收標準

\## 射程更正（Tim 2026-09-06 拍板走 (C)）

本單原本押了兩件事，而只有一件還活著：

- ⛔ **schema 產物那半整段退場** —— `commands_schema.json` 的語意消費端 100% 在 python
  （`run_cmd.py` / `tavern_cmd.py`）；C# 只寫不讀，Senate CLI 只把它當 JSON parser 的測試素材。
  Cmd 全面改走 Senate CLI 之後不該再處理它 ⇒ 歸 TASK-0107 拍板②／TASK-0108。
- ✅ **活著的那半跟 schema 無關**：`ArgsSpec` 還有第二個消費端 ——
  `UCL_AgentCommandRunner:349 → UCL_CmdArgsValidator.Validate`（**執行前**擋下，不執行 handler）。
  而 `Validate` 對 `ArgsSpec == null` 的 handler **直接 return true**
  ⇒ 「`Cmd_Task` 零 ArgsSpec」的真正意義是：**ucmd 這條唯一的路上，它沒有執行前參數閘。**


- [x] ① `Cmd_Task` 補 `ArgsSpec`：宣告 **14** 個 op（switch 實際有 14 個 case；開單當天寫 13、改射程時我寫成 15，兩個都錯，以 code 為準），
      並**只**宣告 handler 自己已經會 throw 的必填
      （保守原則，沿用 `Cmd_Tavern` 那句「leave 沒有任何 reject ⇒ 刻意不宣告 required」）
- [x] ② `Cmd_Tavern.ArgsSpec.Ops` 補 `catchup`（`persona` 必填，對齊 `Op_Catchup` 的 `RejectLastOp`）
- [x] ③ 陽性讀數：`op=show` 缺 `index` ⇒ **在 handler 執行前**被擋，訊息由 validator 出：
      `[Task op=show] 參數檢查未過｜沒帶必要參數：[index]（你目前傳的：[op, persona]）`
      —— 不是 handler 的 `[Task] 這個 op 需要 --arg index=<單號>`
- [x] ④ 反向對照：合法呼叫沒有被新閘擋掉 —— `op=list` / `op=kanban` / `op=show --arg index=69` /
      **完全不帶 `op`**（走預設 `list`）四格全 Success；`Tavern op=catchup --arg advance=0` Success 且游標未推進
- [x] ⑤ 交件前 grep 既有呼叫端：**沒有任何一個會被新閘擋下**，而理由是構造性的 ——
      本次只宣告 handler 已經無條件 `throw` 的參數 ⇒ **今天會成功的呼叫，明天一樣成功**；
      今天會失敗的那些只是**更早失敗、訊息更好**。（實際 grep 到的呼叫端：`run_cmd.py:1566` friction 開單範例、
      `UCL_TaskReconcile.cs:206`、skill 文件範例 —— 全部帶齊。）

\### ⚠ 射程外（本單不處理，寫下來免得被當成沒做）

- **未知參數名**仍然會被靜默吃掉。`Validate` 只檢查 Required／RequiredPresent，
  **沒有白名單** ⇒ `--arg zzz=1` 照樣過。那是 **TASK-0109 ②**（拍板乙：等 Server 搬完）。
  📌 本單是它的**前置**：`ArgsSpec == null` 的 handler 連白名單都無從掛起（本單已解掉 Cmd_Task 那格）。
- ⊘ **`catchup` 的陰性對照從 `senate ucmd` 打不出來**：dispatcher 會把 `--persona <me>` 注入成 `persona` 參數，
  所以「缺 persona」在這條 client 上不可達。宣告本身與 handler 對齊，但那一格**只擋得到不帶 persona 的派遣端**
  （酒保 / daemon / 直寫 queue.json）。這是射程陳述，不是通過。
- `commands_schema.json` 的產物內容、`ExportCmdSchema` 重跑後的 `cmp` 結果 —— **不再是本單的驗收**。
