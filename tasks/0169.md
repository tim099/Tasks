## 任務描述

## 症狀（Tim 2026-09-07 21:5x 實撞）

在 `UCL_ReadingNotesManagePage` 的「作品入口搜尋」打 **`奇葩小国`**（简体）⇒

```
「奇葩小国」找到 1 個入口。Archive 結果只供人工確認與遷移，不會被新流程讀取。
  Archive（legacy，唯讀）  奇葩小國（小約翰可汗）
    slug: xiaoyuehan-qipa-xiaoguo   原文: 奇葩小国
```

**正本一筆都沒出現** —— 而它存在：`Library/works/qi-pa-xiao-guo` ＋ `Library/media/series-qi-pa-xiao-guo`，
底下 `readers/{calli,summit}/chapters/0001/r1_2026-08-19.md` 都在。

⇒ 讀者的合理推論是「這作品**還沒遷移**」（頁面那句話就是這樣寫的），
而事實是**新 store 早就有它** ⇒ 下一個動作會是去跑 migrate，**把已經在的東西再遷一次**。

## 🔬 成因一：`SearchLibrary` 的比對欄位集合**比 Archive 那邊窄**

```csharp
// SearchLibrary
if (!Matches(query, title, mediaId, workId)) continue;      // ← 三欄
// SearchArchive
if (!Matches(query, title, original, slug)) continue;       // ← 多一欄 title_original
```

拿真資料代進去（`Matches` 是 OrdinalIgnoreCase 的 `IndexOf`）：

| 欄位 | 值 | 含 `奇葩小国`？ |
|---|---|---|
| `work.json.title` | `奇葩小國` | ❌ **繁體「國」** |
| `media_id` | `series-qi-pa-xiao-guo` | ❌ |
| `work_id` | `qi-pa-xiao-guo` | ❌ |
| **`work.json.aliases`** | `[奇葩小國, **奇葩小国**, 小约翰可汗, 小約翰可汗, bilibili 奇葩小国, Bizarre Small Countries]` | ✅ **而它不在比對集合裡** |

⇒ 那個欄位**正是為這件事存在的**（繁簡兩體＋up 主名＋英文名一應俱全、寫得很完整），
而搜尋沒有讀它。⛔ 不是「资料缺」，是**查的地方少一欄**。

📌 而 Archive 那邊會中，是因為它多比了 `title_original`，那一欄剛好是简体 ——
**舊層的比對比新層寬** ⇒ 症狀是「只有 legacy 查得到」，讀起來完全像「還沒遷移」。

## 🔬 成因二：`_migration/registry.json` 不認識這一筆（所以「隱藏已遷移」也藏不住它）

Tim 那張圖裡「顯示已遷移的 Archive（預設隱藏）」是**沒勾的**，而 Archive 仍然列出來 ⇒ 它沒被標為已遷移：

```
AgentCommands/BookNotes/_migration/registry.json   mtime 2026-08-07 17:59（一個月沒動）
  提到 xiaoyuehan-qipa-xiaoguo ⇒ False
  提到 qi-pa-xiao-guo          ⇒ False
```

⇒ **「遷移」其實有兩條路**：① 走 `op=scan / migrate`（會寫 registry）②**新流程直接在新 store 建**
（本例：StreamWatch 場次 `sw-20260818T233343Z-summit`，2026-08-19 落 `chapters/0001/r1_…md`）。
registry **只記得第一條**，所以第二條路造出來的資料在遷移帳上永遠是「沒遷」。

## ⚠ 而查下去發現的第三件事（比上面兩件嚴重，但先只報讀數）

兩個 store 裝的**不是同一批內容**：

| store | 內容 | 日期 |
|---|---|---|
| Archive（legacy，唯讀） | branch `ame`：`ch37_…chile-911-allende…` / `ch38_…nicaragua-sandino-somoza…` ＋ 4 張人物卡（sandino/somoza/zelaya/zeledon） | 2026-07-11 |
| Library（正本） | `readers/{calli,summit}/chapters/0001`（第 01 話 阿爾巴尼亞） | 2026-08-19 |

⇒ legacy 的 **ch37/ch38 ＋ 四張人物卡從來沒進正本**，而正本只有 0001。
**同一個作品的心得同時活在兩個 store，而搜尋頁依「你打繁體還是简体」決定讓你看到哪一邊。**
⛔ 我不宣告該怎麼合（那是遷移策略，不是這張單的修法）—— 本單只修「看得見」。

## 建議

- **(甲) `SearchLibrary` 把 `aliases` 納入比對**（正本那邊本來就有這個欄位，且 `Cmd_Library` 生成時會填）。
  ⭐ 這條同時修掉繁简、up 主名、英文名三種查法，代價是一行。
- **(乙) 「找到 N 個入口」那句要能說出「其中 0 筆是正本」**——
  現在 N=1 全是 Archive 與 N=1 是正本印同一句話，而兩者的下一步相反（一個去遷移、一個去讀）。
- ⛔ 不建議「把 aliases 抄進 title」：那讓同一個量有兩個說法，是漂移源。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

2026-09-07 Tim 在 UCL_ReadingNotesManagePage「作品入口搜尋」打「奇葩小国」（简体），截圖顯示「找到 1 個入口」且唯一結果是 Archive（legacy，唯讀）slug=xiaoyuehan-qipa-xiaoguo、原文=奇葩小国，正本零筆。代碼讀數（Assets/Plugins/UCL_Core/UCL_Core_Scripts/EditorCore/UCL_EditorMenuPages/UCL_ReadingNotesManagePage.cs）：SearchLibrary 只比 `Matches(query, title, mediaId, workId)`，SearchArchive 比 `Matches(query, title, original, slug)`（多一欄 title_original）；Matches 是 OrdinalIgnoreCase 的 IndexOf。資料讀數：Library/works/qi-pa-xiao-guo/work.json 的 title='奇葩小國'（繁體「國」，不含查詢字串）、title_original 空、work_id/media_id 皆拼音，而 aliases=['奇葩小國','奇葩小国','小约翰可汗','小約翰可汗','bilibili 奇葩小国','Bizarre Small Countries'] 內含查詢字串 —— aliases 不在比對集合裡。Archive/xiaoyuehan-qipa-xiaoguo/book.json 的 title_original='奇葩小国' ⇒ 舊層比對比新層寬。BookNotes/_migration/registry.json（mtime 2026-08-07 17:59）不含 xiaoyuehan-qipa-xiaoguo 也不含 qi-pa-xiao-guo ⇒「顯示已遷移的 Archive」未勾時它仍列出。內容對照：Archive 有 branches/ame/chapters/ch37_l37-chile-911-allende-fall-detective.md、ch38_l38-nicaragua-sandino-somoza-detective.md ＋ characters/{sandino,somoza,zelaya,zeledon}（2026-07-11），正本只有 readers/{calli,summit}/chapters/0001/r1_2026-08-19.md ⇒ 兩 store 內容不重疊。
