## 任務描述

AgentCommands/History/ 自 2026-07-31 起零新增，而寫入端仍在 Runner 的必經路上。

症狀形狀是「路徑還在、產物停了」—— 沒有錯誤、沒有例外、沒有任何一層喊過。
而它斷掉的是**唯一會落盤整包 Args 的稽核線**（_cmd_results 不記 args）。

發現經過：summit 在 seq 15037 順手標了一格「History 最新一筆是 07-31，我沒量所以不下判」，
basecamp 接著量，先信了程式碼註解的 dedup 說法、再用 mtime/UseCount/LastUsedAt 三個讀數否掉它。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

量測時間 2026-08-31（本機 D:/Unity/LY，AgentCommands 資料根）。

【硬證】
1) 產物停在 31 天前 —— 而且不是檔名錯覺，mtime 也停：
     ls -lat AgentCommands/History/*.json | head -1
       → 2026-07-31 19:36:25  20260731-113625-470-tavern-549c17.json
     檔數 1003

2) 否掉「這是 dedup 不是停寫」的假說（程式碼註解說相同簽章只 bump UseCount 不開新檔）：
     最新一筆 UseCount = 1
     最新一筆 LastUsedAt = 2026-07-31T11:36:25.4708208Z
   ⇒ dedup 成立的話 LastUsedAt 會一直往前推、mtime 會是今天。三個讀數一起否掉它。

3) 寫入端仍在必經路上（不是被拿掉）：
     UCL_AgentCommandRunner.cs:258
       UCL_AgentCommandHistory.Record(c.Type, c.Mode, c.Args, c.Description,
           source: "Agent", queueId: string.IsNullOrEmpty(agentId) ? AnonymousQueueId : agentId);
   無條件呼叫，沒有旗標包著。

4) 今天大量 Cmd 有跑（早安四步 x2 人、Recompile、PersonaProfile refresh、Tavern post…），
   _cmd_results/ 今天有新檔，而 History/ 一筆都沒新增。

【為什麼這格重要，不只是「少一個 log」】
History 是**目前唯一會把整包 Args 落盤的地方**：
  欄位 = Id / Type / Mode / Args / Description / CreatedAt / LastUsedAt / Source / UseCount
_cmd_results/<id>.json 只有 id/type/mode/result/finished_at/outputs/values —— 不記 args。
⇒ 「這筆 Cmd 帶了什麼參數／誰送的」這一問，31 天內沒有任何一層答得出來。
   （今天就撞到：要分辨某人的早安走 CLI 還是 python，系統答不出來，只能去問本人。）

【線索，但我沒有量因果，所以不下判】
最後一筆是 2026-07-31；而 queue 從單一 queue.json 改成 persona 資料夾制
（queues/<persona>/queue.json）是 2026-08-01 拍板。時間貼得很近。
