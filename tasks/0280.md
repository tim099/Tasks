# TASK-0280 — DelegateAppendToServer 的執行檔名留一條可注入的縫 —— 讓 TASK-0267 ⑤⑦ 不必弄壞共用宿主才驗得到

> `feature` / `normal` / `done`　開單：kotoko　參與：kotoko(dev)

## 驗收標準

- [x] ① 執行檔名變成可注入欄位（預設 `"senate"`）—— ⛔ 不新增設定檔、不新增路徑解析器，只留一個測試餵得進去的縫　✅ kotoko 2026-09-22
- [x] ② 餵一個**不存在的名字** ⇒ `UCL_ChatTavernIO.DelegateAppendToServer` 的 `Win32Exception` 分支**活體走到**，且那一則**沒有寫出去**（憑據＝房間訊息數不變，⛔ 不是只看有拋例外）　✅ kotoko 2026-09-22
- [x] ③ 錯誤訊息仍然是「能動手的那一句」（含「把 publish 加進 PATH」與切回 editor 寫入端兩條出路）　✅ kotoko 2026-09-22
- [x] ④ 🔴 **全程不動任何人的環境**：不改進程 PATH、不改共用設定、不在樹上種執行檔（憑據＝跑完後 `senate` 照常可用，⛔ 這格是本單存在的理由）　✅ kotoko 2026-09-22
- [x] ⑤ 同一條縫能不能讓 `SCP_ServerAutoStart` 的 `TimedOut`／`SpawnFailed` 兩臂也走到 —— 走得到就順手補，⛔ 走不到就照實寫「這條縫只夠 ②」　✅ kotoko 2026-09-22

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

TASK-0267 ⑤「Server 起不來仍然整筆失敗且大聲」與 ⑦ 的兩個失敗臂，今天**兩個人各自獨立**撞到同一堵牆：

- summit（0267 留言 #9）：`FileName = "senate"` 靠**進程 PATH** 解析（`UCL_ChatTavernIO.cs:1017` ＋ `:1020` `UseShellExecute = false`），而 PATH 在 Editor 起來時就固定了 ⇒ 不改 code 製造不出「叫不到 senate」。
- summit（留言 #11）：後來找到一條 —— `Cmd_Invoke` 反射呼叫 `Environment.SetEnvironmentVariable("PATH", …)`。還原路徑她**先驗過**（備份 ↔ 探針回讀 1203 bytes 逐字相同）。⛔ 而破壞那一步被宿主權限閘擋下、**沒有執行**。
- kotoko QA（留言 #12／#13）：⇒ 判定 ⑤⑦ **留空不勾**。理由不是怕麻煩，是 **一個需要弄壞共用宿主才跑得動的驗收，跑得了一次、跑不了第二次**（要 Tim 開權限＋要知會在線的人＋那三分鐘全樹 Editor 酒館寫入會倒）⇒ 它會變成「有人在 2026-09-22 勾過」，而它守的那條分支之後怎麼漂都不會有人知道。

⇒ 兩人**各自獨立**走到同一個出口：把那個執行檔名變成可注入欄位。餵一個不存在的名字，`Win32Exception` 那條分支當場走得到，**不動任何人的環境、可以重跑、可以進自動化**。

⛔ 顯式未量：那條縫夠不夠讓 `SCP_ServerAutoStart` 的 `TimedOut`／`SpawnFailed` 也走到 —— **沒有查**，列為 ⑤。

## 結單說明

五格全過，落地 UCL_Core `91cdce1e`。

⚠ **我兼 dev 與 QA，沒有第二個人**（Tim 授權「280 全包」）—— 顯性寫在這裡，⛔ 不用兩個勾假裝有兩個人。

**讀數**：② 注入不存在的名字 ⇒ 發文整筆失敗，房間訊息檔 13→13、`_seq` 176→176、探針內文在所有房間零命中（⛔ 沒降級成本地訊息）；③ 訊息印的是**實際用的名字**、兩條出路都在；① 縫的來回用回傳值驗（Set 回 null ⇒ 起點是生產、Clear 回 `senate-does-not-exist-0280` ⇒ 真的清掉了），清完 `writer=server` 發文成功（seq 178）；④ `HKCU\Environment` 的 Path 仍含 publish、`senate` 仍解析得到、`tavern.writer` 回讀 `editor`／`explicit=1`。編譯 errors 0／stale 0／saw_in_progress 1。

**⑤ 照實寫：這條縫只夠 ②。** `SCP_ServerAutoStart` 跑在 **CLI 那個 process 裡**（Unity 端從來沒呼叫過 `Ensure`，全檔只有一處註解提到它）⇒ 讓 CLI 起不來的縫，結構上到不了 `TimedOut`／`SpawnFailed`。那兩臂要的是 **spawn 注入點**上的縫，在 CLI 側。

**⛔ 本筆沒有替 TASK-0267 ⑤⑦ 打勾** —— 縫有了，那兩格要在 0267 上另外跑一次活體。

🩸 自驗時撞到兩格、都當場修掉／還原了：① 第一版**設得進、清不掉**（驅動端沒有傳 null 的寫法）⇒ 補了無引數的 `Clear…`；② 落盤時把整支檔 1846 行 CRLF 換成 LF，而 `git diff --stat` 因為正規化**照樣只報 52 行** ⇒ 已還原。兩格的讀數都在 commit 訊息裡。
