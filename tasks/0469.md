# TASK-0469 — 球面 OpenGL 3D 管線：可在地球上放建築

> `epic` / `normal` / `todo`　開單：basecamp　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 子單 A（球面 GPU 地表預覽）已結
- [ ] 子單 B（建築放置）已結
- [ ] 後台球面頁上同時看得到地表格子與至少一棟由雕刻作品放上去的建築，拖曳、縮放時建築跟著地表走、不漂、不抖

## 任務描述

## 為什麼
Tim 2026-10-09：CPU 渲染其實不慢（720² 約 50 ms），但之後要在地球上放 3D 建築，並發展成城建模擬（大家一起建設地球）。
逐像素光線求交的 CPU 路沒有深度、沒有網格，接不了建築 ⇒ 球面要有一條 OpenGL 3D 管線。

## Tim 已拍板（2026-10-09）
1. 建築來源＝雕刻作品匯出的體素模型 ＋ 一份設定檔（建造費用、建築功能等；**功能細節 Tim 還在想，先不做**）。
2. 建築直接以模型放置，⛔ 不轉成地表 voxel（細緻很多）⇒ 要做 culling，遠距離顯示低模或轉貼圖。
3. 尺度有切換選項（參考 SculptureViewerPage 的做法）。
4. CLI 的 render／export：格子回讀的正本仍是 CPU；畫不畫建築有選項可以設定。
5. 放置紀錄沿用球面慣例：事件只追加、可 Undo。
6. 預覽要能拖曳、縮放；GPU 端資料要快取（格子轉成貼圖、建築轉成模型，留在 GPU 上即時渲染），⛔ 不是每幀從 CPU 重建。

## 設計方向（basecamp 的建議，Tim 同意）
- 球：全畫面四邊形 ＋ fragment shader 解析求交（取格方式與 CPU 同一套），寫入深度 ⇒ 建築直接光柵化上去，前後遮擋自然正確。
- 格子資料：256² 分塊圖集 ＋ 索引貼圖（只上傳畫過的分塊；寫入後只更新髒分塊）。⛔ 不整面上傳（N=8192 時 6 面 RGBA 要 1.6 GB）。
- 面基底從 meta 傳進 shader，⛔ 不在 GLSL 寫死第二份（兩份基底不一致 ⇒ 接縫錯位／鏡像，而且不會報錯）。
- 精度：建築局部座標系（錨點的東、北、上三軸）在 CPU 用 double 算，以鏡頭為原點傳成 model matrix ⇒ 避開 float32 在公尺尺度的抖動。
- 鏡頭：透視、軌道式；GPU 不在時退回現在的 CPU 預覽，並說原因（照雕刻渲染器的失敗模式）。
