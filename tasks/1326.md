> `improvement` / `normal` / `in_progress`　開單：ame　參與：ame(dev)

## 驗收標準

- [x] 一份快取清單列出全部本地快取（路徑、工具、指紋檢查、一定要／可以沒有），新的烘焙產物照它登記　✅ ame 2026-11-19
- [x] 一個新開的 worktree 不抄、不連任何快取，node 工具照樣讀得到主樹那份（氣候、城鎮規劃、導航網至少各量一支工具）　✅ ame 2026-11-19
- [x] 反向對照：worktree 改了某一份快取的輸入程式 ⇒ 不借主樹那份、報錯指出要重烘哪一支（不安靜地用過期的）　✅ ame 2026-11-19

- [x] 狀態指令列出每一份在不在、新不新、從哪借的　✅ ame 2026-11-19

## 任務描述

Tim 2026-11-19：「別人的 worktree 讀不到氣候 有好的解決方案嗎 或是直接進git?」「B做法有辦法防呆嗎(且是否可以讓一些類似的烘焙資訊也用同一套方法 目前的導航網也進git嗎?)」「開單」

**現在**：烘焙產物多半是本地快取（不進 git、要進成品，packaging/electron/build.sh 照各自的 --check 烘）
| 快取 | 大小 | 工具 |
|---|---|---|
| world/climate/（TASK-1323） | 319 MB | tools/climate_bake.py |
| world/townmesh/ | 81 MB | tools/town_mesh_bake.cjs |
| world/chunk_bake.bin | 38 MB | tools/chunk_bake.cjs |
| world/townplans/ | 11 MB | tools/town_bake.cjs |
| world/navmesh.bin | 9.7 MB | tools/navmesh_bake.cjs |
| world/navdeep.bin、navshallow.bin | 0.6 MB＋ | tools/navdeep_bake.cjs |
| world/ship_bake.json | 0.7 MB | tools/ship_bake.cjs |
（進 git 的只有 world/nav/ 的航線快取 graph.js、net.js、ports.js）

⇒ worktree 裡都沒有。現在各自手動繞：抄 townplans、`_cache`／townmesh 用 junction（`git worktree remove --force` 可能順著刪到主樹）、抄 navdeep／navmesh、氣候設 BLOCKSAIL_CLIMATE
⇒ 兩種安靜的錯：① 讀不到當成沒有（例：氣候沒有 ⇒ 寫了氣候條件的作物一律不合、不報錯）② 借到過期的（worktree 改了 water.js 卻讀主樹照舊程式烘的導航網）

**做法（提案）**
1. 一份快取清單：路徑、產生的工具、檢查的指令（指紋）、缺了是「一定要」還是「可以沒有」
2. node 工具共用一支借用規則：自己 worktree 的 ⇒ 沒有就照 `git rev-parse --git-common-dir` 找主樹那份，**指紋跟這個 worktree 現在的程式對得上才借**；對不上 ⇒ 報錯、指要跑哪一支重烘。不用 junction
3. 大聲失敗：「一定要」的缺了、指紋不對 ⇒ node 工具 exit 1；瀏覽器開發頁面紅色橫幅（缺哪一份、哪一支工具烘）
4. 一支狀態指令：每份快取在不在、新不新、從哪借的（開 worktree 先跑）
5. 開發伺服器（world_serve.py／globe.sh）缺檔照同一套轉到主樹那份
6. 打包照舊在自己的樹烘；原始資料（例：CHELSA `_cache/chelsa`）也照同一套找主樹的 `_cache`

相關：TASK-1323（氣候格子是本地快取的那一份）、TASK-1324（土壤格子之後也照這套）
