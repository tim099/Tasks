## 現象
`bank-request` 收 `source_kind`／`source_ref`，說明寫「核准後寫進帳本」，但核准端從不讀它們 ⇒ 給了不生效、也不警告。

## 修法方向（待 Tim 選）
- (a) 改 help：照實寫「只記在請款單上，帳本一律是 payout_request＋單號」，並在漏發補款的說明指路 `bank-reconcile op=apply`（會寫帶逐則 ref 的 work_post）。
- (b) 改核准端：source_ref 是逐則 ref 時，入帳腳帶上它（要改冪等鍵與 PayoutApprovalGuard 的判準，牽動較大）。
⚠ 不論哪個，`bank-request` 收到 source_kind 卻不會進帳本時，應該當場印一行說明（現在的形狀是「給了而從來沒被讀」那族）。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

- `senate cmd help bank-request` 的 `source_kind`：「op=request：核准後寫進帳本的 source_kind（預設 manual_request）」。
- 2026-10-05 basecamp 開請款單 `0ac59a`：`--arg source_kind=work_post --arg source_ref=tavern#seq=21462`。Tim 以 BankAdminPage 一鍵批准（central）。
- 帳本實際寫入（`Bank/ledger/2026-10-05/031222_403_84479b__credit.json`）：`"kind": "payout_request"`、`"ref": "0ac59a"` —— 不是 work_post、也不是 manual_request；source_ref 沒進帳本。
- 程式：`src/Senate.Cli/Pages/BankAdminPage.cs` `ApprovePayoutCore` 寫死 `["kind"] = "payout_request"`、`["ref"] = aR.RequestId`（mint 與 central 兩條路都一樣）；`Cmd_Bank.cs` 約 1024 行同形。
- 後果：照 help 填的人以為對帳會認得這筆已付；實際 `bank-reconcile` 仍列在差集（missing=1），要手動登記進 `Bank/payroll_settled.json`，否則 `op=apply` 會再付一次。⇒ 「安靜給錯」，沒有任何一層喊。
