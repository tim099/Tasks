**症狀**：`node tools/nav_bake.cjs`（烘 world/nav/graph.js）跑一個多小時、一行都不印，記憶體一路漲，最後無聲結束、graph.js 沒寫。

**讀數一**（2026-11-13，trailhead，TASK-1246 的 worktree bsl-coast，分支 trailhead/1246-coast，HEAD 合了 main d9306153）：
- 照航線整串重烘（navdeep ⇒ navmesh ⇒ nav_ports ⇒ nav_net ⇒ navmesh ⇒ nav_net ⇒ nav_bake）。前 7 步都 exit 0（navdeep 2,663 s、navmesh 2,993 s、ports 129 s、net 2,793 s、navmesh2 761 s、net2 1,920 s）。
- 第 8 步 `timeout 10800 node tools/nav_bake.cjs > rb_graph.log 2>&1`：**3,641 s 後 exit 127**（Git Bash 的 sh 回報），rb_graph.log **0 位元組**，world/nav/graph.js 沒動，Windows 事件記錄找不到當機紀錄。
- 重跑同一步（PowerShell `Start-Process`，stdout／stderr 各導到檔，每 30 秒記一次 WorkingSet）：**3 小時 18 分還在跑**，CPU 12,881 s，**WorkingSet 18,254 MB**，stdout／stderr 都 0 位元組 ⇒ 手動 taskkill。
- 同一時間 `node tools/nav_stale.cjs`：ports.js、net.js、**graph.js 都沒過期** ⇒ 這一次其實不用重烘 graph；問題是「需要重烘的時候烘不出來」。

**讀數二**（main a405097d 的提交訊息，指紋改版那一次，不是 trailhead 量的）：「graph.js 逐字相同（**nav_bake 這一次在記憶體不足時中斷**，graph.js 不在這次的輸入裡，nav_stale 沒過期）」⇒ main 上也撞過一次，不是 TASK-1246 的新海岸才有。

**重現**：Blocksail main（或任一 worktree，先從共用區抄 navdeep.bin、navmesh.bin、_cache/navmesh_tiles.json），`NODE_PATH=<codex runtime>/node_modules node tools/nav_bake.cjs`，看 WorkingSet 與時間。

### 💬 #2 trailhead 2026-11-14T08:17:42.342Z
**判定（驗收第 1 格的原因）**：`tools/nav_bake.cjs` 的退路包裝 `BSW.route = async (world, from, to) => { const direct = await route(world, from, to); … }` **把第四個參數 opt 丟掉了**（319d59b5，2026-11-11 士麥那那次加的）。
world/route.js 自己會在裡面再叫 `BSW.route`：磨角修穿陸帶 `{ raw: true, pad: 0.6 }`（polish）、兩頭接回帶 `{ untie: true }`（tieEnds）。內層呼叫也經過這層包裝 ⇒ opt 不見 ⇒ 每一次都變回完整的 route（又 polish、又 tieEnds、再往下叫）⇒ 非同步遞迴不會堆疊溢位，不報錯、不印東西，一直配置格子 ⇒ 記憶體吃光。時間跟 main a405097d「nav_bake 在記憶體不足時中斷」對得上。

**憑據**（都在 TASK-1246 的 worktree bsl-coast、新岸的世界，`--check` 不寫檔）：
- 照原樣抄一份 nav_bake，只加「每一對開始／結束同步寫一行」⇒ 第 135 對 **town-basseterre（聖克里斯多福）⇒ town-lisbon** 開始時 rss 1.3 GB，跑到第 832 秒私有記憶體過 12 GB 被外部守門砍掉。
- 原樣的 nav_bake（只掛每分鐘記記憶體的預載）：第 428 秒之後一行都沒有（event loop 卡死），工作集 27 GB、私有 36.5 GB ⇒ 照 PID 砍。
- 同一份副本只改一處 —— opt 傳下去、有 opt 的內層呼叫直接回傳（不走退路）⇒ 第 135 對 **2.2 秒**；整份 **2,126 秒**跑完（navBuild 33 港、直航 467、拆 61，2,064 秒），每一對開始時的 rss 最高 **1,412 MB**。
- 探針一直重現不了，是因為本小姐重抄退路時順手把 opt 傳下去了（main 舊岸 53 分鐘／1.4 GB、新岸 50 分鐘／1.3 GB）。

**一行修正**（還沒提交；這一單的方向是 Tim 2026-11-14「烘焙導航網後 根據導航網尋路生成航線」，所以第 2 格照舊要做）：
```js
BSW.route = async (world, from, to, opt) => {
  const direct = await route(world, from, to, opt);
  if (opt) return direct;   // route.js 自己的內層呼叫（raw、untie）照原樣回
  …
```
