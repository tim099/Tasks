### 💬 #2 trailhead 2026-11-14T08:17:42.342Z
**判定（驗收第 1 格的原因）**：`tools/nav_bake.cjs` 的退路包裝 `BSW.route = async (world, from, to) => { const direct = await route(world, from, to); … }` **把第四個參數 opt 丟掉了**（319d59b5，2026-11-11 士麥那那次加的）。
world/route.js 自己會在裡面再叫 `BSW.route`：磨角修穿陸帶 `{ raw: true, pad: 0.6 }`（polish）、兩頭接回帶 `{ untie: true }`（tieEnds）。內層呼叫也經過這層包裝 ⇒ opt 不見 ⇒ 每一次都變回完整的 route（又 polish、又 tieEnds、再往下叫）⇒ 非同步遞迴不會堆疊溢位，不報錯、不印東西，一直配置格子 ⇒ 記憶體吃光。時間跟 main a405097d「nav_bake 在記憶體不足時中斷」對得上。

**憑據**（都在 TASK-1246 的 worktree bsl-coast、新岸的世界，`--check` 不寫檔）：
- 照原樣抄一份 nav_bake，只加「每一對開始／結束同步寫一行」⇒ 第 135 對 **town-basseterre（聖克里斯多福）⇒ town-lisbon** 開始時 rss 1.3 GB，跑到第 832 秒私有記憶體過 12 GB 被外部守門砍掉。
- 原樣的 nav_bake（只掛每分鐘記記憶體的預載）：第 428 秒之後一行都沒有（event loop 卡死），工作集 27 GB、私有 36.5 GB ⇒ 照 PID 砍。

- 探針一直重現不了，是因為本小姐重抄退路時順手把 opt 傳下去了（main 舊岸 53 分鐘／1.4 GB、新岸 50 分鐘／1.3 GB）。

**一行修正**（還沒提交；這一單的方向是 Tim 2026-11-14「烘焙導航網後 根據導航網尋路生成航線」，所以第 2 格照舊要做）：
