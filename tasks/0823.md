# TASK-0823 — 《Blocksail》城鎮模型預先網格化：開伺服器時烘成網格存在本地（不進 git、打包帶上），Blockside 收到就不再網格化

> `improvement` / `normal` / `in_progress`　開單：kaguya　參與：kaguya(dev)

## 驗收標準

- [ ] 烘網格：world/townkit/ 每個模型（近、中兩份）照 Blockside 同一支網格化（VoxelKit meshChunk，照 63_towns.js townMesh 的接法）預先做成網格，壓縮二進位存 world/townmesh/（不進 git）；每份記指紋（模型格子的雜湊、voxelkit.js 指紋、格式版本）
- [ ] 開地球儀的伺服器（globe.sh／menu.sh）時跟城鎮規劃一起在背景烘：只烘過期、還沒烘的；不擋伺服器啟動
- [ ] Blockside 收到烘好的網格且指紋對得上（voxelkit.js 指紋＝自己成品裡記的、格式版本相同）⇒ 解壓直接上傳，不再網格化；沒有、對不上、解不開 ⇒ 照舊現場算
- [ ] 反向對照：烘好的網格跟瀏覽器裡現場算的逐位元組相同（全部模型）；模型或 voxelkit.js 換了 ⇒ 指紋對不上 ⇒ 現場算（負對照）
- [ ] 量測：有畫面的 Chrome，君士坦丁堡第二次去、全新設定檔各量，模型組好（kitMs）與城出現的秒數改前改後並列；頁面錯誤 0
- [ ] 文件：TOWN_TOOLS（烘網格、怎麼清）、PACKAGING（打包帶 world/townmesh/）、Blockside MAP_CHUNK 或 63_towns.js 檔頭（收網格的格式與退路）

## 任務描述

Tim 2026-10-22：「模型解成網格那段 是房屋模型嗎 是否一樣可以預處理緩存在本地(之後打包時要包處理過的版本)」「照預處理做 開單全包GO」

背景（TASK-0819 留言 #5）：君士坦丁堡第二次去，城鎮模型組（27 個）在 iframe 裡解成網格要 3～10 s 牆鐘，CPU 只有約 0.8 s（meshChunk 佔 95%），其餘是跟飛行鏡頭、收海圖塊搶主執行緒。

量過的代價（node 跑同一支 meshChunk，67 個模型近＋中）：格子 1.3 MB（base64）⇒ 網格 41.7 MB、deflate 11.3 MB；全部網格化 2.6 s。最大的聖索菲亞 deflate 1.25 MB。⇒ 拿空間換時間，打包多約 11 MB（Tim 同意走這條）。

做法：
- Blocksail tools/ 一支烘網格（node 載 external/Blockside/VoxelKit/voxelkit.js），globe.sh 背景烘時一起跑；存 world/townmesh/<名>.bin ＋ 指紋清單。
- mapgen townmodels 回模型時，烘好的且模型格子雜湊對得上 ⇒ 附上網格。
- Blockside townKit：網格指紋對得上 ⇒ 不網格化，解壓直接上傳；否則照舊。
