# TASK-0834 — 《Blockside》開船時的砲口與蓋板照船型快取（同型每艘不再各算一次；portsFloodInit 佔開一艘約 45%）

> `improvement` / `normal` / `in_progress`　開單：basecamp　參與：basecamp(dev)

## 驗收標準

- [ ] 砲口（25_doors.js portHole）照船型快取：同一型、同一個砲口格、同一舷只算一次
- [ ] 開船時建的蓋板（portsFloodInit → 62_ports.js）：同一型第一艘照舊算，幾何（鉸鏈、軸、方向、house、ring、掀蓋順序）存在船型上；之後每艘只造自己的狀態、幾何拿副本。戰鬥中途懶建那條路（portsAnim、開局分段 flowWarmSteps）不動
- [ ] 一致：快取造出來的每一片跟照舊算的那一份逐欄相同（同型多艘、有蓋板與沒蓋板的船型各量一次）
- [ ] 對拍：戰局跟改之前逐步相同（有蓋板的同型對同型、不同型各一組）
- [ ] 讀數：8 艘同型開船，每艘的時間改之前／改之後並排（機器忙的時候只看比例，寫明）

## 任務描述

Tim 2026-10-22：「同一型船的船體網格與房間 好像有機會出現重複解析」→（量了）「這部分是否能直接做一份複製」→「開單做砲口與蓋板照船型快取 GO」

量過（dev 652b39b，headless，8 艘同型憲法號、型別快取熱的時候；機器忙，只看比例）：
- 船型層（解碼、船殼網格、平滑、裝甲網格、水的房間）同型只算 1 次 —— 沒有重複解析。
- 開一艘約 275–300 ms，其中 portsFloodInit（TASK-0822 砲口進水）約 131 ms（45%）：portsBuild 每艘建一份蓋板約 90–105 ms、portHole 每門砲找砲口 54 次約 41 ms。兩樣結果只看船型與開局那一刻的砲位 ⇒ 同型每艘都一樣。
- 房間擺家具＋進水格＋走路格加起來 < 2%；繩的固定檢查約 33%（另外量，不在這張）。
⚠ 程式是 calli 的 TASK-0822（還開著）：動之前在酒館講範圍。
