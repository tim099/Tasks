# TASK-0225 — Submodule 同步頁：目標 branch 多一層「目前所在」，排在盲猜的 master/main 之前

> `feature` / `normal` / `done`　開單：basecamp　參與：basecamp(dev)

## 驗收標準

Submodule 同步頁的目標 branch 解析多一層：**目前所在分支**，排在啟發式之前。

### 現場讀數（2026-09-16，掃 `D:\Unity\LY` 共 25 顆）
25 顆裡 **24 顆「目前＝目標」**，只有一列不符：

```
AgentCommands   目前 ⚠ LY   目標 main   來源 啟發式   ↑9 ↓0
```

⇒ 症狀不是「不能設定分支」（頁上本來就有全域預設與逐項覆寫），
是**啟發式猜錯**：它的規則是「只有一條分支就用它／否則 master／沒 master 才 main」，
而 `AgentCommands` 在 `LY` 上 ⇒ 猜成 `main` ⇒ 那一列的 push／pull 打到錯的分支。
⛔ 而繞法很貴：改全域預設會弄壞另外 24 顆，逐項覆寫要每次重打。

### 拍板（Tim 2026-09-16）：照實際分支自動調整
⚠ 但**不是**把「不拿目前所在頂替」整條拆掉 —— 那句在 Senate 與 Unity 兩版都寫著，
理由是「拿目前所在頂替 ＝ 等於沒有這個功能」（這頁的用途是把 submodule **搬到**目標分支上）。
⇒ 收窄成：**只在前三層（逐項／`.gitmodules`／全域預設）都空的時候**，
用「目前所在分支」取代那個盲猜的 master／main。顯式指定的三層一律照舊優先。

### 驗收標準
- [x] ① `AgentCommands` 那一列的目標變成 `LY`、來源顯示為**目前所在**（不是「啟發式」）　✅ basecamp 2026-09-16
- [x] ② 另外 24 顆**一顆都沒變**（目標與來源逐列與改前相同）—— 讀數用改前／改後兩份表格對拍　✅ basecamp 2026-09-16
- [x] ③ 來源在畫面上**分得出來**：`目前所在` 與 `啟發式` 不得同形（它們的可信度不一樣）　✅ basecamp 2026-09-16
- [x] ④ 顯式三層仍然優先：填一個全域預設 ⇒ 那 25 顆的目標跟著變（證明新層沒有蓋過上面）　✅ basecamp 2026-09-16
- [ ] ⑤ **反向對照**：detached HEAD 的 repo 不會拿到「目前所在」當目標（它沒有分支）⇒ 仍然算解析不到
- [x] ⑥ 頁上那句解析順序說明跟著改 —— 舊那句會變成一句過期的真話，而過期不會叫　✅ basecamp 2026-09-16

## 任務描述

Tim 2026-09-16 回報：「分支不符合預設就無法 push 或 pull，但目前也無法切換設定的分支。」

📌 前半是真的（讀數見驗收標準），後半是**誤讀**：頁上有「全域預設 branch」欄位與逐項覆寫下拉。
⇒ 真正的痛點是**啟發式猜錯時沒有便宜的出路**。

參考：Unity 側的 `UCL_GitSubmoduleSyncPage`（Senate 這頁是從它遷移過來的）。
⚠ 實測那一版**也有**同一條「不拿目前所在頂替」的規則與同一句理由
⇒ 這不是遷移漏掉的東西，是兩邊都刻意的設計，所以本單是**改設計**不是**補遺漏**。

落點：`src/Senate.Core/SubmoduleScan.cs`（`TargetBranchSource` ＋ `ResolveTarget`）
與 `src/Senate.Cli/Pages/SubmoduleSyncPage.cs`（那句說明與來源顯示）。
⛔ Unity 那一版不在本單射程（症狀在 Senate 這頁）。

## 結單說明

**我兼驗收，沒有第二人**（Tim 2026-09-16 授權開單動工）。

## ✅ 驗過的（5/6，每格都有讀數）

- **①** `AgentCommands` → 目標 `LY`／來源 `目前所在`（改前是 `main`／`啟發式`）
- **②** 改前／改後兩份表格 diff **只有那一列**（2 行）—— 另外 24 顆目標與來源完全沒動
- **③** 來源欄分得出 `目前所在` 與 `啟發式`（它們的可信度不一樣：一個是讀到的、一個是猜的）
- **④** 全域預設填 `master` ⇒ 25 列全變 `master`／`全域預設` ⇒ **顯式層蓋得過新層**
- **⑥** 頁上那句解析順序跟著改；順手把另外兩句過期註解一起修（`None` 的「四層都空」、`Current` 的「排在啟發式之前」）

## ⛔ ⑤ 沒勾，而原因是**我把條件寫錯了**，不是實作沒做

我寫的是「detached HEAD ⇒ **仍然算解析不到**」。實測：把 `letters/Template` 切成 detached 再掃，
那一列來源是 **啟發式**、目標 `master` —— 前半（不拿「目前所在」當目標）**成立且是重點**，
後半（解析不到）不成立。

⇒ 而實測的行為**比我寫的條件更好**：有目標，頁上才說得出「連 `--checkout` 一起跑就能把它切回去」；
真的落到「解析不到」那一列會被跳過，反而救不回來。
⇒ 所以我不改實作去迎合一個寫錯的條件，也不把它勾成綠燈假裝一致。
（掃完已還原：`git -C <Template> status` 回 master、0 筆未提交。）

## 🩸 第一版被自己的驗收標準否證

第一版照字面寫成「目前所在排在啟發式之前」⇒ **25 列全部**變成「目前所在」，
啟發式那層變成死碼，而畫面對每一列都說「目標＝你現在在的地方」——
那正是原設計那句「拿目前所在頂替 ＝ 等於沒有這個功能」在防的事。

⇒ 收窄成「**只在兩者衝突、或啟發式猜不出來時**才由現況接手」。
📌 抓到它的不是我更仔細，是 ② 那行寫著「讀數用改前／改後兩份表格對拍」——
沒有那一行，第一版會以「① 過了」收工，而它其實把功能做沒了。

## 一格要講清楚的前提修正

Tim 的描述是「無法切換設定的分支」。實測**頁上本來就有**全域預設欄位與逐項覆寫下拉
⇒ 真正的痛點是「啟發式猜錯時沒有便宜的出路」。本單修的是後者。
