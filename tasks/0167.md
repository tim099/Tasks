# TASK-0167 — 出廠驗收第 ④ 關（Server round-trip）不穩定：同一顆 binary 一次紅一次綠，而紅的那次 ping log 是空的

> `bug` / `annoying` / `normal` / `todo`　開單：summit　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

① 先量成因（⛔ 不准先改）：失敗時 `build_ping.log` 空檔 ⇒ 要知道是「ping 沒被啟動」「ping 啟動了但輸出沒被導進檔」還是「ping 真的失敗而 exit code 沒被讀」。
② 修法要讓失敗**帶得出理由**：這一關現在的紅燈只說「失敗，去看那兩個 log」，而其中一個是空的 ⇒ 空 log 不是理由。
③ 若成因是等待條件（server 尚未 ready 就 ping）：等待要**等一個讀數**（心跳檔 mtime／server_state），不是等一個秒數。
④ 活體：連跑 5 次同一關全綠（或能重現失敗並在 log 裡看到理由）。

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

2026-09-07 21:22-21:24，**同一顆 binary**（`build=546be48.20260907T132226Z`）連跑兩次第 ④ 關：

| 次 | 結果 | 讀數 |
|---|---|---|
| 第一次（`./check.sh` 四關全跑） | ✗ 失敗 | `build/build_server.log` 顯示 server **正常啟動**（`pid=30672`、新 build id、心跳與執行器路徑都印了）；而 `build/build_ping.log` **是空檔**（零位元組、無任何一行輸出） |
| 第二次（`./check.sh --gates server`） | ✓ 通過 | `server_pid=40744`／`echo=check`／`server_build=546be48.20260907T132226Z`／`exit_code=0` |

⇒ 同一顆 exe、同一台機器、相差 90 秒，一次紅一次綠 ⇒ **這一關不是決定性的**。

## 已知與未知（分開寫）

- **已知**：失敗那次的失效樣子是「server 起得來，而 ping 一個字都沒印」。
- **未知**：是 `check.sh` 等 server ready 的等待條件不足、ping 自己失敗而輸出被吞、
  還是別的。**我沒有量**，所以不宣告成因。

## 為什麼值得一張單

出廠驗收的關卡**偶爾紅一次**，代價不是那次失敗，是它**訓練人忽略關卡** ——
下一個看到紅燈的人第一反應會是「再跑一次就好」，而那正是關卡失去效力的方式。
（同族判準我今天在 A1 上寫過：做不到時還是會被違反的硬規則，比沒有更糟。）
