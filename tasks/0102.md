# TASK-0102 — senate server start/stop/status：自我登記、build id 握手、build 前先停

> `feature` / `high` / `in_review`　開單：basecamp　參與：basecamp(dev)、summit(qa)

## 驗收標準

Server process 生命週期：`senate server start|stop|status`，手動啟動（Tim ⑦），不自動 spawn。
- [ ] start：以 tag `senate_server` 自我登記進 SCP_ProcessRegistry；已有 Alive 的同 tag 就拒絕第二顆並印出 pid
- [ ] status：走 Validate 三重身分，不只看 pid 檔存不存在；印 pid／start time／build id
      ⤷ 「PID 易主」那條分支**本單不驗**，理由：要 OS 回收再發同一個 pid，QA 造不出活體。分類邏輯改由 **TASK-0101 的 selftest 四態格**覆蓋（2026-09-04 起 29／29 有這格）
- [ ] stop：只對 Alive 下手，PidReused/Unknown 拒絕並說原因
      ⤷ 同上：拒絕分支**本單不驗**（造不出活體）
- [ ] 握手帶 build id（exe 的 assembly informational version 或 mtime hash）；CLI 與 Server 不符時 CLI 印「Server 是舊版，先 stop 再 start」並 exit 3，不照跑
      ⤷ **本單不驗**，理由：要一顆舊 build 的 Server，而重 build 會覆寫別人正在用的 `publish/senate.exe`（QA 判「不動別人的工作區」，PM 同意）
- [ ] build.sh / build.ps1 在 publish 前偵測 Alive 的 Server，印一行並停它（否則 exe 被鎖，D10 血證）
      ⤷ **2026-09-04 有活體讀數**（basecamp 跑 build.sh）：Server 沒在跑時印「· 沒有 Server 在跑（沒有東西要停）」；⚠ 「有 Server 在跑時真的停掉它」那半仍未驗
- [ ] 心跳檔：Server 活著時每 0.5 秒摸一次 `SenateData/runtime/_server_heartbeat.json`（**不是 `.txt`**）；內容結構化：`pid` / `build_id` / `started_at_utc` / `beat_at_utc` / `schema_version`
      ⤷ 2026-09-04 條文修正（QA 留言 #4）：原條文寫 `.txt` 對應 Editor 的 `_heartbeat.txt`，而 status 要印 build 與 started，純文字檔給不了 ⇒ **實作對、條文錯**。錯的那一份是給下一個人看的，所以改條文
- [ ] Ctrl+C 那條路：**要真人在一個互動終端機按一次**（QA 的 shell 非互動、stdin 接 null ⇒ 按不到）。這格是本單唯一還等人的讀數

妳寫「⚠『有 Server 在跑時真的停掉它』那半仍未驗」。我為了驗 TASK-0103 起了一顆，順手把它取了：

```
$ senate server status          → ● Server 在跑　pid=51688　🔢 server_state = running
$ senate server stop
  · 已送出停止請求 → pid=51688，等最多 5 秒…
  ✓ Server 已自行退出（pid=51688，**206 ms**）      ← 自行退出，不是被 kill
$ senate server status          → ・Server 沒在跑　🔢 server_state = **not_running**
```

⭐ 三格分開：**送出請求** → **它自行退出（206ms，在 5 秒寬限內）** → **回讀確認**。
⚠ 判準是最後那次 `status`，不是 stop 印的那句「已自行退出」——
「我送出了停止請求」與「它真的停了」是兩件事，而前者永遠會成功。
