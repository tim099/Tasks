## 操作流程提案

城鎮內的酒館入口 → 酒館招募畫面 → 查看人物卡（職務、人物故事、技能、雇用金與薪資）→ 確認招募 → 進入船隊待命名冊 → 船隊編輯畫面選船／職位槽 → 預覽效果與成本 → 套用。另保留從船隊直接進配置的入口。

第一版建議先處理玩家船隊；AI商船、各城鎮與家族船隊的人事安排另外討論，避免把具名角色同時放到多艘背景船上。沿用一般水手人數與艙內工作分配；特殊人物卡是任職與加成層，不拿22張卡代替整艘船的普通船員。

## 船隊卡片編輯介面

- 桌面：左側船隻列表，中間按職位分組的槽位，右側待命船員／角色詳情；下方顯示本船生效技能、加成來源、薪資和套用／取消。
- 手機：船隻切換 → 槽位清單 → 點空槽選人／點已任職角色更換；拖放為可選輔助，所有操作可用點選完成。
- 草稿與實際配置分開，套用前看到變更及費用；取消不扣款、不改任職。招募扣款與所有權異動應為同一筆可驗證交易，重複點擊不重複收費。
- 每角色同時間只能屬於一艘船的一個槽；交換要移動原有任職，不複製卡片。只能放入相容職務；不相容時說明原因。
- 待討論槽位：船長、大副、航海士、砲術長、水手長、軍需官、船醫、船匠、帆匠、廚師，共10種。方案A：各船固定10槽、每職位1人；方案B：船型定義不同職位／槽數。已向Tim提出此選擇，答覆前不視為定案。
- 提案：第一版空槽保持既有基準性能，有人任職才生效；避免舊存檔或新手因沒招滿人而無法出航。港內可配置；航行中調任、遠距跨船傳送是否允許需拍板。

## 人物與技能資料提案

每角色有穩定ID、姓名、職務相容清單、原作者／資產路徑、故事、招募費、日薪、技能ID；每艘船以船隻實例ID保存槽位對應角色ID。所有權、待命／任職、出現中的招募候選分開；不得靠顯示名稱或船型作唯一識別。

第一版建議每人「1個職務被動＋1個個性特長」，先不加需要戰鬥施放的主動技。技能效果須定義目標指標、適用範圍、條件、同類群組、加算／乘算、上限及失效時機；卡片顯示生效與未生效原因。預設只作用於任職船；艦隊範圍加成須特別標示且有防重複規則。數值待平衡，不先寫死百分比。

| 職位 | 可討論效果方向（非已實作技能） |
|---|---|
| 船長 | 指揮、士氣或特定航況的操船表現 |
| 大副 | 任務協調、換班或工作效率 |
| 航海士 | 航線／近岸航行；不憑空提供引擎沒有的航速加成 |
| 砲術長 | 砲班操作與射擊穩定，接實際存在的戰鬥計算 |
| 水手長 | 索具作業、升降帆與疲勞管理 |
| 軍需官 | 補給管理；不得以buff直接創造貨物或錢 |
| 船醫 | 治療／傷員恢復，需有既有系統落點 |
| 船匠 | 損管／木構修補，保留工具與材料消耗 |
| 帆匠 | 帆面修補與作業效果 |
| 廚師 | 船餐製作、士氣或食材利用，接船餐與實際物資帳 |

同類效果建議「同船同群取最高」起步，異類效果按固定順序計算並設上限；是否需要疊加由各效果定義，不用一個全域規則硬套所有技能。角色故事中的弱點不自動變成懲罰數值。

## 酒館背景美術需求（待另行繪製）
