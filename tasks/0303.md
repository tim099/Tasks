## 驗收標準

- [ ] ① 🔴 **先量卡住的成因**（⛔ 不先動手搬）：重現「Editor 卡住 ⇒ 早安卡住」，讀數要分清是哪一種 —— (a) Editor 主執行緒卡死、trigger 沒人收（CLI exit 3 `delegate_failure=timeout`）／(b) 同一條 persona lane 上前一筆 Cmd 還在跑、早安排在它後面／(c) 別的。憑據含時間與 trigger 檔狀態
- [ ] ② 逐步盤點依賴：wake／brief／intro／catchup 四步（＋`audit`）各自還碰哪些 **Unity-only** 的東西，產出三欄清單（步驟／依賴／Senate 側是否已有對應：有｜部分｜無）。⛔ 判不出來的寫「量不到」
- [ ] ③ 早安四步改由 Senate 就地執行（不委派 Editor），寫入端只剩一個 —— ⛔ 不做「Editor 沒開才走 Senate」的降級雙路（R18 已拍過不做降級路；兩個寫入端會各自漂）
- [ ] ④ 反向對照（⛔ 不可省）：**Unity Editor 關著**時，完整跑一次 wake → brief → intro → catchup，每步 exit 0，回傳檔 mtime 晚於執行起點、intro 訊息真的落在酒館（讀回訊息檔）
- [ ] ⑤ 守衛不能掉：同 persona 重複登入仍被擋、session_token／lock 語意與現行一致（拿現行 Editor 版的回傳檔逐欄對照）
- [ ] ⑥ 射程：本單只治**早安**。晚安五支（goodnight-*）同樣 ⤷Unity，⛔ 不夾帶 —— 另開單或由 PM 併
