## 驗收標準

- [ ] 巢狀：外層關聯的替換套在內層換完的色上（整棵子樹）

- [ ] 淨室測試：互換不連鎖、0 被擋、表外色不動、巢狀順序、舊 schema 擋下（反向對照）；selftest 全過

## 任務描述

Tim 2026-10-14：「我在想是否可以加一個新機制 雕刻作品在引用子作品時 可以指定一些替換色 把指定色替換掉 就可以達到複用效果」「因為目前在優化遊戲素材 希望能做到節省空間」「壓縮功能 ame 已經做了 先開單就好」。

現況（summit 讀碼＋量的，2026-10-14 晚）：
- 關聯：組裝只有一處把子作品的格子放進父作品 —— SCP_SculptLinks.cs SCP_SculptLinkComposer.Place（逐格 翻面 → 轉向 → 平移 → Set(color)）。觀測、匯出 list／obj／vxk 都吃這份組好的空間。
- 匯出 vxk 時關聯是**展開成格子**的（不是引用）。
- 外部模型在 vxk 裡是「網格存一份、擺放記用哪份」；去重的鍵 ＝ 擺好之後的頂點＋材質色 ⇒ 換了色（或轉了向）就再存一份。
  量（_cache 的 vxk，未壓縮的檔頭）：憲法號 215 個模型 → 56 份網格、網格 5.0 MB；三叉戟號 523 → 68、4.6 MB；風暴角號 74 → 24。
- 格子在 vxk 裡壓縮後只佔 1–2 成（風暴角號 96／596 KB、憲法號 175／1,624 KB）⇒ 只在關聯上換色，省的是雕刻庫，不是遊戲檔。
- 壓縮 ame 已經做了（Tim 說）——本單不重做壓縮。

summit 的設計提議（動工前可以再改）：
1. 關聯 `work sub=link … recolor=原色:新色,…`：套用到那條關聯底下的整棵子樹（巢狀：外層看到內層換完的色）；同時換、不連鎖（218:213,213:218 ＝ 互換）；新色不准 0（3D 的 0 ＝ 空）；表外的色不動。
2. 外部模型同樣的 `recolor`：做成**每個擺放的材質覆寫** —— vxk 裡網格照舊共用、擺放上多一份替換表，遊戲畫的時候換色 ⇒ 換色的副本不再多存一份網格。（⚠ 會動 vxk 格式 ⇒ ame 的讀取器要跟著改）
3. links.json／models.json 用到 recolor 就升 schema（同當初 mirror：沒更新的 exe 讀到新欄位會默默丟掉 ⇒ 換色悄悄失效、畫出原色）。
4. 繩、帆、帆的貼圖不在範圍內。

第一個真實樣本：岩堡港（TASK-0580）的樓房 A2、A3 改成 A1＋替換色。
