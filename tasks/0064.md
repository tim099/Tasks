# TASK-0064 — 收工自動匯出：無章名也要出書（##None## 哨兵）＋補名路徑不是手改 txt

> `feature` / `normal` / `todo`　開單：basecamp　參與：summit(qa)

## 驗收標準

- [ ] `prepare` 不填 `chapter_title` ⇒ 收工**真的產出**章檔（實跑一場，不是讀 code 推論）
- [ ] 該章章名為哨兵值，且回傳檔印 ⚠ 與**補名指令原文**（可直接複製執行）
- [ ] 有一條查法能列出「仍掛哨兵的章」，且對已補名的章不再列出
- [ ] 哨兵值來自後台設定（改設定即改字串），不是寫死在 code
- [ ] 用 (a)(b) 兩條補名路徑各跑一次 ⇒ 章名正確、`exported_chapter` 台帳回填不重複、不產生第二章
- [ ] 直接手改 `.txt` 章名 → 重出後被覆寫（**這格要實測並寫進文件**，證明「手動替換」不可行）

## 任務描述

## 需求（Tim 2026-08-26）
> 「自動匯出書籍流程，假如沒有章節名的話，一樣自動匯出，不過章節名可以標記為 `##None##`，
> 之後要補章節名再手動替換就好（也可以用別的字串，`##None##` 只是做示範）。」

## 現況與為什麼要改
`prepare` 的 `chapter_title` 為空 ⇒ **收工不自動匯出**（skill 明寫「沒填章名就不會自動跑，那不是故障 ——
章名不給工具代取」）。
🩸 今晚 ep10 就是這樣：四場全部收工、48 則觀察都在河道上，而**書一章都沒有**，
要我事後手動補跑 `export-watch` 才生出 `Books/watch-apocalypse-hotel/010.txt`。

⇒ 現況的失敗模式是「**整本書不存在**」，而它跟「**這一話沒人看**」在產物上**完全同形** ——
沒有任何一層會喊。相對地，「書存在但章名是 `##None##`」是**看得見的缺**。
📌 而它**沒有違反**原本那條原則：工具仍然沒有代取章名，它只是把「還沒有名字」寫成一個明確的記號。

## 要做的
1. 收工自動匯出：`chapter_title` 空 ⇒ **照樣匯出**，章名用哨兵值（預設 `##None##`，後台可配）。
2. 哨兵值必須**可查**：
   - 匯出當下回傳檔／收播回傳檔印 ⚠「本章章名未定（`##None##`）—— 補名方式見下」
   - 提供一個查法列出「仍掛著哨兵的章」（`library.py` 加一個 list/lint，或既有列表把它標出來）
   ⚠ 沒有這格就會變成：書有了、名字永遠是 `##None##`，而**沒有人會發現** —— 那是把一種靜默換成另一種。
3. 哨兵值的選字要求：**不可能是任何人真的會打的章名**（`##None##` 合格），
   且不得與匯出表頭用到的 markdown／regex 衝突。

## ⚠ 一格要更正 Tim 的措辭：**不能「手動替換」章名**
`010.txt` 的表頭自己就印著「機械匯出 …… **手改會被下次匯出覆寫**；要改內容請改酒館訊息本身」。
⇒ 直接編輯 `.txt` 裡的章名，會在下一次重出時**安靜消失**。
正確補名路徑只有兩條：
- (a) 改 `prepared/<media_id>.json` 的 `chapter_title`，再 `--force` 重出；或
- (b) 直接 `export-watch --force --title "<真章名>"` 重出。
⇒ 本單要同時把**補名路徑寫進回傳檔的提示裡**（而不是只印「請手動替換」）。
📌 反正 TASK-0061（段序重排）落地後這些章本來就要重出一次，補名可以搭同一趟。
