# TASK-1282 — 《Blocksail》城鎮規劃的物種指紋只算規劃真的讀的適地（改樹、動物、魚不再讓規劃過期）

> `improvement` / `normal` / `todo`　開單：Abigail　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 規劃讀的適地照程式查清楚、列成一張表（道路評分、開場農莊、手擺地塊、生產地塊的配方各讀哪幾種），寫在 TOWN_BUILD
- [ ] `'#species'`、取樣、`#areatables` 的 SUITS 只算那幾種；`--restamp` 42 份 plan／dep 逐份相同、`--check` 0、`--verify` 全同
- [ ] 對照（各改一處數 `--check`）：硬木樹、桅材樹、獵物、魚的 env／regions ⇒ 0 份；改哈瓦那附近長的作物（甘蔗、木薯）⇒ 照舊過期（反向）
- [ ] 遊戲執行時「能種什麼」照舊（`land_start.cjs` 檢查過；地球儀進城、建築模式試放一座硬木伐木場與一座農莊）

## 任務描述

Tim 2026-11-13：「接下來希望分析一下目前城鎮烘焙 & 指紋機制 為何修改植物會讓城鎮指紋改變」「應該說物種會如何影響城鎮(如果會影響 應該也不用整個重新烘焙? 只要更新物種相關部分)」⇒ 分析後選「A＋B 一起開」。本單是 A；B（規劃拆成骨架層／農莊層）另一張。

## 現況（Blocksail main 72243911 讀的、量的）
- 規劃不直接讀物種表，經過適地（`BSW.SUITS`）：取樣（`town_sample.js`）每 64 m 一點算 `suitAt` 的位元圖（全部 34 種適地）⇒ 規劃讀它的地方：
  ④ 主要道路挑終點的分數（`town.js` `FARM` 六種：sugar、tobacco、cocoa、indigo、cotton、pasture）、⑬ 開場農莊（`annex.js` `FARM_CROPS` 的作物，每一種長得了的一座＋田）、
  手擺地塊 `use: 'plot'` 記 `o.suit`（全部適地）、生產地塊的配方（`prodPlan` ⇒ `prodRecipesAt` ⇒ `prodSite`）。
- 指紋 `'#species'`（`town_store.js` `townSpeciesText`）算「適地表會看的物種」⇒ 131 種裡 85 種（全部作物＋帶 hardwood、mast、game、fish tag 的）；
  取樣的程式指紋還有 `species.js`、`#areatables`（SUITS 的 realm／env／species／tag）。
- 實測（哈瓦那，每次只改一處、重烘、逐段比）：桃花心木（hardwood）不長古巴、菸草 hMax 500 ⇒ 150 ⇒ **指紋換了、規劃逐位元組相同**（假過期）；
  木薯不長古巴 ⇒ 道路不變、開場農莊重排（地塊 −28／+39、搬 60）；甘蔗不長古巴 ⇒ 道路不變、農莊重排（搬 86、−1）。

## 要做的
收窄規劃的物種指紋到「規劃真的讀的適地」：
- 規劃讀的適地 ＝ `FARM` ∪ `FARM_CROPS` 的作物對到的適地 ∪ 那座城手擺地塊寫的 `use`（適地表的）∪ 生產地塊挑配方會看的（查 `prodRecipesAt` 讀哪幾種）—— 照程式查、列成一張表（`BSW.PLAN_SUITS` 之類），⛔ 不憑印象。
- 取樣的位元圖只算那幾種（或規劃讀圖時只看那幾位）；手擺 plot 的 `o.suit` 只記那幾種（遊戲執行時讀的「能種什麼」是開場檔的 `land`，`land_start.cjs --crops 1` 另外刷，不讀 `o.suit` —— 動之前查清楚有沒有人讀）。
- `'#species'` 只算那幾種適地點名的物種、帶那幾種 tag 的；`#areatables` 的 SUITS 只算那幾種。
- 換算法那一次 `town_bake --restamp`（照 TASK-1274 的做法）：舊算法對得上的只換指紋、規劃一個位元組都不變。
