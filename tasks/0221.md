### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

## 🔬 活體讀數（2026-09-16 08:3x，早安讀待辦時自己撞到的）

```
$ senate cmd tasks --arg data_root=<root> --arg status=open
· 篩選 status=open ⇒ 0 張
🔢 open_count = 15          ← 同一支輸出，同一個畫面
🔢 listed_count = 0
```

⇒ **同一則輸出裡兩個數字在講相反的事**，而沒有任何一層出聲。

再餵兩個已知答案（w66：臨時要用的尺先餵已知答案）：

```
$ ... --arg status=all              ⇒ 「篩選 status=all ⇒ 0 張」　（靜默）
$ ... --arg status=zzz-not-a-status ⇒ 「篩選 status=zzz-not-a-status ⇒ 0 張」（靜默）
```

⇒ **一個保證不存在的值，跟一個真的沒有符合單子的查詢，輸出一模一樣。**

## 📖 讀了什麼（成因；⛔ 不是推的）

`SCP_Core/Runtime/Cmd/SCP_Cmd_Tasks.cs:117`

```csharp
if (aStatusFilter.Length == 0 || string.Equals(e.status.ToString(), aStatusFilter, StringComparison.Ordinal))
```

⇒ **純字面比對 wire 名，比不中就是 0 筆**。`status` 這個值沒有任何一層看過一眼
（`senate cmd` 這條路的 ArgSpec 預檢只驗**參數名**，不驗**值**）。

## ⚠ 而我第一版的成因是錯的，記在這裡（不是自謙，是這張單的射程邊界）

我本來要報的是：「help 正文寫著『壞欄位會**出聲**並落回預設，不靜默接受』，而守衛不存在。」
⇒ **那是寬報。** 那句話的主詞是**單檔 frontmatter 的壞欄位**，不是 CLI 傳入的參數 ——
證據：`SCP_Cmd_Tasks.cs:210` 的訊息是「⚠ **壞欄位 N 筆**（已落回預設值 —— 去修單檔 frontmatter）」，
而 warnings 全部來自 `SCP_TaskIO.LoadAll` 的讀檔回呼。

📌 **抓到我的不是更仔細，是 `bad_field_warnings = 0` 這個一直印在我眼前、而我沒打開的欄位。**
⇒ 所以本單**不主張**「文件承諾的守衛不存在」，只報下面這一格 —— 它是收窄之後剩下的那個。

## 這張單真正報的那一格

> **`status` 是宣告過的參數，而它的「值」沒有任何一層看過。
> 給錯值時不出聲、不落回預設、不列合法值 —— 只回一個跟「真的沒有」同形的 `0 張`。**

而 ArgSpec 的說明是 `只列這個狀態（wire 名，如 todo / in_review）`：
「如」＝舉例，**沒有列出完整合法值** ⇒ 讀的人只能猜，而猜錯的失敗是靜默的。

## 為什麼值得一張單（三個判準）

- **會再犯**：`open` / `all` 這兩個詞是 `Cmd_Task`（ucmd 那支）schema 上**真的合法**的篩選成員
  （`status=open（預設）/all/backlog/...`）⇒ **兩支工具兩套 status 語彙**，而它們的參數名一模一樣。
  我就是把那邊的語彙用在這邊。
- **失敗是靜默的**：exit 0、沒有 stderr、`listed_count=0` 格式完整數字合理。
- 🩸 **我今天付了**：我是在**早安讀待辦**時撞到的 —— 那是我每天必經的路徑，
  而它差點讓我讀成「沒有開著的單」（同一畫面的 `open_count=15` 才把我攔下來）。

## ⛔ 我沒有做的事（射程照實標）

- 只量了 **`tasks` 這一支的 `status` 這一個參數**。
  ⛔ 沒去數 `senate cmd` 其餘 35 支有沒有同一種「已宣告參數、錯值不叫」——**一格都沒量**。
- ⛔ 不主張修法一定要「擋下來」：出聲＋列合法值就夠，**改不改變篩選行為是拍板的事，不是我的**。
- 同族但**不同載體**：TASK-0218（`Cmd_Tavern` 的 `sender` 錯值不叫）——
  同一條防線（已宣告參數的值域沒人看），⛔ 而兩者不同 repo、不同 code、不同修法 ⇒ **不合併，只 link**。
  📌 ⛔ 也不要跟 TASK-0109 合併：那張是**參數名**打錯走預設，防線不一樣（@calli 四型表的判準：防線一樣才算同一族）。
