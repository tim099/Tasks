## 任務描述

## 一句話

`UCL_AgentCommandQueue.Load` 底下那個 `Ok` / `Busy` / `Unreadable` / `Missing` 四態，
**在函式的第一行就有一條路繞過去**：

    if (!File.Exists(path)) { oState = QueueReadState.Missing; return new UCL_AgentCommandQueueData(); }

`UCL_AgentCommandQueue.cs:259`。⛔ 這一格**不拿鎖、沒有重試**，而 `File.Exists` 對**任何**失敗都回 `false`
—— 「檔案真的不存在」與「這一瞬間查不了」在它的回傳值上**同形**。

⇒ 換檔飛過去的那一瞬間，讀取端會拿到 `Missing` ＋ **空 queue**，
而 `Missing` 正是下游被教導成「檔不見了，收尾本來就該有一顆」的那個態
（`SaveMerged` 的錯誤訊息逐字這樣寫）。

🩸 而這條路是 TASK-0264 的修法**自己新引入**的鄰居：那一單花了三輪把
「讀不到 ⇒ 空」拆成四個態、把 `SaveMerged` 的判準收成 `== Ok`（列舉允許），
⛔ 而第一行那個早退沒有一起改。**修好的守衛旁邊留著一扇沒鎖的門。**

⛔ 我**沒有**判斷該怎麼修（補重試？改成 `Busy`？把 `File.Exists` 那格拿掉、
讓 `ReadAllText` 的例外去分類？）—— 那是 dev 的決定。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

同一支 .NET API（`[IO.File]::Replace`，PowerShell 5.1 / .NET Framework 4.x，Windows），
寫入端 8 秒內成功換檔 **1371 次**，讀取端**不拿鎖**、每輪同時問兩個問題：

| 讀取端看到的 | 次數 / 3333 | 比率 |
|---|---|---|
| `File.Exists()` == false | 111 | **3.33%** |
| `ReadAllText` → `FileNotFoundException`（真的不存在） | 224 | 6.72% |
| `ReadAllText` → `IOException`（開不了） | 633 | 18.99% |

**控制組**（同一支讀取端，沒有寫入端，1986 次讀）：`0 / 0 / 0` ⇒ 不是量具雜訊。
⇒ 那 3.33% 裡有一部分是「開不了」而不是「不存在」，而 `Load` 會把它們**全部**報成 `Missing`。

🩸 量這組的路上我先摔了一次，而它就是本族：第一版探針回 `missing = 0`，
而旁邊那把尺寫著 `writes = 0` —— PowerShell 把 `$null` 餵給 `File.Replace` 的 backup 參數
會變成空字串 ⇒ 每次都丟「不合法的路徑格式」。**那個 0 是合法的零：窗口沒被量到，
因為根本沒有人在換檔。** 改 `[NullString]::Value` 之後才有上面那張表。

⛔ **顯式未量（不是「驗過了」）**：
- **沒有**在 Unity 行程內複現（Mono/.NET vs .NET Framework —— 兩邊在 Windows 上都走 `ReplaceFileW`，
  但我沒有對拍過）⇒ 這格是「待對拍」，不是「已證實」。
- **沒有**量到任何一次線上真的因此讀成空 queue。我的寫入速率 ≈ 171 次/秒，遠高於線上。
  **比率會隨速率降，而窗口的存在與否不會** —— 但「線上發生過」我沒有讀數，⛔ 不宣稱。
