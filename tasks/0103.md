\### ⭐ per-lane 串行／跨 lane 並行 —— 證言來自 **Server 自己的終端機**，不是 CLI

三顆 CLI 同時送（`laneA`×1、`laneB`×2），Server stdout：
```
▶ lane 'laneA'：1 筆
▶ lane 'laneB'：1 筆            ← 兩條 lane 同時被撿走（跨 lane 並行）
  ✓ server-ping (…577284)
  ✓ server-ping (…bcd12b)
▶ lane 'laneB'：1 筆            ← laneB 第二筆隔 1 秒**另起一批**（同 lane 串行）
  ✓ server-ping (…ad5269)
· 執行器收尾：本次共跑 11 筆
```
CLI 側 `server_thread` = 10／6／7（跨 lane 不同執行緒）。
📌 我特意用 **Server 的 stdout 當主證**：那是它自己掃磁碟得到的，**不經過 CLI 的任何一行印出**。CLI 說它寫進哪條 lane，Server 說它從哪條 lane 撿到 —— 兩邊獨立對上。

\### ⭐ 「逾時不讀回傳檔」：把手是 `--arg timeout`

單上兩張都寫「沒有會慢過 120 秒的 Cmd ⇒ 這條沒實跑」。
📌 但**不需要慢的 Cmd —— 需要短的等待**。`timeout` 是 CLI 端等待秒數（`CommonSpecs()`），可以壓到 0.01：

```
senate cmd server-ping --arg echo=probe-B --arg timeout=0.01
rc=3
  ✗ Timeout after 0s — Server 接了但沒在時限內寫 result（看它的終端機）
  ⚠ 本筆未完成 ⇒ **回傳檔沒有被更新**。若下一步要讀它，先確認檔頭時間戳。
⛔ 逾時 ⇒ 本 Cmd **不去讀回傳檔**（那份是上一輪的，而它看起來正常）。
🔢 delegate_failure = timeout   🔢 exit_code = 3
```
⇒ **本格通過**，而且是實跑不是讀 code：早退發生在 `ResultLines()` 之前（`ServerDelegateCmd.cs` 逾時分支直接 return）。
（`timeout=0` 會被擋回預設並出聲 `⚠ timeout='0' 不是正數 ⇒ 用預設 120s` —— 那也是對的。）

🐛 順帶兩隻小的：
1. `Timeout: 0s` —— 我傳 `0.001` 與 `0.05`，印出來都是 `0s`（整數截斷）⇒ **我設了多少變成看不見的**。建議印原值。
2. 這條路上 0104 的錯誤報告行為有缺陷 —— **寫在 0104 那張單上**，不重複。
