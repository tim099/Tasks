# TASK-0338 — ucmd 遷移到 Senate CLI 時，Unity 端 Cmd、它的 HelpURL 與 Unity 文件同步廢棄（UCL_URL／HelpURL 機制本身保留）

> `feature` / `high` / `todo`　開單：summit　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] ① 盤點表：每支帶 `HelpURL` 的 Unity Cmd 各一列 —— Senate CLI 是否已有對應、Unity 端還在不在；已搬而 Unity 端還在的列成「待廢棄」
- [ ] ② 「待廢棄」那些：Unity 端 Cmd、它的 `HelpURL` 覆寫、它的 Unity 文件同一筆刪除，文件在 Senate 以 CLI 版本存在（照 TASK-0337 ⑤ 那條規則，本單不另寫一份規則）
- [ ] ③ 查文件的兩支 ucmd（`SearchDocs`／`ExportDocsCatalog`）照同一條搬到 Senate CLI（查 Senate `Docs/`）後，Unity 端 Cmd 刪除；skill／文件裡的 `ucmd run` 改指 Senate —— grep 零命中
- [ ] ④ 反向對照：已刪的 ucmd 被呼叫 ⇒ 明確失敗（未知指令），⛔ 不回空白成功；`UCL_URL`／`[HelpURL]` 機制與遊戲專案的說明連結照常可用
- [ ] ⑤ Unity recompile 0 errors

## 任務描述

Tim 2026-09-29：「原本 UCL_URL & HelpURL 可以廢棄（因為已經遷移到 Senate CLI）」。誰在等：Tim。
現況（2026-09-29 量）：`[HelpURL]` attribute 52 處／48 檔、Cmd 的 `HelpURL` 覆寫 48 處；`UCL_URL.` 呼叫 26 處／11 檔 —— **26 處全部是開文件用**（說明按鈕、文件搜尋、Markdown 檢視、歡迎頁、HelpUrlCheck），沒有非文件用途被牽連。
⚠ 排在 TASK-0337 之後：先有 Senate 的文件查詢，再拿掉 Editor 裡的說明按鈕，⛔ 不要中間留一段兩邊都查不到的窗口。
