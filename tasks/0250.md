## 任務描述

## 現場（2026-09-18 20:32，basecamp 實測，BTC／Bar）

```
senate cmd bank --arg op=open --arg account=template-probe-0242 \
                --arg display_name="Template 驗收探針 0242" --arg amount=7
⇒ ✓ 已開戶 `template-probe-0242`（Template 驗收探針 0242）
senate cmd bank --arg op=balance --arg account=template-probe-0242
⇒ 🔢 balance = 0
```

**`amount=7` 被靜默吃掉** —— 帳開了、錢沒發、而且**沒有任何一層出聲**。

## 成因（讀了實作，不是推的）

`Cmd_Bank.OpOpen`（`src/Senate.Core/Cmd_Bank.cs:179`）逐字只讀三個參數：
`account` / `display_name` / `caller` ⇒ **它從來沒讀過 `amount`**。

而種子那一格**只活在後台頁面**：`src/Senate.Cli/Pages/BankAdminPage.cs:571-595`
（欄位 `bank/f/seed`，二次確認後 `system_init` 憑空增發）。

## 病：**`senate cmd` 有 ArgSpec 預檢，而這一格它擋不住**

`amount` 是 `bank` 這支**合法宣告過**的參數（credit／debit／transfer 都吃它）⇒
預檢看到的是「一個宣告過的參數」，不是「這個 op 不吃它」。
⇒ **參數的合法性是 cmd 層的，而它的意義是 op 層的** —— 兩層之間沒有人把關。

📌 這跟 TASK-0109（`ucmd` 無預檢 ⇒ 未知參數靜默取預設）**是同族的下一格**：
那條講「打錯名字沒人擋」，這條講「**名字沒打錯，而這個 op 根本不看它**」。
兩者的失效樣子一模一樣：一個 ✓Success、一個合理的數字、以及一件沒有發生的事。

## 誰在等

任何一個照 Tim 2026-09-18 拍板「開戶三欄：帳號 id／顯示名／**初始金額（種子）**」
去用 CLI 開戶的人 —— 他會拿到一個餘額 0 的帳戶，而畫面說開戶成功。
今天 TASK-0242 ⑬ 的驗收就是這樣撞到的。

\### 現場（2026-09-21 09:5x，LY／Florin，kotoko 實測）

我讀完《英倫魔法師》ch6 想把期待度從 3 調到 5：

```
senate cmd library --arg op=bookmark --arg persona=kotoko \
    --arg media_id=book-jonathan-strange-mr-norrell \
    --arg anticipation=5 --arg note="（探針）"
⇒ # 🔖 書籤
⇒ - 書籤已更新（book-jonathan-strange-mr-norrell / kotoko）
⇒ 🔢 exit_code = 0
```

回讀 `reader.json`：**`anticipation` 仍然是 3**。
⇒ ✓Success、零 warning、ArgSpec 預檢一聲不吭 —— 跟妳單子上 `amount=7` 那格逐字同形。

\### 成因同構，而**觸發面更大**

- `anticipation` 是 `library` **合法宣告過**的參數 —— 它活在 `op=media_init`（建檔時填期待度）。
- `op=bookmark` 的實作只讀 `note` / `status` / `impression`，**從來沒讀過它**。
- ⇒ 妳寫的那句逐字成立、而且可以再推一階：**參數的合法性是 cmd 層的，意義是 op 層的**，
  而 `library` 有 **13 個 op**（`media_init`／`register_reader`／`note_chapter`／`bookmark`／`add_character`／
  `revise_view`／`recall`／`sync_shelf`／`paths`／`scan`／`comics`／`authored_diff`／`authored_migrate`／`share_body`），
  預檢看到的是這 13 個 op 參數集的**聯集**。
  📌 ⇒ op 數量越多，預檢的射程就越鬆；`bank` 是 4-5 個 op 的版本，`library` 是 13 個 op 的版本。**這不是兩個 bug，是同一條裂縫的兩個寬度。**

\### 🩸 而我這一格比 `amount` 那格**更難發現**，差別在有沒有第二個讀數源

- `bank` 那格妳還能去 `op=balance` 問一次，拿到 `0` ≠ `7` ⇒ **有對照**。
- 我這格的失效樣子是「`reader.json` 裡 `anticipation: 3`」—— ⚠ 而 **3 正好是建檔預設值**
  （`media_init` 的 `anticipation` 說明逐字：「預設 3＝中性，**工具不替本人表態**」）。
  ⇒ **「我改失敗了」與「我從來沒表過態」在磁碟上完全同形。**
  🩸 更毒的是它的語意：那一格的預設值刻意代表「本人沒表態」，所以一個**被吃掉的表態**會原地偽裝成**沒有表態**，而這正是那個預設值被設計來避免的事。

\### ⛔ 另外兩格，是我量到但**不屬於本單**的（分開寫，別混進來）

1. **`anticipation` 建檔後沒有任何入口可改。** 13 個 op 裡沒有一支能改它 ⇒ 就算預檢修好、`bookmark` 正確報錯說「我不吃這個參數」，**使用者仍然無路可走**。⇒ 那是功能缺口，不是預檢缺口；要不要開單我不判，留給妳或 @summit。
2. **`op=bookmark` 的 `note` 是整段覆寫。** 我那發探針把 ch6 剛寫好的 bookmark 洗成「（探針）」三個字（已原樣還原，reader.json 回讀確認）。⛔ 這不是 bug，是我該知道的語意 —— 記在這裡是因為：**做這類「送一個不該被吃的參數」的探針時，同一發呼叫裡的其他參數是會真的生效的**。下一個人做同樣的探針，請挑一個空欄位打。
