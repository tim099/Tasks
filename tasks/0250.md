## 任務描述

## 現場（2026-09-18 20:32，basecamp 實測，BTC／Bar）

```
senate cmd bank --arg op=open --arg account=template-probe-0242 \
                --arg display_name="Template 驗收探針 0242" --arg amount=7
⇒ ✓ 已開戶 `template-probe-0242`（Template 驗收探針 0242）
senate cmd bank --arg op=balance --arg account=template-probe-0242
⇒ 🔢 balance = 0
```

**`amount=7` 被靜默吃掉** —— 帳開了、錢沒發、而且**沒有任何一層出聲**。

## 成因（讀了實作，不是推的）

`Cmd_Bank.OpOpen`（`src/Senate.Core/Cmd_Bank.cs:179`）逐字只讀三個參數：
`account` / `display_name` / `caller` ⇒ **它從來沒讀過 `amount`**。

而種子那一格**只活在後台頁面**：`src/Senate.Cli/Pages/BankAdminPage.cs:571-595`
（欄位 `bank/f/seed`，二次確認後 `system_init` 憑空增發）。

## 病：**`senate cmd` 有 ArgSpec 預檢，而這一格它擋不住**

`amount` 是 `bank` 這支**合法宣告過**的參數（credit／debit／transfer 都吃它）⇒
預檢看到的是「一個宣告過的參數」，不是「這個 op 不吃它」。
⇒ **參數的合法性是 cmd 層的，而它的意義是 op 層的** —— 兩層之間沒有人把關。

📌 這跟 TASK-0109（`ucmd` 無預檢 ⇒ 未知參數靜默取預設）**是同族的下一格**：
那條講「打錯名字沒人擋」，這條講「**名字沒打錯，而這個 op 根本不看它**」。
兩者的失效樣子一模一樣：一個 ✓Success、一個合理的數字、以及一件沒有發生的事。

## 誰在等

任何一個照 Tim 2026-09-18 拍板「開戶三欄：帳號 id／顯示名／**初始金額（種子）**」
去用 CLI 開戶的人 —— 他會拿到一個餘額 0 的帳戶，而畫面說開戶成功。
今天 TASK-0242 ⑬ 的驗收就是這樣撞到的。
