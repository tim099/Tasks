# TASK-0118 — Cmd_Glossary op=register --arg overwrite=true 會重寫 created_at（該欄應不可變）

## 驗收標準

## ① 重現讀數（開單人已填，見 evidence）

- [x] `op=register --arg overwrite=true` 會把既有詞條的 `created_at` 換成此刻
- [ ] 反向對照：**不帶** `overwrite=true` 新建一筆 ⇒ `created_at` 是建立時刻（正常路徑不受影響）
- [ ] 查其他寫入端有沒有同族：`Cmd_Task` / `Cmd_NoteLesson` / `Cmd_Relationship` 的
      `created_at` 在覆寫路徑上會不會也被重寫（**同一個形狀通常不只一處**）

## ② 修正落盤

- [ ] `created_at` 在既有檔案上是**不可變**的：overwrite 時讀回原值沿用，只更新 `updated_at`
      （若 frontmatter 目前沒有 `updated_at`，這一格順帶補上 —— 不然「什麼時候改的」無處可放）

## ③ 異源複驗

- [ ] 對一筆**已存在且 created_at 是昨天以前**的詞條跑 overwrite ⇒ `created_at` 不動、
      `updated_at` 推進（由另一個人跑）
- [ ] 順帶驗 house style：走 `--arg body=` 那條路時 one_line 的引言區塊沒被生成
      （我今天手補的，見 evidence 末段）—— 這格若確認是刻意的就劃掉，不是就一起修

## 📌 為什麼這不是小事

`created_at` 是「這個詞是什麼時候立的」唯一答案。它被寫成「最後一次改的時間」之後，
**兩件事在那一欄上同形**：一筆七月立的老詞條被今天改過、與一筆今天才立的新詞條。
⇒ 而查詞條的人正是想知道前者（老詞條代表它撐過時間）。這是《名字比事實大》的欄位版。

## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

2026-09-03 實測（summit），同一筆詞條前後兩次讀數：

1. 首次 register（無 overwrite）：`Docs/Glossary/session-voucher.md` frontmatter
   `created_at: 2026-09-03T11:49:31Z`、`created_by: unknown`
2. 補作者欄時走 `op=register --arg overwrite=true --arg-file body=<本體>`
   （刻意帶 body，避免裸 overwrite 砸掉本體 —— @calli 2026-09-02 的血證）
3. 之後 frontmatter：`created_at: 2026-09-03T11:53:02Z`、`created_by: summit`

⇒ `created_by` 修好了（那是本次的目的），但 **`created_at` 從 11:49:31 被改成 11:53:02**。
今天同一天所以無害，而它是真的錯：那個欄位的語意是「立於何時」，不是「最後一次寫入」。

diff 也留著（我對拍過基線）：
```
< created_at: 2026-09-03T11:49:31Z
< created_by: unknown
---
> created_at: 2026-09-03T11:53:02Z
> created_by: summit
```

附帶一格（同一次操作發現，可能是刻意的）：走 `--arg body=` 時，
生成的檔案**沒有** one_line 的引言區塊（`> <one_line>` 那行），而其他詞條都有
（例 `Docs/Glossary/scope-misalignment.md`）。我手動補回去了。
