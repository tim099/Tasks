# TASK-0123 — senate ui --no-cleanup：讓 Dead／PidReused 有一條到得了畫面的路

> `improvement` / `low` / `done`　開單：basecamp　參與：basecamp(dev)

## 驗收標準

出處：TASK-0101 QA（summit 2026-09-03 留言 #4）量到的**不可觀測**那格，PM 2026-09-04 判它不在 0101 射程，另開本單。

現況讀數（她造的活體，不是推論）：
```
senate server start            → pid=50328 登記
taskkill /F /PID 50328         → SUCCESS（硬殺，記錄應留下）
ls _process_registry/          → senate_server_50328.json   ← 檔案確實還在磁碟上
senate ui --page process       → 共 0 筆記錄               ← 渲染前已被清掉
```
⇒ `Main` 每次先跑 `CleanupStale`，而 `--window --screenshot` 也是一次新的 `Main`
⇒ **Dead／PidReused 在任何 QA 能驅動的路徑上都到不了畫面**。分類邏輯已由 TASK-0101 的 selftest 四態格覆蓋（29／29），本單補的是**畫面那一半**。

- [x] `senate ui` 加一顆 `--no-cleanup`：只跳過渲染前的 `CleanupStale`，**不改 kill 判準**（Dead／PidReused／Unknown 一律仍不畫 Kill 鈕）　✅ basecamp 2026-09-09
- [x] 帶旗標時畫面上明說「本次未清理失效記錄」—— 否則下一個人會把殘留讀成「現在真的有這麼多 process」　✅ basecamp 2026-09-09
- [x] 驗收：造一顆活體（start → taskkill /F）⇒ `senate ui --no-cleanup --page process` 看得到 Dead 那筆；不帶旗標時仍是 0 筆　✅ basecamp 2026-09-09
- [x] 驗收：PidReused 那態同樣造一次（或明寫「造不出 ⇒ 本單不驗」，⛔ 不留白）　✅ basecamp 2026-09-09
