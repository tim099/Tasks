### 🔬 證據（讀數＋怎麼拿到的）

`senate cmd watch --arg op=untitled`（2026-09-20 20:3x，BTC／Bar）⇒ **5 章章名仍是 `##None##`**：
`watch-humanity-has-declined/003 / 006 / 007`、`watch-made-in-abyss/002`，
以及 `watch-humanity-has-declined/002`（台帳有名字、章檔表頭沒有 —— 這一筆形狀不同）。

它自己印的補名指引逐字是：

> 補名：改 `prepared/<media_id>.json` 的 chapter_title 後帶 `force=1` 重出，或直接給 `title=` 重出
> —— ⛔ **不能手改 .txt**（機械產物，下次匯出會覆寫）。

⛔ **而這段指引已經過期**，`SCP_WatchWriter.WriteChapter` 的 code 逐字：
TASK-0152 之後 `force=1` 的語意從「覆寫」收窄成「**重出落在新版本上**」——
既有 `NNN.txt` 一個位元組都不動，新的那份出成 `NNN_v2.txt`。

⇒ 照指引做的結果是：**正本仍叫 `##None##`，旁邊多一份有名字的 `_v2`**，
而 `_v2` 不符合 `^\d{3}$` ⇒ 章的列舉看不到它 ⇒ `op=untitled` 下次照樣報 5 章。
**補名這條路現在沒有出口。**

📌 同一處還有一格字面過期：`senate cmd help watch` 的 `force` 說明寫「=1 ⇒ 章檔已存在時覆寫」，
而 code 已經不覆寫了。`WriteChapter` 的註解自己承認了這件事
（「⚠ 這個參數名現在比它的行為大 —— 改名要跨兩個 repo 的呼叫端，留一筆待辦」）。

### 為什麼開單而不是順手改

補名要的是**親筆章名**（5 章內容得先讀），而出口本身要先有人決定形狀：
改 `_v2` 的語意／給一個只改表頭的 `op=retitle`／讓 `force` 回到覆寫並另設保護 ——
這是三個不同的決定，不是實作細節。

### 建議的驗收標準

- [ ] ① 決定補名的出口形狀（三選一或第四條），並寫進 `watch op=untitled` 印出來的那段指引
- [ ] ② `help watch` 的 `force` 說明與 code 對齊（現在是「不覆寫、出 `_vN`」）
- [ ] ③ 拿其中一章實跑一次：`op=untitled` 的 5 筆要真的少一筆
