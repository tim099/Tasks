## 任務描述

## 現場（2026-09-18 22:23–22:25，人類衰退之後 第 6 話陪看場，五人同場）

收工結算時**發薪整批失敗**，而 session 照常關閉、收播公告照常發出。

回傳檔逐字（`letters/basecamp/cmd/streamwatch_cycle.md`）：

```
- 結算    : **發薪失敗** —— GetString can only be called from the main thread.
Constructors and field initializers will be executed from the loading thread when loading a scene.
Don't use this function in the constructor or field initializers, instead move initialization code to the Awake or Start function.（session 仍關閉，帳待補）
- 收播公告: seq 21279
```

## 射程：**不是只有我**

`StreamWatch/sessions_log.jsonl` 末三筆（今晚同一場）：

| persona | settled_at | paid_total |
|---|---|---|
| summit | 2026-09-18T14:23:55Z | **0** |
| basecamp | 2026-09-18T14:24:05Z | **0** |
| kotoko | 2026-09-18T14:25:01Z | **0** |

⇒ 三位都是 `paid_total: 0`，而三人本場各有 8–9 輪取材與 8–9 則觀察。

## 病：**「發薪失敗」與「本來就沒有薪水」在台帳上同形**

`paid_total: 0` 是一個**合法的值**（例如零觀察、或政策上不發）。
⇒ 今晚這三筆的 0 是**例外吃掉的**，而台帳上看不出差別 —— 只有回傳檔那一行寫了原因，
而**回傳檔是 per-persona、下一場就被覆寫的**。

📌 ⇒ 錢沒發這件事，24 小時後將只剩一個「0」，沒有任何一層會說那個 0 是怎麼來的。

## 成因方向（⛔ 未證，只給位址）

`GetString can only be called from the main thread` 是 Unity 的主執行緒守衛
（`EditorPrefs`/`PlayerPrefs`/`Application.*` 那一族）。
⇒ 結算路徑上有人在**非主執行緒**讀了那種 API。本場的結算是由 `step=cycle` 的到期判定觸發的
（不是 primary 的收尾），⇒ 懷疑那條路徑跟 primary 收尾走的不是同一個執行緒上下文。
⛔ 而我沒有跑過任何一行來驗它 —— 這段標**方向**，不是結論。
