## 任務描述

Tim 2026-11-13：「希望加一個新功能 區域特色菜單(目前有分地中海 北非 西非) 可以讓每個地區的菜單&船上菜單根據城鎮所在區域 文化變動」「包含城鎮廚房 以及酒館 餐館菜單等」「可以混合方案嗎 有地區菜系(自動) 城鎮也可以手動標(例外城鎮手動標)」「或是烘焙時自動根據地區標一組預設 然後可以手動override」「然後菜系指紋要獨立出來(修改不影響城鎮其他部分指紋 避免重新烘焙)」；外地菜選「硬篩」。

## 現況（Blocksail main 7711d96f 讀的）
- 菜單全球共用：城鎮廚房 `world/food.js` `HOME_RECIPES`／`HOME_MEALS`；酒館、餐館、小飯館、客棧 `world/recipes.js` `SERVE_RECIPES`＋`world/buildings/<用途>.json` 的 `menu`；船上 `world/fleet.js` `SHIP_RECIPES`。
- 酒館 19 道、餐館 16 道都掛著地中海 5 道（`med-*`）、北非 3 道（`na-*`，TASK-1235）；船上的地中海、北非加餐每一艘船都有 ⇒ 篩選只靠「料買不買得到」（`goodReach`），加勒比有粗麥粉就端庫斯庫斯。西非四道（TASK-1279 PLAN.md）還沒接。
- 城上沒有現成的地區標記：`culture` 只有三座加勒比的城寫了；分區 `groups` 不一致（熱那亞只有 `europe`、君士坦丁堡只有 `bosporus`）。

## 架構（討論定的）
1. **菜系表** `world/cuisine.js`（新檔）：`BSW.CUISINES` ＝ `med` 地中海、`na` 北非、`wa` 西非、`common` 不分地區；`fall` 退路鏈（`na` → `med` → `common`，同 `TOWN_STYLES`）。
2. **烘焙自動預設**：`tools/cuisine_bake.cjs` 讀每座城（含 `plan` 的遠城區）市中心的分區，照規則表 `BSW.CUISINE_RULES` 由細到粗比：行政區代碼（例 `fr-13` 馬賽 → med）⇒ 國碼（`it`／`gr`／`tr`… → med；`tn`／`dz`／`ma`／`ly` → na；西非沿岸 → wa）⇒ 其他 `common`。
   寫成生成檔 `world/cuisine_auto.js`（提交，一城一行：菜系＋命中哪一條規則）；`--check` 過期 ⇒ exit 1；手標跟自動一樣 ⇒ 印「可以拿掉」。
3. **手動覆寫**：城那一筆（遠城區 `plan`）寫 `cuisine` ⇒ 蓋過預設。讀的順序：手標 ⇒ 烘好的預設 ⇒ `common`。
4. **菜上標 `cuisine`**（四份表都標；沒寫 ＝ `common`）。**外地菜硬篩**：一座城只上「它的菜系退路鏈上」＋`common` 的菜；建築 json 的 `menu` 不拆，執行時篩（`serveMenu`、`homeMenu`、`shipMenu`／船上挑菜、小飯館、客棧）。
5. **船照母港的菜系**（AI 船 `F.ai.home`；玩家的船照玩家選的母港），靠港不換。
6. **廚房直接吃的菜名**可以照菜系換名字與圖（`HOME_MEALS` 多一欄；熱量、等級不動）。
7. **讀檔**：建築實例上已經掛的外地菜（`menu`、`pick`）照城的菜系篩掉；開場檔照差量補（記憶 blocksail-start-plan-delta）。

## 指紋獨立（Tim：修改不影響城鎮其他部分指紋）
- `world/cuisine.js` ⛔ 不放進 `TOWN_CODE`、`CHUNK_CODE`、`NAV_CODE_FILES`、`DEEP_CODE_FILES`；⛔ 菜系表、規則表不放 `areas.js`（它在規劃與海圖塊的程式指紋裡）。
- 城那一筆的 `cuisine` 欄：`town_store.js` 的 `areaH`（規劃）、`areasKeyIn`（海圖塊）算雜湊時跳過（同現在跳過 `pts`）。town_store.js 不在任何程式清單、現在沒有一筆寫 `cuisine` ⇒ 這個改動本身 0 份重烘。
- 菜的 `cuisine` 標籤：`recipes.js`、`food.js`、`fleet.js` 不在任何指紋；`#tables` 只讀建築的 `recipes`，不讀服務建築的 `menu`。
- 菜系自己的指紋 ＝ 規則表＋每座城市中心那一個分區（id、代碼、groups）＋城的位置＋手動覆寫。
