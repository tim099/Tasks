## 驗收標準

- [ ] 格子（world/tiles，BST1）改存 .bin：world_tiles.py 寫、world.js 用 fetch 讀（ArrayBuffer，不經 base64）；node 工具（tools/town_load.cjs 等）、route_worker、mapgen_worker 同一份讀法

## 任務描述

Tim 2026-11-18：「那生成加讀寫都搬呢(另外地塊資料是否可以不用.js存而是raw binary)」⇒ 開單。

量測（trailhead，TASK-1318 留言 #2、#3）：
- world/tiles 已經是二進位 BST1，base64 包在 .js 裡（給 <script>／file:// 讀）：6,787 檔、743 MB。world/bathy 是 JSON 包在 .js：1,965 檔、191 MB。
- 克雷斯島一片 0.3°×0.2° 原精度：W.need 635 ms，其中讀 .js＋base64 ⇒ 位元組約 60 ms（約一成）；其餘是 BST1 解碼與拼回環（換格式省不掉）。
- 生成（BSW.terrain）16 km 見方 1024×1024 2.9 秒 —— 搬生成是 TASK-1318 的事，這張只管檔案格式。
⇒ 這張的收益：檔案小約 1/4（打包、手機下載）、讀取快約一成；等深線從 JSON 換二進位應該更多。
遊戲一律走伺服器（menu.sh → world_serve.py；exe 也有伺服器）⇒ fetch .bin 可行；代價是 file:// 雙擊開不再支援。

⛔ 等 TASK-1303（全球海岸重建）合 main 之後才動 —— 同一批檔（world/tiles、world/bathy、world_tiles.py、bathy_extract.py）。
