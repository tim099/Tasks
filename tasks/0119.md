## 📌 為什麼它值一張單

而**單子上的驗收標準三格全是 `[ ]`**。
⇒ 「已驗但無處打勾」與「從沒人驗過」在那一欄上**完全同形**，

狀態機管得到 status，管不到它自己的驗收欄。

\## ✅ 四格驗收（讀數全取自磁碟／git，不讀寫入端回傳值）

\### ① 有一條路能把某一格標成完成，且**留下是誰標的**

`op=check --arg index=<N> --arg criteria_index=<n[,n...]>`。勾完那一行變成：

```
- [x] 有一條路可以把某一格驗收標準標成完成，且**留下是誰標的**　✅ summit 2026-09-08
```

**git diff 讀數（勾 1,3 那次）：`4+ / 3-`** —— `updated_at`、兩格勾、一行時間線，**沒有第四處**。

⭐ 一個沒設計進去的效果，而它正好打在本單的病上：
**開單時就手寫成 `[x]` 的那三格沒有署名段**，我勾的四格有 ⇒
「開單人自己宣告已完成」與「有人驗過並簽名」**現在分辨得出來**。
本單原本只要求前者可標記，這一格是白撿的。

\### ② ⛔ 不是「開放整份 criteria 覆寫」

`op=check` 只吃 `index` ＋ `criteria_index`，**沒有 `criteria` 這個參數**；
內部是把那一行的勾選格翻掉再走 `Save`，其餘行原字串傳回。
`--arg-file criteria=` 那條整份覆蓋的路**權限沒有改變**，**新增**細項今天仍然只有它。
⇒ 差別在權限不在方便：整份覆寫讓「正在做它的人」可以把驗收標準整段換掉。

\## 🩸 我在做這張單的時候造了一個事故，寫在這裡

改 `Task_Management_Workflow.md` 時我用 python `open(p,'w')` 就地覆寫，而我的字串裡有
一對 surrogate 逃脫（`📌`）⇒ `write()` 拋 `UnicodeEncodeError`。
**而 `open(p,'w')` 的截斷發生在 write 之前** ⇒ 那個檔被清成 **0 bytes，301 行全刪**。

- **淨損失零**：那個檔是已提交且我改之前未修改的 ⇒ `git checkout --` 完整還原（301 行，git 零 diff）。
- **修法不是「下次更小心」，是換掉那一層**：改成寫暫存檔 ＋ `os.replace` 原子替換 ——
  這樣一個會拋的 write **碰不到原檔**。重做後 git 讀數 `14+ / 2-`（外科手術式，不是整檔）。
- 📌 形狀：**一個「就地覆寫」的寫入端，把「寫入失敗」變成了「刪除成功」。**
  那正是 gen6 §三 那條（不可逆寫入不准順手做 —— 危險不是它會失敗，是它不在任何人的清單上）。
  ⚠ 而擋下我的不是紀律，是**我自己順手去 `wc -c` 看了一下那個檔**。

  讓它在 git 眼中隱形。⇒ 「其餘位元組不變」在**原始位元組層不成立**、在 git 層成立。
  ⛔ 我沒改它，也**沒有**替它開單 —— 要不要開交 PM（§0.5 Q3：開單權在 PM）。
- **多筆勾銷我只量到 `1,3` 與 `1,2` 兩組**（各 2 筆）。三筆以上、以及「跨越已勾行」的
  序號口徑我沒跑 ⇒ 未量。內部是由大到小套用，理由寫在 code 註解上。
- **後台頁（ToolBox → 任務與專案管理）我沒看** —— 那一欄在頁面上長什麼樣、
  署名段會不會被排版吃掉，**沒有畫面讀數**。
- **我沒有第二個人複驗。** Tim 明示授權我全包 ⇒ 這一格是**刻意的**，不是漏掉；

  拿一張妳自己有份的單跑 `op=check --arg index=<N>`（dry-run，零寫入）看清單印不印得出來。
