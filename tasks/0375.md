## 現況（2026-10-02 kaguya 量）

- 會裝東西的地方有三套，各寫各的：`media_admin.py`（whisper／torch／OCR，`pip --user`）、`knowledge_base.py install`（FlagEmbedding，**沒有** `--user`）、`llm_admin.py`（ollama）。
- 安裝位置都不能設：pip 的 site-packages ＋ 預設的 HF 快取（`~/.cache/huggingface`，bge-m3 4.3 GB 在那裡）。
- 叫 Python 的方式不一致：Unity runner 從 PATH 叫 `python`，`memory.py` 用 `sys.executable`。
  ⇒ 同一台機器上「哪一顆 Python、哪一個 site」由呼叫端決定，而它不會叫。`media_admin.py` 解除安裝要跑最多 4 輪就是為了這個（user-site 和系統 site 各有一份）。
- 已知會咬人：知識庫頁的「安裝」跑 `pip install -U torch` 不帶 index-url，可能把 cu126 的 GPU 版換成 CPU 版（`knowledge_base.py` 自己的註解記過這次血證）。
- Senate 這側：`SCP_PathRegistry` 加一個路徑 id 就會自動出現在「路徑管理」頁與 `senate cmd paths`；長時間工作已有固定形狀（`SubmoduleSyncJob`：背景執行緒＋`Snapshot()` 回進度）；下載走宿主的 `SenateHttpFetcher`（SCP_Core 本身不連網）。

## 參考 UCL_MediaAdminPage 時留下 / 不留下的

- 留下：清單驅動（`PLUGINS`）、裝完用**新的子程序**實際 import／實跑才算數、模型以「磁碟上的檔」判定而不是 exit code、危險動作兩段式確認、共用套件不移除。
- 不留下：每個項目的安裝動作寫死在程式裡；沒有進度、只有「⏳ 執行中」；安裝位置不能設。

## Tim 已拍板（2026-10-02）

1. **Python 環境**：可以指定路徑。預設去找系統安裝的 Python；使用者也可以手動指定一個新路徑，讓它在那裡裝一份。
2. **已經裝好的東西**：同上 —— 看選定那個路徑下的 Python 環境實際配置了什麼，有就算有，不搬、不重裝。
3. **Unity 的相關頁面**（影音管理、知識庫管理、AI 模型管理）：之後都會廢棄，遷移到 Senate 並依賴這套系統。
   ⚠ 遷移那三頁**不在本單射程**（本單只做安裝系統本身）；本單要做的是讓它們搬過來時有東西可以依賴。

## skill 缺相依的流程（草案）

1. skill 在 frontmatter 宣告它需要哪些項目。
2. 工具執行時發現缺 ⇒ 回「缺相依」的結果（固定的 exit code ＋ 機讀欄位），內含項目名、大小、來源、安裝指令。
3. agent 照實轉告使用者（大小、從哪下載、裝到哪），**問一次**；使用者同意才跑 `senate cmd install --arg id=<項目> --arg confirm=1`。
4. ⛔ agent 不得自己決定安裝；⛔ 不得把「同意一次」延伸到下一個項目。
