# TASK-0207 — 下棋不綁自由時間：活動 md 加宣告式 needs_session，Cmd_FreeTimeActivity 的場次守衛按宣告放行

> `feature` / `normal` / `done`　開單：calli　參與：calli(dev)

## 驗收標準

- [x] ① 宣告式欄位：活動 md `needs_session`（預設 `true`）⇒ ⛔ Cmd 裡**不得**出現 `if (id == "chess")`　✅ calli 2026-09-11
- [x] ② 閘放行：宣告 `false` 的活動在**沒有自由時間場次**時 `op=pick` / `op=step` / `op=done` 全部通行　✅ calli 2026-09-11
- [x] ③ 反向對照（陰性）：**沒宣告**的活動（預設 true）在無場次時**照舊被擋** —— 證明不是替所有人開門　✅ calli 2026-09-11
- [x] ④ 沒帶 `--arg activity=` 且無場次 ⇒ 照舊擋，並印出「帶上 activity 可能就過」那句出口（⛔ 不猜活動）　✅ calli 2026-09-11
- [x] ⑤ 無場次時**不寫場次計數器**（`activity`／`activities_done`），而**飢餓統計照記**；兩件事都要在回傳檔講出來　✅ calli 2026-09-11
- [x] ⑥ `op=done` 在無場次時**不指向換骰**（那條會擋 —— 指向死路的「下一步」比沒有下一步更貴）　✅ calli 2026-09-11
- [x] ⑦ 編譯 errors 0，且**我改的檔零警告**（⛔ 不拿「總 warning 數」當判準，那會隨組件集合變動）　✅ calli 2026-09-11

## 任務描述

Tim 2026-09-11 拍板：「下棋不綁定自由時間（不用擋）」。

## 症狀（我自己當場撞到的）

驗 TASK-0206 時 `run FreeTimeActivity op=pick --arg activity=chess` 被
`Cmd_FreeTimeActivity` 的 session 守衛擋下（`reason: session 已收工（expired）`）
⇒ 「想走一步棋」變成「要先開一場自由時間」。
而下棋本來就沒有時間壓力（`min_minutes: 0`、每步落盤、一局跨好幾次醒來）。

## 改法：宣告式，⛔ 不寫死 chess

活動 md 加 `needs_session`（預設 `true`）；宣告 `false` 時守衛放行、`iSession` 傳 null。
⛔ **不在 Cmd 裡寫 `if (id == "chess")`** —— 那會把規則裝在其中一條路上，
而下一個「也不該綁場次」的活動不會有人想起來要改那一行。

⭐ 而場次計數器與飢餓統計**剛好可以分開**：`RecordPick(iPersona, id)` 只吃 persona、不吃 session
⇒ 無場次時 `activities_done` 不動，而飢餓統計照記。兩件事都在回傳檔明講。

⚠ 一格邊界：沒有場次時 `activity` **無處可 fallback** ⇒ 沒帶 `--arg activity=` 就解不開是哪個活動，
連「這活動豁免嗎」都判不了 ⇒ 照舊擋，並把那句出口印出來。⛔ 不猜活動（猜錯會把下棋記成閱讀）。
