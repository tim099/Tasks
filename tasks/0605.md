## 驗收標準

- [ ] 新圖紙：參考歷史圖紙與史料「重畫」—— 線形（側面、橫剖面、半寬）、甲板高度、砲位表、桅帆表、蒸汽機外觀（煙囪、螺旋槳）各一張；plan.json 每個數字標「參考資料（附出處）」或「設計決定」，參考資料至少兩份獨立查證並排
- [ ] 0.1 公尺／格（跟遊戲裡其他船一樣）；組裝件與每件子作品都記 meters_per_voxel；船殼 1 元件、空腔 0、link_overlap 0、兩舷鏡像差 0
- [ ] 拿破崙號的船型看得出來：兩層砲甲板的 90 砲戰列艦、蒸汽與風帆並用（煙囪、船尾螺旋槳）、三桅全帆裝＋艏斜桅
- [ ] 砲：每門砲是外部模型、沿用現有元件（work sub=components）、帶 meta kind=gun 與 muzzle／breech 固定點、從砲門往裡退到零碰撞、砲口在船殼外
- [ ] 帆桁從一開始就是模型（每根一件子作品、pivot、meta kind=yard、mast、sail）；每面帆、旗與帆自己的繩照造船規格 §9.1 標 meta（`work sub=meta` 讀數「沒有 meta」0）
- [ ] 遊戲功能：設計水線 meta（kind=ship、waterline_z）、甲板 kind=deck、梯子 kind=ladders、彈藥庫 kind=magazine、舵（kind=rudder 或格子舵）、舵輪等甲板物件帶 kind；每一層要讓人走得到的甲板都有梯子通到
- [ ] 遊戲用規格：外部完整；內部只做大致構造與必要功能。資訊不足處的設計決定寫進 plan.json 與作品筆記
- [ ] 每個階段：作品 notes.md 讀數、todo.md 下一步、overlays/ 過程圖；結果帳（作品＝設計）缺 0／多 0／色差 0
- [ ] 反向對照：每個階段至少一項 —— 刻意錯位或拿掉一件，讀數要報得出來（報 0 的尺不算量過）
- [ ] 匯出 format=vxk include=rig,models,parts,meta，用 Blockside 的 admin.py 匯進遊戲：主選單選得到、checksum 通過、開得了戰；shipcheck ✗ 0

## 設計方向（kotoko，開工時的決定；細節在新圖紙階段定案）
- 原型：法國海軍 Le Napoléon（1850 年下水、Dupuy de Lôme 設計），第一艘專門設計的螺旋槳蒸汽戰列艦，兩層砲甲板、90 門砲。
- 圖紙：參考歷史圖紙與史料「重畫」—— 不描圖；plan.json 是設計來源，每個數字標出處或設計決定，查不到的由我設計。
- 作品 `kotoko-napoleon-01m`（船殼，任務主作品）＋ `-assembly`（組裝件，名稱＝船名「拿破崙號」）＋子作品（tags=sub）。
- 比例 0.1 m／格；產生程式（design/）照 plan.json 算，可重跑、逐位元組相同。管線結構參考三叉戟號（gura-tridente-01m/design，尺寸最接近的一艘），抄來的檔頭註明。
- 遊戲用：外部完整；內部只要甲板、艙口、梯子、彈藥庫、機艙的大致構造。砲、舵輪、火藥桶、燈、羅經櫃、絞盤、小艇沿用現有元件；煙囪與螺旋槳是這艘船自己的。
