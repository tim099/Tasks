# TASK-0060 — StreamWatch 段台帳：全場段序＋seg_index↔seq 對照＋自動標頭（併鍵漂移根治）

> `feature` / `high` / `todo`　開單：basecamp　參與：summit(qa)

## 驗收標準

- [ ] `segments.jsonl` 實跑一場多人陪看後可回讀：段號連續、無重號、無跳號（跳號只在熱點或逾時出現且有紀錄）
- [ ] 兩人同一秒 cycle：兩人拿到**不同** seg_index，且 frontier 不回退（人為併發重演，不是只看 code）
- [ ] `observe_seqs` 對照可回讀：任一段能查回它的 seq；同段發兩則 → 陣列兩筆
- [ ] 自動標頭：agent **不帶任何標頭參數**，發出的訊息仍有完整標頭（拿 seq 回讀訊息檔驗證，不看回傳檔）
- [ ] 未夾住的那輪（人為製造窗口尾端 > 水位）標頭印 **⚠**，不是 ✅
- [ ] 跨人引用：兩位不同 persona 的觀察，段號不撞（現況會撞，需重演對照）
- [ ] 鍵漂移：拿今天的兩份 prepared 檔重演 —— `join` 必須 **blocked 並列出兩份檔**，不得靜默取舊檔
- [ ] skill 四份安裝副本與 Workflow 文件同步（`grep` 確認「手動帶標頭」字樣已無殘留）
- [ ] `check_compile --errors-only` 0 error，且以 DLL mtime 晚於原始碼佐證這次 build 真的含改動

## 任務描述

## 問題（三題共同的根，@meadow #17092 的定位我同意）
「段」沒有持久指涉物。接力狀態整份只有 `relay/<primary>.json` 的 `frontier_epoch`（單調 Max、last-write-wins）
＋ `updated_by`。佔段發生在 `StepCycle`（先佔段再取材，Cmd_StreamWatch.cs:1401）但**佔完只留一個游動的水位** ——
沒有「這是第幾段／誰佔的／起訖在哪」的紀錄。
⇒ 於是：① 訊息無法按素材順序重排；② 標頭只能由 agent 手抄 cycle 回傳檔（漂移／漏帶，實例 seq 17066）；
③ `觀察 #N` 是各人的 cycles 計數，跨人撞號（同一話出現兩個「#1」、兩個「#2」—— Books/watch-apocalypse-hotel/010.txt 可回讀）。

## 要做的四塊
### (a) 段台帳 `StreamWatch/segments.jsonl`（append-only）
佔段時原子發號，一段一行：
`{relay_key, session_id, seg_index, from_epoch, to_epoch, persona, claimed_at, tiles, span_sec,
  tier, overlap_sec, watermark, margin_sec, clamped(bool), is_hotspot, hotspot_id, observe_seqs:[]}`
- 發號來源＝relay 檔新增 `next_seg_index`，**與 frontier 同一次寫入**；
  沿用現有「寫前重讀、只前進不回退」的防回退寫法（Cmd_StreamWatch.cs:1401-1411 那格）。
- 熱點觀看（step=claim）**不佔主線號**，另發 `H<n>`／子熱點 `H<n>.<m>`（見 TASK 熱點遞歸單）。
  理由：保序要靠「主線缺號＝有段沒交」當訊號，而那個訊號不能被合法行為污染。

### (b) 觀看序號全場共用（Tim 2026-08-26 拍板）
`觀察 #N` 的 N ＝ `seg_index`（全場一條號，跨人可引）。
個人 `cycles` **保留**（計酬與個人取材量），但**不再共用「#N」寫法** —— 兩個數不同名不同用途。

### (c) seg_index ↔ tavern seq 對照表（Tim 2026-08-26 21:38 拍板：**不解析訊息本文**）
`observe` 發文成功拿到 seq 的那一刻，把 seq append 進該段的 `observe_seqs`。
⇒ 下游（匯出／UI／統計）只讀對照表。訊息 meta 可以順便帶 `seg_index`（給人與 UI 看），
但**事實源是台帳**：meta 是每則各自帶的，漏寫會長出「一則沒有段號的觀察」而看起來完全正常；
台帳的缺漏會顯示成「這段沒有 seq」——**讀不到與沒有，在輸出上可分**。
對照表天生是 `seg_index → seq[]`，順帶解決「同段多則」。

### (d) 自動標頭
cycle 已算好 `WatchWindowPlan` 但沒落檔 ⇒ 落進段台帳後，`observe` 自組標頭：
段序／起訖／格數／每格秒數／檔位／窗口對帳／餘裕／是否熱點。
⚠ **只自動帶事實欄，判讀仍要 agent 自己寫**；**未夾住那輪標頭印 ⚠ 不是 ✅**。
理由：skill 明寫那四行是判準不是裝飾，自動印會讓人不再讀「尾端 > 水位時那幾格的『沒有字幕』不可信」。
⇒ 同步改 skill（`ucl-stream-watch` 四份安裝副本）與 Workflow 文件，刪掉「手動帶標頭」。

## 併入：鍵漂移（BUG-39，@apex-one 主張拉到最高優先）
`prepare` 以 media_id 落檔、`start`/`join` 以 work slug 查檔 ⇒ 靜默命中上一場舊準備檔。
根治＝**同鍵** ＋ 準備檔帶 `work_id`/`episode` 與 session **cross-check，對不上就 blocked 並印出兩份檔**。
⚠ @meadow #17092 的更正我認：**「寫心得時顯式帶 0010」只是繃帶，不算修好** —— 權宜之計不會自己退場。

\## 🔧 今晚實跑後的三個修復（2026-08-26 23:10，編譯 0 error，DLL 23:10:36 > source 23:10:18）

\### ① 段號缺口（我自己實作的洞，第一輪就撞）

而缺口在設計上的意思是「**有人佔了段卻沒交觀察**」，跟「這一輪水位沒追上」是兩件事 —— **不可同形**。
⇒ 無素材路徑照樣寫一行（`tiles=0`、header 說明水位未追上），號碼因此連續。

\### ② ring buffer 左界沒套在觀看游標上（Tim 點出「最多只能錄 2400」）
`OldestFrameEpoch()` **早就存在**，而且已經套在熱點三處（標記／認領／清單）——
**唯獨 `step=cycle` 的觀看游標沒查**。⇒ 游標可以停在已被覆蓋的時間上，每輪取 0 格，
