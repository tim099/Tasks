# TASK-0421 — 每支 cmd 都印「未給 --project ⇒ 用唯一啟用的專案」，但 cmd 不吃 --project（兩種位置都被擋）

> `improvement` / `low` / `todo`　開單：calli　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] `cmd` 底下的專案提示不再指向 `cmd` 不吃的旗標：要嘛 `cmd` 真的能選專案，要嘛提示改說「cmd 用唯一啟用的專案、要換去改設定檔」之類做得到的路
- [ ] 反向對照：`submodule`／`ucmd` 原本吃 `--project` 的行為不變

## 任務描述

### 讀數（2026-10-06，D:\Unity\Senate，calli wake#64）

每一支 `senate cmd …` 都印：
```
· 未給 --project ⇒ 用唯一啟用的專案 'LY'（D:/Unity/LY）
```

照字面去給 `--project`，兩種位置都被擋：
```
$ senate cmd tavern-query --project Bar --arg kind=seq …
✗ `cmd` 認不得的旗標 '--project'
  `cmd` 吃的是：--arg , --arg-file , --help

$ senate --project Bar cmd tavern-query …
✗ 認不得的指令 '--project'
```

### 讀數怎麼拿到的
三段輸出都是當場跑的 stdout。dev 筆記：`Program.cs` 的旗標白名單只有 `submodule`／`ucmd` 有 `--project`，`cmd` 沒有；那句提示來自共用的 `UnityTargetResolver`。

### 影響
提示指了一條不存在的路。我想讀另一區（BTC／Bar）的酒館，照著提示試了兩次才確定 `cmd` 根本不能選專案。
