## 驗收標準

- [x] ① 設計定案：Discord Inbound（Discord → 酒館）與 Outbound（酒館 → Discord）在 Senate 端的整體機制寫成一份設計（含哪些訊息往外送、外來訊息怎麼落進酒館、身分怎麼標），並經 Tim 拍板　✅ gura 2026-09-28
- [x] ② 部署形狀定案：獨立一顆 Server，或併進酒館 Server —— 兩案的代價與失效樣子並排分析後由 Tim 拍板　✅ gura 2026-09-28
- [x] ③ Outbound：走 Senate 發文路（`tavern-post`／`tavern-write`／每日結算公告）的訊息，照設定轉發到 Discord；**Unity Editor 沒開也照轉**　✅ gura 2026-09-28
- [x] ④ Inbound：Discord 上的訊息落進酒館、標明是外部中繼，**Unity Editor 沒開也照收**　✅ gura 2026-09-28
- [x] ⑤ 後台設定：Senate 後台頁可查看／修改轉發設定（哪些房、哪些 category 往外送、webhook 等），憑證不以明文顯示　✅ gura 2026-09-28
- [x] ⑥ 反向對照：Discord 端點失敗時酒館發文照常成功、不重複轉發；轉發關閉時一則都不往外送　✅ gura 2026-09-28
- [x] ⑦ 切換期不雙發：Editor 那套與 Senate 這套不會同時轉發同一則　✅ gura 2026-09-28
- [x] ⑧ 憑證存放：Bot token 走 Senate 加密檔管理頁（要密碼）；Webhook 以**寫死的金鑰**加密（不必手動輸入密碼），密文存成**獨立檔**、與 `discord_config.json` 放在同一個資料夾（⛔ 不直接放進 json），磁碟與 git 上都沒有 webhook 明文　✅ gura 2026-09-28
- [x] ⑨ Outbound 的名字與頭像跟 Senate 酒館頁同源：username 與酒館頁同一個顯示名（`Agent@persona`，取自 `SCP_TavernDisplay`；現行 Editor 鏡像已是這個形狀，Tim 2026-09-28：保持一致）、頭像取自 `letters/<persona>/profile/avatar.png`（TASK-0317 的 `SCP_PersonaDisplay`）；沒頭像的 persona 用預設圖，⛔ 不借別人的（自 TASK-0317 ⑤ 移入）　✅ gura 2026-09-28
- [x] ⑩ Outbound 依**頻道分類**路由（Tim 2026-09-28：依頻道分類，不是依訊息分類）：分類與封存取自 TASK-0318 的 `SCP_TavernChannels`；封存的頻道一則都不往外送　✅ gura 2026-09-28
- [x] ⑪ Inbound 開著時 Bot 在 Discord 上顯示上線，狀態欄列出目前在線的 persona（名單變了會更新）；Inbound 關掉 ⇒ Bot 轉離線（Tim 2026-09-28：復刻 Unity 版）　✅ gura 2026-09-28
- [x] ⑫ 「Discord Bot」頁可以逐個 Discord Server 開關 Inbound 來源（預設開；關掉的 Server 底下所有頻道都不收）　✅ gura 2026-09-28
