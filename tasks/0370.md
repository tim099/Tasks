## 背景與現況診斷

目前專案透過 UCL_KnowledgeBaseAdminPage 與 knowledge_base.py 使用 BAAI/bge-m3 模型進行文件、教訓（lessons）與記憶碎片（fragments）的檢索。

### 現有架構的局限性：
1. **純 Dense 向量檢索**：knowledge_base.py 目前僅使用 BGE-M3 的 dense_vecs，未發揮其內建的 Sparse（詞彙/關鍵字權重）與 ColBERT 多向量特徵，對於精確專有名詞與代碼識別率不足。
2. **缺乏時序意識（Temporal Blindness）**：向量檢索不具時間概念，歷史狀態與最新事實可能在語意檢索中同時被命中，無法自動處理「狀態失效（State Supersession）」與「矛盾更新」。
3. **無工作記憶（Working Memory）分層**：僅有外存檢索，缺少類似 Context 壓縮、短期暫存、反思（Reflection）與動態 Core Memory 的分層編排。

---

## 2025–2026 年主流長短期記憶方案調研

1. **Mem0（Memory-as-a-Service）**：
   - 專門針對 Agent 的個人化記憶層，區分 User、Agent、Session 三級記憶。
   - 具備實體與事實萃取（Fact Extraction），能自動合併、覆蓋衝突事實。
   - 可純本地部署（SQLite/Chroma + 本地 Embedding）。
2. **Letta / 前身 MemGPT（Memory OS）**：
   - 將記憶視為類似操作系統的分層體系：Core Memory（常駐上下文，Agent 可自主透過 Tool 讀寫編輯）、Recall Memory（對話歷程檢索）、Archival Memory（無限外存庫）。
   - 與本專案的 letters/<persona>/（_constitution.md、_latest.md、ragments/）設計哲學高度契合。
3. **Zep / Graphiti（Temporal Knowledge Graph）**：
   - 雙時態知識圖譜，專門追蹤實體關係的生效與失效區間，適合高度動態的狀態演進。

---

## 模型與檢索層升級空間

1. **BGE-M3 多模態活用**：BGE-M3 依然是頂級開源多語言模型，若啟用 Dense + Sparse 混合檢索即可兼顧語意與精確關鍵字。
2. **引入 Cross-Encoder Reranker**：在 BGE-M3 檢索出 Top-20~30 後，引入 BAAI/bge-reranker-v2-m3 或 jina-reranker-v2 進行重排，預期可提高 15%~30% 的精準度。
3. **新一代 Embedding 評估**：如 Qwen3-Embedding（32K context）、Jina Embeddings v3（LoRA 任務適配）。

---

## 候選方案

- **方案 A（最輕量，ROI 最高）**：現有 knowledge_base.py 升級為 BGE-M3 雙模混合檢索 + 增加 ge-reranker-v2-m3 重排，並加入時間衰減權重。
- **方案 B（記憶中台化）**：引進 Mem0 本地版，負責個人記憶抽取、去重與事實更新，底層對接現有向量庫。
- **方案 C（深度分層）**：參考 Letta 架構，將信件庫與工作記憶規格化為 Core/Recall/Archival 三層工具化記憶。
