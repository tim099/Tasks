# TASK-0164 — Cmd_Tavern op=post 的共享狀態 RMW 稽核（seq 配號無鎖＋金流）—— post 能離開主緒的前置

## 驗收標準

① 逐項列出 `Cmd_Tavern op=post` 那條路上**所有共享狀態的 read-modify-write**，每一項標明：誰是寫者、有沒有第二個寫者、撞了之後看起來是什麼樣子。已知起點：
   · `UCL_ChatTavernIO.IncrementAndGetSeq`（讀 counter → 比對 jsonl_max → 寫回；**無鎖**）
   · 金流那條（發文計酬 / ledger 餘額）—— ⚠ 錢的 RMW 撞了是假帳，這格要最保守
   · inbox / mention state / 房間 members
② 對①的每一項給處置：上鎖 / 收成單一入口 / 判定「只有單一寫者所以本來就安全」（要寫出為什麼）。
③ 活體：兩條 lane 同時 post，對拍 `messages.jsonl` 的 seq **無重號**、ledger 兩筆都在、金額正確。
④ 過了②③才可以把 `op=post` 走 `UCL_AgentCmdOffload.EnterBackground`（TASK-0162 的下一支）。**順序不可反。**
⑤ ⚠ 涉及金流 ⇒ 要第二個人在旁邊看，不是我自己 dev＋QA。

## 為什麼（我自己的建議少查了一格，這張單是那一格的帳）

TASK-0162 我對 Tim 說「`Cmd_Tavern` 可以動，因為它對 `UCL_TaskIO` 的引用數是 0」。
⇒ 那句話是真的，而它**不是完整的判準**：Tavern 有它自己的同族不變式，只是沒有人寫在註解裡。

實測讀到的那一格：`UCL_ChatTavernIO.IncrementAndGetSeq`（約 848 行）

```
int counter  = ReadCurrentSeq(roomId);
int jsonlMax = ReadMaxSeqFromJsonl(roomId);
...
File.WriteAllText(GetSeqPath(roomId), (counter + 1).ToString());
```

**讀 → 判 → 寫，中間沒有鎖。** 今天安全只因為所有 cmd 都跑在單一主緒上 —— 跟
`UCL_TaskIO.cs:202` 註解寫的是同一件事，差別只在**那邊有人寫下來，這邊沒有**。

📌 一般形：**「沒有寫下來的不變式」跟「不存在的不變式」在 grep 上同形。**
所以 offload 的前置條件不是「這支有沒有引用那個檔」，是「這支碰的每一格共享狀態有沒有第二個寫者」。
