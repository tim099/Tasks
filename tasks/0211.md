## 症狀（活體讀數，2026-09-15 09:2x，TASK-0187 ④ 探針途中撞到）

```
senate cmd commit --arg repo=<throwaway> --arg personas=__probe_nobody --arg expect_files=1 --arg dry_run=1
  ⛔ persona 檔不存在或讀不到：__probe_nobody（打錯名字會靜默生出一行掛在不存在的人身上的 trailer）
     ⇒ 假位址進了 git history 就改不掉；要硬幹請顯式帶 `--arg allow_unset=1`。
  exit_code = 3

# 照它說的加上 allow_unset=1：
senate cmd commit ... --arg allow_unset=1
  ⛔ persona 檔不存在或讀不到：__probe_nobody（…）
     ⇒ …要硬幹請顯式帶 `--arg allow_unset=1`。
  exit_code = 3        ← ⚠ 逐字相同的輸出
```

## 成因（讀 code，不是推的）

`SCP_Cmd_Commit.cs`：`aProblems` 是**一個清單收三種問題**，而失敗訊息尾巴那行
「要硬幹請顯式帶 `allow_unset=1`」是**無條件**加在整個清單後面的：

- `BuildTrailers` 內 `iAllowUnset` **只**在「信箱是哨兵／形狀可疑」那一支生效
  （`if (iAllowUnset) …放行; else oProblems.Add(...)`）
- 而「persona 檔不存在或讀不到」與「agent 欄是空的」兩支是 `oProblems.Add(...); continue;`
  —— **完全不看 `iAllowUnset`**

⇒ 三種問題共用同一行出口指路，而那個出口只對其中一種有效。

## 失效的樣子（為什麼這一格會安靜地咬人）

它**不是沒反應**：它認真擋下、認真印了一條看起來可行的出路。
讀的人照做 → **逐字相同的輸出** → 下一個念頭多半是「我參數打錯了嗎」或「工具壞了」，
而真正的答案是「這個出口對這個分支本來就不存在」。

📌 這跟 TASK-0192（跨 Cmd 指路沒有主詞）同族：**指路牌本身沒有守衛**——
編譯不讀它、測試不讀它，唯一的檢查是有人真的照著走一次。

## 建議修法（不指定，列給修的人挑）

- (A) 把尾巴那行改成**逐問題**附出口：哨兵那支才印 `allow_unset=1`；
  persona 不存在那支印「檢查名字拼法／`senate cmd persona` 列表」；agent 欄空那支印「補 `--arg region=`」。
- (B) 讓 `allow_unset` 真的涵蓋三支 —— ⛔ **不建議**：「persona 根本不存在」時放行，
  等於把一行掛在不存在的人身上的 trailer 寫進改不掉的 history，那正是這道閘要擋的事。

⇒ 我傾向 (A)：**壞的是指路，不是閘**。
