🩸 而我要一起交出去的是**我的量法錯在哪**（這比 bug 本身重要）：

## 三個切法（⛔ 我不自己挑，這格有政策成分）

- **(a) 換指向**：按鈕改呼 `Books op=donate`（C# 那側已原生，`Cmd_Books` 有 donate）。
  最小、當天可交，但要對 `agent`（錢從誰的帳出）與 `persona`（誰捐的）兩格 —— 那兩格 C# 都 required，⛔ 不能猜。
- **(b) 拆掉按鈕**：捐書一律走 CLI / ucmd，頁面只留指路文字。
  ⇒ 若 Tim 的意思是「金流不留 GUI 入口」，這才是對的，而 (a) 等於把金流入口又接回 GUI。
- **(c) 只補回饋**：維持現狀但把 exit≠0 顯示在頁面上（不再只進 Console）。
  ⚠ 這一格**單獨做是錯的** —— 它只是讓壞掉的按鈕壞得比較大聲。要做也是配著 (a)/(b) 做。

⇒ (a) 與 (b) 的差別不是工程量，是**捐書該不該有 GUI 入口**這個政策問題。
那是 PM 的格子，不是 dev 的。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

**讀數（2026-09-07 08:5x，全部唯讀＋一次無害探針，零寫入）**

① 消費端還在：`UCL_LibraryManagePage.cs:1010-1022` 組出 `library.py donate --book … --donor … --tokens …`，
   由 `:1033 RunLibrary()` spawn（`:1086 LibraryPyPath()` 指到 `<UCL_Core>/Tools~/AgentCommands/library.py`）。
   ⇒ 後台 ToolBox「圖書館管理」頁的**捐書鈕**走的就是這條。

② 被呼叫的那一支已退場：`library.py:1571 cmd_donate` 自 2026-09-06（TASK-0143）起是**指路 stub**，
   docstring 明寫「不動帳不寫檔」，函式體只 print 指路到 `senate ucmd run Books --arg op=donate`，
   最後 `return 2`。

③ 活體探針（不動帳、不寫檔）：
   `python library.py donate --book test-probe --donor cc --tokens 1` → stderr 印指路四行、`EXIT=2`。

④ 失效樣子（推導自 `RunLibrary` 的分支，`:1069-1080`）：
   exit≠0 ⇒ Unity Console 一行 `LogError [LibraryManage:donate …] library.py exit=2` ＋ stderr 進 LogWarning，
   然後照樣 `LoadData()` 重整清單。**頁面上沒有任何回饋**，書也沒捐成。
   ⇒ 它不是靜默（Console 有紅字），但**按鈕的使用者不看 Console**。

⑤ 射程（我量到哪為止）：
   - `.cs` 裡 spawn `library.py` 的點，掃 `Assets/Plugins` 後**只剩這 1 處**
     （Cmd_ 家族已歸零：`Cmd_StreamWatch.cs:3468` 的 export-watch 於 09-06 改為就地直呼 SCP_Core；
      該檔僅存的 `ProcessStartInfo`（:2689）呼叫的是 `screenstream_montage.py`，**不是** library.py）。
   - 同頁其他按鈕**沒有**呼叫 `publish` / `tip` / `tips` / `donations`（逐字掃過該檔，只有 `donate` 一處）。
   - `.py` 消費端：掃 `Tools~` 與 `AgentCommands` 對 `library.py` 的引用共 7 筆，**全部是註解**，零實際呼叫。
   - ⛔ 手打指令、外部腳本、其他 repo 的複本**量不到** —— 這五格是「我掃得到的範圍」，不是「不存在」。
