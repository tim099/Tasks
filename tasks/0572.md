# TASK-0572 — 《憲法號對轟》甲板規格化：照 meta 判定甲板與通道（梯子），尋路分層＋區域、打壞會斷連

## 驗收標準

- [x] 規格寫好（造船規格）：甲板照關聯 meta 判定 —— 哪一條關聯是甲板、叫什麼、由下往上第幾層、地板高度（含舷弧）；甲板之間的通道（梯子）連哪兩層；換一艘船的檢查表多一行　✅ ame 2026-10-14
- [x] 遊戲裡的三艘船（憲法號、餘燼號、夜隼號）甲板都標好；遊戲不再自己量甲板高度（砲甲板、預備水手走得到的層、停格的「甲板（L）」、艙房屬於哪一層，都照 meta）　✅ ame 2026-10-14
- [x] 尋路分兩段：同一層甲板裡的路 ＋ 跨甲板的通道；讀數：同一個情境，找路的時間（改之前／之後）　✅ ame 2026-10-14
- [x] 梯子被打壞、或梯子兩頭的甲板被打穿 ⇒ 那條通道斷掉，預備水手改走別的梯子；全斷 ⇒ 走不到（不默默穿過去）　✅ ame 2026-10-14
- [x] 尋路動態更新有開關與刷新間隔（Tim 2026-10-14）：關 ⇒ 不刷新（打壞了照樣走過去、可以浮空移動）；開 ⇒ 每個間隔裡有甲板或梯子被打壞才重算那幾層（不頻繁重算）　✅ ame 2026-10-14
- [x] 甲板被打成兩塊以上不通的區域 ⇒ 那一層的走路區域拆成幾塊，各自找路；讀數：拆開的那一刻、每一塊有多大　✅ ame 2026-10-14
- [ ] 艙房綁在甲板上（照關聯路徑）；醫療艙所在的區域走不到 ⇒ 傷員不送過去，配置頁與讀數寫出原因
- [x] 反向對照：沒有甲板 meta 的舊匯出 ⇒ 照舊（量高度的退路）照常運作，不會整個壞掉　✅ ame 2026-10-14

## 任務描述

Tim 2026-10-14：甲板也需要規格化（房間綁定在甲板上）；甲板之間透過樓梯相連（樓梯損毀或甲板破損可能導致甲板之間斷連）；不要直接測量甲板層高，直接根據 meta 判定甲板；以及甲板之間的通道（樓梯），尋路簡化為甲板內的路徑 ＆ 跨甲板通道；甲板如果物理上破損成兩個以上不互通區域，尋路區域拆分（簡化尋路判定）。
起因：餘燼號停格的「甲板（L）」一按就跳到上層砲甲板（船中段量不到上甲板）—— 已先用量高度的暫時修法修掉（ArtGallery 0683ea8），本單把它換成 meta。

## 現況（ame 讀程式）
- 砲甲板：照砲的高度分層（10_ship.js gunDecks）；預備水手走得到的層 ＝ 砲甲板 ＋ 梯子兩頭的高度（42_hands.js navLevels）；停格的 L 量每一欄站得住的高度（74_cutaway.js deckCut）—— 三套各自量。
- 走路格只照開戰時的船：甲板被打穿照樣走過去；梯子不會斷。每層只留最大那一片連通區域。
- 雕刻作品裡甲板已經是關聯（甲板-orlop／-berth／-gun／-spar…、餘燼號多 -lower／-upper／-poop、夜隼號 -主／-後），梯子是甲板底下的關聯 meta kind=ladders，艙房也在甲板底下（甲板-berth/艙房）。

## ame 草案
- 甲板關聯的 meta（meta 誰都能標 ⇒ 三艘船 ame 自己標）：kind=deck、deck=<代號>、level（由下往上，0 起）、name（顯示的名字）、floor（舷弧：幾個「x:z」點，遊戲照它內插；用工具量一次寫進 meta，遊戲執行時不量）。
- 通道：沿用梯子的 meta（foot／lo／hi／head）；兩頭各屬哪一層照 meta 的 floor 判斷（或在梯子關聯上寫 from／to）。
- 尋路：每層一張走路格，切成連通的區域；區域之間的邊 ＝ 通道。跨層先在「區域圖」上找、再在區域裡找。
- 破損：被打掉的格落在某層地板或某座梯子上 ⇒ 那一層重新切區域、那座梯子檢查還在不在（每半秒、只重算有動到的）。

Tim 2026-10-14（開工時）：尋路動態更新要有開關＆刷新頻率；關掉不刷新（破壞後可以浮空移動），開啟後刷新區間內甲板有受到破壞就更新（避免頻繁更新）。
