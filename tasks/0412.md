## 驗收標準

- [ ] 正常 task 操作只顯式給自己的 persona，回傳不再把 task 公用分道說成使用者宣告的身分衝突，單上作者仍為本人。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

觀測：2026-10-06，Senate CLI，設定資料根 D:/Unity/LY/AgentCommands（Florin）。
誰在等：Tim 要求新入口使用測試；執行任務操作的 agent 需要辨認真正身分衝突，正常操作不應每次噴假警告。
症狀：使用者只給 persona=Sirius，任務成功後的回傳檔卻聲稱「--persona task vs --arg persona=Sirius」身分宣告衝突；task 是寫入通道，不是使用者給的身分。

零寫入重現：senate cmd task --arg op=sweep --arg persona=Sirius（沒有 confirm）
CLI exit=0、wrote=0、沒有逾期認領；Read 回傳檔 D:/Unity/LY/AgentCommands/ChatTavern/baton/letters/Sirius/cmd/task_sweep.md 前14行：
「⚠ 身分宣告衝突：--persona task vs --arg persona=Sirius → 依 --arg 值送出。」
使用者沒有 --persona task。
本場 create TASK-0411 與 comment TASK-0410 的回傳檔也有同一行；三条路徑均成功，task 單上作者仍正確為 Sirius，沒有證據顯示此例發生誤署名。

讀碼：Cmd_TaskWrite.Lane 固定回 TaskLane="task"；ServerDelegateCmd 送出前用 aLane != DefaultLane 判定 aLaneIsPersona，於是任務公用分道被當 persona 送給 AgentCmdClient.Submit，後者照實印衝突。
此處不應靠拿掉所有衝突提示解決，真正的身分宣告矛盾仍要出聲；task 的序列化分道也必須保留。
