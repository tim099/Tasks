## 🩸 最貴的那一格（先讀這段再動手）

**旗標是資料，切換的行為是 code —— 兩者在不同的 repo 裡，而它們不同步時沒有任何一層會喊。**

`money_authority=senate_bank` 只是 `bank_settings.json` 裡的一個字串。
真正讓錢改道的是 `UCL_TreasuryAuthority` ＋ `UCL_TreasuryLedger` 的路由（`UCL_Core 8950a496`）。
⇒ 如果 Bar 那棵樹的 `UCL_Core` checkout **還沒拉到那顆 commit**：
- 旗標設了 ⇒ 帳面上「這棵樹已經切了」
- 而 code 不存在 ⇒ 錢**照舊寫進舊 `Treasury/`**
- ⛔ **兩邊都不會報錯**，而且各自都自圓其說

⇒ 所以驗收 ① 排在最前面，且它的讀數是「那個檔案存不存在／sha 是哪一顆」，
⛔ 不是「我記得我 pull 過」。

## 📌 LY 那次量到、BTC 會再遇到的幾格

1. **`bank_diff` 切換之後就不是閘了。** 舊帳本凍結、新銀行繼續走 ⇒ 兩邊必然分岔，差額會變大，**那是預期**。切換後的 `bank_diff` 現在會自己印這句定語（`UCL_Core 6e984242` 之後）。⛔ 別看到紅字就去修一個不存在的 bug。
2. **射程（閘裡有幾戶）是 persona pool 推導的，不是綁定檔。** LY 量到 09-17 是 11 戶、09-18 是 10 戶，而綁定檔自 08-20 一個字沒動。⇒ 跨日要比**射程逐 id 那一行**，⛔ 不是比戶數。
3. **對帳器只能走 `GetAllBalancesLegacy()`。** 我在 LY 那次把 `GetAllBalances` 接上權威，對帳器當場變成拿新銀行跟新銀行比 ⇒「逐戶零差額」**恆真**，而畫面跟真的通過一模一樣。BTC 這邊不必再改，但**驗收時要記得那道閘曾經可以被自己弄成恆真的**。
4. **`senate.exe` 是共用的一顆。** `Cmd_Bank` 的定語已改成逐棵樹推導 ⇒ BTC 沒切之前它仍會對 BTC 說「本帳＝測試用」，那是對的。⛔ 別因為 LY 切了就以為那句話壞了。
5. **Server 是必要條件。** 切換之後寫錢一律派給常駐 Senate Server，沒跑就**整筆失敗且不降級**。Bar 那邊動手前先確認 Server 在跑（`senate server status`，或新的 `ui --page server`）。
