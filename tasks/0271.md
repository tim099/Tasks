# TASK-0271 — 券系統擴充小數點累積精度模型（Fractional Voucher Balance）—— 儲存小數精度、消費限整數、交易累積滿 1 自動進位為可用券

> `feature` / `normal` / `done`　開單：gura　參與：gura(pm)、gura(qa)、kaguya(dev)

## 驗收標準

- [x] ① `SCP_VoucherBook` 與 `letters/<persona>/vouchers/<券名>.json` 擴充小數點記錄欄位（`fractional`），向下相容舊版無小數資料檔　✅ gura 2026-09-22
- [x] ② 收入入帳邏輯（進位計算）：當入帳金額含小數或小數池更新時，計算 $\text{total} = \text{old\_fractional} + \text{incoming}$；整數商 $\lfloor \text{total} \rfloor$ 併入可用券（`Permanent`），餘數 $\text{total} - \lfloor \text{total} \rfloor$ 留存小數池　✅ gura 2026-09-22
- [x] ③ 消費支出限制（整數守衛）：各消費管道（畫布、抵扣等）呼叫券扣減時，僅能扣減整數部分，小數部分嚴禁直接支出或被當成可用張數　✅ gura 2026-09-22
- [x] ④ 數值測試讀數（活體驗證）：以 Tim 範例驗證 —— 初始 2 BTC + 0.5，獲得 1.6 BTC 後，回讀可用整數券為 4 BTC，小數點餘額為 0.1 BTC　✅ gura 2026-09-22
- [x] ⑤ 反向對照：當獲得 0.3 BTC（總累積 0.5 + 0.3 = 0.8 < 1）時，可用整數券維持 2 BTC 不變，小數點正確更新為 0.8 BTC　✅ gura 2026-09-22

## 任務描述

Tim 2026-09-22 拍板「券小數點累積精度」需求：
1. 券需要能額外存儲小數點（供小額發放與市場交易撮合精確計價）。
2. 實際使用（消費）時無法使用小數點部分，只能使用整數可用券。
3. 用在交易與發放上，小數點部分超過 1 就自動進位變成實際可用的整數券。
   例如：目前有 2 BTC + 0.5；若再獲得 1.6 BTC，總計 4.1，則實際可用券變為 4 BTC + 小數餘額 0.1。

PM 規劃（gura）：
- 資料結構：擴充 `SCP_VoucherBook.cs`。
- 運算邏輯：入帳自動進位（Carry-Over）與餘額小數隔離。
- 消費守衛：嚴格禁止未滿 1 的小數點被調用。
