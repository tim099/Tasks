## 任務描述

## 提案（Tim 2026-09-11）

Coding 場改成帶**施工範圍路徑**（絕對路徑、取施工的最大範圍），只要範圍不衝突就可以同時施工。

範例範圍：`D:\Unity\Senate\SCP_Core`／`D:\Unity\Senate`／`D:\Unity\LY\Assets\Plugins\UCL_Core`／`D:\Unity\LY\Assets\Scripts`。
衝突判準＝**路徑包含**：`D:\Unity\LY\Assets\Scripts` 與 `D:\Unity\LY\Assets\Scripts\Conditions` 重疊 ⇒ 衝突。

## 現況（讀了 code，不是推的）

`SCP_ActivitySessionStore.TryStart` 有**兩條正交的軸**：

- **軸1 每人一場**（`FindRunning`，per-persona，跨 kind 擋）
- **軸2 全域互斥**（`FindRunningGlobal`，TASK-0058）—— `IsGlobalExclusive(kind)` 為真時，
  掃全體 persona，**找到第一場進行中的同 kind 就擋**，不看它在改什麼。

⇒ 本提案動的是**軸2**：把「這個 kind 有人在跑」換成「**這個 kind 有人在跑，而且範圍撞到我**」。
　 軸1 不動（一個人仍然一次一場）。

📌 欄位落點現成：`SCP_ActivitySessionStore.MergeOntoRaw` 會**原樣保留這一層不認識的鍵**，
所以 session 檔多一個範圍欄位不會被收工流程吃掉。

## ⚠ 一個提案本身沒有涵蓋的洞（所以 ① 要先拍板）

**同一個 repo 會出現在多個互不重疊的路徑上。** SCP_Core 現在有 5 份工作副本：
`D:/Unity/Senate/SCP_Core`、`D:/Unity/LY/Assets/Plugins/SCP_Core`、`D:/Unity/Bar/...`、
`D:/Unity/BarBak/...`、`D:/Unity/osawari01/...`。

⇒ 兩個人分別宣告 `D:\Unity\Senate\SCP_Core` 與 `D:\Unity\LY\Assets\Plugins\SCP_Core`：
**路徑判準會說不衝突，而他們改的是同一個 repo 的同一支檔。**
失效樣子不是當場報錯，是**兩邊各自 commit 之後 push 分叉**，或後 pull 的那份被 `--ff-only` 擋在半路。

兩種處置都說得通，而它們**相反**，所以要拍板不要猜：
- (a) 純路徑判準 —— 同 repo 不同副本**視為不衝突**（本來就是刻意分開的兩棵樹，分叉由 git 那層管）
- (b) 範圍先解析成 repo 身分 —— 同 repo 即衝突（那會讓「改 Senate 那份避開 Unity 施工場」這條現行走法失效）

## 為什麼現在值得做（成本那一側）

今天現場：@kiara 的場 00:47Z→03:47Z 改 `UCL_Core` 的 HButton/HActionPanels（TASK-0189/0190/0191），
而我要改的是 `UCL_Core/.../Task/Cmd_Task.cs`（TASK-0199）—— **同一棵樹、不同支檔，三小時全程互斥**。
⛔ 而「這道閘擋下過幾次」我**沒有讀數**：`sessions/<persona>.json` 只留當前那一場，
被擋下的那些沒有留痕 ⇒ 我拿不出頻率，只能舉今天這一次。

📌 本單與 TASK-0193（綁單＋自動收場）是**同一條軸的兩半**：那張縮短**持有時間**，這張縮小**持有範圍**。

## ⛔ 不在本單射程

- 軸1（每人一場）不動。
- 其他 kind（FreeTime／StreamWatch）不動 —— 它們現在根本不走 `TryStart`（直接 `Save`）。
- `build.sh` 出廠驗收那一格不動。
