## 任務描述

`resolution_note` 有寫入端、沒有讀取端 ⇒ 任何會重新落檔的 op（link / comment / update / claim…）
都會把已關單的整段 `## 結單說明`（含 QA 代簽紀錄）**靜默刪掉**。

⚠ 失效樣子：那個 op **回 Success**、它自己要改的欄位也真的改對了 ——
少掉的那一段沒有任何一層在看。而結單說明正是「這張單為什麼可以關、誰驗的」的唯一落點。

🩸 這一隻是我今天自己踩出來的（對 0082 跑 link），而回頭掃 git 歷史發現
**它已經吃掉 10 次、跨 5 個人的 commit、其中 2 次是今天**。
⇒ 它不是新的，它只是從來沒有人在同一個 diff 裡同時看那兩件事。

📌 而它為什麼躲過所有驗收：每一次驗收問的都是「我改的那一欄對不對」，
沒有人問「原本有的東西是不是都還在」。

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

**① 程式碼層（決定性讀數）**：`resolution_note` **有寫入端、沒有讀取端**。
全 UCL_Core `grep resolution_note` 只有 5 處：

- `UCL_TaskModels.cs:195` 欄位宣告
- `Cmd_Task.cs:1000/1002` resolve 時寫進 model（`note` ／ `qa_note`）
- `UCL_TaskIO.cs:305-306` 落檔時**寫出** `## 結單說明`
- **⛔ 沒有任何一行把 `## 結單說明` 讀回 model。**

⇒ 任何會重新落檔的 op（`link` / `comment` / `update` / `claim` …）載入時
`resolution_note` 是空字串，於是那一段被**整段刪掉**。
（`UCL_TaskIO.cs:133` 的已知區塊清單**有** `## 結單說明` ⇒ 它被切得出來，只是沒有人把它裝回去。）

**② 現場（我自己踩的，2026-09-07 02:39）**：
`TASK-0082` 於 01:19 `resolve` 時寫了結單說明 ＋ QA 代簽紀錄，並在 `5f253c5` 進版控。

兩份檔已留存對照（`scratchpad/0082_after_link.md` 為受損版；已用 `git checkout` 還原）。

**③ 歷史（不是只有我，也不是今天才開始）**：
