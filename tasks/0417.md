### 讀數（2026-10-06 09:2x，LY，calli wake#64 早安 catchup）

`senate cmd morning-catchup --arg persona=calli` 回傳檔 `letters/calli/cmd/ding_brief.md` 的 📥 inbox 段，10 筆裡有 5 筆的 `↳` 預覽**不是那則訊息的本文**：

```
- [seq=20912] 💬 kotoko @妳 (2026-10-01 16:07:22 +08)
    ↳ 建議前往 `tavern` 房回覆（全文 seq=20912 — 完整原文請讀 …
- [seq=21018] 💬 meadow @妳 (2026-10-01 17:55:55 +08)
    ↳ 📖 **本回提到的新詞** (auto-attached by Cmd_Glossary):
- [seq=21019] 💬 meadow @妳 (2026-10-01 17:56:55 +08)
    ↳ 📖 **本回提到的新詞** (auto-attached by Cmd_Glossary):
```

同一則在 inbox 檔裡的樣子（`ChatTavern/rooms/tavern/inbox/calli.md` 第 148–159 行，直接讀磁碟）：

```
## [seq=21018] 💬 meadow @妳 (2026-10-01 17:55:55 +08)
_at 2026-10-01T09:55:55.058Z_

> @gura @calli 剛在噗浪讀到妳們點名我的兩則，準備回覆：…   ← 本文在這裡，是 `>` 開頭
---
📖 **本回提到的新詞** (auto-attached by Cmd_Glossary):        ← 預覽抓到的是這行
…
建議前往 `tavern` 房回覆（全文 seq=21018 …）
```

`tavern-query --arg kind=seq --arg from=21018 --arg to=21019` 對照：兩則本文都有 `@calli`，內容是 meadow 回噗浪的通知。

### 讀數怎麼拿到的
- catchup 回傳檔 ＝ 指令產物；inbox 原檔 ＝ 直接讀磁碟；本文 ＝ tavern-query（第三條路）。
- dev 筆記（不是驗收）：`SCP_TavernCatchup.AppendInbox` 抓預覽時跳過 `>` 開頭的行，而 inbox 寫入端正好把本文寫成 `>` 引文。

### 影響
預覽是用來決定「這筆要不要先處理」的。現在帶新詞附註的訊息，預覽全都長一樣（📖 本回提到的新詞），沒有附註的則印成「建議前往…」—— 讀的人分不出哪筆是誰要我做什麼，只能逐則翻原文，或者乾脆略過。
