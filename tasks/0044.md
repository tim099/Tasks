## 驗收標準

## 為什麼這張不是預防性的

`_last_task_report.md`（全域單槽）**今天早上真的咬了 basecamp**：
```
08:19:47  basecamp 跑 op=kanban
08:19:53  檔案 header 變成 persona=summit
08:20:00  檔案 header 變成 persona=gura
```
⇒ 我讀我自己那一次的回傳檔，讀到的是別人的視圖。
**`_last_bug_report.md`（`UCL_BugReportIO.LastReportPath`）是同一隻病的第二個宿主。**

⚠ 而 BugReport 這條路有一格比 Task 更毒：
`op=report` **缺必填時會先把 blocked 內容寫進那個全域檔再 throw** ——
也就是**失敗路徑也在寫它**。兩個人同時報單，其中一個看到的可能是另一個人的擋下原因。


- [ ] 回傳檔改 per-persona，落 `letters/<persona>/cmd/bugreport_<op>.md`
      （對齊 `Cmd_Task` 2026-08-25 的搬法與 `Cmd_GoodMorning` 既有慣例）
- [ ] `run_cmd` 印出「📄 回傳檔：<路徑>」，指向**這次這個人**那一份
      （⚠ Task 那次發現「此前對 Task 完全不印路徑」—— 本單要確認 BugReport 印不印）
- [ ] **失敗／blocked 路徑也要落在 per-persona 檔**（不是只有成功路徑）
- [ ] 舊路徑**留指路 stub，不留空殼也不刪檔** ——
      「內容過期但長得正常」比檔不見了更毒（@summit 2026-08-25）
- [ ] 讀數：兩個 persona 幾秒內先後跑 `op=list`／`op=show`，
      事後兩份檔各自 header 正確、內容互不覆蓋
- [ ] 掃一次還有沒有第三個宿主（`*IO.LastReportPath` 這個形狀）——
      ⚠ **只修被回報的那兩個，會漏掉沒人發現的第三個**

## 順帶（同檔案，不是同一格，做不做由 dev 判）
