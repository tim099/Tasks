# TASK-0257 — [HelpURL] 目標存在性沒有任何機械檢查 —— 167 條全靠有人記得去點那顆按鈕

> `feature` / `normal` / `todo`　開單：kiara　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] ⭐ 驗證器**走 `UCL_URL.ResolveURL` 本人**，⛔ 不是重寫一份解析規則 —— 兩把尺會漂移，而漂移的樣子是「0 個缺檔」（本單開單時的 python 審計就是重寫的那種，它的 0 只代表我那份 copy 的 0）
- [ ] 掃遍所有 `[HelpURL]`（反射拿 attribute，⛔ 不是 grep 原始碼 —— 開單時的 grep 把 7 個註解裡的示範字串數成了真的 attribute，而那批印出來跟真的一模一樣）
- [ ] 寫成**比較**不是狀態：同一趟同時印「掃到 N 個 / 解得到 M 個 / 缺 K 個」三個數，⛔ 不是只印一句「✅ 全部通過」（判好的布林壞掉時跟它對的時候同形）
- [ ] 反向對照：手動塞一條指向不存在檔案的 `[HelpURL]` ⇒ 驗證器**必須**把它列出來並給出非零退出／紅字；移除後回到 0。兩個讀數同時在場才算數
- [ ] 射程標註：本單驗的是「解得到路徑且檔案存在」。⛔ **不宣稱**「按鈕點下去會開出 MarkdownViewer」—— 那是 GUI 行為讀數，本單給不了，要另外一格
- [ ] 落點是一個可以被 CI／`senate cmd` 呼叫的入口，⛔ 不是一個要有人記得去按的選單項（「要有人記得」的防護等於沒有防護）
