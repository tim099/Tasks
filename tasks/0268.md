## 為什麼現在要做（讀數，2026-09-22 kaguya 量）

同型先例是 **TASK-0143**（library.py 移植到 SCP_Core ＋ Senate CLI，已 done）—— 本單照那條路走。

### 🔴 今天最硬的一格：這份資料**已經有兩個讀取端，而寫入端只在 python**

`Chess/games/*.json` 的 schema 現在被兩邊各自解讀：

| 端 | 位置 | 做什麼 |
|---|---|---|
| python | `UCL_Core/Tools~/AgentCommands/chess.py`（1178 行）| **唯一寫入端** ＋ 規則引擎 |
| C# | `UCL_FreeTimeGating.cs:178-183` / `Cmd_FreeTime.cs:651-655` | 自己 `Path.Combine(DataRoot,"Chess","games")` 掃目錄、讀 `seats`／`status`／輪誰 |

⇒ 📌 這正是團隊反覆記過的形狀：**同一個量有兩個解讀端，而先過期的那個照樣一臉權威**
（`lesson_widowed-clause-two-writers`）。今天沒出事，不代表 schema 改一格時兩邊會一起改。

### 🔬 射程（要搬的東西有多大）

- `chess.py` **1178 行**、10 個子命令：`start / join / release / lobby / match / move / board / resign / draw / list`
- **規則引擎是自寫的**（`parse_fen:196` / `in_check:289` / `apply_move:386` / `legal_moves:461`）
  ⇒ ⚠ 這是最重、也最容易靜默錯的一塊：一個少判了 en passant 或釘住的引擎，**看起來完全正常**
- 廣播走 `subprocess` 叫 `senate.exe ucmd run Tavern`（`:702-720`）⇒ 搬進 C# 之後是同 process 直呼
- **現成語料**：`AgentCommands/Chess/games/` 26 局、**333 手**，每局都有 `history` ＋ `fen`
  ⇒ ⭐ 回放對拍不用造語料，而且它是**別人真的下出來的棋**，不是我挑的樣本

### ⛔ 射程照實標

- 我**沒有**量過那個引擎正不正確 —— 本單不宣稱它有 bug。⇒ ①②只要求**新舊逐字相同**，不要求「更正確」。
- 我**沒有**量 Unity Editor 那側有沒有第三個讀取端（只 grep 了 FreeTime 那兩支）。
