## 任務描述

### 🔬 證據（開單時附；含「讀數怎麼拿到的」）

六份 book.json 分成兩種互不相容的格式，而兩個寫入端**都活著**。

## 讀數（2026-09-11 08:5x，calli；走 Bash 直接量磁碟，不經 Cmd）

判準是三根軸：縮排 / 冒號後有無空格 / 有無結尾換行。

| 格式 | 張數 | 書 | mtime |
|---|---|---|---|
| `tab` / 冒號無空格 | 3 | basecamp-foot-of-the-mountain、basecamp-rooms-with-the-same-name、meadow-bridge-notes | 09-07 08:32 / 09-07 08:32 / 09-08 13:29 |
| `2 空格` / 冒號有空格 | 3 | book-gura-abyssal-verifications、calli-receipt-is-not-goods、sirius-night-lamp | 09-09 12:07 / 09-10 16:00 / 09-10 08:33 |

⇒ mtime **交錯**（09-07/09-08 一組、09-09/09-10 另一組）＝不是「舊檔殘留＋新檔」，兩條路都在用。

## 兩個寫入端（都不是退場 stub）

- `UCL_BooksIO.SaveJson`（`data.ToJsonBeautify()`）⇒ tab / 冒號無空格。呼叫端 `Cmd_Books` 等 6 個 `.cs` 活著。
- `SCP_Cmd_Book`（`SCP_JsonWriter.Write(iIndented:true, iIndent:"  ")`，`:344`/`:422`）⇒ 2 空格 / 冒號有空格。入口 `senate cmd book` 活著。

## 🩸 而同一個檔真的翻過一次（git 當獨立證人，非我寫的資料）

`BookNotes` submodule，`git show <sha>:basecamp-foot-of-the-mountain/book.json | sed -n 2p`：

```
2634344  08-23 15:17   2 空格 / 冒號有空格
83aa846  09-06 20:50   tab    / 冒號無空格
```

⇒ **不是兩群檔各自穩定，是同一個檔在兩條寫入端之間來回。**

## 為什麼是缺陷而不是「兩種寫法而已」

TASK-0143 判定 Books 那一族「同一個 store ⇒ 對拍有意義」，並以**逐位元組對拍**當退場憑據
（TASK-0146 ④ 也用 `md5sum` 當判定）。⇒ 那把尺的前提是「同輸入 ⇒ 同輸出」，
而現在同一份資料走哪條入口決定它的位元組長相 ⇒ **對拍會把「格式換了」讀成「搬壞了」，兩者同形。**

⛔ 射程：本單只管 `BookNotes/<slug>/book.json`。新 Library store（`Library/**/*.json`）那邊我另量到
355/359 份與 `SCP_LibraryIO.SaveJson` 產出不同形，但那支**目前零呼叫端**（尚未造成損害）⇒ 記在 TASK-0166 ①，不併進本單。

\## 判定：UCL 那側**不學** SCP 的格式，而是走同一支 writer

⛔ 不在 `UCL_BooksIO` 重寫一個「跟 SCP 同格式」的 formatter —— 兩份 formatter 保持同步靠的是
「記得注意」，而那是修法優先序的最後一級（讓失敗不可能 ＞ 當場喊 ＞ 記得注意）。

走法 ＝ 型別邊界收成一個點：`JsonData → 文字 → SCP_JsonData → SCP_JsonWriter`
⭐ 這是既有手勢的反向：`UCL_PersonaProfile.cs:137`（`JsonData.ParseJson(aScp.ToJson(false))`），
那裡的註解寫著「型別邊界只有這一個點……**收成一個點的理由是它可驗**」。

⇒ 格式漂移從此在**結構上**不可能發生，不是靠下一個人記得。
