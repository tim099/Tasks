# TASK-1229 — 《Blockside》找最近實心格（anchorNear）建置時預烘：每一型一張表，開戰照表拿、不再現算

> `improvement` / `normal` / `in_progress`　開單：Abigail　參與：Abigail(dev)

## 驗收標準

- [ ] 每一型船（含堡壘、砲台）的「找最近的實心格」結果在建置／匯入時用遊戲自己的程式烘好，寫進一份預烘檔；開戰時照表拿，不再現算
- [ ] 讀數：開戰時每一型還要現算幾次（烘好 ⇒ 0）、開一場的時間改前改後
- [ ] 指紋對不上（作品重新匯入過、算法改過）或沒烘 ⇒ 遊戲照舊現算（結果一樣），建置最後一行列出哪幾型要重烘
- [ ] 匯入、重新匯入會自己烘那一型
- [ ] 反向對照：無頭對拍（幾組船、含堡壘）跟改之前逐字相同

## 任務描述

## 要什麼

Tim 2026-11-05（TASK-1224 時）：「另外 anchorNear是否在匯入時就計算好 希望不要在戰鬥時才計算」；照推薦做 ⇒ 建置時用遊戲自己的程式烘。

## 現況（Abigail 讀的，Blockside dev ed3104d）

- `anchorNear(T, x, y, z, r)`（js/10_ship.js）：在船型的原始格子 `T.hullG` 裡找 (x,y,z) 附近 r 格內最近的實心格；每次掃 (2r+1)³ 格（r 8 ⇒ 4,913）。
- 呼叫點全在開戰時：模型的「腳」（帆桁、舵、提燈 bail、壁掛燈 mount、轉軸、螺旋槳、錨、門、槳）、蓋板、繩的兩端、帆的錨、布料綁定（29_sailrecipe、30_rig_physics）、陣營旗（77_colours）。戰鬥中沒有。
- 結果只跟「那一型的 .vxk（含裝甲拆出去的格）＋演算法」有關 ⇒ 一型一張表「(格座標, 半徑) ⇒ 結果」不會錯；沒烘到的鍵就現算。

## 做法（照 ships/showlod.js 那一套）

- 無頭 Chrome 跑成品 `?ancbake=<船>`（同 shipcheck／showlod 開一場），記下這一型每一次查詢與結果 ⇒ admin.py 寫 `ships/anchor.js`。
- 指紋 ＝ 算法版本 ＋ 那一型 .vxk 的 lock（同 showlod）；對不上 ⇒ 不用表、照舊現算。
- 匯入、重新匯入自己烘那一型；建置最後一行列出要重烘的。
- 不在匯入端用 Python 重寫：遊戲的 `T.hullG` 先拆裝甲；兩份程式遲早對不上。也不重匯 44 艘。
