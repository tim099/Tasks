# TASK-0691 — 《Blockside》划槳：動力改成傳輸鏈（每一節可出力、最後一節輸出、一件可以就是整條鏈）＋槳與槳手＋划槳動畫（之後的槳帆船）

> `feature` / `normal` / `todo`　開單：ame　⚠ **尚無參與者**（沒有人在做這件事）

## 驗收標準

- [ ] 動力鏈：動力件串成鏈 A ⇒ B ⇒ C ⇒ D，每一件只是鏈上的一節（不分傳動件這一類：軸、蒸汽管也是一節）；每一節都可以出力也可以不出、最後一節輸出（只有一節 ⇒ 同時出力也輸出）；中間每一節可以省略。輸出 ＝ 從第一節往後「前面傳來的 × 這一節完好度 ＋ 這一節出的力」。現有的鍋爐 ⇒ 主機 ⇒ 軸 ⇒ 螺旋槳、魔法管風琴都改走這條鏈，不再寫死種類
- [ ] 槳 ＝ 一件就是整條鏈（出力＋輸出）（模型 meta kind=oar）：作用點 ＝ 槳座；完好度 ＝ 槳還在 × 槳手到崗比例；不接主機、不接軸；俥鐘照用（倒划 ＝ 後退）。讀數（__game.drive）列每支槳的到崗、輸出
- [ ] 架構不分叉：31_drive.js 不為槳另寫一套推力／受損／偏轉；輸出件的種類（螺旋槳、槳）只決定「完好度怎麼算」和「怎麼畫」。單上列出改了哪幾個函式、各差在哪
- [ ] 槳手：新職位，每支槳一個站位、人數照槳的 meta；倒下 ⇒ 那一支輸出照到崗比例降；預備水手補位，跟補砲班、搬傷員、抽水排好先後（單上寫明誰先）；船隻配置頁看得到人數
- [ ] 偏轉：一舷的槳打掉一半 ⇒ 船往那一舷偏（量給數字：同一場只打掉左舷 vs 只打掉右舷，偏航率正負相反）
- [ ] 動畫：一下 ＝ 前後掃＋入水出水（回槳時槳葉離開水面），不是單純旋轉；同一舷同節奏、槳頻跟俥鐘走、停俥停槳、倒划反著划；斷掉的槳不動。只是畫面：拿掉動畫 ⇒ 戰局對拍逐位元組相同
- [ ] 造船規格：kind=oar 的標法（槳座、槳葉端、槳手數、舷側）寫進造船規格；meta 規格表加一列（admin.py metaspec 對得過）；匯入檢查列每艘的槳數、少標的報 ⚠
- [ ] 改走動力鏈之後，沒有槳的船戰局對拍逐位元組相同（八組；含三艘有螺旋槳、主機、軸的鐵甲艦、風暴角號的管風琴；動力件檢查開 ?drvcheck=1 再對一次）
- [ ] 試做：一艘測試用的槳船（可以是現成船型加幾支槳的測試檔，不用美術）跑一場，量航速 0→90% 的時間、全速航速，跟 cfg.base 對得上（誤差寫出來）
- [ ] 反向對照：把一支槳的槳手設 0 ⇒ 那一支輸出 0、其他照舊
- [ ] 差動轉向（Tim 2026-10-18：「船有左右側動力的話(包含雙螺旋槳) 轉彎時可以停掉一邊動力(甚至倒車)加速轉彎(自動化的 不用手動操作)」）：左右舷都有輸出（雙螺旋槳、兩舷的槳）⇒ 打舵時自動把內側那一舷減出力、舵打得深時倒車；玩家和電腦都自動、不用另外操作。量給數字：同一艘、同一個舵角，開關差動的迴轉半徑與轉 180° 的秒數；只有一舷有輸出或中線單螺旋槳 ⇒ 不作用（戰局不變）

## 任務描述

Tim 2026-10-18：「分析一下 目前的動力架構是否可以支援 划槳(之後打算加入獎帆船) 動力跟鍋爐類似 不過只需要獎跟船員 然後獎需要有合適的動畫(非單純旋轉)」→「開一張划槳的單，照妳的拆法列驗收標準，先不動工」→「如果可以的話 加入槳的架構(可以儘量合併到目前動力系統 只有演出差異) 動力系統目前傳動件應該要是可以省略的(槳不用) 然後動力件本身可以是輸出件(槳)」→「應該說動力有點像一個傳輸鍊 可以是A => B => C => D 也可以直接A包含全部」→「B => C就是傳輸鍊的一環」。

## 設計方向（Tim 拍板）
- **動力 ＝ 一條傳輸鏈**：A ⇒ B ⇒ C ⇒ D（例：鍋爐 ⇒ 主機 ⇒ 軸 ⇒ 螺旋槳；蒸汽管接在鍋爐與主機之間）。每一節是一件動力件，只看三件事：接在誰後面、自己還剩幾成（傳得過去的比例）、自己出不出力（出多少）。不分「傳動件」這一類 —— 軸、蒸汽管跟主機一樣只是鏈上的一節（B ⇒ C 就是其中一環）。
  - **每一節都可以出力，也可以不出**（Tim：「鍊上每一個節點都可以提供動力(也可以不提供)」）：鍋爐、主機出力，軸只傳；同一條鏈上可以有好幾節出力。
  - **最後一節輸出**（推船的那一件：螺旋槳、槳）；只有一節的鏈 ⇒ 它同時出力也同時輸出（Tim：「單節點的話 就是同時提供動力 也同時輸出」）。
  - 中間每一節都可以省略：沒標就不走那一段（現在的「沒標 ⇒ 照舊」變成正式規則）。
  - **一件可以就是整條鏈**（A 包含全部）：槳 ＝ 出力（槳手）也是輸出；魔法的管風琴 ＝ 出力（＋看不見的輸出）。
  - 傳到輸出的動力：從第一節往後走，每一節先把前面傳來的乘上自己的完好度，再加上自己出的力 —— 輸出 ＝ (((A 出力) × B 完好 ＋ B 出力) × C 完好 ＋ C 出力) × D 完好 ＋ D 出力。壞一節，它前面出的力全部少掉，它後面出的照舊。現在的主機 × 軸 × 鍋爐是這條式子的一個特例，改成照鏈走，不寫死「主機、軸、鍋爐」這幾種。
- 併進現在的動力系統，跟螺旋槳同一套，只差演出：槳跟螺旋槳都是「輸出」角色，差在完好度怎麼算（槳：槳手到崗）和怎麼畫（螺旋槳轉、槳划）。
- 軸、蒸汽管這幾節可以省略：沒標就不走那一段（槳不用）。現在的程式已經是「沒標 ⇒ 照舊」，這張要把「只有一節、自己出力自己輸出」也變成一條正式的路，而不是退回「一具看不見的主機」。
- 槳的「燃料」是槳手：完好度 ＝ 槳還在 × 槳手到崗比例（跟鍋爐照剩幾成出汽同一個位置）。

## 現有架構能直接用的（31_drive.js，TASK-0630／0653）
- 動力源清單 sh.drive.P：額外動力每一項有作用點、份量 w、完好度 ok；推力 k·v²、水阻 k·v|v|，最高航速 ＝ √Σv²。槳 ＝ 一項輸出件（同螺旋槳那幾項），每支槳一項、作用點 ＝ 槳座、自己就是動力源（drvBind 不找主機、不找軸）。
- 受損降輸出：完好度合起來是上限，俥鐘要的超過就給到上限 ⇒ 槳斷、槳手倒下自然降速。
- 偏轉：額外動力照 (y − 平衡點) × 推力算力矩 ⇒ 一舷的槳被打掉或槳手倒光，船自然往那一側偏。不用另外寫。
- 俥鐘：9 格比例照用（前進全速 ＝ 衝刺划、停俥 ＝ 停槳、後退 ＝ 倒划），E／T 鍵、電腦一直全速照舊。
- 槳是模型：被打中、有血量、打飛都照現有那一套（打斷槳 ＝ 那一支沒了）。

## 缺的
1. 槳手：新職位（跟砲班同一類：每支槳一個站位、幾個人 ＝ 槳的 meta），倒下 ⇒ 那一支的輸出照到崗比例降、預備水手補位（跟補砲班一起排先後）。鍋爐的角色由「槳手到崗」取代。
2. 動畫：現在的模型只能繞一根軸轉一個角度（modelLocal 的 m.sw／spv／sax：螺旋槳、舵、門、spin 都走這條）。划槳一下是兩個動作疊在一起 —— 前後掃（繞槳座的直立軸）＋ 槳葉入水出水（繞沿船身的水平軸），回槳時槳葉抬起。要讓模型能套一個完整的旋轉（兩軸或一個轉動矩陣），照划槳的相位算；同一舷同一節奏、槳頻跟俥鐘走。照 spin 的原則：只是畫面，模擬照靜止的外框。
3. 造船規格：kind=oar（模型）—— 槳座固定點（轉的中心）、槳葉端、幾個槳手、左右舷；meta 規格表（config/meta_kinds.json）加一列、匯入檢查認得它。
