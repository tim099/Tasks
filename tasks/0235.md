# TASK-0235 — 舊 Treasury 寫帳時同步鏡像一筆到新銀行（雙寫並存期）—— 掛在 UCL_TreasuryLedger 一處

> `feature` / `normal` / `done`　開單：basecamp　參與：basecamp(dev)

## 驗收標準

舊 `Treasury/` 仍是權威（D27 未切）；每一筆錢在寫舊帳本之後，**額外**透過 senate CLI 往新銀行寫一筆同形的帳。
跑一段時間之後拿對帳器逐戶比，確認會同步 —— 那是權威切換（TASK-0216 ⑧-⑩）的前提讀數。

### 形狀（Tim 2026-09-17 說「透過原流程額外去發 senate CLI」；**那個「額外」放在寫帳路徑外面**）
- 實作是 **cursor pull**：`UCL_BankMirror` 讀 ledger 檔、逐筆發 `senate cmd bank`。
  ⛔ **不在 `WriteEntry` 裡 spawn** —— 每次 commit 領薪都會寫帳，而在寫帳路徑上等一顆外部 process，
  等於讓發動 commit 的人等一條跟他無關的鏈。形狀取自既有的 `UCL_DiscordTreasuryMirror`（「寫入端零 spawn」）。
- 鏡像失敗**不准連累舊帳本**：舊的早就落盤了，鏡像只是還沒讀到 ⇒ 那是**結構保證**不是 try/catch。
- 鏡像帶 `idem_key = treasury/<舊分錄 uuid>` ⇒ 重跑不會多一筆。

### 驗收標準
- [x] ① 掛點只有一處，且**新增一個呼叫端不必改鏡像程式碼**（讀數：挑一個既有呼叫端實跑，新銀行那側也跟著多一筆）　✅ basecamp 2026-09-17
- [x] ② 鏡像失敗不連累舊帳本 —— **反向對照**：把 senate 執行檔路徑改成不存在的，舊分錄照樣落盤、回傳照樣成功，而畫面上**看得到**鏡像失敗那一行　✅ basecamp 2026-09-17
- [x] ③ 同一筆重跑 ⇒ 新銀行判重（餘額不動、分錄不多一筆），⛔ 不是多一筆　✅ basecamp 2026-09-17
- [x] ④ 對帳器：一支能把「舊 Treasury 餘額」與「新銀行餘額」逐戶並排、把差額**逐戶點名**的讀數（⛔ 不是一個總差額）　✅ basecamp 2026-09-17
- [x] ⑤ 🧪 用 `Template` persona 實跑一筆真扣款 ＋ 一筆真入帳，兩邊都回讀（Tim 2026-09-08 授權金流實跑用它）　✅ basecamp 2026-09-17
- [x] ⑥ 未綁 persona 的帳戶（`discord:*`／幽靈戶）鏡像時**怎麼處置**要顯式寫下來 —— ⛔ 不是靜默跳過　✅ basecamp 2026-09-17
