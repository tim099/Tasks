## 任務描述

## 為什麼要做

`Cmd_StreamWatch` 已經有 `up=` / `title=` / `desc=` / `url=` 四個場次層參數，
而 code 註解自己寫著「影片介紹（**Tim 之後會隨影片一起給**）」 ⇒ **這四格目前是 Tim 手打的**。
Tim 2026-08-26 提：給一條 bilibili 連結，準備階段就自動把標題／up 主／簡介填好。

## 可行性已驗（summit 2026-08-26 23:0x，Bash 端實打，非推論）

端點 `GET https://api.bilibili.com/x/web-interface/view?bvid=<BV>`，樣本 `BV1PiuJ6XEQ4`：

| 探針 | 讀數 |
|---|---|
| 帶顯式 UA + Referer | `http 200` / `code=0` / 欄位齊全 |
| **不帶 UA**（python 預設） | **HTTP 412 Precondition Failed** |
| 不存在的 BV（`BV1zzzzzzzzzz`） | **`http 200`** / `code=-400`「请求错误」 |
| 格式錯的 BV（`NOTABV`） | `http 200` / `code=-400`（**與上一列完全相同**） |
| `b23.tv` 短連結 | 自動 redirect 到 `www.bilibili.com/video/<BV>/` |

實得欄位：`title` / `owner.{mid,name}` / `desc` / `duration=2337` / `pubdate` / `pic` / `pages[]` / `bvid` / `aid` / `cid`。
⚠ 該樣本的 `desc` 是 `'-'`、`tname` 是空字串。

## 要做什麼

1. `step=prepare` 新增 `--arg url=<bilibili 網址>`：解析出 BV（含 `b23.tv` 短連結 → 跟隨 redirect），
   打 view API，把 `video_title` / `up_name` / `up_mid` / `desc` / `duration` / `pubdate` / `pages` 落進準備檔。
2. 這四格**人有給就以人為準**，只有缺的才自動填；回傳檔要逐格印「這格是誰填的（人／API）」。
3. `start` 沿用準備檔的值（現況 SourceMeta 由 `start` 的 args 供給，改成缺值時讀準備檔）。

## ⛔ 邊界（這些是本單的重點，不是附註）

- **絕對不自動生 media/work slug。** bilibili 的 work 鍵是 `bilibili-<up主 slug>`，
  而本樣本 up 主叫「老宋CHANNEL」—— 中文轉 slug 是**命名決策**不是抓取。
  工具只**建議** slug ＋ 附既有 `bilibili-*` work 清單，**由人確認**。
  （血證：BUG-39 就是同一個鍵在兩處各自長出來、兩邊都不報錯。自動 slug 會把它放大成「每支影片一個 work」。）
- **`up_mid` 要存**：up 主名會改，數字 mid 才是穩定鍵（本樣本 `15418765`）。當旁證存，不當 slug 用。
- **`title` 參數名在兩步是兩個意思**：`prepare` 的 `title`＝作品名（「末日後酒店」），
  `start` 的 `title`＝影片標題。⇒ 自動填的那個叫 **`video_title`**，不共用。
- **判定看 `code==0`，不看 HTTP 狀態**（200 + -400 是失敗）。
  且 -400 同時代表「不存在」與「格式錯」⇒ 回傳檔照實說**B 站沒告訴我是哪一種**，不挑一個。
- **`desc` 三態必須不同形**：有簡介／作者留了 `-`／欄位缺。`-` 不是簡介。
- **抓不到就 blocked**（412／`code!=0`／無網／逾時），印原始 `code` 與 `message`，
  ⛔ 不要靜默留空 —— 空標題會讓開播公告的「📺 本場節目」變成空的，而**公告不可 amend**。
- UA 必填（412 那格就是它）。只讀公開 metadata、GET、不帶 cookie。
