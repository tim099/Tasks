\## ② ⛔ 而這一格我要擋下來：`catch (IOException) when (File.Exists(fullPath))` **分不出撞檔與寫到一半失敗**

你的註解逐字寫著：「⚠ catch 只吃『因為檔案已存在』那一種 IOException —— 磁碟滿 / 路徑失效那類要原樣往上炸，
⛔ 不可以被降級成『撞檔』（那會讓 self-heal 白重試三次，然後報一個錯的成因）。」

**它現在做的正好是你禁止的那件事。** 讀數三格：

**[A] `FileStream(CreateNew)` 一建構，檔案就已經存在了（0 bytes，內容還沒寫）**
```
[A] FileStream(CreateNew) 建構後、寫入前：File.Exists = True；此刻檔長 = 0 bytes
```
⇒ 所以 `when (File.Exists(fullPath))` 這個條件，在**任何**建構之後才發生的 IOException 上都是 **true**。
它問的不是「我是不是撞到別人」，而是「這個路徑上現在有沒有檔」—— 而那顆檔**可能是我自己剛建的**。

**[B] 真的磁碟空間不足（不是我丟的假例外：`SetLength(可用空間 + 64GB)`，NTFS 合法）**
```
[C] 被 `catch (IOException) when (File.Exists)` 吃掉 ⇒ 回報 wrote=false（＝撞檔）
    而真正的成因是：IOException: 磁碟的空間不足。
    往上炸出去了嗎：❌ 沒有（被降級成撞檔）
    這個 seq 的位置留下孤兒檔嗎：✅ 留下了，0 bytes
```

**[C] 於是下游整條路的失效樣子（讀 `UCL_ChatTavernWriteService.cs:102-127`）**
`wrote=false` ⇒ self-heal 白轉 3 次，**每一次都再建一顆 0-byte 孤兒檔**；
而 `CountMessageFiles`（`:689-694`）數的是**檔名不是內容** ⇒ 那幾顆孤兒**永久佔住 seq、且會被 reader 拿去 parse**；
三次之後丟出的例外寫的是「資料層可能真的損壞，需要人工檢查 messages/ 目錄」——
**而真正的成因是磁碟滿。** 那句話會把人送去翻一個沒有壞的目錄。

🩸 **而這是回歸**：舊版 `File.WriteAllText` 在磁碟滿時是**原樣往上炸、成因正確**的。
⇒ 這一格不是「本來就有」，是這次修法換進來的。

\## ③ 修法我量了，不是猜的：兩種例外的 win32 code 不同
